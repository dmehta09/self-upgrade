Interview prep · flashcards

Active-recall flashcards.

Quiz yourself across every module — CI/CD, Docker, Kubernetes, Terraform, AWS, deploy strategies, GitOps, reliability, and DevSecOps. Tap a card to flip; mark it Known or Review. Shuffle and repeat until it sticks.

01 The deck

Recall beats re-reading. Try to answer out loud before flipping — that's the muscle the interview tests.

0/0 known

  • CI vs CD vs continuous deployment?

    CI = auto build + test every change. Continuous delivery = every green build is release-ready, a human approves. Continuous deployment = that release is automatic too.

  • Why "build the artifact once"?

    So the exact bytes tested in staging are what run in prod. Rebuilding per environment breaks that guarantee. Tag by commit SHA and promote unchanged.

  • How should CI authenticate to AWS?

    OIDC federation: the CI provider issues a short-lived token and the pipeline assumes a least-privilege IAM role. No long-lived access keys stored as secrets.

  • What is a flaky test and how do you handle it?

    A test that passes/fails non-deterministically. Quarantine it (non-blocking), file a ticket, fix the root cause (timing/order/shared state). Don't mask it with blanket retries.

  • Image vs container?

    An image is an immutable, layered OCI template. A container is a running instance of that image with its own writable layer and isolated namespaces.

  • What makes a container lightweight vs a VM?

    Containers share the host kernel and isolate with namespaces + cgroups — no guest OS. VMs virtualize hardware and boot a full OS, so they are heavier and slower to start.

  • How do you make a Docker image small and safe?

    Multi-stage build, a minimal base (distroless / -slim / Alpine), run as a non-root USER, copy only what's needed, and scan it (e.g. Trivy) in CI.

  • CMD vs ENTRYPOINT?

    ENTRYPOINT sets the executable that always runs; CMD provides default arguments (or the default command). Args you pass at docker run override CMD.

  • What is a Pod?

    Kubernetes' smallest deployable unit: one or more containers that share a network namespace (same IP) and storage volumes, scheduled together on one node.

  • Deployment vs StatefulSet vs DaemonSet?

    Deployment = stateless replicas with rolling updates. StatefulSet = stable identity + per-pod storage (databases). DaemonSet = exactly one pod per node (agents).

  • What does a Kubernetes Service do?

    Gives a stable virtual IP + DNS name in front of a changing set of pods (matched by labels) and load-balances traffic to them. ClusterIP, NodePort, or LoadBalancer.

  • What is the reconciliation loop?

    Controllers continuously compare actual cluster state to the declared desired state and take action to close the gap. This is what makes Kubernetes self-healing.

  • Liveness vs readiness probe?

    Liveness failing restarts a hung container. Readiness failing pulls the pod out of the Service load balancer until it can serve, without restarting it.

  • What lives in the K8s control plane?

    API server (front door), scheduler (placement), controller-manager (reconcile loops), and etcd (the cluster's source-of-truth key-value store).

  • What is Infrastructure as Code (IaC)?

    Defining infrastructure in version-controlled, declarative files so it's reproducible, reviewable, and automated — instead of clicking in a console.

  • What is Terraform state and why is it sensitive?

    A file mapping your config to real resources. It can contain secrets, so store it remotely with locking (e.g. S3 + DynamoDB) and never commit it to Git.

  • What is configuration drift?

    When real infrastructure no longer matches the IaC state — usually a manual console change. terraform plan surfaces it; re-applying or importing reconciles it.

  • Terraform vs OpenTofu?

    Same workflow and HCL. Terraform moved to the BSL license in 2023 (HashiCorp, now IBM); OpenTofu is the MPL-licensed open-source fork under the Linux Foundation.

  • Security group vs NACL?

    Security group = stateful, instance-level, allow-rules only. NACL = stateless, subnet-level, supports allow and deny. You usually shape access with security groups.

  • ECS/Fargate vs EKS vs Lambda — when?

    ECS/Fargate = simple serverless containers on AWS. EKS = managed Kubernetes when you need its ecosystem/portability. Lambda = event-driven, spiky, pay-per-request work.

  • How do EKS pods get AWS permissions?

    IRSA or EKS Pod Identity: pods assume a scoped IAM role via OIDC, so each workload gets least privilege instead of inheriting broad node-instance credentials.

  • What does an Auto Scaling Group give you?

    It keeps a desired count of EC2 instances healthy, replaces failed ones, and scales in/out on policies — typically across multiple AZs behind a load balancer.

  • Blue-green vs canary deployment?

    Blue-green runs two full environments and flips all traffic at once (instant rollback, double cost). Canary shifts a small % to v2 and widens only if metrics stay healthy.

  • How does a rolling update roll back?

    By rolling the other way — re-deploying the previous ReplicaSet (kubectl rollout undo). It's safe but gradual, not instant like a blue-green traffic flip.

  • What does a feature flag decouple?

    Deploy from release. Code ships dark and you toggle it on per cohort at runtime — enabling progressive rollout and instant kill-switch without a redeploy.

  • What is GitOps?

    A model where Git is the single source of truth for infra/apps and an in-cluster agent (Argo CD, Flux) continuously pulls and reconciles the cluster to match it.

  • Why is pull-based GitOps preferred over push?

    The cluster syncs itself, so no external CI holds prod credentials, and the agent auto-corrects drift back to the Git state. Git history is your audit + rollback log.

  • What are the DORA four keys?

    Deployment frequency, lead time for changes, change-fail rate, and failed-deployment recovery time (MTTR). First two = throughput; last two = stability.

  • What is a blameless postmortem?

    An incident review that treats failure as a systems/process problem, not individual fault — so people share facts honestly. Output is action items, not blame.

  • What is "shift-left" in DevSecOps?

    Moving security earlier — into the pipeline and dev loop: dependency + image scanning (Trivy), SBOMs, secret detection, and least-privilege IAM, caught before prod.

  • What is an SBOM, and why sign artifacts?

    An SBOM (SPDX/CycloneDX) lists every component in a build so you can answer "are we affected?" fast. Signing (cosign/Sigstore) + SLSA proves provenance and integrity.
