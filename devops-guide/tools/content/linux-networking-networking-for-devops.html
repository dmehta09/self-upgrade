Networking for DevOps.

Half of debugging cloud infra is networking: a DNS record that didn't propagate, a security group that drops traffic, a subnet with no route out. Learn how a request really travels from a browser to your pod.

01 The request's journey

A request crosses a chain: DNS turns a name into an IP, TCP/TLS opens a secure pipe, a load balancer picks a healthy target, and a security group decides whether the packet is even allowed in. Break any link and the page won't load.

You rarely configure one box anymore — you configure the path. The visual below is the canonical "what happens when I type the URL" flow, AWS edition.

In plain English analogy

The internet is a postal system. DNS is the address book that turns "example.com" into a street address (an IP). Ports are apartment numbers — the building has one address but many doors (443 for HTTPS, 22 for SSH). TLS is a sealed, tamper-proof envelope so nobody on the route can read or swap the contents. The load balancer is the mailroom that routes each letter to whichever clerk is free.

02 DNS, ports & TCP vs UDP

DNS maps names to addresses; an A record points a name at an IP, a CNAME points a name at another name. Records are cached for their TTL — which is why a DNS change isn't instant. Transport is either TCP (reliable, ordered) or UDP (fast, fire-and-forget).

DimensionTCPUDP
Setup3-way handshake (SYN / SYN-ACK / ACK)None — just send
GuaranteesReliable, ordered, retransmits lossBest-effort; may drop or reorder
CostHigher latency, more overheadLow latency, lightweight
Used byHTTP/HTTPS, SSH, most APIsDNS queries, video/VoIP, some gaming

A port is the door number on a host: HTTPS on 443, HTTP on 80, SSH on 22. HTTPS = HTTP over TLS — the TLS handshake presents a certificate (proves the server is who it claims), uses SNI to say which hostname you want (so one IP can serve many certs), and yields an encrypted channel. That's the "why HTTPS": authenticity + privacy + tamper-resistance.

dns.sh
dig shop.example.com +short      # the A/ALIAS record -> an IP
dig shop.example.com CNAME       # is it an alias to another name?
curl -v https://shop.example.com 1>/dev/null   # watch TCP + TLS handshake

03 CIDR, subnets, NAT & load balancers

A CIDR block like 10.0.0.0/16 defines an IP range; the number after / is how many bits are fixed as the network prefix. A VPC is split into public subnets (route to the internet) and private subnets (no inbound from the internet — outbound via NAT).

Read a CIDR by the prefix: a /24 fixes 24 bits, leaving 8 for hosts → 256 addresses (≈ 251 usable in AWS, which reserves 5). A /16 leaves 16 host bits → ~65,536 addresses. Smaller prefix number = bigger network.

/16
~65,536 addresses — a whole VPC.
/24
256 addresses — a typical single subnet.
Public subnet
Has a route to an Internet Gateway; resources can be reached from / reach the internet.
Private subnet
No inbound from internet. Outbound (e.g. pulling images) goes through a NAT gateway in a public subnet.

Load balancers split by layer. An NLB is L4 (transport): it forwards raw TCP/UDP by IP and port, ultra-fast, no idea what HTTP is. An ALB is L7 (application): it reads the HTTP request and routes by path or host (/api → one target group, /img → another), terminates TLS, and does header-based routing.

NLB — Layer 4
  • Routes on IP + port only.
  • Doesn't read HTTP; can't path-route.
  • Extreme throughput, low latency, static IPs.
  • Use for: TCP/UDP, gRPC, raw sockets.
ALB — Layer 7
  • Reads HTTP host, path, headers.
  • Path/host routing, TLS termination, redirects.
  • Slightly more overhead, far more routing power.
  • Use for: HTTP/HTTPS web services (the default).

04 Firewalls: security groups vs NACLs

AWS gives you two firewalls. Security groups wrap a resource (an instance/ENI) and are stateful — if you allow a request out or in, the return traffic is automatically allowed. NACLs wrap a subnet and are stateless — you must allow both directions explicitly.

Security groupNACL
Attaches toAn instance / ENIA subnet
StateStateful — return traffic auto-allowedStateless — must allow both ways
RulesAllow onlyAllow and deny, evaluated in order
DefaultDeny all inbound, allow all outboundDefault NACL allows all both ways
Common trap gotcha

Security groups are stateful; NACLs are stateless — one of the most common interview confusions. With a security group, allowing inbound 443 means the response goes back out automatically. With a NACL you must also allow the outbound ephemeral port range (≈ 1024–65535) or replies get silently dropped. Reach for security groups by default; use NACLs as a coarse, subnet-wide backstop.

You add a security group rule allowing inbound TCP 443 to your instance, but add no outbound rule. Can it reply to web requests?

Right. Statefulness is the whole point of a security group: it tracks the connection, so replies on an established inbound connection flow back without an explicit outbound rule. (Default outbound is allow-all anyway.) That manual return-path bookkeeping is a NACL concern, not a security-group one.

05 Interview rapid-fire

What's the difference between an L4 and an L7 load balancer?core
Model answer

An L4 load balancer (AWS NLB) works at the transport layer — it forwards TCP/UDP based only on IP and port, doesn't understand HTTP, and is built for raw throughput and low latency. An L7 load balancer (AWS ALB) works at the application layer — it parses the HTTP request and can route by path, host, or headers, terminate TLS, and do redirects. Rule of thumb: ALB for HTTP services that need smart routing; NLB for raw TCP/UDP, gRPC, or extreme performance with static IPs.

Say it out loud say it

"L4 — the NLB — routes raw TCP/UDP by IP and port, blazing fast but HTTP-blind. L7 — the ALB — reads the HTTP request and routes by path or host and terminates TLS. ALB for web, NLB for raw throughput."

How do you read a CIDR block like 10.0.1.0/24?warm-up
Model answer

The /24 means the first 24 bits are the fixed network prefix, leaving 8 bits for hosts — so 2⁸ = 256 addresses, from 10.0.1.0 to 10.0.1.255 (AWS reserves 5, so ~251 usable). A smaller number means a bigger range: a /16 leaves 16 host bits, ~65,536 addresses — usually a whole VPC. So you'd carve a /16 VPC into several /24 subnets.

Say it out loud say it

"The slash number is fixed network bits; 32 minus it is host bits. A /24 leaves 8 host bits — 256 addresses, one subnet. A /16 is a whole VPC. Smaller number, bigger network."

Follow-ups to expect
  • How many usable hosts in a /28? (16 total, 11 usable after AWS's 5 reserved.)
  • Why must subnet CIDRs not overlap? (Routing becomes ambiguous; AWS rejects overlaps within a VPC.)
Security group vs NACL — when does the difference bite?stretch
Model answer

A security group attaches to an instance/ENI and is stateful — allow an inbound connection and its return traffic is automatically permitted, so you mostly write inbound rules. A NACL attaches to a subnet, is stateless, and supports explicit deny rules evaluated in order — so for any allowed inbound you must also allow the outbound ephemeral ports, or replies vanish. The classic bug: traffic works until someone adds a restrictive NACL and forgets the return path. Default to security groups; use NACLs as a coarse subnet-level guardrail (e.g. block a bad CIDR).

Say it out loud say it

"Security groups are stateful and per-instance, allow-only — return traffic is automatic. NACLs are stateless and per-subnet, support deny, and need both directions opened. I default to security groups and use NACLs as a coarse subnet backstop."
