Kubernetes · packaging

Helm & Kustomize packaging.

Raw YAML doesn't scale across environments. Helm packages apps as versioned charts with values; Kustomize layers patches over a base. Most teams use one as the primary, and often both at the edges.

01 Why packaging exists

You need the same workload in staging and prod with different replicas, images, and secrets — without copy-paste drift. Packaging tools generate or overlay the final manifests the cluster applies (often via GitOps).

In plain English analogy

Helm is a recipe card with blanks ("servings," "oven temp") you fill per dinner. Kustomize is the same photo of a plated dish with sticky notes for "double the salt in prod" — you keep the base photo and layer edits.

02 Helm charts

A chart is a versioned package: templates + values.yaml + Chart.yaml. helm install/upgrade renders templates and talks to the API server (or you render and hand YAML to Argo CD).

values.yaml
Defaults; override per env with -f values-prod.yaml or --set.
Templates
Go-templated Kubernetes manifests under templates/.
Release
A named install of a chart in a namespace — Helm tracks revision history for rollback.
OCI / repos
Charts published as OCI artifacts or classic chart repos.
values-prod.yaml
replicaCount: 4
image:
  tag: "1.8.2"
resources:
  requests: { cpu: 250m, memory: 256Mi }
ingress:
  enabled: true
  host: api.example.com

03 Kustomize overlays

Kustomize (built into kubectl -k) keeps plain YAML in a base/ and applies strategic patches / images / replicas in overlays/staging and overlays/prod. No template language — diffs stay readable.

overlays/prod/kustomization.yaml
resources:
  - ../../base
images:
  - name: ghcr.io/acme/api
    newTag: "1.8.2"
replicas:
  - name: api
    count: 4

04 When each wins

HelmKustomize
StrengthPackaging/sharing apps; complex optionality; ecosystem chartsEnv overlays; GitOps-friendly plain YAML; small diffs
CostTemplate logic can hide intent; values sprawlAwkward for highly optional features; less "app store"
Common comboVendor Helm chart → helm template → Kustomize overlay for your cluster
Gotcha trap

Don't maintain three full copies of every manifest "because GitOps." Either chart values or overlays should be the single place env differences live. Pin chart versions; never latest in prod.

05 Check yourself

You consume a third-party operator chart but need your own NetworkPolicies and replica counts. Sensible approach?

Right. Charts are for distribution; overlays/values are for your env deltas. Forking every upstream chart is how drift and CVE lag explode.
