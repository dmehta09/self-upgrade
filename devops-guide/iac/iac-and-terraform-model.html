IaC · the model

IaC & the Terraform model.

Infrastructure as Code means your servers, networks, and databases are defined in version-controlled code and applied repeatably — not clicked together by hand. Terraform is the dominant tool, and interviewers probe how its plan / apply / state model actually works.

01 Code, not clicks

IaC = your infrastructure described in version-controlled code and provisioned repeatably by a tool. The opposite is ClickOps: building it by hand in the console — unrepeatable, undocumented, and impossible to review.

The code is the single source of truth. To stand up an identical staging environment you re-run the same files; to audit a change you read the diff in a pull request. No tribal knowledge, no "who turned this on in 2023?"

In plain English analogy

IaC is a blueprint plus a robot builder. You write the blueprint (the code); the robot (Terraform) reads it and constructs the building exactly as drawn — and will rebuild an identical one on demand. ClickOps is hand-assembling each room with no drawings: nobody can reproduce it, and nobody remembers why the wiring looks like that.

ClickOps (console by hand)
  • Steps live in someone's head, not in Git.
  • Prod and staging silently drift apart.
  • No diff, no review, no rollback.
  • "Recreate it" = a day of archaeology.
Infrastructure as Code
  • Every change is a reviewed commit.
  • Spin up an identical env from the same files.
  • Audit trail and blame log for free.
  • Tear down and rebuild on demand.

02 Declarative vs imperative

Terraform is declarative: you describe the desired end state, and the tool computes the diff to get there. Imperative means you write the ordered steps yourself.

Declarative is convergent — run it twice and the second run is a no-op, because reality already matches the desired state. You say "I want 3 instances," not "create an instance" three times and hope you counted right.

Declarative
"I want this end state." The tool figures out create/update/destroy. Terraform, CloudFormation, Kubernetes manifests.
Imperative
"Do these steps in this order." You own the logic and the idempotency. A raw aws ec2 run-instances script.
Why it matters
Declarative is idempotent by design — the diff is computed from current vs desired, so re-applying is safe.
Heads up nuance

Ansible is mostly imperative-feeling (ordered tasks) but strives for idempotent modules; it's used for configuring machines. Terraform is for provisioning cloud resources. Different jobs — interviewers like that you know the split.

03 The Terraform model: plan → apply → state

Terraform connects to a cloud through a provider (e.g. aws). You declare resources in HCL. terraform plan previews the exact diff; terraform apply makes it real and records what it built in the state file.

main.tf
provider "aws" {
  region = "us-east-1"
}

resource "aws_instance" "web" {
  ami           = "ami-0abc123"
  instance_type = "t3.micro"
  tags = { Name = "web-1" }
}

State is updated after apply, then read on the next plan to compute the new diff. It's the as-built record.

The state file (terraform.tfstate) maps your code to the real cloud resources — their IDs, attributes, dependencies. It is Terraform's source of truth for what it manages; without it, Terraform has no idea which resources are "its."

Common trap gotcha

Two traps with state. (1) Never hand-edit a Terraform-managed resource in the console — reality no longer matches state, so the next plan wants to "fix" your manual change. That mismatch is called drift. (2) The state file can contain secrets (DB passwords, keys) in plaintext, so it must be stored remotely and encrypted, never committed to Git — covered on the next page.

04 The ecosystem: Terraform, OpenTofu & AWS-native

Interviewers in 2026 expect you to know the license split. HashiCorp relicensed Terraform to the BSL (Business Source License) in 2023; IBM then acquired HashiCorp. The community forked the last open version into OpenTofu.

ToolWhat it isLicense / owner
TerraformThe original, cloud-agnostic IaC tool (HCL).BSL since 2023; HashiCorp, now owned by IBM.
OpenTofuOpen-source fork of Terraform; near drop-in compatible.MPL (open source), under the Linux Foundation.
CloudFormationAWS-native declarative IaC (YAML/JSON), AWS-only.AWS managed service; no state file to host.
CDKDefine AWS infra in real code (TypeScript/Python); synthesizes to CloudFormation.AWS, open source.
Terraform vs CloudFormation
Terraform is multi-cloud and has its own state to manage; CloudFormation is AWS-only and AWS manages the state for you.
Terraform vs OpenTofu
Same language and model; the difference is licensing/governance (BSL vs open MPL), not capability.

What does terraform plan do?

Right. plan is the architect showing you precisely what will be created, changed, or destroyed before any construction. Nothing changes until apply — which is exactly why you review the plan in a PR.

05 Interview rapid-fire

Why use Infrastructure as Code instead of the console?warm-up
Model answer

Because IaC makes infrastructure repeatable, reviewable, and auditable. It lives in Git, so every change is a reviewed commit with history and rollback; you can stand up identical environments from the same files; and there's no undocumented tribal knowledge. ClickOps drifts and can't be reproduced.

Say it out loud say it

"Clicking in the console is unrepeatable and undocumented. With IaC the infra is code in Git — reviewed, versioned, and reproducible — so staging and prod actually match and I can rebuild from scratch."

Declarative vs imperative — and what is the Terraform state file?core
Model answer

Declarative means you describe the desired end state and Terraform computes the diff (idempotent — re-running is safe). Imperative means you write the ordered steps yourself. The state file (terraform.tfstate) maps your code to the real cloud resources and their attributes; it's Terraform's source of truth for what it manages, and it's how plan knows what already exists.

Say it out loud say it

"Declarative: I declare the end state, the tool figures out the steps and it's idempotent. State is Terraform's record of code-to-real-resource mappings — drop it and Terraform forgets what it owns."

Follow-ups to expect
  • What is drift? (Real infra diverging from state — usually a manual console change — so plan wants to revert it.)
  • Why must state be remote? (It holds secrets in plaintext and must be shared + locked across a team.)
Terraform vs CloudFormation, and Terraform vs OpenTofu?stretch
Model answer

Terraform vs CloudFormation: Terraform is cloud-agnostic and manages its own state; CloudFormation is AWS-only and AWS hosts the state for you. Terraform vs OpenTofu: OpenTofu is the open-source (MPL, Linux Foundation) fork created after HashiCorp relicensed Terraform to the BSL in 2023 and was later acquired by IBM — same model and HCL, the difference is licensing and governance.

Say it out loud say it

"CloudFormation is AWS-only with managed state; Terraform is multi-cloud and you manage state. OpenTofu is the open MPL fork after Terraform went BSL — same HCL, different license."
