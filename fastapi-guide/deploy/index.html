Ship it · testing & deployment

Prove it works, then put it online.

The final mile: write automated tests so you can change code with confidence, then run your app in production. FastAPI makes testing genuinely pleasant, and deployment is just “run uvicorn somewhere.”

01  Testing with TestClient

FastAPI's TestClient calls your app in-process — no running server, no network — so tests are fast and reliable. It's backed by httpx, and you run the suite with pytest.

test_main.py
# pip install pytest httpx
from fastapi.testclient import TestClient
from main import app

client = TestClient(app)

def test_read_root():
    response = client.get("/")
    assert response.status_code == 200
    assert response.json() == {"message": "Hello, FastAPI"}

def test_create_item():
    response = client.post("/items", json={"name": "Wand", "price": 9.99})
    assert response.status_code == 201
    assert response.json()["name"] == "Wand"

def test_validation_error():
    response = client.post("/items", json={"price": 9.99})   # missing name
    assert response.status_code == 422
    assert response.json()["detail"][0]["loc"] == ["body", "name"]

Run them with pytest. Each test_* function is a test; an assert that fails marks it red.

02  A throwaway test database

Tests shouldn't touch your real database. Use app.dependency_overrides to swap the session dependency for one backed by a fresh in-memory SQLite — this is where the yield dependency from earlier pays off.

test_heroes.py
from sqlmodel import SQLModel, Session, create_engine
from sqlmodel.pool import StaticPool
from fastapi.testclient import TestClient
from main import app, get_session

# a private in-memory database for the test
test_engine = create_engine(
    "sqlite://", connect_args={"check_same_thread": False}, poolclass=StaticPool,
)
SQLModel.metadata.create_all(test_engine)

def override_get_session():
    with Session(test_engine) as session:
        yield session

app.dependency_overrides[get_session] = override_get_session   # swap it
client = TestClient(app)

def test_create_hero():
    r = client.post("/heroes", json={"name": "Deadpond"})
    assert r.status_code == 201
    assert r.json()["name"] == "Deadpond"
This is why dependencies matter

Because your routes ask for the database via Depends(get_session) instead of reaching for a global, you can replace it in one line for tests. Loose coupling pays off.

03  Running in production

In development you used fastapi dev (auto-reload). In production you want multiple worker processes and no reload:

terminal
# simplest: the FastAPI CLI in production mode
fastapi run main.py --workers 4

# or call uvicorn directly
uvicorn main:app --host 0.0.0.0 --port 80 --workers 4

# classic combo: gunicorn managing uvicorn workers
gunicorn main:app -k uvicorn.workers.UvicornWorker -w 4 -b 0.0.0.0:80

Workers = roughly your number of CPU cores. Put a reverse proxy (nginx, or your platform's load balancer) in front for TLS and static files.

04  A Dockerfile

Containerizing makes “works on my machine” work everywhere. A minimal image:

Dockerfile
FROM python:3.13-slim

WORKDIR /code
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .

EXPOSE 80
CMD ["fastapi", "run", "main.py", "--port", "80"]

Build and run: docker build -t hero-api . then docker run -p 80:80 hero-api.

05  Before you ship — a checklist

Secrets in env
No keys in code. Load SECRET_KEY, DB URLs, etc. from environment variables / a secrets manager.
Real database
Swap SQLite for PostgreSQL (just the connection string), and manage schema changes with Alembic migrations.
CORS
Set allow_origins to your actual front-end domains — not "*" in production.
Disable reload
Run with workers, no --reload. Set log level appropriately.
HTTPS
Terminate TLS at a proxy or your platform. Never serve auth over plain HTTP.
Tests green
pytest passes in CI before every deploy.
