Python · typing in depth

The type system FastAPI runs on.

The refresher covered basic hints. Now the toolkit you'll actually reach for in real backends: unions and literals, generics with TypeVar, Protocols for duck-typed interfaces, and Annotated — the construct FastAPI uses to attach Query, Path, and Depends to a parameter.

01  Why typing matters here

Python doesn't enforce type hints at runtime — but two things do read them. A type checker (like mypy or your editor) catches mistakes before you run. And Pydantic/FastAPI turn your hints into real, runtime validation. So in a FastAPI codebase, hints aren't decoration — they're behavior.

Two readers, two payoffs

The type checker gives you red squiggles in your editor. FastAPI gives you parsing, validation, and docs. Same annotations, doing double duty — which is why investing in them pays off twice.

02  Optional, Union & Literal

Plain English: sometimes a value can be one of several types, or one of a few specific values.

The everyday vocabulary
int | str
a union — an int or a string (the modern way to write Union[int, str])
str | None
“optional” — a string or nothing (older name: Optional[str])
Literal["left", "right"]
only these exact values are allowed
Final
a constant — must not be reassigned

Literal becomes a dropdown in your docs

Declare a query parameter as Literal["asc", "desc"] and FastAPI both validates it and renders a neat enum picker in /docs. The type is the spec.

03  Collection & Callable generics

Container types take a parameter in square brackets to say what's inside: list[int], dict[str, float], tuple[int, str]. And functions themselves have a type — Callable[[ArgTypes], ReturnType] — so you can annotate a function that takes another function.

04  TypeVar & Generic

What if a function or class works with any type, but you want to say “whatever goes in is what comes out”? A type variable (T) is a placeholder the checker fills in per call. A Box[int] gives back an int; a Box[str] gives back a str — one class, type-safe for all.

generic.py
123 hello
int str
You've seen generics already

list[int] is a generic — list parameterized by int. TypeVar just lets you write your own generic helpers, like a paginated Page[T] response model that works for users, items, or anything else.

05  Protocol — structural typing

Normally a type relationship needs inheritance. A Protocol flips that: it says “anything with these methods qualifies, no inheritance required.” This is structural typing — also called duck typing, checked. If it has a speak() method, it's a Speaker.

protocol.py
woof
beep
“If it quacks like a duck” analogy

A Protocol doesn't ask “what are you?” — it asks “what can you do?” Any object shaped right fits the slot. It's how you depend on capabilities (a thing that can .read()) instead of on a specific class.

06  TypedDict & Annotated

TypedDict describes the shape of a plain dictionary — useful when JSON-ish dicts flow through your code but you still want key/type checking. At runtime it's just a dict.

typeddict.py
Up 2009
dict

Annotated attaches metadata to a type: Annotated[T, extra] reads as “this is a T, and here's some extra info about it.” That's the exact hook FastAPI uses to bolt validation and dependencies onto a parameter:

annotated.py
from typing import Annotated
from fastapi import FastAPI, Query, Depends

app = FastAPI()

@app.get("/search")
def search(
    q: Annotated[str, Query(min_length=2, max_length=50)],   # type + rules
):
    return {"q": q}

# Annotated is also how dependencies attach:  Annotated[User, Depends(get_user)]

What does Annotated[str, Query(max_length=50)] mean?

Right. Annotated keeps the base type (str) while carrying extra instructions. FastAPI reads that metadata to validate input and document the parameter — without changing the type itself.
Exercise

Using a TypeVar, write a generic last(items) that returns the last element of a list — keeping the element's type.

last([1, 2, 3]) should give 3; last(["x", "y", "z"]) should give "z".

(write your solution and press Run)
Show solution solution
solution.py
from typing import TypeVar

U = TypeVar("U")

def last(items: list[U]) -> U:
    return items[-1]

print(last([1, 2, 3]))         # 3   (checker knows: int)
print(last(["x", "y", "z"]))   # z   (checker knows: str)

Because the return type is the same U as the list's elements, a type checker infers last([1,2,3]) is an int and last(["x"]) is a str — no casting, no Any.
