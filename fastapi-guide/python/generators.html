Python · generators & context managers

Produce values lazily, clean up reliably.

Two related superpowers. Generators hand back a sequence one item at a time, on demand, without building the whole thing in memory. Context managers (the with statement) guarantee setup-then-teardown. They meet in FastAPI's yield dependencies and streaming responses — so this page is the “why” behind both.

01  Iterables vs iterators

An iterable is anything you can loop over — a list, string, or dict. An iterator is the object that actually walks through it, producing one item each time you call next(). A for loop does this for you: it calls iter() to get an iterator, then next() over and over until there's nothing left.

iterator.py
10
20
30
for hides this dance

You almost never call iter()/next() by hand — for x in nums: does it. But knowing the mechanism explains how an infinite sequence can still be looped over safely: items are pulled only when asked for.

02  Generators & yield

The easiest way to make an iterator is a generator function: write yield instead of return. Each yield hands back one value and pauses the function, keeping all its local state; the next next() resumes right where it left off. Nothing is computed until it's asked for.

gen.py
3
2
1
[5, 4, 3, 2, 1]
A vending machine, not a warehouse analogy

A list is a warehouse — everything stocked up front, taking space. A generator is a vending machine: it makes the next item only when you press the button. Perfect when the full sequence is huge, or never-ending.

03  Generator expressions & laziness

A generator expression looks like a list comprehension but with parentheses. It produces values lazily — one at a time — so it can feed sum(), max(), or a loop without ever materializing the whole list. The itertools module is a toolbox of these lazy building blocks, including ones that work on infinite streams.

lazy.py
generator
55
[10, 11, 12]
A generator is single-use

Once consumed, it's empty — iterate it again and you get nothing. If you need the values twice, capture them in a list(...) first. This trips up everyone once.

04  The with statement

A context manager borrows a resource and guarantees it's released — even if an exception is thrown. The everyday example is files: with open(...) as f: closes f automatically when the block ends, so you never leak a file handle.

The exit step runs whether the body succeeded or raised — just like a finally.

05  Writing your own context manager

Two ways to build one. The easy way: a generator decorated with @contextmanager — code before yield is setup, the yielded value is what as binds, and code after yield (ideally in a finally) is teardown. If that shape looks familiar, it should: it's exactly a FastAPI yield dependency.

cm.py
open session
using ada
close session

The explicit way is a class with __enter__ and __exit__ — same behavior, more ceremony:

class_cm.py
class Session:
    def __enter__(self):
        print("open session")
        return {"user": "ada"}        # what 'as s' receives
    def __exit__(self, exc_type, exc, tb):
        print("close session")        # runs even if the body raised

with Session() as s:
    print("using", s["user"])

In a @contextmanager generator, when does the code after yield run?

Right. Setup runs up to yield; the block runs with the yielded value; then teardown runs after. This is precisely how FastAPI's yield dependencies open and close a database session per request.
You've now seen the whole FastAPI plumbing

A yield dependency is this pattern, run per request. App lifespan uses the async cousin @asynccontextmanager. And a streaming response is just a generator yielding chunks. Three FastAPI features, one Python idea.

Exercise

Write a generator evens(limit) that yields even numbers from 0 up to (but not including) limit.

list(evens(10)) should produce [0, 2, 4, 6, 8].

exercise.py
(write your solution and press Run)
Show solution solution
solution.py
def evens(limit):
    n = 0
    while n < limit:
        yield n
        n += 2

print(list(evens(10)))   # [0, 2, 4, 6, 8]

# Bonus — a lazy generator expression does it in one line:
print(list(n for n in range(10) if n % 2 == 0))

The generator yields each even number on demand. The bonus line shows the same idea as a generator expression — lazy by default, materialized with list(...).
