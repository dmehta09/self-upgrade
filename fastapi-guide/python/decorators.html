Python · decorators & closures

Functions that wrap functions.

A decorator is a function that takes another function and returns an enhanced version of it — that's the @something line you've already seen on @app.get and @field_validator. To really get decorators, we build up through two ideas first: functions as values, and closures.

01  Functions are objects

In Python a function is just another value. You can store it in a variable, pass it to another function, or return it — all without calling it. The trick: shout is the function; shout() calls it. Leave off the parentheses and you're handling the function itself.

first_class.py
HELLO!
HI!
A recipe card vs cooking the meal analogy

shout is the recipe card — you can hand it to someone (pass it around) or photocopy it (assign it). shout("hi") is actually cooking the dish. Decorators work by passing recipe cards around before anyone cooks.

02  Closures

A function defined inside another can keep using the outer function's variables even after the outer function has returned. That captured, remembered state is a closure. It's the mechanism that lets a decorator's inner wrapper remember the function it's wrapping.

closure.py
20
30
double and triple are independent

Each call to multiplier creates a fresh closure with its own captured factor. That's why double and triple don't interfere — each remembers its own value.

03  Writing a decorator

Now combine the two: a decorator takes a function, defines a wrapper (a closure that remembers it), and returns the wrapper. The @logged line above a definition is pure shorthand — add = logged(add). The *args, **kwargs let the wrapper forward any arguments through.

decorator.py
calling add
-> 5
add
Don't forget functools.wraps

Without it, the wrapped add would report its name as "wrapper" and lose its docstring — which breaks debugging and, in FastAPI, can confuse tools that introspect your functions. Always wrap the wrapper.

04  Decorators with arguments

How does @app.get("/items") take an argument? With one more layer: an outer function takes the option(s) and returns a decorator. So @repeat(times=3) first calls repeat(times=3), which returns the real decorator that then wraps your function.

05  Stacking decorators

You can apply several decorators to one function. They stack from the bottom up: the one closest to the def wraps it first. Reading the example below, it's exactly exclaim(shout(greet)).

stack.py
HI!

The line @logged written above def add(...) is shorthand for what?

Exactly. A decorator replaces the name with the result of calling the decorator on the original function. That single idea explains every @ you'll ever read.
FastAPI is decorators all the way down

@app.get("/") is a decorator-with-arguments that registers your function as a route. @field_validator("name") registers a validator on a Pydantic model. You now know precisely what those lines do.

routes.py
from fastapi import FastAPI

app = FastAPI()

@app.get("/items")        # decorator with an argument: registers this route
def list_items():
    return [{"id": 1}]
# same as: list_items = app.get("/items")(list_items)
Exercise

Write a decorator squared that squares whatever a function returns.

With @squared on an add(a, b) function, add(2, 3) should give 25 (because (2+3)**2). Use *args, **kwargs so it works on any function.

exercise.py
(write your solution and press Run)
Show solution solution
solution.py
import functools

def squared(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs) ** 2
    return wrapper

@squared
def add(a, b):
    return a + b

print(add(2, 3))   # (2 + 3) ** 2 = 25

The wrapper calls the original func, then squares its result before returning. Because of *args, **kwargs, the same decorator works on any function regardless of its signature.
