FastAPI · validation & errors

Reject bad input, clearly.

FastAPI's automatic validation is its superpower. Here you'll add precise constraints, write custom validators, learn to read the 422 error envelope it returns, and raise your own errors with HTTPException.

01  Field constraints

Beyond the type, Field(...) adds rules. Numbers get ge/gt/le/lt; strings get min_length/max_length/pattern; lists get length bounds.

constraints.py
from pydantic import BaseModel, Field

class SignUp(BaseModel):
    username: str = Field(min_length=3, max_length=20)
    age: int = Field(ge=18, description="must be an adult")
    email: str = Field(pattern=r"^[^@]+@[^@]+\.[^@]+$")
It's pattern, not regex

Pydantic v2 renamed the regex constraint to pattern. Old v1 code using regex=... will error. (For real email validation, install pydantic[email] and use the EmailStr type instead of a hand-rolled pattern.)

02  Custom validators

When a rule needs logic, use @field_validator. It runs after type coercion and can transform the value or raise an error.

validators.py
from pydantic import BaseModel, field_validator

class User(BaseModel):
    username: str

    @field_validator("username")
    @classmethod
    def no_spaces(cls, v: str) -> str:
        if " " in v:
            raise ValueError("username cannot contain spaces")
        return v.lower()       # validators can also normalize

03  The 422 envelope, dissected read this

When validation fails, FastAPI returns HTTP 422 Unprocessable Entity with a body shaped like this. Learn to read it once and every future error makes sense:

422 response
{
  "detail": [
    {
      "type": "greater_than_equal",   // WHAT rule failed
      "loc": ["body", "age"],          // WHERE  (source, then field)
      "msg": "Input should be greater than or equal to 18",
      "input": 15                       // the value you sent
    }
  ]
}
type
A machine-readable slug for the failure: missing, int_parsing, string_too_short, greater_than_equal, string_pattern_mismatch…
loc
The location. First element is the source (body/query/path), then the field name(s).
msg
A human-readable explanation.
input
The exact value that was rejected — great for debugging.

You can produce this same list yourself from Pydantic with ValidationError.errors(). Run it:

errors.py · runs real Pydantic v2
('username',) string_too_short - String should have at least 3 characters
('age',) greater_than_equal - Input should be greater than or equal to 18

04  Raising your own errors

Validation handles bad input. For business errors — “that item doesn't exist”, “you're not allowed” — raise an HTTPException with the status code and message you want.

errors.py
from fastapi import FastAPI, HTTPException

app = FastAPI()
items = {1: "Wand"}

@app.get("/items/{item_id}")
def get_item(item_id: int):
    if item_id not in items:
        raise HTTPException(status_code=404, detail="Item not found")
    return {"item_id": item_id, "name": items[item_id]}

# GET /items/999 -> 404 {"detail": "Item not found"}
Need site-wide error shaping?

You can register an exception handler with @app.exception_handler(...) to customize how any error (including the 422) is rendered. Most apps never need to — the defaults are good.
