FastAPI · dependency injection

Reusable plumbing, declared not wired.

A dependency is a function FastAPI runs before your endpoint and passes the result in. It's how you share logic — pagination params, “get the current user”, a database session — across many routes without copy-paste. Declare what you need; FastAPI provides it.

01  What & why

Imagine ten endpoints that all need the logged-in user. Without dependencies you'd repeat the “read the token, look up the user, reject if invalid” code ten times. A dependency lets you write it once and just ask for it.

Like ordering ingredients, not cooking them analogy

Your endpoint is a recipe that says “I need a prepped onion.” The dependency is the prep cook who peels and dices it. The recipe never worries about how the onion got prepped — it just receives it ready to use.

02  Annotated + Depends

The modern pattern: annotate a parameter with Annotated[ReturnType, Depends(the_function)]. FastAPI calls the_function (parsing its parameters from the request too) and injects the result.

deps.py
from typing import Annotated
from fastapi import FastAPI, Depends

app = FastAPI()

# a dependency is just a function
def pagination(skip: int = 0, limit: int = 10) -> dict:
    return {"skip": skip, "limit": limit}

# name the type once, reuse it everywhere
PageParams = Annotated[dict, Depends(pagination)]

@app.get("/items")
def list_items(page: PageParams):
    return {"page": page}

@app.get("/users")
def list_users(page: PageParams):    # same logic, zero duplication
    return {"page": page}
Make a type alias

Defining PageParams = Annotated[...] once and reusing it keeps signatures short and readable. You'll see SessionDep and CurrentUser aliases used the same way on the next pages.

03  Reusable dependencies

Dependencies can do real work and raise errors. A classic is “get the current user, or reject” — used to protect routes:

auth_dep.py
from typing import Annotated
from fastapi import Depends, Header, HTTPException

def get_current_user(x_token: Annotated[str | None, Header()] = None) -> str:
    if x_token != "secret":
        raise HTTPException(status_code=401, detail="Invalid token")
    return "ada"          # in reality: decode the token, load the user

CurrentUser = Annotated[str, Depends(get_current_user)]

@app.get("/me")
def read_me(user: CurrentUser):
    return {"user": user}      # only reached if the token was valid

04  Sub-dependencies

Dependencies can depend on other dependencies. FastAPI resolves the whole chain for you and caches each one within a single request, so a shared dependency runs only once even if several things need it.

sub.py
def get_db_user(user: CurrentUser) -> dict:        # depends on get_current_user
    return {"name": user, "is_admin": user == "ada"}

def require_admin(account: Annotated[dict, Depends(get_db_user)]) -> dict:
    if not account["is_admin"]:
        raise HTTPException(status_code=403, detail="Admins only")
    return account

@app.delete("/items/{id}")
def delete_item(id: int, admin: Annotated[dict, Depends(require_admin)]):
    return {"deleted": id, "by": admin["name"]}

05  Dependencies with yield important

A dependency that yields can run teardown code after the response is sent — perfect for opening a resource, using it, then closing it. This is exactly how database sessions are managed (next page).

yield_dep.py
def get_session():
    session = open_session()      # setup, before the endpoint
    try:
        yield session             # the endpoint runs with this value
    finally:
        session.close()           # teardown, after the response

SessionDep = Annotated[Session, Depends(get_session)]

@app.get("/items")
def list_items(session: SessionDep):
    return session.query(...)     # session is auto-closed afterwards

When does the code after yield in a dependency run?

Right. Everything before yield is setup; the yielded value is injected; the code after yield (typically in a finally) runs once the response is done. That's how sessions get reliably closed.
