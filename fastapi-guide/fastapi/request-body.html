FastAPI · request body & models

Accepting data, the typed way.

Path and query params are fine for small bits of data. To send a whole object — creating an item, signing up a user — you send a request body (JSON). In FastAPI you describe that body with a Pydantic model, and validation comes free.

01  Request bodies

Declare a function argument whose type is a Pydantic model, and FastAPI reads the JSON body, validates it against the model, and hands you a ready-to-use object.

main.py
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class Item(BaseModel):
    name: str
    price: float
    tags: list[str] = []          # default -> optional

@app.post("/items")
def create_item(item: Item):       # body is parsed & validated into `item`
    return {"received": item.name, "total": item.price}

Send {"name": "Wand", "price": 9.99} and item arrives fully typed: item.name is a str, item.price a float. Send something invalid and FastAPI returns a 422 before your function runs.

02  Pydantic models

A Pydantic model is a class that subclasses BaseModel. Each annotated attribute is a field; the type hint defines its type and whether it's required. This is the same Pydantic you met as “structured data” — here it's the heart of every FastAPI body. Run it:

models.py · runs real Pydantic v2
name='Wand' price=9.99 in_stock=True tags=['magic']
{'name': 'Wand', 'price': 9.99, 'in_stock': True, 'tags': ['magic']}
Pydantic v2 method names

Use .model_dump() (to a dict) and .model_dump_json() (to a JSON string), and Model.model_validate(data) to build from a dict. The v1 names .dict() / .parse_obj() are deprecated — if a tutorial uses them, it's old.

03  Nested models

Models can contain other models, giving you deep, validated structures from plain JSON:

nested.py
class Address(BaseModel):
    city: str
    zip: str

class User(BaseModel):
    name: str
    address: Address          # a model inside a model
    roles: list[str] = []

# FastAPI validates the whole tree from one JSON body:
# {"name": "Ada", "address": {"city": "London", "zip": "EC1"}, "roles": ["admin"]}

04  Response models

You can also declare the shape of the response with response_model. FastAPI will filter and validate what you return to match — perfect for hiding fields like a password hash.

response_model.py
class UserIn(BaseModel):       # what we accept
    name: str
    password: str

class UserOut(BaseModel):      # what we return (no password!)
    name: str

@app.post("/users", response_model=UserOut)
def create_user(user: UserIn):
    save(user)                 # store it somewhere
    return user                # password is stripped from the response
Separate “In” and “Out” models

A common, healthy pattern: one model for input, one for output. It keeps secrets out of responses and makes your API contract explicit. You'll see Create/Read/Update variants again on the Databases page.

05  Try it: send a body

POST /items expects {name, price, tags?}. Send a valid body for a 201, or break it to see the 422 — note how loc points into ["body", ...].

Where does a value for a request-body field go in the 422's loc?

Correct. The first element of loc tells you the source: body, query, or path. The rest drills into the exact field. Send the “Missing name” preset above and look.
