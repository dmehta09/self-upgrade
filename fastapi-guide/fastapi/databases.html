Home/Databases (SQLModel)
FastAPI · databases

Make your data survive a restart.

So far everything vanished when the server stopped. A database stores data permanently. We'll use SQLModel — built by FastAPI's author on top of SQLAlchemy and Pydantic — so your database tables are Pydantic models. One class, used for both.

01  Why SQLModel

SQLModel sits on two giants: SQLAlchemy (the battle-tested Python ORM that talks to the database) and Pydantic (validation). It glues them so a single class is both a validated data model and a database table.

terminal
pip install sqlmodel
# we'll use SQLite — a zero-setup file database, perfect for learning
SQLModel is pre-1.0

It's still on 0.0.x versions and evolving. The patterns here are current and stable, but check the docs for the latest details. SQLite is great to learn on; switching to PostgreSQL later is mostly a connection-string change.

02  Table models & schemas

A class with table=True becomes a real database table. It's good practice to also define plain (non-table) models for input and output — so your API contract is separate from your storage.

models.py
from sqlmodel import SQLModel, Field

class HeroBase(SQLModel):           # shared fields
    name: str = Field(index=True)
    age: int | None = None

class Hero(HeroBase, table=True):   # the actual table
    id: int | None = Field(default=None, primary_key=True)

class HeroCreate(HeroBase):         # what POST accepts (no id)
    pass

class HeroPublic(HeroBase):         # what we return (id included)
    id: int

class HeroUpdate(SQLModel):         # PATCH — every field optional
    name: str | None = None
    age: int | None = None

03  The engine & a session

The engine is your connection to the database (create it once). A session is a short-lived workspace for a unit of work — you get a fresh one per request via a yield dependency (remember those?).

db.py
from typing import Annotated
from fastapi import Depends
from sqlmodel import SQLModel, Session, create_engine

engine = create_engine("sqlite:///database.db")

def create_db_and_tables():
    SQLModel.metadata.create_all(engine)     # create tables if missing

def get_session():
    with Session(engine) as session:         # opens, then auto-closes
        yield session

SessionDep = Annotated[Session, Depends(get_session)]

Call create_db_and_tables() once at startup (we wire that into lifespan on the Advanced page).

04  CRUD: create, read, update, delete

With the session injected, the four operations are short. Note SQLModel's own select() + session.exec(...) (not SQLAlchemy's .execute()).

routes.py
from fastapi import FastAPI, HTTPException
from sqlmodel import select

app = FastAPI()

@app.post("/heroes", response_model=HeroPublic, status_code=201)
def create_hero(hero: HeroCreate, session: SessionDep):
    db_hero = Hero.model_validate(hero)      # HeroCreate -> Hero
    session.add(db_hero)
    session.commit()
    session.refresh(db_hero)                 # reload to get the new id
    return db_hero

@app.get("/heroes", response_model=list[HeroPublic])
def list_heroes(session: SessionDep, offset: int = 0, limit: int = 20):
    return session.exec(select(Hero).offset(offset).limit(limit)).all()

@app.get("/heroes/{hero_id}", response_model=HeroPublic)
def get_hero(hero_id: int, session: SessionDep):
    hero = session.get(Hero, hero_id)        # fetch by primary key
    if not hero:
        raise HTTPException(404, "Hero not found")
    return hero

@app.patch("/heroes/{hero_id}", response_model=HeroPublic)
def update_hero(hero_id: int, data: HeroUpdate, session: SessionDep):
    hero = session.get(Hero, hero_id)
    if not hero:
        raise HTTPException(404, "Hero not found")
    hero.sqlmodel_update(data.model_dump(exclude_unset=True))  # only sent fields
    session.add(hero); session.commit(); session.refresh(hero)
    return hero

@app.delete("/heroes/{hero_id}", status_code=204)
def delete_hero(hero_id: int, session: SessionDep):
    hero = session.get(Hero, hero_id)
    if not hero:
        raise HTTPException(404, "Hero not found")
    session.delete(hero); session.commit()
Two common trip-ups

1) Use exclude_unset=True on updates so you only overwrite fields the client actually sent. 2) After commit(), call refresh() if you need server-generated values (like the new id) back on the object.

05  Relationships

Link tables with a foreign key and a Relationship so you can navigate from one object to its related rows in Python.

relationships.py
from sqlmodel import SQLModel, Field, Relationship

class Team(SQLModel, table=True):
    id: int | None = Field(default=None, primary_key=True)
    name: str
    heroes: list["Hero"] = Relationship(back_populates="team")

class Hero(SQLModel, table=True):
    id: int | None = Field(default=None, primary_key=True)
    name: str
    team_id: int | None = Field(default=None, foreign_key="team.id")
    team: Team | None = Relationship(back_populates="heroes")

# now: my_hero.team.name   and   my_team.heroes

06  Migrations (a heads-up)

create_all() only creates tables that don't exist — it won't alter an existing table when you change a model later. For evolving a real database safely, you use migrations. The standard tool is Alembic (it ships with SQLAlchemy): it records each schema change as a versioned script you apply in order.

For now, learning is fine without it

While experimenting, deleting the SQLite file and letting create_all() rebuild is perfectly OK. Reach for Alembic once you have data you can't lose.

You added a new column to a model. Why didn't it appear in your existing SQLite table?

Exactly. create_all() is create-if-missing only. To change an existing table's shape, use a migration tool like Alembic (or, while learning, recreate the database).
