FastAPI · routing & parameters

Endpoints, and the data that comes with them.

An endpoint is a function plus the URL and HTTP method that trigger it. Here we cover the four pieces of every route: the operation (method + path), path parameters, query parameters, and the status code — then poke a real one in the playground.

01  Path operations

You attach a function to a URL with a decorator named after the HTTP method: @app.get, @app.post, @app.put, @app.delete, @app.patch. The string is the path.

main.py
from fastapi import FastAPI

app = FastAPI()

@app.get("/items")        # list items
def list_items():
    return [{"id": 1}, {"id": 2}]

@app.post("/items")       # create an item  (same path, different method)
def create_item():
    return {"created": True}

The HTTP method conveys intent: GET reads, POST creates, PUT/PATCH update, DELETE removes. Same path, different methods, different functions.

02  Path parameters

Put a name in {curly braces} in the path and add a matching function argument. Give it a type hint and FastAPI converts & validates it for you.

main.py
@app.get("/items/{item_id}")
def get_item(item_id: int):           # <- int, not str
    return {"item_id": item_id}

# GET /items/42   -> {"item_id": 42}
# GET /items/abc  -> 422, because "abc" is not an int
Route order matters

A fixed path like /items/featured must be declared before /items/{item_id}. FastAPI matches top-to-bottom, so a greedy {item_id} defined first would swallow “featured”.

03  Query parameters

Function arguments that aren't in the path become query parameters — the ?key=value part of a URL. Give them a default to make them optional; omit the default to make them required.

main.py
@app.get("/items")
def list_items(q: str | None = None, limit: int = 10):
    return {"q": q, "limit": limit}

# GET /items                 -> {"q": null, "limit": 10}
# GET /items?q=book&limit=5  -> {"q": "book", "limit": 5}

To add constraints (and richer docs), wrap the type with Annotated[..., Query(...)] — the modern FastAPI style:

constraints.py
from typing import Annotated
from fastapi import FastAPI, Query

app = FastAPI()

@app.get("/items")
def list_items(
    q: Annotated[str | None, Query(max_length=50)] = None,
    limit: Annotated[int, Query(ge=1, le=100)] = 10,
):
    return {"q": q, "limit": limit}

# limit must be 1..100; q at most 50 chars — else 422

How do you make a query parameter required?

Right. No default ⇒ required (missing it gives a 422). A default value ⇒ optional. Putting it in the path makes it a path parameter instead.

04  Status codes

By default a successful response is 200 OK (or 200 for everything). For creation you usually want 201 Created; set it on the decorator:

status.py
from fastapi import FastAPI, status

app = FastAPI()

@app.post("/items", status_code=status.HTTP_201_CREATED)
def create_item():
    return {"created": True}      # responds 201

Common families: 2xx success, 4xx the client did something wrong (404 not found, 422 validation failed), 5xx the server errored. You'll raise 4xx errors yourself on the next pages.
