FastAPI · overview

A web framework that reads your type hints.

FastAPI lets you build web APIs in Python fast, with very little code. Its trick: it uses ordinary Python type hints to validate incoming data, serialize responses, and generate interactive documentation — automatically. You write a normal function; FastAPI does the plumbing.

What problem does it solve?

An API is how programs talk to each other over HTTP — a mobile app asking your server for data, one service calling another. Writing that by hand means endless boilerplate: parse the request, check every field, handle bad input, format JSON, document it for other developers. FastAPI removes almost all of that:

Less code

Declare what you expect with type hints; FastAPI handles parsing, validation, and serialization.

Validation built in

Bad input is rejected with a precise 422 before your code runs — powered by Pydantic.

Free interactive docs

A live API explorer at /docs is generated from your code — no extra work.

Hello, world

A complete FastAPI app is just a few lines. Save this as main.py:

main.py
from fastapi import FastAPI

app = FastAPI()

@app.get("/")
def read_root():
    return {"message": "Hello, FastAPI"}

@app.get("/hello/{name}")
def greet(name: str):
    return {"message": f"Hello, {name}"}

Run it with fastapi dev main.py and visit http://127.0.0.1:8000/. Returning a Python dict is enough — FastAPI serializes it to JSON for you. Here's that first endpoint, live:

Try editing the path to /hello/yourname and hit Send. (The /hello/{name} response just echoes the name back — we'll explain path parameters next.)

The automatic docs

This is the feature that wins people over. Because FastAPI knows your endpoints and their types, it generates a full OpenAPI schema and serves two doc UIs for free:

/docs
Swagger UI — an interactive explorer where you can try every endpoint in the browser.
/redoc
ReDoc — a clean, readable reference page for the same API.
/openapi.json
The raw machine-readable schema other tools can consume.
Your docs are always correct

Because the docs come straight from your code's type hints, they can never drift out of date. Change a parameter and /docs updates the moment you reload.

Under the hood (just enough)

You don't need the internals, but two names will come up:

  • Starlette — the lightweight toolkit FastAPI is built on; it handles the raw HTTP, routing, and async machinery.
  • Pydantic — the library that does data validation from your type hints (we use Pydantic v2 throughout).
  • ASGI & uvicorn — ASGI is the modern async standard for Python web apps; uvicorn is the server that speaks it and runs your app.

The one idea to hold onto

Your type hints are the source of truth. Parameters, request bodies, responses, validation, docs — all flow from the types you declare. Everything in the rest of this guide is a variation on that theme.
