Grafana dashboards.

A Grafana dashboard is a collection of panels wired to one or more data sources. The difference between a dashboard that's actually used and one that nobody opens comes down to structure, template variables, and discipline about what to show.

01 Panels, data sources & template variables

A panel runs one or more queries against a data source and renders the result. Template variables turn static dashboards into dynamic ones — a single dashboard covers all services with a dropdown instead of 50 clones.

In plain English analogy

A car dashboard shows the 5 things that matter — speed, fuel, temperature, RPM, warnings — not every sensor in the engine bay. A Grafana dashboard should do the same: the 5–10 signals your team needs to know "are we healthy right now?" The goal is signal, not coverage.

Panel types
Time-series graph, stat (single number), gauge, bar chart, table, heatmap, logs panel.
Data sources
Prometheus, Loki, Tempo, PostgreSQL, Elasticsearch — Grafana queries them all with a unified panel editor.
Template variables
A variable like $service is populated from a label-values query. Every panel uses {service="$service"}. One dashboard, any service.
Grafana 12 — Git Sync
Dashboards as code: store JSON definitions in a git repo, edit via in-UI pull requests. Reviewed, versioned, and reproducible.

02 What makes a good dashboard

Structure determines usefulness. A wall of 50 unordered graphs is decoration. The RED method (Rate, Errors, Duration) applied per service, top-down, turns a dashboard into a diagnostic tool.

Well-structured service dashboard
1

Overview row — fleet health

Total RPS, error rate %, p95 latency across all services. One glance answers "is anything on fire?"

2

Per-service RED rows

Rate, Errors, Duration for each service. Template variable $service filters to the one you care about. Drill into outliers without switching dashboards.

3

Drill-down panels (Drilldown GA in Grafana 12)

Click a spike → Drilldown surfaces correlated metrics, logs (Loki), and traces (Tempo) in context. No manual copy-pasting of time ranges.

Top-down: fleet → service → instance → request. Each level links to the next.
Vanity dashboards nobody reads gotcha

A dashboard no one opens during an incident is a liability: it's stale, unmaintained, and actively misleads. You alert on SLOs, not by eyeballing graphs. Dashboards are for investigation after an alert fires — not the detection mechanism.

03 Grafana 12 features worth knowing

Two new capabilities in Grafana 12–12.3 matter for interviews: Observability-as-Code (Git Sync) and Drilldown GA.

Before Git Sync
  • Dashboard JSON lives in Grafana's DB
  • Changes are ad-hoc, unreviewed
  • Rollback = manual export/import
  • No way to diff two dashboard versions
With Git Sync (Grafana 12)
  • Dashboard JSON lives in a git repo
  • Changes go through in-UI pull requests
  • Rollback = git revert
  • Diff, review, CI check — like any code
Drilldown (GA Grafana 12)
From a metric spike, jump directly to correlated Loki logs and Tempo traces in the same time window. No time-range copy-paste between tabs.
Dynamic dashboards (auto-grid)
Panels auto-arrange based on the template variable — if $service returns 8 services, you get 8 panels, not a static layout that breaks at 9.
Commercial context
Datadog and New Relic offer built-in dashboards tied to their agents — less setup, but locked to the vendor. Grafana OSS + Prometheus is the open path.

Why should you alert on SLOs rather than eyeballing dashboards for anomalies?

Right. Detection should be automatic and symptom-based. Dashboards are investigation tools — you use them after an alert fires to understand why.

04 Interview rapid-fire

What makes a Grafana dashboard actually useful during an incident?core
Model answer

Structure and signal. A useful dashboard shows RED metrics (Rate, Errors, Duration) top-down — fleet overview → per-service → per-instance — so you can narrow from "something is wrong" to "this specific service is slow" in seconds. Template variables let one dashboard cover all services. If it takes more than 10 seconds to orient, it's too complex.

Say it out loud say it

"RED method, top-down, template variables for scope. The dashboard is for investigation — alerts do detection."

What is dashboards-as-code and why does it matter?warm
Model answer

Storing dashboard JSON in git (Grafana 12 Git Sync) means changes are reviewed, versioned, and rollback-able — the same lifecycle as application code. It prevents "who touched this dashboard?" mysteries and makes dashboards part of the deployment pipeline.

Say it out loud say it

"Dashboard JSON lives in git, gets reviewed like code, and rolls back like code. Grafana 12 Git Sync does this in-UI with PRs."

What's the advantage of Grafana Drilldown vs manually correlating metrics and logs?stretch
Model answer

Drilldown (GA in Grafana 12) automatically surfaces correlated Loki logs and Tempo traces in the same time window as the metric spike you clicked. Previously you had to copy the time range, switch to Loki, paste a trace ID — several minutes of context switching. Drilldown makes the jump in one click.

Say it out loud say it

"Click the spike, Drilldown shows the correlated logs and traces in the same window — no manual time-range copy-paste."
