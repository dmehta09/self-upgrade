Reference

Glossary.

A–Z definitions for every term in this guide. One line each — crisp and precise. Use Ctrl/Cmd+F to jump directly to a term.

01 A–Z

Alertmanager
Prometheus component that receives firing alerts, deduplicates them, groups by label, silences, and routes to receivers (PagerDuty, Slack, email).
Burn rate
How fast error budget is being consumed relative to sustainable pace; 1× = on budget, 14.4× = page threshold for the 1-hour window of a 99.9% SLO.
Cardinality
The number of unique time series a metric generates; the product of all unique label-value combinations. High cardinality (e.g. user_id label) can exhaust Prometheus memory.
Context propagation
The mechanism that carries trace_id and span_id across service boundaries — typically W3C traceparent HTTP headers — allowing spans from different services to be stitched into one distributed trace.
Correlation ID
A unique identifier assigned at request entry and propagated through all services, logs, and spans; allows you to find every record belonging to one user request. Synonymous with trace_id in OTel contexts.
Counter
A metric type that only increases (resets to zero on restart). Use rate() or increase() in PromQL; never alert on the raw counter value.
Error budget
The allowed amount of unreliability derived from an SLO: (1 − SLO) × window. For 99.9% over 30 days = 43.2 minutes. Budget drives the reliability vs. velocity trade-off.
Exemplar
A sample data point attached to a histogram bucket that includes a trace_id from a real request in that latency bucket. Enables one-click metric-to-trace navigation in Grafana.
Exporter
A component that converts a system's metrics into Prometheus format — e.g. node_exporter (host metrics), postgres_exporter (DB metrics). Prometheus then scrapes the exporter's /metrics endpoint.
Four golden signals
From Google SRE: Latency, Traffic, Errors, Saturation. The minimum viable dashboard for any service. Essentially RED + Saturation.
Gauge
A metric type that can go up or down, representing a current value (memory usage, queue depth, active connections).
Head sampling
Sampling decision made at the root span (trace start). Cheap but blind to trace outcome — misses rare slow or error traces. Compare: tail sampling.
Histogram
A metric type that samples observations into pre-defined buckets; exposes _bucket, _sum, _count. Use histogram_quantile() to compute percentiles at query time. Aggregatable across replicas.
Instrumentation
The code (or auto-instrumentation agent) that emits telemetry from a service — creating spans, recording metrics, emitting log events. OTel provides a vendor-neutral API for this.
Log
A timestamped record of a discrete event. Structured logs (JSON key-value) are machine-parseable and filterable. Expensive at high volume; use trace_id to filter before querying.
LogQL
Loki's query language for log streams: select by label, then pipe through filters, parsers, and aggregations. Syntax: {service="checkout"} |= "ERROR" | json.
Loki
Grafana's log backend: indexes only labels (not log content) and stores compressed chunks in object storage. Query with LogQL. Ships logs via Grafana Alloy (OTel Collector distro).
Metric
A numeric measurement of a system characteristic over time. Stored as time series (metric name + label set + timestamps + values). Cheap to aggregate; limited to bounded-cardinality label values.
Mimir
Grafana's horizontally scalable, long-term metrics backend compatible with Prometheus remote-write. The managed scale-out option when a single Prometheus instance isn't enough.
Monitoring
Alerting on known failure modes via pre-defined dashboards and thresholds. Answers questions you thought of before the incident. Contrast: observability.
Native histogram
A Prometheus 3.x histogram type with automatic exponential bucket boundaries — no pre-defined buckets. Better resolution at high values and lower cardinality. Still experimental; opt-in via --enable-feature=native-histograms.
Observability
The property of a system that allows you to understand its internal state from its external outputs (logs, metrics, traces) — including for failure modes you didn't predict. Subsumes monitoring.
OpenTelemetry (OTel)
CNCF project providing a vendor-neutral standard for telemetry: the API, SDK, Collector, and OTLP protocol. Traces + Metrics APIs are stable; Logs maturing; Profiles in public alpha (Mar 2026).
OpenTelemetry Collector
A standalone pipeline agent: receives OTLP (and other formats), processes (filter, enrich, tail-sample), exports to any backend. Decouples instrumentation from backend choice.
OTLP
OpenTelemetry Protocol — the wire format for all three signals over gRPC or HTTP/protobuf. One protocol to replace a zoo of vendor-specific formats. Prometheus 3.x ingests OTLP natively.
PromQL
Prometheus Query Language — a functional expression language for selecting and aggregating time series. Key functions: rate(), increase(), histogram_quantile(), sum by().
Pyroscope
Grafana's continuous profiling backend (the emerging 4th observability pillar). Stores CPU, memory, and goroutine flame graphs; correlates with traces in Grafana Tempo.
Quantile / percentile
A value below which a given fraction of observations fall. p99 = 99th percentile — at most 1% of requests exceed this value. Use percentiles (not averages) for latency SLOs.
RED
Rate, Errors, Duration — a dashboard pattern for request-driven services. If you instrument every service with these three panels, you can spot degradation at a glance.
Sampling
Deciding which traces (or fraction of traces) to keep and store. Necessary because storing 100% of traces at scale is prohibitively expensive. Key strategies: head, tail, error-only, adaptive.
Scrape
Prometheus's pull mechanism: HTTP GET to a target's /metrics endpoint on a configurable interval (default 15 s). Simple auth, no retry storms. Contrast: push (Pushgateway, OTLP).
Semantic conventions
OTel's standardized attribute names for common operations (http.request.method, db.system, messaging.system). HTTP + database + messaging are stable (~v1.41). Ensure portable, dashboard-ready instrumentation.
SLI (Service Level Indicator)
The actual measurement used to track a service's reliability — e.g. the fraction of successful HTTP requests, or the fraction of requests completing under 500 ms.
SLA (Service Level Agreement)
A contractual commitment to a customer, typically looser than the internal SLO (e.g. SLO = 99.9%, SLA = 99.5%) to provide a buffer before contractual penalties apply.
SLO (Service Level Objective)
The internal target for a service's reliability, expressed in terms of an SLI — e.g. "99.9% of requests succeed over a 30-day window." Drives error budget calculation.
Span
A single named, timed operation within a trace — e.g. an HTTP call, a DB query. Spans have start/end timestamps, attributes, status, and a parent span ID that creates the tree structure.
Structured logging
Emitting logs as key-value pairs (typically JSON) rather than free-form strings. Machine-parseable, filterable without regex, and easily enriched with trace_id for cross-signal correlation.
Summary
A metric type that computes quantiles client-side. Accurate but cannot be aggregated across replicas. Prefer histograms for latency in distributed systems.
Tail sampling
Sampling decision made after buffering the complete trace at the Collector. Keeps errors, slow traces, and novel paths; costs Collector memory. Contrast: head sampling.
Telemetry
Data emitted by a system to describe its behavior: logs, metrics, and traces. Telemetry is the raw material; observability is the property that telemetry enables.
Tempo
Grafana's trace backend: stores traces in object storage (S3/GCS/ABS); queries via TraceQL; integrates with Loki for log correlation and Prometheus exemplars for metric-to-trace linking.
Trace
A directed acyclic graph of spans representing a single end-to-end request across all services. The root span is the entry point; child spans represent downstream calls.
trace_id
A globally unique 128-bit identifier assigned to a trace at its root span and propagated across all services via the W3C traceparent header. Enables full end-to-end trace stitching.
TraceQL
Grafana Tempo's query language for searching spans by attribute, duration, and status. Example: { span.http.status_code = 500 && duration > 1s }. Enables aggregate trace search without knowing trace_id upfront.
USE
Utilization, Saturation, Errors — a dashboard method for infrastructure resources (CPU, disk, network). Answers "is this resource a bottleneck?" before it causes user-visible impact.
Wide event
A single, highly-contextual structured event per request containing all the fields you might ever slice by (user_id, feature flags, DB timings, cache hit, etc.). Popularized by Honeycomb as "observability 2.0."
