Metrics · Metric Types

The four metric types.

Every Prometheus-style metric is one of four shapes. Choose the wrong shape and your graphs are meaningless — or worse, silently misleading.

01 The four shapes

Pick the type that matches how the value behaves over time — not what it measures.

Each type encodes different math. A counter reset looks catastrophic on a gauge graph. A summary's quantiles can't be added across instances. Getting this right is foundational.

In plain English analogy

A counter is the car's odometer — it only goes up (and resets when you restart). A gauge is the speedometer — it bounces freely up and down. A histogram is a timing sheet from a race: you record every lap, sort them into buckets, and later compute any percentile you want.

02 Type-by-type reference

Type Behaviour How to query Best for
Counter Monotonic, only goes up; resets to 0 on restart rate() or increase() Requests, errors, bytes sent
Gauge Snapshot — can go up or down freely Raw value; or avg_over_time() Memory, queue depth, concurrency, temp
Histogram Buckets of observations + count + sum exposed as separate series histogram_quantile(0.99, rate(…_bucket[5m])) Latency, request size — when you need server-side percentiles
Summary Quantiles computed in the client at collection time Raw _quantile label value — no aggregation possible Latency in single-instance apps where aggregation isn't needed
Counter reset
A Prometheus restart resets all counters to 0. rate() accounts for this; raw counter graphing does not.
Histogram buckets
Defined at instrumentation time (e.g. [0.005, 0.01, 0.05, 0.1, 0.5, 1]). Prometheus 3.x native histograms use exponential buckets and are still opt-in with --enable-feature=native-histograms.
Summary quantiles
Calculated inside the process at scrape time. Efficient for single instances; cannot be merged.

03 Choosing the right type

1

Does the value only go up?

Yes → Counter. Examples: http_requests_total, errors_total, bytes_sent_total.

2

Is it a snapshot of current state?

Yes → Gauge. Examples: memory_usage_bytes, active_connections, queue depth.

3

Do you need percentiles across multiple instances?

Yes → Histogram. Percentiles are computed server-side from bucket data, so aggregation across pods is valid.

4

Single instance, accurate quantiles, no aggregation needed?

Then a Summary works — but document the constraint so no one tries to aggregate later.

Common trap gotcha

Graphing a counter's raw value produces a sawtooth that spikes to millions then crashes to zero on every restart. Always wrap counters in rate() — it handles resets and gives you a per-second rate that makes sense.

Second trap: trying to average summary _quantile series across 10 pods. The math is invalid. Use a histogram instead.

04 Check yourself

You want to track the number of cache hits since the service started. Which type?

Right. Cache hits accumulate monotonically. Use rate(cache_hits_total[5m]) to get hits per second in a dashboard.

You have 20 pods each exposing a summary p99. What's wrong with averaging them in Grafana?

Right. Quantiles are not additive. To get a valid p99 across 20 pods, instrument with a histogram and use histogram_quantile() on the merged buckets.

05 Interview rapid-fire

What's the difference between a counter and a gauge?warm
Model answer

A counter is monotonically increasing — it only goes up and resets on restart. A gauge is a snapshot of current state that can go up or down freely. You should always derive a rate from a counter; you can read a gauge directly.

Say it out loud say it

"Counter is the odometer — only climbs. Gauge is the speedometer — bounces. Graph the raw counter and you'll get a sawtooth; always use rate()."

Why choose a histogram over a summary for tracking request latency?core
Model answer

Histograms expose raw bucket counts that can be merged across instances. histogram_quantile() then computes a valid percentile over the combined traffic. Summary quantiles are pre-computed client-side and cannot be aggregated — so they break the moment you run more than one replica.

Say it out loud say it

"Histograms win in multi-instance deployments because you can aggregate the buckets. Summaries lock in quantiles at the client, so you can never merge them across pods."

What are Prometheus native histograms and why do they matter?stretch
Model answer

Native histograms (Prometheus 3.x, still opt-in via --enable-feature=native-histograms) use exponential bucket boundaries auto-generated at the client, rather than a fixed list you hard-code. This means better precision at all scales, smaller cardinality, and no more "oops, I forgot the 10-second bucket" at 2 AM.

Say it out loud say it

"Native histograms auto-generate exponential buckets, so you don't have to pick boundaries upfront. Still experimental/opt-in in Prometheus 3.x, but the direction the ecosystem is heading."
