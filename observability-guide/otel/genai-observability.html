OpenTelemetry · GenAI

GenAI observability.

LLM calls are just another remote dependency — until you forget to record model, tokens, and cost. The experimental gen_ai semantic conventions give those spans a shared vocabulary so latency, errors, and spend show up next to the rest of your stack.

01 Why LLM calls need spans

A chat completion is an RPC with variable latency, non-deterministic output, and a per-token bill. If it is not a span with stable attributes, you cannot SLO it, alert on it, or explain a cost spike.

Treat the model provider like Postgres or Stripe: wrap each call in a client span, propagate context into tool/agent child spans, and export via OTLP. Product-level GenAI patterns live in the companion GenAI guide; this page is the telemetry contract.

In plain English analogy

Shipping packages without tracking numbers, carrier names, or weight. You know “something left the warehouse,” but you cannot explain delays or the freight bill. gen_ai attributes are the shipping label for every model call.

Heads up experimental

The gen_ai.* semantic conventions are experimental as of ~v1.41. Names can still shift. Prefer official instrumentations and pin versions; expect migration notes when the group goes stable.

02 Core gen_ai attributes

At minimum record system (provider), model, and token usage. Those three unlock latency dashboards, error rates by model, and cost rollups.

gen_ai.system
Provider / product: openai, anthropic, azure.ai.openai, …
gen_ai.request.model
Requested model id: gpt-4.1, claude-sonnet-4.
gen_ai.response.model
Model that actually served (may differ under routing).
gen_ai.operation.name
Operation kind: chat, embeddings, execute_tool.
gen_ai.usage.input_tokens
Prompt / input token count.
gen_ai.usage.output_tokens
Completion / output token count.
llm_span_attrs.py
# Illustrative — prefer official gen_ai instrumentations
span.set_attributes({
    "gen_ai.system": "openai",
    "gen_ai.operation.name": "chat",
    "gen_ai.request.model": "gpt-4.1-mini",
    "gen_ai.usage.input_tokens": usage.prompt_tokens,
    "gen_ai.usage.output_tokens": usage.completion_tokens,
})

03 Latency, cost, and errors

Instrument once; derive the three questions every interview (and every CFO) asks.

What each signal answers for LLM calls
latency
Span duration
TTFT + total
p95 by model
cost
Token attrs
input × price
+ output × price
errors
Span status
timeouts, 429s
content filters
Export histograms on duration and counters on errors; keep raw token counts on the span (or as metrics with low-cardinality labels: model, system, operation).
Latency
Use span duration; optionally record time-to-first-token as an event or child span for streaming.
Cost
Derive from input_tokens / output_tokens × your price table. Never put raw prompts in metric labels.
Errors
Set span status + record exception. Distinguish provider 5xx, rate limits, and application validation failures.
Common trap gotcha

Putting full prompts, completions, or user PII into span attributes or log labels. That creates a privacy incident and a cardinality bomb. Keep content in a redacted store or sampling pipeline; keep gen_ai attrs operational (model, tokens, status).

Finance asks why LLM spend doubled overnight. Which attributes do you need on every chat span?

Right. Provider + model + tokens let you attribute cost. Prompt text as a label is both a privacy risk and a cardinality disaster.

04 Interview rapid-fire

What are gen_ai semantic conventions?warm
Model answer

An OpenTelemetry attribute group for generative-AI operations — provider, model, operation name, token usage, and related fields. They are still experimental (~v1.41), but they are the portable way to make LLM spans queryable across languages and backends.

Say it out loud say it

“Standard names for LLM spans — system, model, tokens — still experimental, but that’s the contract.”

How would you observe latency and cost for an agent that chains three model calls?core
Model answer

One parent span for the agent turn; one child span per model/tool call with gen_ai.* attrs. Sum child durations for critical-path latency; sum token attrs (or derived cost metrics) for spend. Propagate the same trace_id so logs and eval traces stay joined.

Say it out loud say it

“Parent agent span, child spans per LLM call with token attrs — latency from the waterfall, cost from the tokens.”

Where does deeper GenAI product guidance live relative to this guide?stretch
Model answer

Telemetry conventions and OTel wiring stay here. Agents, RAG, evals, and product patterns belong in the sibling GenAI guide. Cross-link rather than duplicating curriculum.

Say it out loud say it

“I’d keep gen_ai spans in the obs guide and send product/agent design to the GenAI guide.”
