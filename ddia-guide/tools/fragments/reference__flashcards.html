01 The deck

0/0 known

  • Fault vs failure

    A fault is one component deviating from spec; a failure is the whole system stopping. The goal of reliability is to stop faults becoming failures.

  • The three concerns of a data system

    Reliability (tolerate faults), scalability (handle growth), maintainability (operability, simplicity, evolvability).

  • Why report percentiles, not the mean?

    The average hides the tail. Users feel the slowest few percent — report p50/p95/p99 and write SLAs on p99 / p99.9.

  • Tail-latency amplification

    When one request waits on several backends, it's only as fast as the slowest — so its effective high-percentile latency climbs as fan-out grows.

  • Load parameter

    A number that describes load (QPS, followers/user, fan-out). “Is it scalable?” is meaningless until you name what grows.

  • Fan-out: on write vs on read

    On write = precompute each follower's timeline (fast reads, costly celebrity writes). On read = assemble at query time (cheap writes, heavy reads). Twitter shipped a hybrid.

  • Scale up vs scale out

    Up = a bigger machine (simple, but capped). Out = more machines (unbounded, but you take on distributed-systems hardness).

  • Accidental vs essential complexity

    Essential is inherent to the problem; accidental comes from our implementation. Maintainability = killing accidental complexity with good abstractions.

  • The impedance mismatch

    The awkward translation between relational tables and the nested objects in application code. The document model reduces it for tree-shaped data.

  • When does the document model win?

    Self-contained, one-to-many data read as a unit — a résumé, an order, a product. One read, great locality, no joins needed.

  • When do relational / graph win?

    many-to-one and many-to-many data. Relational lets the DB do joins; graph excels at dense, variable-depth connections (social, fraud, recs).

  • Schema-on-read vs schema-on-write

    On-read = structure interpreted when reading (flexible, no migration to add a field). On-write = enforced when writing (guaranteed shape, needs a migration).

  • Locality (data model)

    Keeping data that's accessed together physically together, so one read fetches it all. A core strength of the document model.

  • Declarative vs imperative queries

    Declarative (SQL/Cypher) says what you want; the engine picks how and can parallelise. Imperative spells out the steps, pinning the execution order.

  • Property graph

    A model of vertices and edges where both can carry properties. Built for many-to-many, variable relationships; queried declaratively with Cypher.
