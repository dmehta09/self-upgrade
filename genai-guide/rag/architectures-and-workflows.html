Architectures & workflows IV NEW

RAG means: look things up, then answer from what you found. This page maps the shapes you actually say in interviews — naive RAG → hybrid + rerank → GraphRAG → agentic RAG — each with one simple picture. Ship hybrid search + a reranker first. Add GraphRAG or an agent loop only when a measured failure needs it.

4 stages Which flow? Naive Hybrid + rerank Rewrite / HyDE GraphRAG Agentic Long context Upgrade ladder

01  Four stages (same for every flavor)

Every RAG system is the same story. The tools change; the stages do not.

flowchart LR
  A[Prepare knowledge] --> B[Find chunks]
  B --> C[Pack context]
  C --> D[Answer and check]

Pipeline names: ingest / index → retrieve → context assembly → generate + eval / guardrails.

  • Prepare — chunk docs, add metadata, embed, and index (vector store ± keyword index).
  • Find — retrieve the top passages that might answer the question.
  • Pack — assemble context for the prompt and keep citations / source IDs.
  • Answer — generate; then check faithfulness (did we invent facts?) and apply guardrails.

02  Which flow should I use?

Ask these in order. Do not jump to an agent loop before hybrid + rerank is solid.

flowchart TD
  Q[New question] --> Tiny{Docs fit in one prompt?}
  Tiny -->|Yes| LC[Long context - no RAG]
  Tiny -->|No| Exact{Need exact codes or IDs?}
  Exact -->|Yes| Hy[Hybrid + rerank]
  Exact -->|Maybe| Hy
  Hy --> Rel{Need links across many docs?}
  Rel -->|Yes| G[GraphRAG]
  Rel -->|No| Hard{Multi-hop or fuzzy?}
  Hard -->|Yes| Ag[Agentic RAG budgeted]
  Hard -->|No| Done[Hybrid + rerank enough]

Fix retrieval first. Use an Adaptive router as the cost valve — only spend an agent loop when one-shot hybrid retrieval is not enough.

03  Naive RAG (basic loop)

The smallest useful loop: chunk → embed → vector search (cosine) → generate. Great for learning. Usually too weak alone in production because it is dense-only (no keyword / sparse path).

flowchart LR
  D[Docs] --> S[Chunk]
  S --> E[Embed + vector store]
  E --> F[Cosine retrieve top-k]
  F --> A[Generate from chunks]

Also called naive RAG: one bi-encoder retrieve, then stuff context into the prompt.

  • When — demos, tiny corpora, teaching the retrieve–augment–generate idea.
  • Watch out — misses exact IDs / error codes (sparse terms); top-k can be “almost right but wrong.”
  • Next step — hybrid search & rerank.

04  Strong default: hybrid + rerank

Search by meaning and by exact words (dense + BM25), merge ranks with RRF, retrieve wide (~20–100), then rerank the shortlist with a cross-encoder (keep ~3–8). When chunks lose meaning alone, prepend a short “where this came from” note — Contextual Retrieval-style — before you embed and before you build the BM25 index.

flowchart LR
  D[Docs] --> C[Chunk + contextual note]
  C --> I[Dense + BM25 indexes]
  Q[Question] --> H[Hybrid retrieve]
  I --> H
  H --> M[RRF merge]
  M --> R[Cross-encoder rerank]
  R --> A[Generate + cite]
  A --> V[Faithfulness check]

2026 production baseline: contextual chunks → dense + BM25 → RRF → cross-encoder rerank → citations → faithfulness.

  • Why it works — dense catches paraphrases; BM25 catches IDs/SKUs; RRF fuses ranks without score gymnastics; the cross-encoder fixes noisy top-k order.
  • Biggest win — usually the reranker step.
  • Deep dive — hybrid page · chunking strategies.
Librarian + Ctrl-F analogy

Dense search is a librarian who hears what you mean. BM25 is Ctrl-F for exact strings. Hybrid + RRF hires both; the cross-encoder is the senior editor who re-reads only the shortlist.

Interview one-liner say it

“I’d start with hybrid search — dense plus BM25 fused with RRF — then cross-encoder rerank the top ~50 down to a handful, require citations, and measure faithfulness. That’s the quality jump most teams see first.”

05  Smarter finding: rewrite, multi-query, HyDE

Sometimes the user’s question does not look like the docs. Use query rewrite or multi-query expansion — or HyDE (Hypothetical Document Embeddings): draft a fake answer, embed that, and search for passages that look like the draft. Then run the same hybrid → rerank path.

flowchart LR
  Q[User question] --> W[Rewrite multi-query or HyDE]
  W --> S[Hybrid retrieve]
  S --> R[Rerank]
  R --> A[Generate]

Query-side transforms sit in front of retrieve → RRF → cross-encoder; they do not replace hybrid.

  • When — after hybrid + rerank still miss specific question types.
  • Watch out — extra LLM calls add cost and latency; A/B measure before you keep them.
  • More — advanced retrieval.

06  GraphRAG

When the answer needs connections across docs, a flat chunk store is weak. At index time, extract entities and relations, build a knowledge graph, and write community summaries. At query time, choose local (walk neighbors) or global (theme / corpus-level) retrieval — then generate.

flowchart LR
  D[Docs] --> X[Extract entities + relations]
  X --> G[Build knowledge graph]
  G --> Sum[Community summaries]
  Q[Hard question] --> Walk[Local or global retrieve]
  Sum --> Walk
  Walk --> A[Generate]

GraphRAG-style: entity/relation extract → graph + community reports → local vs global retrieval.

  • When — “how do these themes relate?” / multi-hop “who owns X that depends on Y?”
  • Watch out — indexing is heavier and costlier; overkill for single-fact FAQ lookup.
  • Deep dive — GraphRAG lesson.

07  Agentic RAG (bounded loop)

Retrieval becomes a loop with a budget (~3 tries). An Adaptive router sizes the question (skip / one-shot / loop). Inside the loop: retrieve → grade chunks (CRAG: correct / ambiguous / incorrect → rewrite or web fallback) → generate → Self-RAG-style groundedness check. Prefer cheap structured graders over special reflection tokens.

flowchart TD
  Q[Question] --> R{Adaptive router}
  R -->|Easy| Skip[Answer without retrieve]
  R -->|Normal| One[One hybrid + rerank]
  R -->|Hard| Loop[Retrieve]
  Loop --> Grade{Chunks good enough?}
  Grade -->|No tries left| Fix[Rewrite or web CRAG]
  Fix --> Loop
  Grade -->|Yes| Gen[Generate]
  Gen --> Check{Grounded Self-RAG?}
  Check -->|No tries left| Loop
  Check -->|Yes| Out[Return with citations]

Adaptive routing + CRAG grading/fallback + Self-RAG-style support checks, with a hard retry budget.

  • When — multi-hop, ambiguous, or high-stakes questions after hybrid + rerank still fail.
  • Watch out — always put the Adaptive router and a retry cap in front; open-ended agents burn latency and money.
  • Deep dive — Agentic RAG · LangGraph HITL if a human must approve.

08  Tiny knowledge base (long context)

If the whole library fits in the model’s context window, you may skip RAG and use long context plus prompt caching. Switch to RAG when the corpus grows or you need precise citations at scale.

flowchart LR
  D[Small doc set] --> P[Long context + prompt cache]
  P --> A[Generate]

Long context is simpler ops; hybrid RAG wins once the library no longer fits or must stay fresh without stuffing the prompt.

  • When — product FAQ, one policy binder, a short handbook.
  • Trade — fewer moving parts; weaker once the corpus is huge or multi-tenant.
  • Compare — RAG vs fine-tune vs long context.

09  Upgrade ladder

Climb only as far as your failures force you. Measure after each step.

flowchart LR
  A[Fix chunking] --> B[Hybrid dense + BM25]
  B --> C[Cross-encoder rerank]
  C --> D[Rewrite or HyDE]
  D --> E[GraphRAG]
  E --> F[Agentic budgeted]

Most “RAG is broken” tickets die at chunking → hybrid → rerank. Do not skip to agentic.

How you know it works evals

Track context precision / recall (did we retrieve the right chunks?) and faithfulness (did the answer stick to them?). Automate in CI when you can — see RAG & agent eval.

10  Say it out loud

60-second answer say it

“RAG is retrieve then generate. I’d ship hybrid — dense plus BM25 with RRF — then a cross-encoder reranker, citations, and a faithfulness check. Contextual notes on chunks if they lose meaning alone. GraphRAG when answers need entity links or global themes. Agentic only behind an Adaptive router with a ~3-try budget — CRAG-style grade/fallback and a groundedness check — not an open-ended agent.”

11  Self-check

Retrieval often misses exact ticket IDs like E-1234. What should you try first?
Exact IDs are a classic win for hybrid (dense + BM25) with RRF. A cross-encoder cleans the shortlist. Agentic loops are a later upgrade.
When is GraphRAG worth the extra indexing work?
Graphs shine on multi-hop / global questions. Flat hybrid + rerank is enough for most single-fact lookups.
Your hybrid + rerank FAQ bot is already accurate on simple lookups. Why not make every query agentic?
Agentic RAG trades money and time for harder questions. Keep hybrid + rerank as the default path; Adaptive routing decides when a budgeted loop is worth it.
