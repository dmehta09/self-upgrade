LLM internals — overview

You've met tokens; now let's open the box. This module is the one place in the guide where we go under the hood of a language model — how text becomes numbers, how the model decides which words matter, what a transformer actually is, and how it produces one token after another. Get this module and almost everything else (RAG, agents, fine-tuning, serving) becomes a variation on a theme you already understand.

01  Predicting the next token is the whole game

Here's the secret that makes LLMs feel less magical: a chat model has exactly one trick. Given all the text so far, it predicts a probability for every possible next token, picks one, appends it, and repeats. Essays, code, answers, poems — all of it is that loop running hundreds of times. Everything in this module is just detail about how each step of that loop works.

Reading a sentence out loud, one word at a time analogy

Imagine reading a sentence aloud where the next word is hidden until you say it. To guess well you'd use everything you've read so far — grammar, topic, tone. The model does the same, but over a vocabulary of ~100k tokens and with a confidence score for each. Then it commits to one word and the hidden next word appears — and it guesses again. That repeat-until-done loop is an LLM.

02  The forward pass, end to end

One trip through the model to produce one token is called a forward pass. Five stages, then a loop back to the start:

From your prompt to the next token — then do it again
1 · embed
tokens → vectors
each token becomes a list of numbers (its meaning)
2 · transformer blocks
mix the meanings
attention + feed-forward, stacked dozens of times
3 · logits
a score per token
one raw number for every word in the vocabulary
4 · sample
pick one token
softmax → probabilities → choose
5 · repeat
append & loop
add the token to the input, go back to step 1
This is autoregressive generation: the model's own output becomes part of its next input. It stops when it emits a special end-of-turn token (or hits a length limit).

Steps 1–3 are the model's learned machinery; step 4 is the only place you get knobs (temperature, top-p — covered in Sampling & decoding).

03  Training vs inference — same machine, two modes

People conflate these in interviews, so keep them crisp. Training is when the model learns the billions of numbers (weights) inside those blocks, by being shown text and corrected when its next-token guess is wrong. Inference is when those weights are frozen and you simply run the forward-pass loop to get answers. The architecture below is identical in both; only whether the weights change differs.

Training
Adjust weights to minimise next-token error over a huge corpus. Expensive, done once (then refreshed). Covered in Training lifecycle.
Inference
Weights fixed; run forward passes to generate. Every chat you have. Its speed and cost are the Inference & serving module.

05  Why internals show up in interviews

You rarely get asked to derive attention on a whiteboard. You get asked questions whose answer is an internals fact: “Why is long context expensive?” (attention is quadratic + the KV cache grows). “Why does temperature 0 still vary?” (batching and MoE routing). “Why can't it spell ‘strawberry’?” (tokenization). Knowing the machine lets you reason about cost, latency, and failure modes instead of memorising trivia.

“The model thinks, then answers” — careful gotcha

A base model does not deliberate; it runs one forward pass per token, full stop. What looks like “thinking” in reasoning models is just the model generating extra tokens (a scratchpad) before the final answer — same loop, more steps. Don't anthropomorphise the forward pass in an interview; describe the mechanism.

How to say it out loud say it

“An LLM is an autoregressive next-token predictor. Each forward pass embeds the tokens, runs them through a stack of transformer blocks, produces a logit per vocabulary token, and we sample one — then we append it and repeat. Training learns the weights; inference just runs that loop. Almost every practical question about cost, latency or quirks traces back to some step of that loop.”

06  Self-check

What does “autoregressive” mean for a chat model?
Autoregressive = the next prediction depends on the model's own previous outputs. The model emits one token, appends it to the running text, and runs another forward pass — looping until it emits a stop token.
“Walk me through what happens between my prompt and the first word of the answer.”Core
Model answer

The prompt is tokenized, each token is embedded into a vector, and those vectors flow through a stack of transformer blocks (attention + feed-forward). The final block produces a logit for every token in the vocabulary; a softmax turns those into probabilities, and we sample one according to the decoding settings. That sampled token is the first word — then it's appended to the input and the whole pass runs again for the next token.

How to say it out loud say it

“Tokenize, embed, run the transformer stack, get a logit per token, softmax and sample one. Append it and repeat — that loop is the whole generation process.”

“What's the difference between training and inference?”Warm-up
Model answer

Same architecture, different mode. Training updates the weights by penalising wrong next-token predictions over a huge corpus — expensive and done ahead of time. Inference freezes the weights and just runs the forward-pass loop to generate text — that's every API call. Confusing the two leads to mistakes like thinking the model “learns” from your chat (it doesn't, unless you explicitly fine-tune).

How to say it out loud say it

“Training learns the weights; inference runs them. The model doesn't learn from a normal chat — the weights are frozen at inference time.”
