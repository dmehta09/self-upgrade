Attention is all you need IV

Embeddings give each token a meaning in isolation — but “bank” means different things by a river versus a vault. Attention is the mechanism that lets every token look around at the others and pull in the context it needs. It's the heart of the transformer, the reason these models understand long-range relationships, and the single most-asked internals topic in interviews.

01  Every word looks around the room

Picture each word in your sentence as a person at a meeting. Before deciding what it “means” here, each person glances around and decides who else in the room is worth listening to. The word “it” looks back and pays most attention to the noun it refers to; a verb looks at its subject. Attention is just this: for every token, compute how much to listen to every other token, then build an updated meaning as a weighted blend of what those tokens are “saying.”

A meeting where everyone weighs in analogy

In “The trophy didn't fit in the suitcase because it was too big,” the word “it” needs to know whether it means the trophy or the suitcase. Attention lets “it” poll the room, put most of its weight on “trophy,” and update its meaning accordingly. No fixed rules — the model learned who should listen to whom.

02  Query, Key, Value — attention as a search

The cleanest way to explain attention is as a tiny search engine run by every token. From its embedding, each token produces three vectors:

Query (Q)
What this token is looking for. (“I'm a pronoun — I need the noun I refer to.”)
Key (K)
What this token advertises about itself. (“I'm a singular concrete noun.”)
Value (V)
The actual information this token will hand over if attended to.

The mechanism: each token's Query is compared against every token's Key (a dot product — high when they “match”). Those match scores are softmaxed into weights that sum to 1, and the output is the weighted sum of the Values. Search for the right thing (Q), find who matches (K), collect their content (V).

RoleIn a library searchIn attention
QueryWhat you type into the catalogueWhat a token wants from context
KeyThe index card / title of each bookWhat each token offers as a match target
ValueThe book's actual contentsThe information passed on when matched
ScoreHow well your search matches each cardQ·K, softmaxed into attention weights

A scaling factor (dividing by the square root of the head size) keeps those dot-product scores from getting too large before the softmax — a small but standard detail you can mention.

03  Self-attention vs cross-attention

Where do the Queries, Keys and Values come from? That distinction names the two flavours:

Self-attention
Q, K and V all come from the same sequence — tokens attending to other tokens in the same text. This is what a language model does at every layer.
Cross-attention
The Queries come from one sequence and the Keys/Values from another. It's how one stream of data reads from a different one — e.g. a decoder attending to an encoder's output, or an image generator attending to your text prompt.

You'll meet cross-attention again in multimodal models and diffusion image generators, where the text prompt's Keys/Values condition the image being built — see text-to-image control and vision-language models.

04  Multi-head = several points of view

One attention calculation captures one kind of relationship. Real language has many at once — grammar, coreference, topic, tone. So transformers run several attention computations in parallel, called heads, each with its own learned Q/K/V projections. One head might track subject-verb agreement, another which pronoun points where, another the overall topic. Their outputs are concatenated and combined.

A panel of specialists analogy

Instead of one generalist reading the sentence, imagine a panel: a grammarian, a fact-checker, a tone analyst, each reading the same text and reporting what they noticed. Multi-head attention is that panel — many specialised readings of the same sequence, merged into one richer understanding.

05  Causal masking: no peeking ahead

A chat model generates left to right, so when predicting token 5 it must only use tokens 1–4 — never tokens it hasn't written yet. Causal masking enforces this by blocking each token from attending to any future position (those scores are set to negative infinity before the softmax, so they get zero weight). This is the difference between a decoder (causal, generative) and an encoder (sees the whole sequence both ways).

Encoder vs decoder, not “better vs worse” gotcha

Don't say decoders are “weaker” because they can't look ahead — the mask is required for generation (you can't condition on words you haven't produced). Encoders see both directions because they're built for understanding a fixed input (e.g. embeddings), not generating new text. Different jobs, different masking.

06  Why long context is expensive: O(n²)

Here's the fact behind half the “why is this slow/pricey?” questions. Every token compares its Query against every token's Key, so for a sequence of n tokens you compute roughly n × n scores. Double the context and you quadruple the attention work — that's quadratic cost, written O(n²) in both compute and the memory for that score matrix.

This is why million-token context windows are a real engineering feat, not just a config change, and why so much work goes into making attention cheaper — FlashAttention (a faster, memory-frugal way to compute the same thing), the KV cache (don't recompute past Keys/Values), and architectural tricks like GQA covered in Transformer architecture and KV cache.

How to say it out loud say it

“Attention lets each token attend to every other token: from each token we derive a Query, Key and Value, score Query against Key, softmax to get weights, and output a weighted sum of the Values. Multiple heads capture different relationships, and a causal mask stops a decoder from seeing the future. Because every token attends to every other, cost is quadratic in sequence length — which is why long context is expensive and why we lean on the KV cache and tricks like GQA and FlashAttention.”

07  Self-check

Why does doubling the input length roughly quadruple the attention computation?
Self-attention compares each of n Queries against each of n Keys → about n² scores. Double n and n² grows 4×. That quadratic scaling is the core reason long context is costly in both compute and memory.
“Explain Q, K and V like I've never seen a transformer.”Core
Model answer

Think of a search. Each token makes a Query (what it's looking for), a Key (what it advertises), and a Value (the info it carries). We score every Query against every Key with a dot product, softmax those into weights, and each token's output is the weighted sum of the Values. So a token “retrieves” information from the tokens most relevant to it — that's how context flows.

How to say it out loud say it

“Query asks, Key advertises, Value delivers. Score Q against K, softmax, take a weighted sum of V — each token retrieves what's relevant from the rest.”

“What's the difference between self-attention and cross-attention?”Warm-up
Model answer

In self-attention the Queries, Keys and Values all come from the same sequence — tokens attend to each other within one text. In cross-attention the Queries come from one sequence and the Keys/Values from another, letting one stream read from a different one — like a diffusion image model attending to your text prompt, or a decoder attending to an encoder's output.

How to say it out loud say it

“Self-attention: Q, K, V from the same sequence. Cross-attention: Q from one sequence, K/V from another — that's how text conditions an image generator.”
