LLM internals · architecture

Inside a transformer IV NEW

Attention is the star, but a transformer is more than attention. It's a tall stack of near-identical blocks, each refining the meaning a little more, wrapped in a few tricks that make training stable and inference cheap. This page assembles the full machine — and the 2025–26 upgrades (RoPE, GQA, Mixture-of-Experts, KV compression) that every current model uses.

01  Three shapes: decoder, encoder-decoder, encoder

“Transformer” names a family with three layouts. Which one a model is tells you what it's for:

ShapeSees the input…Best atExamples
Decoder-onlyLeft-to-right (causal mask)Generating textEssentially all modern chat LLMs (GPT, Claude, Gemini, Llama, Qwen, DeepSeek families)
Encoder-decoderEncoder both ways; decoder generatesTranslation, seq-to-seqT5-style models; classic machine translation
Encoder-onlyBoth directions, no generationUnderstanding / embeddingsBERT-lineage; many embedding & reranker models

For interviews the headline is simple: chat LLMs are decoder-only. Encoder-only models power embeddings and rerankers (the vectors and RAG modules); encoder-decoder is now niche for general chat.

02  Block anatomy: attention + FFN + residual + norm

Stack the same block dozens of times and you have an LLM. Each block has two “sub-layers,” each wrapped in a residual connection and a layer norm:

Attention moves information between tokens; the feed-forward network processes each token on its own. Stacking many blocks lets meaning build up gradually.
Feed-forward (FFN/MLP)
A small two-layer network applied to each token independently. Most of a model's raw parameters live here — it's where a lot of “knowledge” is stored.
Residual connection
Add a sub-layer's input to its output (a “skip”). Lets gradients flow through very deep stacks so training stays stable.
Layer norm
Rescales each token's vector to a sane range so numbers don't blow up or vanish. (RMSNorm is the common modern variant.)
Pre-norm
Normalise before each sub-layer (not after). Now standard because it makes deep models far easier to train.

03  Positional encoding & RoPE NEW

Attention by itself is order-blind: it sees a bag of tokens with no sense of which came first. We have to inject position. The modern answer is RoPE (Rotary Positional Embeddings): instead of adding a “position number,” it rotates each token's Query and Key vectors by an angle that depends on its position. Because rotation preserves angles, the dot product between two tokens then naturally encodes how far apart they are — relative position falls out for free.

Clock hands for position analogy

Imagine each token holds a little clock, and its position sets how far the hand has turned. Two tokens close in the sentence have hands at similar angles; far-apart tokens have very different angles. Attention reads those angle differences as distance — so the model knows order without anyone numbering the words.

Why it matters in 2026: RoPE is essentially universal in current LLMs, and it's the lever for context extension — scaling the rotation frequencies (e.g. YaRN-style methods) lets a model trained at, say, 8k tokens generalise to far longer contexts. When someone asks “how do models get to 1M context?”, RoPE scaling is part of the answer.

04  GQA / MQA: fewer KV heads, smaller cache NEW

During generation we cache every token's Keys and Values so we don't recompute them each step (the KV cache). That cache is often the biggest memory hog at inference. The fix: let many Query heads share Key/Value heads.

SchemeKV headsKV-cache sizeTrade-off
MHA (multi-head)One per query headLargestHighest quality, heaviest cache
GQA (grouped-query)A few, shared in groupsMuch smallerNear-MHA quality — the 2026 default
MQA (multi-query)Exactly one, shared by allSmallestCheapest, slight quality cost

So GQA keeps lots of Query heads (different points of view) but only a handful of Key/Value heads, shrinking the cache with almost no quality loss. It's standard in current models because it directly cuts memory and speeds up long-context generation.

05  Mixture of Experts: huge params, constant compute NEW

A Mixture of Experts (MoE) model replaces the single feed-forward network in a block with many parallel FFNs called “experts,” plus a tiny router that, for each token, picks just the top-k experts (often 2 of dozens) to actually run. The other experts stay idle for that token.

A hospital of specialists, not one GP analogy

A small clinic has one doctor who must know everything. A big hospital has dozens of specialists at the front desk — but you only see the one or two relevant to your problem. MoE is the hospital: enormous total expertise on staff, yet each patient (token) only consults a couple of specialists, so the visit is fast.

The payoff is the line worth memorising: huge total parameters, but roughly constant compute per token (this is “sparse activation”). A model can hold, say, hundreds of billions of parameters of knowledge while only running a small fraction for any given token — capacity grows without inference cost growing in step. Most frontier and open-weight families in 2026 are MoE.

“MoE means many small models voting” — no gotcha

Experts aren't independent mini-models, and it isn't an ensemble vote. They're swappable FFN sub-layers inside each block, and a learned router sends each token to a few of them. Also note: MoE saves compute, not memory — every expert's weights still have to be loaded, so VRAM stays high even though each token is cheap to run.

06  MLA, KV compression & “activated” parameters NEW

Two more current ideas worth a crisp sentence each:

MLA (Multi-head Latent Attention)
Goes further than GQA: instead of just sharing KV heads, it stores the Keys/Values in a small compressed (latent) form and expands them on the fly. Result: a dramatically smaller KV cache at long context, popularised by the DeepSeek line. Think “GQA's goal, taken to compression.”
Parameters vs activated parameters
In an MoE model, total parameters is everything on disk (all experts); activated parameters is how many actually run per token (the router's top-k). A model might be “400B total, ~30B activated” — knowledge of a giant, speed of a small one.
How to say it out loud say it

“Modern LLMs are decoder-only transformers: a deep stack of blocks, each with attention plus a feed-forward network, wrapped in residual connections and pre-norm. Position comes from RoPE, which rotates Q and K so attention encodes relative distance. To cut the KV cache they use GQA — many query heads sharing a few KV heads — or MLA to compress it further. And many are Mixture-of-Experts: a router sends each token to a couple of expert FFNs, so total parameters are huge but activated parameters per token stay small, giving big-model knowledge at small-model compute.”

07  Self-check

In a Mixture-of-Experts model, what does “huge total parameters, but constant compute per token” mean?
Sparse activation: the router selects a few experts per token, so adding more experts grows capacity (total params) without growing per-token compute (activated params). The weights still all live in memory, so VRAM stays high.
“Why did GQA become standard, and what does it trade off?”Core
Model answer

Because the KV cache dominates inference memory, and GQA shrinks it by having many query heads share a few key/value heads. You keep most of multi-head attention's quality (you still have lots of query views) while cutting cache size and speeding up long-context decoding. The trade-off is a tiny quality drop versus full multi-head — usually negligible, which is why it's the default. MQA pushes it to a single KV head for even less memory at a slightly larger quality cost.

How to say it out loud say it

“GQA shares KV heads across query heads to shrink the KV cache — near multi-head quality, much less memory. MQA is the extreme with one KV head; MLA compresses the cache further.”

“What's a transformer block made of, and what does each part do?”Warm-up
Model answer

Two sub-layers. First, multi-head attention mixes information across tokens; second, a feed-forward network processes each token independently and holds much of the model's knowledge. Each sub-layer has a residual connection (add the input back) so deep stacks train stably, and a layer norm (modern: RMSNorm, applied pre-norm) to keep the numbers well-scaled. Stack the block dozens of times and that's the model.

How to say it out loud say it

“Attention mixes across tokens, the feed-forward thinks per token; residuals and pre-norm keep a deep stack trainable. Repeat the block many times.”
