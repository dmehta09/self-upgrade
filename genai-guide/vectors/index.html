Embeddings & vectors · overview

Vectors — overview IV

You already met embeddings as meaning turned into coordinates. This module zooms out from “what is a vector?” to “how do I run vector search over millions of documents, cheaply, in production?” The one-liner to anchor everything: keyword search finds the word; vector search finds the meaning. Get that distinction crisp and the rest of this module — embedding models, vector databases, quantization, and chunking — falls into place.

01  Quick recap: meaning as coordinates

If you skipped the internals module, here's the whole idea in three sentences. An embedding is a fixed-length list of numbers — a vector — that a model assigns to a piece of content so that similar meanings land in similar places. “Refund policy” and “how do I get my money back?” look nothing alike as strings, but their vectors sit right next to each other. To find related things, you don't read every document — you just look at what's nearby in the space.

A library with no shelves, just a map analogy

Picture a library where books aren't sorted alphabetically but by topic-similarity: every cookbook clusters in one corner, every legal text in another, and a book about “tax law for chefs” sits on the border between them. To answer a question you walk to the right neighbourhood and grab the closest few books. Keyword search is the old card catalogue — it only finds you a book if you spelled the title exactly. Vector search is the map: get near the meaning and the right books are within arm's reach.

The full intuition — what the numbers are, why they're learned, token vs sentence vs document embeddings — lives in LLM internals · Embeddings & vectors. This module assumes that and builds the system around it.

02  Keyword search vs vector search

Traditional search (think classic full-text search, or the BM25 algorithm) matches on literal words: it scores a document by how often your query terms appear in it. It's fast, cheap, and unbeatable when the exact term matters — product codes, error strings, names. But it's blind to meaning: search “laptop won't turn on” and a doc titled “notebook fails to boot” scores zero shared words.

Vector search (also called dense, semantic, or neural search) embeds the query and every document, then returns the documents whose vectors are closest to the query's. It matches concepts, survives synonyms and paraphrases, and even works across languages — at the cost of an embedding model and an index.

Keyword / BM25 (sparse)Vector / semantic (dense)
Matches onExact words & their frequencyMeaning / direction in vector space
Great atCodes, names, rare exact terms, typos-as-typedSynonyms, paraphrases, “the gist”, cross-lingual
Blind toSynonyms & rephrasingsExact rare strings it never learned (e.g. ERR_0x8F)
NeedsAn inverted index (cheap)An embedding model + a vector index
Vector search isn't strictly better — it's different gotcha

A classic interview trap is to declare vector search the upgrade that retires keyword search. It isn't. Dense search regularly loses on exact identifiers, part numbers and rare jargon the embedding model never saw — it'll happily return something “semantically close” but wrong. That's exactly why the production default is hybrid search: run both and fuse the results. We cover that in the RAG module; here, just don't claim dense replaces sparse.

04  Vectors aren't only for RAG

RAG made vector search famous, but the same “embed-then-find-neighbours” move powers a whole family of features. Recognising them signals system-level maturity:

Semantic search
Search that understands intent, not just keywords — over docs, tickets, code, products.
RAG
Retrieve relevant chunks and paste them into an LLM prompt. The headline use-case.
Recommendations
“More like this”: embed items and users, recommend nearby items. No keywords involved.
Deduplication & clustering
Near-identical vectors = near-duplicate content. Cluster vectors to discover topics.
Classification & routing
Embed an input, find the nearest labelled examples, borrow their label (k-NN classifier).
Multimodal search
Models like CLIP put images and text in one space, so “a red bicycle” can find a photo.
How to say it out loud say it

“Keyword search finds the word; vector search finds the meaning. You embed your content once into a shared space, embed the query with the same model, and return the nearest neighbours. It's the engine behind semantic search, RAG, recommendations, dedup and clustering — anywhere ‘similar’ beats ‘exact match.’ In production I'd usually combine it with keyword search rather than replace it.”

06  Self-check

A user searches your support site for the exact error code ERR_0x8F and your brand-new pure-vector search returns vaguely related articles but not the one that names the code. What's the most likely explanation?
Embedding models generalise meaning, so a rare token like ERR_0x8F often has a weak, generic vector — semantically “close” isn't “exact.” This is the textbook case for keeping keyword search in the mix (hybrid search), not for abandoning vectors.
“What's the difference between keyword search and vector search?”Warm-up
Model answer

Keyword search (like BM25) matches the literal words and their frequency — great for exact terms, codes and names, blind to synonyms. Vector search embeds query and documents into a shared space and returns the nearest neighbours by meaning — great for paraphrases and cross-lingual queries, weaker on rare exact strings. In practice you often run both and fuse them (hybrid search).

How to say it out loud say it

“Keyword finds the word, vector finds the meaning. Keyword wins on exact codes and names; vector wins on synonyms and intent. The strong default is hybrid — use both.”

“Name three uses of vector search that aren't RAG.”Core
Model answer

Recommendations (“more like this” via nearest items), deduplication and clustering (near-identical vectors flag near-duplicate content; clustering discovers topics), and classification/routing (k-NN: embed an input, borrow the label of its nearest labelled examples). Multimodal search — finding images from a text query via a shared CLIP-style space — is a fourth.

How to say it out loud say it

“The same embed-and-find-neighbours trick powers recommendations, dedup, clustering, k-NN classification and multimodal search — RAG is just its most famous customer.”
