GenAI flashcards IV

Flip a card, say the answer, mark what you knew; shuffle resurfaces the ones you missed. Six decks of the highest-signal terms — the ones an interviewer reaches for first. Drill until every card is a reflex. Tap a card to flip; ✓ Got it banks it, ↻ Review keeps it in rotation.

01  Fundamentals

0/0 known
  • term

    Token

    The atomic unit a model reads and writes — a sub-word chunk (~4 chars / ¾ of a word in English). Everything is priced and limited in tokens, not words, so non-English and code cost more per concept.

  • term

    Embedding

    A vector that places text (or any input) in a space where similar meanings sit close. Powers semantic search and RAG — key point: query and document must use the same model.

  • term

    Attention (Q·K·V)

    Each token forms a Query, Key, and Value; it scores its Query against every Key to decide how much of each Value to pull in. That weighted mix is how tokens share context — the core of the transformer.

  • term

    Temperature

    A sampling knob that flattens or sharpens the next-token distribution. Low (≈0) is near-deterministic and factual; high adds diversity and risk. Key point: it shapes randomness, not correctness.

  • term

    Context window

    The max tokens (prompt + output) a model can attend to at once. Everything outside it is invisible — the budget you fill with system prompt, history, and retrieved context. Bigger isn't free: cost and latency scale with it.

  • term

    Hallucination

    A fluent, confident output that is factually wrong or unsupported. It's inherent to next-token prediction, not a bug. Key point: you reduce it with grounding (RAG) and citations — you don't eliminate it.

  • term

    Reasoning model

    A model trained to spend extra tokens "thinking" before answering (chain-of-thought at inference). Trades latency and cost for accuracy on hard, multi-step problems — overkill for simple lookups.

02  Prompting & RAG

0/0 known
  • term

    Few-shot prompting

    Putting a handful of input→output examples in the prompt to steer format and behavior without training. Key point: it teaches the shape of the answer; quality and order of examples matter more than count.

  • term

    Chain-of-thought (CoT)

    Prompting the model to reason step-by-step before the final answer. Lifts accuracy on multi-step tasks. Gotcha: on modern reasoning models it's built in — bolting on "think step by step" can hurt.

  • term

    Context engineering

    Deciding what goes in the limited context window and in what order — instructions, retrieved chunks, history, tools. The discipline beyond prompt wording: curate, compress, and position for signal over noise.

  • term

    Chunking

    Splitting documents into retrievable passages before embedding. Key point: chunk size is a trade-off — too big dilutes the embedding, too small loses context; overlap and semantic/structural boundaries help.

  • term

    Hybrid search

    Combining dense (semantic/vector) and sparse (keyword/BM25) retrieval, fused with a method like RRF. Catches both meaning and exact terms — names, IDs, and rare jargon that pure vectors miss.

  • term

    Reranker

    A second-stage cross-encoder that re-scores the top-k retrieved candidates by reading query and passage together. Big precision win at the top; gotcha: it's slower, so you rerank a shortlist, not the whole corpus.

  • term

    RAG vs fine-tuning

    RAG injects knowledge at query time (fresh, citable, cheap to update); fine-tuning bakes in behavior/format/style. Rule of thumb: facts → RAG, skill/tone → fine-tune; they compose.

03  Agents & tools

0/0 known
  • term

    Function / tool calling

    The model emits a structured call (name + JSON args) against schemas you provide; your code runs it and returns the result. Key point: the model decides what to call — you still execute and validate.

  • term

    MCP

    Model Context Protocol — an open standard for connecting models to tools and data via servers. "USB-C for tools": write a server once, any compatible client can use it, instead of N bespoke integrations.

  • term

    ReAct loop

    Reason → Act → Observe, repeated: the model thinks, calls a tool, reads the result, and loops until done. The backbone of most agents. Gotcha: needs a stop condition and step cap or it spirals.

  • term

    Agent memory

    State an agent keeps beyond one context window: short-term (scratchpad/history) vs long-term (facts persisted to a store, often a vector DB, and retrieved later). Key point: memory is retrieval, not magic — you decide what to write and recall.

  • term

    Supervisor vs swarm

    Two multi-agent shapes: a supervisor (orchestrator) routes work to specialist sub-agents; a swarm lets peers hand off to each other. Supervisor = control and observability; swarm = flexibility, harder to debug.

  • term

    Tool vs agent

    A tool is a single deterministic capability the model can invoke; an agent is the loop that chooses tools and acts toward a goal over multiple steps. Key point: add an agent only when control flow can't be hard-coded.

04  Fine-tuning & serving

0/0 known
  • term

    SFT (supervised fine-tuning)

    Training on curated prompt→response pairs so the model imitates desired outputs. The first adaptation step. Key point: quality and diversity of data beat quantity — a few thousand clean examples go far.

  • term

    LoRA

    Low-Rank Adaptation — freeze the base weights, train tiny low-rank adapter matrices instead. Cheap to train, swappable, hundreds per base model. Key point: ~99% fewer trainable params, near-full-FT quality.

  • term

    QLoRA

    LoRA on top of a 4-bit quantized base model. Slashes memory so you can fine-tune large models on a single GPU. Key point: same LoRA idea, the base is quantized to fit — quality holds up remarkably well.

  • term

    DPO vs RLHF

    Both align a model to preferences. RLHF trains a reward model + RL (PPO) — powerful, fiddly. DPO optimizes directly on preference pairs, no reward model or RL loop. Key point: DPO is simpler and stabler; RLHF still leads at the frontier.

  • term

    KV cache

    Cached Key/Value tensors for past tokens so each new token is generated without recomputing the whole sequence. The reason decoding is fast. Gotcha: it grows with context length and dominates inference memory.

  • term

    Quantization (GGUF / AWQ)

    Storing weights at lower precision (e.g. 4-bit) to shrink memory and speed inference. GGUF = the llama.cpp/CPU-friendly format; AWQ = activation-aware GPU quantization. Trade-off: smaller and faster for a small quality dip.

  • term

    vLLM

    A high-throughput serving engine whose PagedAttention manages the KV cache like OS paging, plus continuous batching. Key point: it packs many concurrent requests efficiently — far higher throughput than naive serving.

05  Evaluation & safety

0/0 known
  • term

    LLM-as-judge

    Using a strong model to score or compare outputs against a rubric — scalable, cheaper than human eval. Gotchas: position and verbosity bias, and self-preference; mitigate with rubrics, randomized order, and human spot-checks.

  • term

    RAGAS

    A framework for RAG eval with reference-free metrics: faithfulness, answer relevancy, context precision/recall. Key point: it splits "did retrieval find it?" from "did generation use it faithfully?" so you debug the right stage.

  • term

    Prompt injection

    Malicious instructions smuggled into model input (often via retrieved/3rd-party content) that hijack behavior. Key point: it's the #1 LLM risk — untrusted text is data, not commands; never let it reach privileged tools unchecked.

  • term

    OWASP LLM #1

    Top of the OWASP LLM Top 10: Prompt Injection. Signals you know the canonical threat list. Key point: no prompt-level fix is complete — pair input handling with least-privilege tools and output checks.

  • term

    Guardrail principle

    Validate at the boundaries: filter/validate inputs and outputs around the model, and never trust the model with more privilege than needed. Key point: defense-in-depth — guardrails wrap the model, they aren't in it.

  • term

    Hallucination eval

    Measuring groundedness — does each claim trace to the provided context? Done via faithfulness scoring (often LLM-as-judge) or claim-by-claim citation checks. Key point: you measure support, not raw truth.

06  Multimodal & diffusion

0/0 known
  • term

    Diffusion

    A generative process that learns to reverse gradual noising: start from pure noise and denoise step-by-step into an image. Key point: it's iterative refinement — quality vs steps is the core speed trade-off.

  • term

    Latent diffusion

    Run diffusion in a compressed latent space (via a VAE) instead of raw pixels, then decode. Key point: this is what made Stable Diffusion practical — far cheaper compute for the same fidelity.

  • term

    DiT (Diffusion Transformer)

    A diffusion model whose denoiser is a Transformer instead of a U-Net. Key point: it scales like LLMs — more params/data keep paying off — and underpins modern image/video systems like Sora.

  • term

    Flow matching

    An alternative to step-by-step diffusion that learns a direct, straighter path (velocity field) from noise to data. Key point: fewer sampling steps for similar quality — faster generation; powers recent frontier image models.

  • term

    CLIP

    A model trained to embed images and text into a shared space via contrastive learning. Key point: it lets you compare image↔text directly — the backbone of text-to-image guidance and zero-shot classification.

  • term

    VLM (vision-language model)

    An LLM that also takes images: a vision encoder turns pixels into tokens the language model reasons over. Powers captioning, document/UI understanding, and visual Q&A. Key point: images become tokens — they cost context too.

  • term

    Video generation

    Generating frames that stay coherent over time, typically a DiT diffusing in a spatiotemporal latent space. Key point: the hard part is temporal consistency — objects and motion holding up across frames — at huge compute cost.
