Interview prep · the method

How to interview for GenAI roles

Knowing the material isn't quite the same as interviewing well. This module turns everything in the guide into something you can perform under pressure: what GenAI interviews actually test, a repeatable way to answer, and the drills — a question bank, system-design walkthroughs, cheat-sheets and flashcards — to rehearse with.

01  What GenAI interviews actually test

For a candidate with ~2 years' experience, GenAI interviews cluster into a handful of buckets. You don't need to be world-class at all of them — you need to be clear across them and deep in one or two.

Fundamentals

How LLMs work — tokens, embeddings, attention, sampling, reasoning models. “Explain X simply.”

Retrieval & RAG

Chunking, embeddings, hybrid search, rerankers, agentic RAG; the classic “RAG vs fine-tuning?”

Agents & tools

Function calling, MCP, the ReAct loop, memory, multi-agent patterns, and keeping them reliable.

Adapt & serve

LoRA/QLoRA, DPO vs RLHF; KV cache, vLLM, quantization, cost & latency.

Evaluation & safety

LLM-as-judge, RAGAS, observability; prompt injection, OWASP LLM Top 10, guardrails.

System design

“Design a RAG chatbot / an agent / an LLM gateway” — the highest-signal round for seniority.

02  The way to answer: define → trade-off → gotcha

Strong answers have a shape. Whatever the question, reach for this three-beat structure — it's exactly what the green “How to say it out loud” boxes throughout the guide rehearse.

1

Define it crisply

One or two plain sentences. Show you actually understand the concept, not just the buzzword.

2

Name the trade-off

“You'd use it when… but it costs… so the alternative is…”. Seniority lives in trade-offs.

3

Call the gotcha

Mention the failure mode or common mistake. It signals you've actually shipped, not just read.

Say less, but say it sharp tip

A tight 30-second answer that names a trade-off beats a rambling two-minute brain-dump. If they want depth, they'll ask a follow-up — and the guide's Q&A blocks list the follow-ups to expect.

03  The 6-step system-design method

The design round scares people, but it's just a checklist. For any “design a ___ with GenAI,” walk these six steps out loud. The system-design method page teaches it in full, and there are seven worked case studies.

1 · Requirements
Clarifying questions: who uses it, what “good” means, what's in scope.
2 · Constraints & SLAs
Latency (p50/p95), throughput, cost per request, freshness, safety.
3 · High-level architecture
The boxes and arrows: client → gateway → retrieval → model → post-processing.
4 · Component deep-dives
Chunking, embeddings, prompt assembly, caching, streaming.
5 · Trade-offs & bottlenecks
RAG vs fine-tune, rerank or not, self-host vs API; where it breaks.
6 · Extensions & scaling
Multi-tenant, eval/guardrail rollout, cost controls.

05  Warm-up

An interviewer asks “what's an embedding?” What's the strongest 20-second answer shape?
Define → trade-off → gotcha. “An embedding maps text to a point in space where similar meanings sit close; you trade more dimensions for quality against cost; and you must embed queries and documents with the same model.” Crisp, senior, done.
“We have 30 minutes — walk me through designing a chatbot over our docs.”Stretch
Model answer

Don't dive into code. Run the six steps: clarify scope and “good,” state SLAs (latency, cost/req, freshness, safety), sketch the architecture (ingest → chunk → embed → vector store → hybrid retrieve + rerank → prompt assembly → model → guardrails → cite), deep-dive the risky boxes, name trade-offs (RAG vs long-context, rerank cost), and finish with eval + scaling. See the RAG chatbot case study.

How to say it out loud say it

“Let me start with requirements and SLAs, then sketch the pipeline, deep-dive retrieval since that's where quality lives, call the trade-offs, and end with how I'd evaluate and scale it.”
