Memory for agents IV NEW

An LLM is amnesiac by default: each call only knows what's in its context window right now. Memory is how we give an agent a past — a scratchpad for the current task, learned skills, durable facts about you, and recollections of earlier sessions. This page borrows the four cognitive memory types from how humans remember, draws the line between programmatic and agentic memory, peeks at the Letta/MemGPT “memory OS” idea, and tackles the spicy 2026 claim that for agents, memory may start eating RAG's lunch.

01  Why agents need memory at all

The model itself stores nothing between calls. Everything it “remembers” lives in the context window you assemble each turn — and that window is finite and costs money per token. So you can't just dump an entire history in forever. Memory is the discipline of deciding what to keep, where to keep it, and what to put back into the window when it's relevant.

A colleague with no long-term memory analogy

Imagine the smartest coworker you've ever had — who forgets everything the moment they leave the room. Every morning you'd re-explain the project, your name, and what you decided yesterday. Exhausting. Memory is the sticky-notes, the shared wiki, and the “oh right, we tried that last week” instinct that turns a brilliant stranger into a teammate who actually knows you. Without it, even a genius model feels like Groundhog Day.

02  The four cognitive memory types NEW

The 2026 vocabulary borrows straight from cognitive science. Knowing these four names — and an example of each — is the most testable thing on this page.

TypeHoldsLifespanAgent example
WorkingThe here-and-now of the current taskThis sessionThe running message history / scratchpad for the task in flight
ProceduralHow to do things — skills & rulesLong-term, slow-changingThe system prompt, learned tool-use routines, “always confirm before deleting”
SemanticFacts about the world & the userLong-term“The user is on the Pro plan and prefers metric units”
EpisodicSpecific past experiences/eventsLong-term“Last Tuesday we debugged the login bug and the fix was X”

A quick way to keep them straight: working = what's on my desk right now; procedural = skills in my hands; semantic = facts I know; episodic = things that happened to me. Working memory maps onto the context window; the other three are what you persist outside it and retrieve when relevant.

03  Programmatic vs. agentic memory NEW

Orthogonal to what is stored is the question of who decides to store and recall it. This is the other distinction interviewers probe.

Programmatic memory (developer-defined)
You, the engineer, write the rules: after each turn, summarise it; on every request, fetch the user's profile and prepend it. The model has no say — your code manages memory deterministically. Predictable and easy to audit.
Agentic memory (model-managed)
You give the model memory tools — save_memory("..."), search_memory("...") — and let it decide, mid-task, what's worth remembering and when to look something up. Flexible and human-like, but less predictable: the agent might save junk or forget to recall.
An assistant who files vs. one you file for analogy

Programmatic memory is you handing your assistant a strict filing system: “every receipt goes in the blue folder, no exceptions.” Agentic memory is trusting the assistant to decide what's worth keeping and to go dig it out when needed. The strict system never misfiles but can't adapt; the trusted assistant handles novelty but occasionally saves a grocery list in the tax folder. Most real systems blend the two.

Where the framework code lives note

We teach the concepts here; the plumbing is framework work. On LangGraph, short-term/working memory is a checkpointer persisting state per conversation thread, and long-term memory across threads is the Store (a key-value/semantic store the agent reads and writes). For that code — checkpointers, threads, and the Store — see the Lang Stack guide.

04  The memory-OS idea: Letta / MemGPT NEW

The window is small; your memories are large. MemGPT (the research that became Letta) framed this exactly like an operating system managing RAM vs. disk — and gave the agent tools to page information in and out itself. Three tiers (as of June 2026):

TierOS analogyWhat's thereIn the context window?
Core memoryRAM / always-onThe essentials: who the user is, the agent's persona, current goals — small & always presentAlways
Recall memoryRecent filesSearchable conversation history (past messages/events)Pulled in on demand
Archival memoryDisk / cold storageArbitrary long-term facts & documents, unboundedPulled in on demand

The unlock is that the agent uses tools to move data between tiers — promoting an important fact into core memory, or searching archival storage when the answer isn't in the window. That's agentic memory taken to its logical conclusion: the model manages its own memory hierarchy, so it can act like it has unbounded memory while only ever holding a small working set in context.

05  The four operations: write, retrieve, update, forget NEW

Whatever the storage, a memory system does four things — and the last two are the ones beginners skip:

Write
Decide something is worth keeping and store it (often as a short, distilled note rather than the raw turn). The trap is writing everything and drowning in noise.
Retrieve
At the right moment, pull the relevant memories back into the context window — usually by semantic search over stored notes, then inject the top hits.
Update
Facts change. “User is on the Free plan” must become “Pro” — not sit beside it as a contradiction. Reconciling rather than just appending is what keeps memory trustworthy.
Forget
Prune stale, wrong, or low-value memories. Unbounded memory rots: it grows costly, contradictory, and slow to search. Forgetting is a feature, not a bug.
More memory is not better memory gotcha

It's tempting to “remember everything,” but a memory store that only ever grows becomes a liability: stale facts contradict current ones, retrieval gets noisier as the pile grows, and every recall costs more tokens. An agent that confidently tells a user their old address — because nobody updated or forgot it — is worse than one with no memory. Budget your memory, reconcile on update, and prune on a schedule. The skill is in curation, not accumulation.

06  Memory vs. RAG NEW

These overlap so much that people conflate them — and an interviewer will check whether you can separate them cleanly. Mechanically they rhyme: both store text outside the model and retrieve relevant bits into the context window. The difference is purpose and source.

RAGAgent memory
SourceAn external knowledge corpus (docs, wiki, web)The agent's own experience & interactions
Answers“What does the documentation say?”“What do I know about you / what happened before?”
Who writes itIngested ahead of time by a pipelineAccumulated by the agent as it runs
Typical shapeRead-mostly, large, curatedRead-write, personal, evolving

The provocative 2026 claim worth knowing (and tagging): as of June 2026, some practitioners argue that for personalised, long-running agents, contextual memory is overtaking RAG as the primary way to keep the model grounded — because what these agents most need isn't more documents, it's a persistent, evolving model of the user and the task. It's a directional argument, not a settled fact: RAG still wins decisively when the answer lives in a big external corpus. The grown-up take is that they're complementary — RAG for world knowledge, memory for personal/experiential context — and many agents use both.

How to say it out loud say it

“Agent memory comes in four cognitive types — working, procedural, semantic, episodic — and is managed either programmatically, where my code controls writes and reads, or agentically, where the model uses memory tools to decide itself. MemGPT/Letta frames it like an OS with core, recall, and archival tiers the agent pages between. The real operations are write, retrieve, update, and forget — and forgetting matters, because an ever-growing store goes stale and noisy. Memory and RAG overlap mechanically, but RAG grounds on an external corpus while memory grounds on the agent's own experience; as of June 2026 some argue contextual memory is starting to overtake RAG for personalised agents, though I'd treat them as complementary.”

07  Self-check

An agent stores “the user lives in Berlin.” The user moves and later asks for local weather, but the agent answers for Berlin. Which memory operation was neglected?
It wrote and retrieved fine — it surfaced “Berlin.” The failure is that memory must be updated when facts change (and stale entries forgotten). A store that only appends will confidently serve outdated information.
“Name the types of agent memory and how they map to a real system.”Core
Model answer

Four cognitive types: working (the current task's scratchpad — basically the context window), procedural (skills and rules, like the system prompt and tool routines), semantic (facts about the world and the user), and episodic (specific past events). In a system, working memory is the live message state for a session; the long-term three are persisted outside the window — a per-session store for working, and a cross-session store you semantically search for the rest — and retrieved when relevant. Who manages it is the second axis: programmatic (my code) vs. agentic (the model uses memory tools).

How to say it out loud say it

“Working, procedural, semantic, episodic. Working = the context window for now; the other three are persisted and retrieved. And it's either programmatic — my code manages it — or agentic — the model manages it with tools.”

“How is agent memory different from RAG?”Core
Model answer

Mechanically they're cousins — both retrieve text from outside the model into the context window. The difference is source and purpose: RAG pulls from an external, pre-ingested knowledge corpus to answer “what do the docs say?”, while memory accumulates the agent's own experience to answer “what do I know about you and what happened before?” RAG is read-mostly and curated; memory is read-write and personal. They're complementary, and as of June 2026 some argue memory is overtaking RAG for personalised agents — though for big external knowledge bases RAG still wins.

How to say it out loud say it

“Same plumbing, different source. RAG = external corpus, ‘what do the docs say.’ Memory = the agent's own experience, ‘what do I know about you.’ Complementary — and for personalised agents, memory's star is rising.”
