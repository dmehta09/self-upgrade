Reference

Model reference table NEW

A scannable snapshot of the model landscape as of June 2026 — frontier families, how to pick a tier, embeddings, image & video, and a pricing mental model. It's a quick lookup, not a leaderboard; for the deeper discussion of why the field looks like this, see The 2026 model landscape.

Read this as capabilities, not patch numbers gotcha

Versions churn weekly — point releases, renamed tiers, new context limits. Reason about capabilities and tiers, not patch numbers. Quoting “model X.4 beats model Y.7 on benchmark Z” dates you instantly and is probably stale by the time you say it. Everything on this page is as of June 2026 and is meant for rough orientation; always re-verify specifics against a current provider page or public leaderboard before you rely on them.

01  Frontier LLM families as of June 2026

A handful of strong families, each ahead at different things and refreshed every few weeks. The split that actually matters in practice is open-weight (you can download and self-host the weights) vs closed (you call a hosted API). Context figures are the published maxima for the family's larger tiers — treat them as ballpark, not contract.

GPT-5.xOpenAIClosed (API)Broad frontier capability; strong reasoning variants~256K–400K+ tokens
Claude Opus 4.xAnthropicClosed (API)Long-context, coding & agentic work; careful alignment~200K–1M tokens

Closed families publish frontier quality fastest; open-weight families are close enough behind — and often an order of magnitude cheaper to run — that self-hosting one behind a gateway is a mainstream production answer (as of June 2026).

02  Picking a tier

There is no “best model.” A senior answer matches the model tier to the job, then validates on a task-specific eval. Map your dominant need to a starting point:

You need…Reach for…Why
Hard reasoning, planning, mathA frontier reasoning modelSpends extra “thinking” tokens for accuracy on hard problems — more cost, more latency
Bulk / cheap classification & extractionA small or open-weight modelRoutine tasks rarely need the frontier; small/cheap is fast and usually good enough
Coding & coding agentsA top coding model with long contextCode benefits from large context (whole repos) and strong tool-use / agentic behavior
Private / at scaleA self-hosted open-weight modelData stays in-house; fixed GPU cost beats per-token pricing at high volume
The default rule say it

“Start with the smallest model that might pass a task-specific eval, then escalate to a bigger or reasoning model only where it fails — and consider a self-hosted open-weight model for scale or privacy.” This is the routing idea behind model gateways.

03  Embedding model families as of June 2026

Embeddings power semantic search and RAG. Choose along two axes: where it runs (hosted API vs open-weight you host) and how many dimensions the output vector has. More dimensions can capture more nuance but cost more to store and compare — dimension is a storage/latency knob, not a quality score.

Family typeWhere it runsTypical dimsGood for
Hosted API (general)Provider's servers; you call an endpoint256–3072 (often truncatable)Fastest to ship; strong quality; no GPU ops
Open-weight (general)Your own hardware / VPC384–1024 (some to 4096)Privacy, cost control, on-prem, no per-call fee
Multilingual variantsEither768–1024Mixed-language corpora & cross-lingual search
Code / domain variantsEither768–1536Code search and specialized domains
Matryoshka (MRL): one vector, many sizes remember

Many modern embeddings are trained with Matryoshka Representation Learning — the most important information is packed into the earliest dimensions, so you can truncate a long vector to its first N numbers and it still works. Embed once at full size, then keep a small slice for fast first-pass search and the full vector to re-score survivors. Don't chase the highest dimension “for quality”: benchmark retrieval on a public leaderboard like MTEB, validate on your data, then choose dimensions for your budget (as of June 2026). More in Embedding models.

04  Image & video generators as of June 2026

Generative media has converged on a small set of ideas. You don't pick these by brand so much as by approach and the controls you need (see DiT & flow matching and Video generation).

ModalityDominant approachWhat that buys youExamples generic
Image Latent diffusion with a DiT (diffusion-transformer) backbone, increasingly trained via flow matching High-res quality at lower cost (work in a compressed latent space); fewer sampling steps; scales well Frontier closed image models closed and strong open checkpoints open
Video Spatiotemporal DiT (attention across space and time), now commonly with native audio generation Temporal consistency across frames; synchronized sound; longer, more coherent clips Frontier closed video generators closed and emerging open models open

Specific product names churn fastest of all here, so they're left generic on purpose — reason about the technique (latent diffusion / DiT + flow matching for image; spatiotemporal DiT + native audio for video) and the controls you need (as of June 2026).

05  A pricing mental model

You're billed per token, and the relationships below hold far more reliably than any specific dollar figure — so reason about the shape of the bill, not a price you'll have to update next week.

What you pay forRelative costImplication
Input tokens (prompt, context, retrieved docs)Baseline (cheapest per token)Long context & big RAG payloads add up quietly — trim what you don't need
Output tokens (the model's reply)Typically several× inputVerbose answers cost more; ask for concise output where it's fine
Reasoning / “thinking” tokensBilled like output — a surchargeA reasoning model can cost far more than a short answer for the same question
Cached input (repeated prefix)Steep discount on cache hitsStable system prompts & shared context get much cheaper with prompt caching
Tier / model sizeFrontier ≫ small / open-weightRoute easy work to a cheap model; reserve the frontier for hard cases
A taxi meter analogy

Input tokens are the distance you've already traveled; output tokens are a premium surcharge for every word the model speaks back. A reasoning model is a taxi that sometimes circles the block (thinking) before answering — better route, bigger fare. Prompt caching is a regular's discount for retracing a familiar prefix. (Numbers vary by provider and change often — see Cost & latency and Tokens, context & cost.)
