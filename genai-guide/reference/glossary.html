Reference

Glossary

Every term in the guide, in one place — type to filter.

ANN (approximate nearest neighbor)

A search trick that finds almost the closest vectors very fast by skipping a brute-force check of every item, trading a tiny bit of accuracy for huge speed — see Embeddings & vectors.

Agent

An LLM put in a loop where it can plan, call tools, look at the results, and keep going until a goal is met — instead of answering in one shot (see Agent fundamentals).

Agent memory

How an agent remembers things across steps or sessions — episodic (what happened before) and semantic (durable facts) — so it isn't starting from scratch each turn (see Agent memory).

Agentic RAG

Retrieval where the model decides when and what to search, can re-query if results are weak, and loops until it has enough — RAG run by an agent (see Agentic RAG).

Attention

The mechanism that lets a model, for each token, look back at every other token and decide which ones matter most right now — the core idea behind transformers (see Attention).

AWQ

A 4-bit quantization method that protects the few weights tied to important activations, keeping quality high while shrinking the model (see Quantization & scale).

Benchmark

A standard set of questions used to score and compare models — useful for rough ranking, but easy to game (see Benchmarks).

Bi-encoder

An embedding model that encodes the query and each document separately into vectors, so matches are fast — at some cost to precision (contrast the reranker; see Hybrid search & reranking).

BM25

A classic keyword-matching score that ranks documents by how often your exact search words appear (with smart weighting) — the workhorse behind lexical search (see Hybrid search & reranking).

BPE (byte-pair encoding)

The most common way to build a tokenizer: start from characters and repeatedly merge the most frequent pairs into reusable word-pieces (see Tokens & tokenization).

Chain-of-thought (CoT)

Prompting (or training) a model to write out its reasoning steps before the final answer, which improves accuracy on harder problems (see Advanced prompting).

Chunking

Splitting long documents into smaller passages before embedding them, so retrieval returns focused, relevant pieces rather than whole files (see Chunking strategies).

CLIP

A model trained so that matching image-and-caption pairs land near each other in one shared vector space — letting you search images with text and vice versa (see Vision-language models).

ColBERT / late interaction

A retrieval style that keeps a vector per token and compares them at query time, getting cross-encoder-like accuracy at near bi-encoder speed (see Advanced retrieval).

Constrained decoding

Forcing the model's output to follow a grammar or schema at generation time by blocking any token that would break the rules — guaranteeing valid structure (see Structured outputs).

Context engineering

The craft of deciding what information to put in the limited context window — and what to leave out — so the model has exactly what it needs (see Context engineering).

Context window

The maximum amount of text (in tokens) a model can read and write in one go — its working memory for a single request (see Tokens & tokenization).

Continuous batching

A serving trick that adds and drops requests from a running batch token-by-token, instead of waiting for a whole batch to finish — keeping the GPU busy (see Serving engines).

Cosine similarity

A score from -1 to 1 that measures how closely two vectors point in the same direction — the usual way to ask "how similar is this meaning?" (see Embeddings & vectors).

Cross-encoder

A model that reads the query and a document together to score their match very accurately — too slow to scan everything, so it's used to rerank a shortlist (see Hybrid search & reranking).

Decoder-only

The architecture behind GPT-style chat models: a stack that reads left-to-right and predicts the next token, using a causal mask so it can't peek ahead (see Transformer architecture).

Diffusion

An image-generation method that learns to turn random noise into a picture by removing a little noise at a time, guided by your prompt (see Diffusion models).

Distillation

Training a small "student" model to copy the outputs of a big "teacher" model, getting most of the quality at a fraction of the cost (see Distillation & tooling).

DiT (diffusion transformer)

A diffusion model that swaps the old U-Net for a transformer backbone, which scales better and powers many modern image and video generators (see DiT & flow matching).

DPO (direct preference optimization)

A simpler alternative to RLHF that teaches a model from pairs of "preferred vs rejected" answers directly, without training a separate reward model (see Preference optimization).

Embedding

A list of numbers that captures the meaning of a piece of text (or image), so similar things end up close together (see Embeddings & vectors).

Few-shot

Showing the model a handful of example input-output pairs inside the prompt so it copies the pattern — no retraining needed (see Prompting fundamentals).

Flow matching

A newer way to train generative models to follow a near-straight path from noise to data, giving high quality in far fewer steps than classic diffusion (see DiT & flow matching).

Foundation model

One big model pretrained on broad data and then reused for hundreds of tasks — the shared base under chatbots, coding tools, and search (see What is GenAI?).

FP8

An 8-bit floating-point number format that halves memory versus 16-bit while keeping enough range for both training and fast inference on modern GPUs (see Quantization for inference).

Function calling

The mechanism where a model, instead of answering in prose, emits a structured request to run a named function with arguments — the basis of tool use (see Function calling).

GGUF

A single-file format for quantized models popular with llama.cpp, designed to load and run easily on laptops and consumer hardware (see Quantization & scale).

GPTQ

A post-training method that quantizes weights to 4 bits one layer at a time while minimizing error, so a big model fits on a smaller GPU (see Quantization & scale).

GQA (grouped-query attention)

An attention variant where several query heads share one set of key/value heads, cutting memory and speeding inference with little quality loss (see Transformer architecture).

GraphRAG

Retrieval that first builds a knowledge graph of entities and relationships from your documents, helping answer broad "connect-the-dots" questions plain search misses (see Advanced retrieval).

Guardrail

A safety check around the model that screens inputs or outputs — blocking unsafe content, leaks, or off-policy answers before they reach the user (see Guardrails & defenses).

Hallucination

When a model states something false but fluent and confident, because it generates what's likely, not what's verified true (see What is GenAI?).

HNSW

A popular ANN index that links vectors into a layered "small-world" graph you can hop through to reach nearest neighbors in a few jumps — fast, with high recall (see Embeddings & vectors).

Hybrid search

Combining keyword search (BM25) with vector search and fusing the results, so you catch both exact terms and semantic matches (see Hybrid search & reranking).

HyDE

A retrieval trick where the model first drafts a hypothetical answer, then searches with that — because a fake answer often matches real documents better than the bare question (see Hybrid search & reranking).

IVF

An ANN index that clusters vectors into buckets and only searches the few buckets nearest your query, instead of all of them (see Embeddings & vectors).

Jailbreak

A prompt crafted to trick a model into ignoring its safety rules — via role-play, obfuscation, or clever framing (see Prompt injection & jailbreaks).

JSON mode

A setting that makes a model return syntactically valid JSON, so your code can parse the answer instead of scraping prose (see Structured outputs).

KV cache

Stored key/value vectors from earlier tokens so the model doesn't recompute them for every new token — the main reason generation stays fast (see KV cache & attention optims).

Latent diffusion

Running diffusion in a small compressed "latent" space (via an autoencoder) instead of on raw pixels, making high-res image generation far cheaper (see Diffusion models).

LLM gateway

A proxy that sits in front of many model providers, giving you one API plus routing, fallbacks, rate limits, caching, and cost tracking (see Routing & gateways).

LLM-as-judge

Using one model to grade another's outputs against a rubric — a fast, scalable (if imperfect) stand-in for human evaluation (see LLM-as-judge).

Logits

The raw, unnormalized scores a model produces for every possible next token, before softmax turns them into probabilities (see Sampling & decoding).

Logprob

The log of a token's probability — a handy measure of how confident the model was about each word it chose (see Sampling & decoding).

LoRA

A fine-tuning method that freezes the big model and trains tiny low-rank "adapter" matrices instead, so you customize a model cheaply (see PEFT · LoRA/QLoRA).

Matryoshka (MRL)

An embedding trained so you can chop it shorter and it still works — letting you pick a smaller dimension for speed or a longer one for accuracy from the same vector (see Embedding models).

MCP (Model Context Protocol)

An open standard that lets models connect to tools and data sources through a common interface — like a USB port for plugging capabilities into an LLM (see Model Context Protocol).

MLA (multi-head latent attention)

An attention design that compresses the key/value cache into a small latent form, slashing memory use during long-context inference (see Transformer architecture).

MoE (mixture of experts)

A model split into many "expert" sub-networks where a router activates only a few per token — giving huge total size but cheap per-token cost (see Transformer architecture).

Model routing

Automatically sending each request to the cheapest model that can handle it, escalating to a stronger one only when needed (see Routing & gateways).

Multi-agent

A system of several specialized agents working together — dividing a big job into roles that coordinate (see Multi-agent patterns).

Multi-head attention

Running several attention "heads" in parallel so the model can focus on different relationships at once (grammar, topic, position) and combine them (see Attention).

ORPO

A preference-tuning method that folds instruction-tuning and preference learning into one step, skipping the need for a separate SFT pass (see Preference optimization).

OpenTelemetry GenAI

An emerging set of standard conventions for tracing LLM calls — prompts, tokens, latency, cost — so you can monitor AI apps with normal observability tools (see Observability & tracing).

OWASP LLM Top 10

A widely-cited checklist of the biggest security risks for LLM apps — like prompt injection and data leakage — used to threat-model your system (see OWASP & threats).

PagedAttention

A memory trick (from vLLM) that stores the KV cache in small fixed-size pages like an operating system, cutting waste and fitting more requests (see KV cache & attention optims).

PEFT (parameter-efficient fine-tuning)

The umbrella for methods like LoRA that adapt a model by training a tiny fraction of parameters instead of all of them (see PEFT · LoRA/QLoRA).

Pretraining

The first, expensive stage where a model reads a huge corpus and learns to predict the next token — building broad knowledge before any fine-tuning (see Training lifecycle).

Prompt caching

Reusing the model's work on a repeated prefix (like a long system prompt) across calls, so you pay less and respond faster (see Cost & latency).

Prompt engineering

The skill of writing clear instructions, examples, and structure in a prompt to reliably get the output you want (see Prompting fundamentals).

Prompt injection

An attack where hidden instructions in user input or fetched content hijack the model into ignoring its real task (see Prompt injection & jailbreaks).

Q / K / V (query, key, value)

The three vectors attention derives from each token: a query asks, keys advertise, and values carry the content that gets mixed in (see Attention).

QLoRA

LoRA on top of a 4-bit quantized base model, so you can fine-tune very large models on a single consumer GPU (see PEFT · LoRA/QLoRA).

Quantization

Storing a model's numbers in fewer bits (e.g. 16-bit to 4-bit) to shrink memory and speed it up, with a small quality trade-off (see Quantization & scale).

RAG (retrieval-augmented generation)

Fetching relevant documents and putting them in the prompt so the model answers from real, current sources instead of memory alone (see Naive RAG).

RAGAS

A framework that scores RAG systems on things like faithfulness and answer relevance — often using an LLM judge — without hand-labeled data (see RAG & agent eval).

ReAct

An agent pattern that interleaves reasoning ("thought") with acting (tool calls) and observing results, looping until done (see Advanced prompting).

Reasoning model

A model trained to "think" with a long internal chain of thought before answering, spending more compute to do better on hard problems (see Reasoning models).

Reranker

A second-pass model that reorders a retrieved shortlist by true relevance, pushing the best passages to the top before they hit the LLM (see Hybrid search & reranking).

RLHF

Reinforcement Learning from Human Feedback: train a reward model on human preferences, then tune the LLM to score well — the classic way to make a model helpful and aligned (see Training lifecycle).

RoPE (rotary position embedding)

A way to tell a transformer where each token sits by rotating its query/key vectors — encoding position smoothly and extending to long contexts well (see Transformer architecture).

Sampling

How the model picks the next token from its probability distribution — greedy (always the top) or random draws shaped by temperature and top-p (see Sampling & decoding).

Semantic caching

Serving a cached answer when a new query means the same as a past one (matched by embedding similarity), not just when the text is identical (see Cost & latency).

SFT (supervised fine-tuning)

Teaching a pretrained model to follow instructions by training it on curated prompt-and-ideal-answer pairs (see SFT & data).

Softmax

The function that turns a model's raw logits into proper probabilities that add up to 1, so the next token can be chosen (see Sampling & decoding).

Speculative decoding

Letting a small fast model guess several tokens ahead, then having the big model verify them in one pass — speeding up generation with identical output (see Speculative decoding).

STT (speech-to-text)

Turning spoken audio into written text — also called transcription or ASR (see Speech (STT/TTS)).

Structured output

Making a model return data in a fixed shape (like JSON matching a schema) so software can use it reliably (see Structured outputs).

Supervisor

A multi-agent pattern where one "manager" agent plans the work and delegates sub-tasks to specialist agents, then assembles their results (see Multi-agent patterns).

Swarm

A multi-agent pattern with no central boss — peer agents hand control to one another as the task moves along (see Multi-agent patterns).

SynthID

Google's watermarking tech that embeds an invisible, detectable signature into AI-generated text, images, audio, or video (see Watermarking & governance).

System prompt

The hidden, top-level instruction that sets a model's persona, rules, and task before the user's messages arrive (see Prompting fundamentals).

Temperature

A knob that flattens or sharpens the next-token probabilities: higher means more random and creative, lower means more focused and deterministic (see Sampling & decoding).

Test-time compute

Spending extra computation at answer time — by thinking longer or trying multiple paths — to boost accuracy on hard problems (see Reasoning models).

Token

The small unit of text a model actually reads and writes — often a word-piece — and the thing you're billed by (see Tokens & tokenization).

Tokenizer

The component that chops text into tokens (and back), using a fixed vocabulary the model was trained on (see Tokens & tokenization).

Tool

An external function a model can call — search, a calculator, an API, code execution — to do things its text generation can't (see Function calling).

Top-k

A sampling cutoff that keeps only the k most likely next tokens and draws from those, ignoring the long tail (see Sampling & decoding).

Top-p (nucleus)

A sampling cutoff that keeps the smallest set of top tokens whose probabilities add up to p, then draws from those — adapting to how confident the model is (see Sampling & decoding).

Transformer

The neural-network architecture (2017) built from stacked attention and feed-forward blocks that underpins virtually every modern LLM (see Transformer architecture).

TTS (text-to-speech)

Turning written text into natural-sounding spoken audio — the voice side of speech models (see Speech (STT/TTS)).

Vector

An ordered list of numbers — here, an embedding — that represents a point in a high-dimensional "meaning space" (see Embeddings & vectors).

Vector database

A database built to store embeddings and find the nearest ones to a query fast, using ANN indexes — the backbone of semantic search and RAG (see Vector databases).

VLM (vision-language model)

A model that takes both images and text as input and reasons over them together — describing pictures, reading charts, answering visual questions (see Vision-language models).

vLLM

A popular open-source serving engine that uses PagedAttention and continuous batching to run LLMs with high throughput (see Serving engines).

Watermarking

Embedding a hidden, detectable signal in AI-generated content so it can later be identified as machine-made (see Watermarking & governance).
