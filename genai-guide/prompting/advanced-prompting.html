Prompting & context · reasoning-era

Reasoning-era prompting IV NEW

Once a task needs thinking — multi-step math, planning, tricky logic — plain instructions aren't enough. A toolbox of techniques coaxes models to reason: chain-of-thought, self-consistency, decomposition, ReAct. But there's a 2026 twist that interviewers love to test: with today's reasoning models, you often shouldn't hand-write these techniques anymore. Knowing when to stop is the skill.

01  Chain-of-thought — and when to skip it NEW

Chain-of-thought (CoT) prompting asks the model to “think step by step” and write its reasoning before the final answer. Giving the model room to lay out intermediate steps reliably boosts accuracy on math, logic, and multi-step problems — because each step it writes becomes context for the next, instead of forcing a leap straight to the answer.

“Show your work” on a math test analogy

A student who blurts the final number often slips; one who writes each step catches their own mistakes along the way. CoT is telling the model to show its work — and just like with students, the act of writing the steps is what improves the answer, not just the explanation it leaves behind.

Here's the 2026 twist. Reasoning models already do this thinking internally — they spend extra “test-time compute” on a hidden reasoning pass before answering. On those models, manually adding “think step by step” is usually redundant and can even hurt: you're fighting or duplicating machinery the model already runs. The modern rule:

Standard (non-reasoning) model
Explicit CoT still helps on hard multi-step tasks — ask it to reason before answering.
Reasoning model
Skip manual CoT. Instead state the goal and constraints clearly and, if available, turn up the reasoning-effort / thinking-budget control. Let the model think; don't script its thoughts.
“Think step by step” is not free, and not always helpful gotcha

Every reasoning token costs money and latency. On a reasoning model, bolting on manual CoT can double-up the thinking and slow responses for no gain. And reasoning helps math/logic/planning far more than pure recall — for a simple factual lookup, extra “thinking” mostly wastes tokens. Match the technique to the task (as of June 2026).

02  The reasoning-technique family

CoT is the root; several techniques build on “make the model reason out loud”:

Self-consistency
Sample the same CoT prompt several times at non-zero temperature, then take a majority vote on the final answers. Trades extra calls (cost) for accuracy on problems with one right answer.
Least-to-most
First ask the model to break a hard problem into easier sub-problems, then solve them in order, feeding earlier answers into later ones. Great when the full problem is too big to nail in one shot.
Step-back
Before diving in, ask a more general question first (“what principle governs this?”), then apply that principle. Helps the model anchor on the right concept instead of pattern-matching surface details.
Decomposition
The umbrella idea: split one big ask into a sequence of smaller, well-scoped asks. Underlies prompt chaining (§4) and most agent designs.
Self-consistency = asking three experts and going with the majority analogy

If you ask one expert a hard question they might slip. Ask three independently and take the answer two of them agree on, and you're usually safer. Self-consistency does exactly that with multiple sampled reasoning paths — you pay for three opinions to get one more reliable answer.

03  ReAct: the bridge to agents

The techniques above all reason inside the model's own head. ReAct (Reason + Act) breaks out of the head: the model interleaves thought with action — it reasons about what it needs, calls a tool (search, calculator, code), reads the result (an observation), reasons again, and loops until done.

The ReAct loop
thought
reason
“I need today's price”
action
call a tool
search(\"AAPL price\")
observation
read result
“$214.30”
loop / answer
reason again
enough? → reply, else repeat
Reason → act → observe → repeat. This loop is the core of an agent — ReAct is where prompting turns into agency.

That thought→action→observation loop is exactly the skeleton of an agent. If you understand ReAct, you understand the heart of agent fundamentals — agents are largely ReAct plus tools, memory, and control logic.

04  Prompt chaining vs one mega-prompt

For a multi-stage job you have two shapes. A mega-prompt crams every instruction into one call. Prompt chaining splits the work into a pipeline of focused calls, each doing one thing and passing its output to the next (extract → classify → draft → format).

One mega-promptPrompt chaining
ShapeEverything in a single callA pipeline of small, focused calls
Wins onLatency & cost (one round-trip)Reliability, testability, debuggability
Struggles withJuggling many goals at onceMore calls = more latency & orchestration
DebuggingHard — one opaque blobEasy — inspect each step's output

Rule of thumb: start with one clear prompt; chain when a single call has to satisfy several goals it keeps dropping, or when you need to inspect and validate an intermediate step. Each link in a chain is easier to prompt, test, and fix in isolation.

05  Don't blindly stack techniques NEW

It's tempting to pile it all on: CoT and self-consistency and a long few-shot block and step-back, on a reasoning model. Resist. Each technique adds tokens, calls, or latency, and the costs multiply: self-consistency over a long CoT prompt with many examples can be an order of magnitude more expensive than a clean single call — often for marginal or even negative gains, especially on models that already reason internally.

Techniques compose multiplicatively in cost gotcha

Five self-consistency samples × a 2,000-token few-shot prompt × a reasoning model's hidden thinking is a very expensive way to answer a question. Add one technique at a time, measure whether it actually helps your task, and keep only what pays for itself. More machinery is not more accuracy.

06  Models differ — prompts aren't portable NEW

A prompt tuned for one model family won't behave identically on another. As of June 2026, the differences that matter most in practice:

Reasoning vs standard
Reasoning models want goals + constraints + a thinking budget, not scripted CoT. Standard models still benefit from explicit step-by-step prompting.
Structure preferences
Some families (notably Claude) respond especially well to XML-style tags; others lean on Markdown headings. Match the convention the family was trained on.
System-prompt weight
Families differ in how strongly the system prompt overrides later turns, and in their default verbosity and refusal style.
Control knobs
Reasoning-effort/thinking-budget, JSON/structured-output modes, and tool-calling formats vary per provider — read the model's own prompting guide.
How to say it out loud say it

“Chain-of-thought and its cousins — self-consistency, least-to-most, step-back — help non-reasoning models on multi-step tasks. But on a modern reasoning model I usually skip manual CoT and just set a clear goal plus a thinking budget, since it reasons internally. ReAct adds tools to that loop and is basically the agent skeleton. I prefer prompt chaining over a mega-prompt when I need reliability or to inspect steps, and I add techniques one at a time because their costs multiply. And I re-tune per model family — prompts don't port cleanly.”

07  Self-check

You're using a modern reasoning model for a multi-step math task. What's the best first move?
Reasoning models already think internally, so hand-written CoT and stacked techniques mostly add cost and latency. Give clear goals/constraints and use the model's thinking-budget control instead.
“What is chain-of-thought, and why might you skip it in 2026?”Core
Model answer

CoT asks the model to write its reasoning steps before the answer, which improves multi-step accuracy because each step conditions the next. You skip explicit CoT on reasoning models because they already spend test-time compute thinking internally — manual CoT then duplicates that work, costs extra tokens and latency, and can even hurt. On those models I set clear goals and a thinking budget instead.

How to say it out loud say it

“CoT is ‘show your work,’ and it helps standard models on hard tasks. Reasoning models already do it internally, so I skip manual CoT and use the thinking-budget knob instead.”

Follow-ups: Does CoT help factual recall? (Not much — it shines on math/logic/planning.) · What's self-consistency? (Vote over multiple sampled CoTs.)
“How does ReAct relate to agents?”Core
Model answer

ReAct interleaves reasoning with actions: the model thinks, calls a tool, observes the result, and loops. That thought→action→observation cycle is the core control loop of an agent — an agent is essentially ReAct plus a tool set, memory, and stopping logic. So ReAct is the bridge from prompting into agentic systems.

How to say it out loud say it

“ReAct is reason-act-observe in a loop. Add tools, memory, and a stop condition and you've got an agent — it's the agent skeleton.”
