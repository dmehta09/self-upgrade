Evaluation & obs. · LLM-as-judge

LLM-as-a-judge IV NEW

If grading open-ended text needs a human reading a rubric, and humans are slow and expensive — what if you let a capable model do the grading? That's LLM-as-a-judge: one model scores another model's output against a rubric. By 2026 it's the workhorse of GenAI eval, because it scales like code but judges like a human. The catch — and the reason interviewers love it — is that the judge has biases you must defend against.

01  A grader model marking homework

Picture a teaching assistant handed a stack of essays and a grading rubric. They don't need the answer; they read each essay and score it against the rubric: on-topic? well-argued? factually sound? An LLM-judge is that TA — you give a strong model the question, the answer (and sometimes the context or a reference), plus clear criteria, and it returns a score with a justification.

The TA with a rubric analogy

Why does this work? Because judging is easier than generating — it's far simpler to tell whether an answer is faithful than to write a perfect one from scratch. A model that might occasionally hallucinate an answer can still reliably spot whether another answer is grounded. That asymmetry is the whole reason LLM-judges are trustworthy enough to use — as long as you keep them honest with calibration.

02  Pointwise, pairwise, reference-guided NEW

There are three ways to ask the judge a question, and they suit different goals:

ModeThe judge is asked…Best for
Pointwise
(direct scoring)		“Score this single answer 1–5 on faithfulness.”Absolute quality, regression gates, online eval
Pairwise
(A vs B)		“Here are two answers — which is better, A or B?”Comparing two models/prompts; humans agree more on comparisons than absolute scores
Reference-guided NEW“Here's a gold answer. How well does this output match it?”When you do have a reference and want grounding for the score

Pairwise is often the most reliable: people (and models) are better at saying "B is better than A" than at assigning a lonely number. Pointwise is what you need for an absolute gate ("faithfulness must average ≥ 4"). Reference-guided anchors the judge when a gold answer exists, reducing drift.

03  Rubrics, G-Eval & calibration

A vague prompt ("is this good?") gives noisy, unreproducible scores. A good judge prompt reads like a grading guide: a specific axis, a defined scale, and ideally anchor examples for each score. Asking for a short justification before the score (chain-of-thought) measurably improves agreement with humans.

G-Eval = named form of this recipe name it

G-Eval is the interview name for LLM-as-judge with a written criterion, CoT-style evaluation steps, then a numeric score — often averaged over a few samples. Frameworks (DeepEval and others) package it; the idea is the same as a calibrated rubric with reasoning-before-score. Say “G-Eval” when they ask for a deterministic-feeling LLM-judge framework; defend it the same way: pin the judge, calibrate to humans, watch position/verbosity bias.

judge_prompt.py — a calibrated pointwise rubric
JUDGE = """You are grading an answer for FAITHFULNESS to the context.

Context:
{context}

Answer:
{answer}

Score 1-5 using this rubric:
5 = every claim is directly supported by the context
3 = mostly supported, one minor unsupported detail
1 = contains claims that contradict or aren't in the context

First write one sentence of reasoning, then output:
SCORE: <n>"""

# parse the trailing "SCORE: n" — reasoning-then-score lifts agreement

Calibration = checking the judge's scores line up with trusted human scores, and tuning the rubric until they do. You also pin the judge (fixed model + temperature 0 + fixed prompt) so its scores are comparable across runs.

04  The biases you must defend against NEW

This is the section interviewers probe. An LLM-judge is not neutral; it has well-documented, named biases:

Position bias
In pairwise mode, the judge tends to favour whichever answer is shown first (or sometimes last), regardless of quality.
Verbosity bias
Judges over-reward longer, more elaborate answers even when a concise one is better or equally correct.
Self-preference (self-enhancement) bias
A judge tends to prefer text written by itself or its own model family — so grading GPT with GPT can inflate GPT's scores.
The fixes are concrete — name them gotcha

Don't just list the biases; give the mitigations. Position bias: run the pair both ways (A/B and B/A) and average, or only count a win if it's consistent across both orders. Verbosity: add "do not reward length" to the rubric and track answer length as a covariate. Self-preference: use a different model family as judge than the one that generated the answer (or an ensemble of judges). The senior move is to assume the judge is biased and design the harness so the bias cancels out.

05  Validate the judge against humans

An unvalidated judge is just another model that might be confidently wrong. Before you trust it as a gate, you prove it agrees with people: collect a few hundred human-labelled examples, run the judge on the same set, and measure agreement (simple accuracy, or correlation like Cohen's κ / Spearman). If the judge agrees with humans about as often as humans agree with each other, it's good enough to automate. Re-check periodically — judges drift as you change the rubric or swap the underlying model.

How to say it out loud say it

“LLM-as-judge uses a strong model to grade outputs against a rubric — judging is easier than generating, so it scales human-like evaluation. I'd use pointwise for absolute gates and pairwise for model comparisons, with a calibrated rubric and reasoning-before-score. But the judge is biased — position, verbosity, self-preference — so I swap A/B order and average, penalise length, and never let a model grade its own family. Then I validate the judge against a few hundred human labels before trusting it as a gate.”

06  Self-check

You run pairwise LLM-judging and notice answer A wins far more often — purely because it's always shown first. Which bias is this, and what's the fix?
Favouring whichever answer appears first is position bias. The standard mitigation is to evaluate both orderings and average the result (or only count a win if it holds in both orders), so the position effect cancels out.
“Why is LLM-as-judge trustworthy if the judge can also hallucinate?”Core
Model answer

Because judging is an easier task than generating. Verifying whether an answer is grounded in a given context is a constrained, checkable problem, while producing the perfect answer is open-ended. A model can be a reliable grader even if it's an imperfect author. We still validate the judge against human labels and control its biases before trusting it.

How to say it out loud say it

“Grading is easier than writing. Checking groundedness against a context is verifiable, so a judge can be reliable even when generation isn't — once we calibrate it against humans.”

“Pointwise vs pairwise judging — when do you use each?”Core
Model answer

Pointwise scores one answer on an absolute scale — use it for gates and tracking a single system over time ("faithfulness ≥ 4"). Pairwise asks which of two answers is better — use it to compare two models or prompts, because relative judgments are more reliable than absolute scores for both humans and judges. Pairwise needs position-bias control (both orderings).

How to say it out loud say it

“Pointwise for an absolute gate; pairwise to pick a winner between two candidates — and pairwise needs both-order averaging to kill position bias.”
