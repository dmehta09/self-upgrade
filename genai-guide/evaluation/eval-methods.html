Ways to evaluate IV NEW

Once you accept that you need to measure quality, the next question is how. There's a whole toolbox — from dirt-cheap string checks to a model grading another model — and the skill is picking the right tool for the right axis. This page lays out the three families, the classic text metrics (and why they fall short), and the offline-vs-online split that confuses a lot of candidates.

01  Three families of evaluator

Almost every LLM metric falls into one of three buckets. Knowing the buckets lets you reason about any new metric you meet:

FamilyHow it scoresCost / speedGood for
Deterministic
code / heuristic		A rule or formula — exact match, regex, JSON-valid, BLEU/ROUGE, contains-keywordFree, instant, repeatableClosed-form answers, format checks, classification labels
Rubric
LLM-judge or human		A grader reads the output against a rubric and scores it (1–5, or pass/fail)Slow + costs tokens (or human time)Open-ended text: tone, helpfulness, faithfulness
Composite NEW
blend		Combine several of the above into one scorecard or weighted gateMixedReal systems — the production-default in 2026
Spell-check vs a human editor analogy

A deterministic check is your spell-checker: instant, free, but it only catches mechanical mistakes — it can't tell you the essay is boring. A rubric grader is a human editor: expensive and a bit subjective, but it judges quality. A composite eval uses both — let the spell-checker catch the cheap stuff first, then send the rest to the editor. That's how real pipelines are built.

02  Reference-based metrics & their limits

Reference-based means you have a "gold" answer to compare against. The classics:

Exact match (EM)
Output must equal the reference string, character for character. Perfect for a label or a number; useless for a sentence.
BLEU
From machine translation — measures n-gram overlap (how many word-sequences the output shares with the reference). Precision-leaning.
ROUGE
From summarization — also n-gram overlap but recall-leaning (did the output cover the reference's content?).
Semantic similarity
Embed both texts and take cosine similarity — captures meaning, not exact words, so it's far kinder to paraphrase.
BLEU/ROUGE punish good paraphrases gotcha

These metrics count word overlap, so "The cat sat on the mat" and "A feline rested upon the rug" score near zero despite meaning the same thing. For open-ended generation they correlate poorly with human judgment — a fluent, correct answer that uses different words gets a low score. They're fine as a cheap signal or for narrow tasks (translation), but never lean on them alone to judge open-ended text. That gap is exactly why LLM-as-judge took over.

03  Task-specific (reference-free) metrics

Often you have no gold answer — you just want to know if this output is good on some axis. These are reference-free and usually computed by an LLM-judge or a small classifier:

Faithfulness / groundedness
Is every claim in the answer supported by the provided context? The core anti-hallucination metric for RAG.
Relevance
Does the answer actually address the question that was asked?
Toxicity / safety
Does the output contain harmful, biased, or policy-violating content? Usually a dedicated classifier.
Conciseness / tone
Style axes — is it the right length, the right register for your product?

Notice these don't need a reference answer at all — they judge the output (sometimes against the input/context). That's what makes them practical in production where no gold label exists.

04  Offline eval sets vs online eval NEW

This split trips up a lot of candidates, so be crisp about it:

Offline evalOnline / production eval
WhenBefore you ship — in CI, on a changeAfter you ship — on live traffic
DataA fixed, curated dataset (inputs + maybe gold answers)Real user requests, no gold answers
ScoringAny family; can use referencesReference-free: LLM-judge, classifiers, user thumbs-up
Answers“Did this change help vs baseline?”“Is quality drifting? Any live regressions?”

Offline eval is your gate — repeatable, comparable, run on every change. Online eval is your smoke alarm — it samples live outputs (you can't score them all) and flags drift or spikes in bad answers. The two feed each other: a failure caught online becomes a new row in the offline dataset.

How to say it out loud — “how would you evaluate a summarizer?” say it

“I wouldn't use exact match — there are many good summaries. I'd build a composite: cheap deterministic checks first (length bounds, no banned phrases, valid format), then a reference-free LLM-judge scoring faithfulness — does every claim trace to the source — plus relevance and conciseness on a 1–5 rubric. If I have reference summaries I'd add ROUGE and semantic similarity as a secondary signal, knowing ROUGE undercounts paraphrase. I'd run that as an offline gate on a fixed dataset, then sample production outputs with the same judge to catch drift.”

05  What a composite scorer looks like

A composite is just a function that runs several scorers and returns a scorecard. Cheap checks gate the expensive ones:

composite_eval.py — one row of an eval set
def evaluate(question, answer, context, reference=None):
    scores = {}

    # 1) deterministic — cheap, run first
    scores["valid_format"] = answer.strip().endswith(".")
    scores["within_length"] = len(answer.split()) <= 80

    # 2) reference-based (only if we have a gold answer)
    if reference is not None:
        scores["semantic_sim"] = cosine(embed(answer), embed(reference))

    # 3) rubric — an LLM-judge scores faithfulness 1-5 vs the context
    scores["faithfulness"] = llm_judge(
        answer=answer, context=context, axis="faithfulness")

    # the gate: must pass cheap checks AND clear the judge bar
    scores["passed"] = (
        scores["valid_format"]
        and scores["within_length"]
        and scores["faithfulness"] >= 4
    )
    return scores

Run this over every row of your dataset, aggregate (mean faithfulness, % passed), and compare to the previous run. That aggregate is your release gate.

05b  Eval in CI · the release gate senior

Offline eval is useless if it only runs on a laptop. Wire a golden set into CI so every prompt/model/RAG change must beat (or not regress) the last score.

promptfoo / DeepEval / custom pytest
Assert faithfulness, toxicity, schema validity, or “contains citation” on a checked-in JSONL fixture. Fail the PR on threshold drop.
LangSmith experiments
Same idea hosted: dataset + evaluators + compare runs. See the Lang Stack evals page.
What goes in the gate
Small (20–100) curated cases that encode your product risks — not a public leaderboard. Promote production failures back into the set.
Say it out loud

“I treat eval like unit tests: a golden set in CI, thresholds as the merge gate, and every production miss becomes a new fixture.”

06  Self-check

You're evaluating open-ended chatbot answers and have no gold reference. Which metric is most appropriate?
With no gold answer, reference-based metrics (exact match, BLEU) don't apply. Reference-free task-specific metrics — relevance, faithfulness, toxicity — judge the output directly, which is exactly the production situation.
“What are BLEU and ROUGE, and why are they weak for chatbots?”Core
Model answer

Both measure n-gram overlap with a reference — BLEU is precision-leaning (from translation), ROUGE is recall-leaning (from summarization). They're weak for open-ended chat because they reward word overlap, not meaning: a correct paraphrase that shares few words scores low, so they correlate poorly with human judgment. They're useful as a cheap secondary signal or for narrow tasks like translation.

How to say it out loud say it

“They count shared word-sequences with a reference. Great for translation, poor for open-ended text — they punish good paraphrases. That's why we moved to semantic similarity and LLM-judges.”

“Difference between offline and online evaluation?”Warm-up
Model answer

Offline eval runs before shipping, on a fixed curated dataset, often with gold answers — it's the repeatable gate that answers "did this change help?" Online eval runs on live traffic with no gold answers — reference-free judges and user feedback sample real outputs to catch drift and regressions. Production failures get added back to the offline set.

How to say it out loud say it

“Offline = fixed dataset, the gate before deploy. Online = sampled live traffic, the smoke alarm after deploy. They feed each other.”
