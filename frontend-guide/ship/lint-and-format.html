ESLint, Biome & formatting

Linting and formatting are two different jobs that get lumped together. One finds bugs and bad patterns; the other makes every file look identical so diffs stay about logic, not whitespace. Knowing which tool does which — and the June-2026 lineup — is table-stakes for a pro setup.

00 Two different jobs

A linter catches mistakes and risky patterns. A formatter rewrites style so the layout is consistent. Don’t make them fight over the same rules.

ESLint analyzes your code for likely bugs and anti-patterns; Prettier or Biome reprints it to one canonical style. Modern setups keep formatting out of the linter so the two never overlap — the linter judges meaning, the formatter judges shape.

Think of it like… analogy

Linting is the spell-checker — it underlines actual mistakes (“you used == here”, “this variable is unused”). Formatting is auto-typesetting — it doesn’t care what you wrote, it just lays out the page with consistent margins and spacing. You want both, doing their own job.

Linter (ESLint / Biome)
Finds bugs & bad patterns: unused vars, missing hook deps, accidental any, == vs ===. Many rules auto-fix.
Formatter (Prettier / Biome)
Reprints code to one style: quotes, semicolons, indentation, line width. No opinions about correctness.

01 ESLint 10 is flat-config only

As of ESLint 10 (June 2026), the flat config file eslint.config.js is the only supported format — the legacy .eslintrc family and eslintignore are gone. Config is a plain array of objects; for TypeScript you compose typescript-eslint 8.

eslint.config.js
import js from "@eslint/js";
import tseslint from "typescript-eslint";

// Flat config: an exported array of config objects.
export default [
  js.configs.recommended,
  ...tseslint.configs.recommended,
  {
    rules: { "no-console": "warn" },
  },
];
Common trap gotcha

Copy-pasting an old .eslintrc.json (with extends / env / an .eslintignore file) silently does nothing in ESLint 10 — those formats were removed, not just deprecated. Use eslint.config.js; ignores live in an { ignores: […] } object inside it.

02 Biome 2 — the fast all-in-one

Biome 2 is a Rust-based tool that does both linting and formatting in one binary, with near-zero config. It’s dramatically faster than the ESLint + Prettier pair and a single command checks the whole repo.

terminal
# Lint + format check in one pass; --write applies safe fixes.
npx @biomejs/biome check --write ./src

The trade-off: ESLint + typescript-eslint still has the deepest rule ecosystem (custom plugins, type-aware rules). Biome covers the common ground at a fraction of the time — great for CI and on-save.

 ESLint 10 + PrettierBiome 2
ScopeLint (ESLint) + format (Prettier) — two toolsLint and format in one tool
SpeedJS-based; slower on big reposRust; typically multiple times faster
Configeslint.config.js + .prettierrcOne biome.json, sensible defaults
EcosystemHuge: plugins + type-aware rulesGrowing; covers the common rules

Either way, run it in two places: on save in the editor (instant feedback) and in CI as a blocking check (so unformatted or lint-failing code can’t merge).

03 Check yourself

You inherit a repo with a working .eslintrc.json and upgrade to ESLint 10. Lint now reports zero problems on obviously broken code. Why?

Right. Flat config is the only format in ESLint 10. With no eslint.config.js, ESLint finds no config and effectively lints nothing — migrate the rules into the flat array.

04 Interview rapid-fire

What changed with ESLint flat config?core
Model answer

Config moved from a cascading .eslintrc with magic extends/env strings to a single eslint.config.js that exports a plain array of config objects you compose explicitly. As of ESLint 10 it’s the only supported format — legacy .eslintrc is removed.

Say it out loud say it

“Flat config is just a JS array you compose — explicit imports, no cascading .eslintrc. In ESLint 10 it’s the only format, so old configs just stop working.”

ESLint + Prettier or Biome — how do you choose?core
Model answer

Biome 2 is one fast Rust binary that lints and formats with almost no config — ideal when speed and simplicity win, especially in CI. ESLint + typescript-eslint still has the richest rule set and type-aware rules, so reach for it when you need plugins or deep custom rules.

Say it out loud say it

“Biome for speed and one-tool simplicity; ESLint when I need its ecosystem and type-aware rules. Many teams even run Biome to format and ESLint for the deep rules.”

What’s the difference between linting and formatting?warm
Model answer

A linter analyzes code for likely bugs and bad patterns (unused vars, missing hook deps); a formatter only reprints code to a consistent style (quotes, indentation, line width). One is about correctness, the other purely about layout — keep formatting rules out of the linter so they don’t conflict.

Say it out loud say it

“Lint catches mistakes; format makes everything look the same. Spell-check versus typesetting — two jobs, don’t let them overlap.”
