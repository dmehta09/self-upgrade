Zustand for client state

When many components need the same client value — theme, the logged-in user, a sidebar toggle — Zustand gives you one tiny store they read directly. No providers to nest, no prop-drilling, almost no boilerplate.

00 The idea

Zustand is a hook-shaped global store. You create it once; any component reads a slice with a selector and re-renders only when that slice changes.

The store lives outside React, so there’s no Context Provider and no prop chain. Components subscribe with a selector function; pick the smallest slice you need and that component ignores every other update.

Think of it like… analogy

A shared whiteboard on the wall. Any component can walk up and read it or write on it — no one has to pass a clipboard hand-to-hand down the hallway (prop-drilling). And you only glance at the corner you care about: change the date in the top-left and people watching the bottom-right don’t look up.

01 Create a store, read a slice

The store holds state and the actions that change it. A component subscribes by selecting exactly the field it renders — not the whole store.

useBearStore.ts
import { create } from 'zustand';

const useBearStore = create<{ bears: number; add: () => void }>((set) => ({
  bears: 0,
  add: () => set((s) => ({ bears: s.bears + 1 })),
}));
Counter.tsx
// selects ONE field -> re-renders only when `bears` changes
const bears = useBearStore((s) => s.bears);
const add = useBearStore((s) => s.add); // actions are stable refs

02 Multiple fields → useShallow

Selecting several fields means returning a new object each render. By default Zustand compares with Object.is, so a fresh object always looks “changed” — an infinite render loop in v5. useShallow shallow-compares the object so it only re-renders when a field actually differs.

v5 infinite loop
// new object every render -> never equal -> loops
const { bears, add } = useBearStore((s) => ({
  bears: s.bears,
  add: s.add,
}));
useShallow
import { useShallow } from 'zustand/react/shallow';

const { bears, add } = useBearStore(
  useShallow((s) => ({ bears: s.bears, add: s.add }))
);
Common trap gotcha

In Zustand v5, a selector that returns a new object or array without useShallow can cause an infinite render loop — the snapshot is never reference-equal, so React re-renders forever. Either select one primitive per call, or wrap multi-field selectors in useShallow.

Which of these belongs in a Zustand store?

Right. Theme and an open/closed UI flag are true client state. Fetched products are server state (TanStack Query); shareable filters belong in the URL. Zustand is for client/UI/session only.

03 Interview rapid-fire

Zustand vs Redux vs Context — when each?core
Model answer

Context is for low-frequency cross-cutting values (theme, locale) — but every consumer re-renders on change. Redux Toolkit suits large, heavily-audited state with middleware needs. Zustand is the lightweight default for most global client state: one store, selector-scoped re-renders, no provider.

Say it out loud say it

“Context for rarely-changing cross-cutting values, Redux for big audited state, Zustand as the low-boilerplate default with per-selector re-renders.”

What state actually belongs in Zustand?core
Model answer

True client/UI/session state that multiple components share: theme, sidebar open/closed, the authenticated user object, a multi-step wizard’s cross-step data. Not server data (that’s TanStack Query) and not shareable/bookmarkable state (that’s the URL).

Say it out loud say it

“Global client state only — theme, session, UI toggles. Server data goes to Query; bookmarkable state goes in the URL.”

Why do you need useShallow in Zustand v5?stretch
Model answer

Zustand compares the selector’s output with Object.is to decide whether to re-render. A selector returning a new object/array is never reference-equal, so in v5 it triggers an infinite re-render loop. useShallow swaps in a shallow comparison, so it re-renders only when a selected field truly changes.

Say it out loud say it

“Multi-field selectors return a fresh object that’s never Object.is-equal, so v5 loops. useShallow shallow-compares it and stops the loop.”
