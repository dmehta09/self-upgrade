TypeScript for React

In a React codebase, TypeScript isn’t about ceremony — it’s about making impossible UI states unrepresentable. Type your props, your hooks, and your events well, and a whole category of bugs simply can’t compile.

00 The idea

Types are contracts checked before runtime. The win isn’t annotations — it’s making bad states impossible to construct.

A well-typed component documents itself, autocompletes for the next dev, and refuses to render with the wrong props. The skill is modeling your data so the compiler — not a user — catches the mistake.

Think of it like… analogy

Types are guardrails on a mountain road. They don’t slow the good driver — they just make it impossible to drive off the cliff. any is removing the guardrails because they felt inconvenient; the road didn’t get safer, you just stopped seeing the edge.

Loose: any allows nonsense
// ❌ a "Button" that accepts contradictions
type Props = { variant: any; href?: any };

// All of these compile — and all are bugs:
<Button variant="ghost" href={42} />
<Button variant={{}} />
<Button /> // missing variant, no error
Discriminated union: only valid shapes
// ✅ link vs button are mutually exclusive
type Props =
  | { as: "link"; href: string }
  | { as: "button"; onClick: () => void };

<Button as="link" href={url} />   // ok
<Button as="button" href={url} /> // ❌ error
type vs interface
Both type props. Use type by default (unions, intersections, mapped types); reach for interface when you want declaration merging or are modeling an extensible object/class shape.
Discriminated union
A union of objects sharing one literal “tag” field (as, kind, status). The tag lets the compiler narrow to exactly one variant.

01 The utility types you actually use

You don’t need the whole standard library — five carry most of the weight. They transform existing types instead of re-declaring them, so props stay in sync.

UtilityWhat it does
Partial<T>Makes every field optional — great for update payloads and default-merge.
Pick<T, K>Keeps only keys K — expose a narrow prop subset from a big type.
Omit<T, K>Drops keys K — e.g. spread native props but remove the ones you override.
Record<K, V>An object with keys K and values V — typed maps and lookup tables.
ReturnType<F>The type a function returns — derive a hook’s value type without re-typing it.
props.ts
// Extend a native <input> but swap our own onChange
type InputProps =
  Omit<React.ComponentProps<"input">, "onChange"> & {
    onChange: (value: string) => void;
  };

// Derive a value type from a hook's return — no duplication
type Auth = ReturnType<typeof useAuth>;

02 Generics, narrowing & as const

Generics let one component or hook work over many types without losing the specific one. Pair them with narrowing and as const so literals stay literals, not widened to string.

List.tsx
// Generic component: T flows from items → render
function List<T>({ items, render }: {
  items: T[];
  render: (item: T) => React.ReactNode;
}) {
  return <ul>{items.map(render)}</ul>;
}

// `as const` keeps literals narrow (not widened to string[])
const TABS = ["home", "profile"] as const;
type Tab = (typeof TABS)[number]; // "home" | "profile"

Narrowing is how the compiler proves which branch you’re in. A discriminant check (if (props.as === "link")) or a typeof guard lets TS know the exact shape inside that block — no casts needed.

Common trap gotcha

Event handlers and refs trip everyone. A change handler is React.ChangeEvent<HTMLInputElement>, not any. And a DOM ref must start as null: const ref = useRef<HTMLInputElement>(null) — the null is required, and ref.current is then nullable until mounted.

03 Typing hooks & avoiding any

Most useState calls infer fine. You only annotate when the initial value can’t express the full type — e.g. state that starts null but later holds a User. For unknown inputs, prefer unknown over any: it forces you to narrow before use.

hooks.tsx
// Inferred — no annotation needed
const [open, setOpen] = useState(false);

// Annotate when the initial value can't carry the type
const [user, setUser] = useState<User | null>(null);

// `unknown` forces a check; `any` would silently let bugs through
function parse(json: string): unknown {
  return JSON.parse(json);
}
const data = parse(s);
if (isUser(data)) data.name; // ✅ narrowed, safe

You have a Button with a variant that must be "primary" or "ghost". Which type best prevents an invalid variant from ever rendering?

Right. A literal union restricts the value to exactly the allowed set, so a typo like "primry" fails to compile and autocompletes the valid options. string and any both let invalid variants through.

04 Interview rapid-fire

type vs interface — which do you use for props, and why?warm
Model answer

I default to type because props often need unions, intersections, or mapped/utility types, which type handles cleanly. interface is great when I want declaration merging or an extensible object/class contract, but for component props the two are mostly interchangeable.

Say it out loud say it

“type by default — it does unions and utility types. interface when I need merging. For props, pick one and stay consistent.”

How do you make a reusable component generic over its data?core
Model answer

Add a type parameter and let it flow from a prop. A List<T> takes items: T[] and a render: (item: T) => ReactNode; TS infers T from the array, so the render callback is fully typed at the call site with no manual annotation.

Say it out loud say it

“I parametrize the component with <T> and let it infer from the items prop, so the render function gets the exact element type for free.”

Why model component variants with a discriminated union?stretch
Model answer

It makes invalid prop combinations unrepresentable. A link variant requires href and a button variant requires onClick — the shared discriminant (as) lets TS narrow to exactly one shape, so you can’t pass href to a button or forget the right field. The compiler enforces the contract instead of a runtime check.

Say it out loud say it

“Discriminated unions make impossible states impossible — each variant carries exactly its required props, and TS narrows on the tag so bad combos won’t compile.”
