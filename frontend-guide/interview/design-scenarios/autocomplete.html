Design an autocomplete

The classic warm-up: a search box that suggests as you type. It looks tiny, but a strong answer touches debouncing, race conditions, caching, and full keyboard accessibility — which is exactly why interviewers love it.

00 The idea

An autocomplete is an input that fetches suggestions as you type. The hard parts aren’t the UI — they’re not over-fetching, not showing stale results, and keyboard control.

User types, you query a backend, you render a dropdown of matches they can pick with mouse or keyboard. Get there with the six-step method — the interesting decisions are all in steps 3–5 (data, perf, a11y).

Think of it like… analogy

A librarian narrowing suggestions as you describe a book. You don’t want them sprinting to the stacks after every single word — they wait a beat until you pause (debounce). And if you change your mind mid-sentence, they should drop the old search, not hand you the book you no longer want (cancel stale requests).

01 The six steps, on a typeahead

A quick pass so you have the full shape before we go deep on the tricky parts.

1 · Requirements
Remote or local data? Min characters before searching? How many results, and is there a “no matches” state? Single-select.
2 · API & state
Props: onSelect(item), placeholder, optional minChars. State: query, results, status, activeIndex, open.
3 · Data & caching
Debounce the query; cancel in-flight requests; cache results by query key so re-typing is instant.
4 · Rendering & perf
Don’t fire a request per keystroke. Render a bounded list; only re-render on real changes.
5 · A11y & edges
Combobox roles, arrow/enter/escape, aria-activedescendant. Empty, loading, error, and out-of-order states.
6 · Trade-offs
Debounce delay vs snappiness; client cache vs always-fresh; how it scales to huge result sets.

02 What happens on a keystroke

The whole lifecycle of one character typed — this is the trace you should draw on the whiteboard.

1

Keystroke

User types; query state updates and the input re-renders immediately (input stays controlled and snappy).

2

Debounce

Wait ~250 ms of no typing before doing anything network-y. Rapid typing resets the timer, so we fetch once at the pause, not per key.

3

Cancel previous

Before the new fetch, abort() the prior in-flight request so a slow earlier response can’t overwrite a newer one.

4

Fetch

If under minChars, skip. Otherwise request suggestions for the debounced query and set status: "loading".

5

Cache

Store results keyed by the query string. Re-typing a seen query is served from cache — zero network, instant list.

6

Render list

Show the dropdown with roles wired up; arrow keys move activeIndex, Enter selects, Escape closes.

03 A debounced, cancelable fetch hook

The core of step 3 in ~15 lines: debounce the query, then fetch with an AbortController whose cleanup cancels the previous request. Out-of-order responses simply can’t land.

useAutocomplete.ts
function useAutocomplete(query: string, minChars = 2) {
  const [results, setResults] = useState<Item[]>([]);

  useEffect(() => {
    if (query.length < minChars) { setResults([]); return; }
    const ctrl = new AbortController();
    const t = setTimeout(async () => {        // debounce
      const res = await fetch(`/api/search?q=${query}`, { signal: ctrl.signal });
      setResults(await res.json());           // only the latest survives
    }, 250);
    return () => { clearTimeout(t); ctrl.abort(); }; // cancel prior
  }, [query, minChars]);

  return results;
}
Heads up — in a real app note

In production you’d reach for TanStack Query v5: useQuery keyed by ["search", query] gives you the caching, dedupe, and stale handling for free — you just debounce the key. The hand-rolled hook is the version to explain so the interviewer sees you understand the mechanics underneath.

04 Keyboard & ARIA (the senior signal)

This is where most candidates stop short. A real autocomplete is a combobox, and it must be fully operable without a mouse.

Roles
Input has role="combobox", aria-expanded, aria-controls pointing at the listbox; the dropdown is role="listbox" with role="option" children.
Active option
Keep DOM focus on the input; mark the highlighted option with aria-activedescendant so screen readers announce it without moving focus.
Keys
↓/↑ move activeIndex, Enter selects, Escape closes the list, typing reopens it.
States
Empty (“type to search”), loading, no-matches, and error each need a visible, announced message.
Common trap — out-of-order responses gotcha

Type “re” then “react”. The slow “re” request can resolve after “react” and clobber the correct list — a classic race condition. Fix it by aborting the prior request (as above) or ignoring any response whose query no longer matches the current one. Never just “await and setState” blindly.

Why debounce the input instead of fetching on every keystroke?

Right. Debounce collapses a burst of keystrokes into one request at the pause — less load, fewer races, and a smoother list. It’s about request volume, not React or a11y.

05 Interview rapid-fire

How do you prevent stale suggestions from a slow response?core
Model answer

Cancel the previous request with an AbortController before starting the next, or tag each response with its query and ignore any whose query no longer matches the current input. That kills out-of-order races so only the latest result renders.

Say it out loud say it

“I abort the in-flight request on each new keystroke, or drop responses whose query is stale — so a slow old request can never overwrite a newer one.”

Debounce vs throttle — which here, and why?core
Model answer

Debounce. We only care about the final query after the user stops typing, so we wait for a pause and fire once. Throttle (fire at a steady rate) suits continuous streams like scroll or resize, not “settle then act” search.

Say it out loud say it

“Debounce — I want to act once the user settles, not on a fixed cadence. Throttle is for continuous events like scroll.”

How do you make the dropdown accessible?stretch
Model answer

Build it as a combobox: input with role="combobox" and aria-expanded, a listbox of options, focus staying on the input, and the highlighted item exposed via aria-activedescendant. Wire arrow keys, Enter, and Escape.

Say it out loud say it

“It’s a combobox — focus stays on the input, the active option is announced with aria-activedescendant, and arrows, Enter, and Escape all work.”
