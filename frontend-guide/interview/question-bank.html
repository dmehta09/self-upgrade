01 React

What is a render, and what triggers one?warm
Model answer

A render is React calling your component function to get a description of the UI. Exactly three things trigger it: the component’s own state changed, its parent re-rendered, or a context it reads changed. New props aren’t a separate trigger — a parent re-render is what delivers them.

Say it out loud say it

“A render is just React calling my function. It fires on state, parent, or context — props aren’t separate, the parent re-render delivers them.”

Is re-rendering a performance problem?core
Model answer

Usually not. A render is a cheap function call; React reconciles the output and only mutates the DOM where it actually differs, so a no-op render commits nothing. You optimize when a render body is genuinely expensive or fires far too often — not reflexively by render count.

Say it out loud say it

“Re-rendering is cheap; the DOM commit is the cost. I profile a hotspot before optimizing, not the render count.”

Why are list keys important, and why is index-as-key a trap?core
Model answer

Keys give items a stable identity so React can match them across renders and reorder rather than rebuild. Using the array index breaks when the list reorders, inserts, or deletes — React keeps the DOM node but feeds it the wrong data, so input state and focus jump to the wrong row.

Say it out loud say it

“Keys are identity. Index-as-key looks fine until the list reorders — then state sticks to the position, not the item.”

What is useEffect for — and what is it not for?core
Model answer

It synchronizes your component with a system outside React — subscriptions, timers, non-React widgets, manual DOM. It’s not for deriving state (compute during render) or responding to a user event (do it in the handler). If there’s no external system, you probably don’t need an effect.

Say it out loud say it

“Effects synchronize with the outside world. Deriving state or handling a click doesn’t need one — that’s a render or an event handler.”

Follow-ups to expect
  • What does the cleanup function do, and when does it run?
  • How does useEffectEvent help with stale closures in 19.2?
What do the Rules of Hooks protect against?core
Model answer

React matches hooks to their state by call order, not by name. Calling a hook conditionally or in a loop shifts that order on the next render, so a hook reads another hook’s state. That’s why hooks must run at the top level of a component, in the same order every time.

Say it out loud say it

“Hooks are tracked by order, not name. A conditional hook shifts the order and crosses the wires — so they stay at the top level.”

When does memo/useMemo/useCallback help, and does the React Compiler change that?stretch
Model answer

They help when a subtree or computation is genuinely expensive and its inputs are stable; otherwise they add overhead and noise. With React Compiler 1.0 (GA since Oct 2025, used in 19.2) most of this is automatic at build time, so manual memoization is now reserved for measured hotspots or cases the compiler can’t prove safe.

Say it out loud say it

“Expensive work plus stable inputs. But the compiler auto-memoizes now, so I lean on it and hand-tune only what I’ve profiled.”

What changed for refs in React 19?core
Model answer

For new components you take ref as a normal prop — forwardRef is no longer required. React 19 also lets a ref callback return a cleanup function. This pairs with other API cleanups like <Context> as a provider and document-metadata hoisting.

Say it out loud say it

“In React 19 ref is just a prop — no forwardRef for new components, and ref callbacks can return cleanup.”

What does use() do that hooks can’t?stretch
Model answer

use() reads a resource — a promise (suspending until it resolves) or a context. Unlike hooks, it can be called conditionally and inside loops, because it isn’t tracked by call order. It’s the idiomatic way to unwrap a promise passed from a Server Component.

Say it out loud say it

“use() reads a promise or context and can be called conditionally — it’s how a Client Component unwraps a promise handed down from the server.”

02 Next.js / RSC

Server vs Client Components — what’s the split?core
Model answer

In the App Router, components are Server Components by default: they run only on the server, can be async, fetch data and read secrets, and ship zero JS. Adding "use client" opts a subtree into the browser — it gets state, effects, and event handlers but adds to the bundle. You compose them: server fetches, client interacts.

Say it out loud say it

“Server by default — fetch and secrets, no JS shipped. "use client" for interactivity. I keep the boundary low so less JS reaches the browser.”

Follow-ups to expect
  • Can a Server Component import a Client Component? (Yes.) The reverse? (Only as children/props.)
Walk through SSG, SSR, ISR, and PPR.core
Model answer

SSG builds HTML at build time (great for static content); SSR renders per request (personalized/fresh); ISR is SSG plus timed revalidation (catalogs that drift). PPR is the modern blend: a static shell served instantly with dynamic holes streamed in — in Next 16 it ships via Cache Components rather than the old experimental flag.

Say it out loud say it

“Build-time, per-request, or build-plus-revalidate. PPR is the best of both — static shell, dynamic holes streamed — and in Next 16 it’s Cache Components.”

How does caching work in Next.js 16?stretch
Model answer

It’s dynamic-by-default now — you opt into caching with the "use cache" directive on a function, component, or route, and the compiler derives the cache key from inputs. That supersedes unstable_cache. You enable the model with cacheComponents: true in next.config.ts.

Say it out loud say it

“Dynamic by default — I mark what I want cached with "use cache" and the compiler keys it. That replaced unstable_cache.”

How do you invalidate cached data after a mutation?stretch
Model answer

From a Server Action: revalidateTag(tag, profile) — which now takes a cache-life profile as its second argument — or revalidatePath. For read-your-writes within the same action use the new updateTag(), and refresh() for an uncached re-fetch. Tag your "use cache" entries with cacheTag so you can target them.

Say it out loud say it

“In the Server Action I call revalidateTag with a cache-life profile, or updateTag when I need to see my own write immediately.”

What is a Server Action, and why prefer it over an API route?core
Model answer

A Server Action is a server function marked "use server" that you call directly from a component or pass to a form’s action, with no hand-written endpoint or fetch plumbing. It keeps the mutation co-located, type-safe end to end, and progressively enhanced — the form works before JS loads. It’s stable in Next 16.

Say it out loud say it

“It’s a server function I call straight from the form — no API route, type-safe, and it works before JS hydrates.”

Which request APIs became async, and why does that matter?core
Model answer

In Next 16, params, searchParams, cookies(), and headers() are async — you await them. This lets the framework start rendering the static shell before request-specific data is read, which is what makes Partial Prerendering possible. Forgetting to await is a common migration bug.

Say it out loud say it

“params, searchParams, cookies, headers are async now — awaiting them lets Next prerender the shell before reading request data.”

What replaced middleware.ts, and what changed with the bundler?warm
Model answer

middleware.ts is deprecated in favour of proxy.ts for request interception at the edge. Separately, Turbopack is now stable and the default for both next dev and next build — you opt out with --webpack if a plugin still needs it.

Say it out loud say it

“Middleware became proxy.ts, and Turbopack is the default builder now for both dev and build.”

How does loading.tsx relate to Suspense in the App Router?stretch
Model answer

loading.tsx is sugar: Next wraps the route segment in a <Suspense> boundary whose fallback is your loading file. While the server streams the segment’s data, the user sees that fallback instantly. You can add finer-grained <Suspense> boundaries inside a page to stream independent regions.

Say it out loud say it

“loading.tsx is just a Suspense boundary for the segment — the shell streams instantly and I add inner boundaries to stream regions independently.”

03 Rendering & performance

What is hydration, and what does it cost?core
Model answer

Hydration is React attaching state and event listeners to server-rendered HTML so it becomes interactive. The cost is that it re-runs your component code on the client and ships the JS to do so — that’s why a page can look done but not respond yet. RSC reduces it by keeping server-only components out of the client bundle.

Say it out loud say it

“Hydration wires listeners onto server HTML. It re-runs code and ships JS — so the page can look ready before it can react. RSC trims what needs hydrating.”

How does streaming SSR improve perceived performance?core
Model answer

Instead of waiting for all data before sending HTML, the server flushes the ready shell immediately and streams slower parts — wrapped in <Suspense> — as they resolve. The user sees and can read content sooner, improving TTFB and often LCP, even though total time is similar.

Say it out loud say it

“Stream the shell now, stream slow parts behind Suspense as they finish. Same total time, but the user sees content far sooner.”

Name the Core Web Vitals and their targets.warm
Model answer

Three: LCP (largest contentful paint) ≤ 2.5 s for loading, INP (interaction to next paint) ≤ 200 ms for responsiveness, and CLS (cumulative layout shift) ≤ 0.1 for visual stability. Targets are measured at the 75th percentile of real field data, not lab numbers.

Say it out loud say it

“LCP under 2.5 seconds, INP under 200 milliseconds, CLS under 0.1 — all at the 75th percentile of field data.”

INP is poor. How do you debug and fix it?stretch
Model answer

INP measures the worst interaction-to-paint of the visit, so I look for long tasks blocking the main thread around interactions. Fixes: ship less JS, break long tasks into yields, move heavy work off the critical path (a transition, a worker, or the server), and defer non-urgent updates with useTransition.

Say it out loud say it

“INP is about long tasks near interactions. I cut JS, break up the work, and defer the non-urgent part with a transition so the handler paints fast.”

Biggest levers to cut JS bundle size in a Next app?core
Model answer

Keep components on the server — every "use client" boundary and its imports ship to the browser, so push interactivity to the leaves. Then code-split heavy client widgets with next/dynamic, prefer lighter dependencies, and let tree-shaking and route-level splitting do the rest.

Say it out loud say it

“Move work to the server, keep client boundaries at the leaves, lazy-load heavy widgets, and pick lighter deps. The boundary placement is the big lever.”

What ships to the client under CSR vs SSR vs RSC?core
Model answer

CSR sends an empty shell and all the JS, which renders in the browser. SSR sends full HTML for fast first paint but still ships all the JS to hydrate it. RSC sends HTML for server components — whose code never reaches the browser — plus JS only for the Client Components, so the bundle scales with interactivity, not page size.

Say it out loud say it

“CSR ships everything, SSR ships HTML plus all the hydration JS, RSC ships HTML plus JS only for the interactive bits.”

A page has a high CLS. What’s likely wrong?warm
Model answer

Content loading without reserved space — images without dimensions, late-loading ads or embeds, or web fonts swapping in and reflowing text. Fix by setting explicit width/height or aspect-ratio, reserving slots for dynamic content, and using sensible font-display fallbacks.

Say it out loud say it

“Something loads without reserving space — images, ads, or fonts. I set explicit sizes and reserve slots so nothing jumps.”

04 Data & state

TanStack Query vs Zustand vs URL vs local state — how do you choose?core
Model answer

Match the tool to the kind of state. Server data → TanStack Query (it caches, dedupes, and revalidates). Shareable state like filters/tabs/page → the URL. Global client/UI state like theme or cart → Zustand. Anything local and ephemeral → useState. Most “state management” pain is putting server data in a client store.

Say it out loud say it

“Server data in Query, shareable state in the URL, global UI in Zustand, local in useState. The classic mistake is caching server data in a client store.”

Explain staleTime vs gcTime.core
Model answer

staleTime is how long fetched data is considered fresh — during that window Query won’t refetch on mount or focus. gcTime (renamed from cacheTime in v5) is how long unused data stays in the cache after the last observer unmounts, defaulting to 5 minutes. Fresh-vs-stale controls refetching; gcTime controls memory.

Say it out loud say it

“staleTime decides when it refetches; gcTime — the old cacheTime — decides how long unused data lingers in cache.”

Why is TanStack Query “a cache, not state management”?stretch
Model answer

Server data isn’t owned by your app — it can change anywhere, anytime. Query treats it as a cache of a remote source of truth: keyed entries, background refetching, dedupe, and invalidation. Trying to manage it as plain client state means hand-rolling all of that and constantly fighting staleness.

Say it out loud say it

“The server owns that data, not me. Query caches a remote source of truth — keys, refetch, dedupe, invalidation — instead of pretending it’s client state.”

How do you implement an optimistic update?core
Model answer

Apply the expected result to the UI immediately, then reconcile with the server response — rolling back on error. In Query you cancel in-flight queries, snapshot the cache in onMutate, write the optimistic value, and restore the snapshot in onError. In React itself, useOptimistic manages the temporary state around an Action.

Say it out loud say it

“Show the result now, snapshot the cache, then roll back on error. Query does it with onMutate/onError; React has useOptimistic for Actions.”

Zustand v5: why can a selector cause an infinite loop?stretch
Model answer

If a selector returns a new object or array each call (e.g. (s) => ({ a: s.a, b: s.b })), Zustand sees a new reference every render, assumes the slice changed, re-renders, and loops. Wrap it in useShallow so it compares the result shallowly instead of by reference.

Say it out loud say it

“An object-returning selector makes a fresh reference each render, so Zustand thinks it changed and loops. useShallow compares the contents instead.”

When would you put state in the URL?core
Model answer

Whenever the state should be shareable, bookmarkable, or survive a refresh — the active tab, search filters, sort, pagination, a selected detail id. The URL becomes the source of truth, so deep links just work and the back button behaves. In Next you read it via async searchParams.

Say it out loud say it

“If a teammate should be able to paste the link and see the same view — filters, tab, page — it belongs in the URL.”

How do you validate a form in 2026?warm
Model answer

react-hook-form for state (uncontrolled inputs, minimal re-renders) plus zodResolver from @hookform/resolvers with a Zod 4 schema. The win is one schema shared between client and server — the same validation runs in the Server Action, so you never trust the client alone.

Say it out loud say it

“RHF plus a Zod schema via zodResolver — and I run the same schema in the Server Action so the server validates too.”

05 Styling

What’s different about Tailwind v4?core
Model answer

It’s CSS-first. Configuration moves into CSS: a single @import "tailwindcss"; and a @theme {} block of design tokens that become real CSS variables — no tailwind.config.js (it’s legacy via @config). The Oxide engine is much faster, and container queries are native with the @container variant.

Say it out loud say it

“v4 is CSS-first — tokens live in @theme as CSS variables, no JS config, faster Oxide engine, native container queries.”

What does cn() do and why do you need it?core
Model answer

cn() is twMerge(clsx(...)). clsx joins class names with conditionals; twMerge then resolves Tailwind conflicts so the last utility wins — so a passed-in className can override a component’s default (px-2 vs px-6) instead of both ending up in the string and the cascade deciding arbitrarily.

Say it out loud say it

“cn is twMerge(clsx()) — conditional classes plus conflict resolution, so an overriding className actually wins.”

What problem does cva solve?core
Model answer

cva (class-variance-authority) turns a tangle of conditional class logic into a declarative, typed map of variants — variant, size, defaults, compound variants. The component exposes a clean prop API, TypeScript autocompletes the options, and the class strings live in one place.

Say it out loud say it

“cva maps typed props like variant and size to class strings — declarative, autocompleted, all in one spot instead of ad-hoc ternaries.”

Is shadcn/ui a component library? Why does “you own the code” matter?stretch
Model answer

No — it’s a distribution of copy-in components. npx shadcn@latest add writes Radix-based, cva-styled source straight into your repo, and from then on it’s yours to edit. You get accessible primitives and a head start with zero version lock-in or upgrade churn from a black-box dependency — the trade-off is you maintain the code.

Say it out loud say it

“It’s copy-in, not a dependency — the code lands in my repo on Radix primitives, so I customize freely with no version lock-in, but I own the upkeep.”

How does shadcn handle theming with Tailwind v4?core
Model answer

Through CSS variables — semantic tokens like --background and --primary defined in OKLCH, flipped under a .dark selector. Components reference those tokens, so re-theming is editing variables, not components. The current default style is new-york, and components ship data-slot attributes for targeting.

Say it out loud say it

“Semantic CSS variables in OKLCH, swapped under .dark. Components read the tokens, so theming is editing variables, not components.”

Doesn’t utility-first CSS bloat the HTML and stylesheet?warm
Model answer

The markup looks busier, but the stylesheet shrinks: utilities are reused across the whole app, so CSS stops growing per component and stays small and cacheable. v4’s engine scans your source and emits only the classes you actually use, and repeated class strings gzip well.

Say it out loud say it

“The HTML looks busier but the CSS doesn’t grow — utilities are reused, only used classes ship, and it caches and gzips well.”

06 Testing & tooling

What does “test behavior, not implementation” mean in practice?core
Model answer

Write tests the way a user interacts: query by role or visible text, fire events, and assert on what renders — not on internal state, class names, or which hook fired. The payoff is tests that survive refactors and actually catch regressions, since they only break when behavior breaks.

Say it out loud say it

“I query by role and text and assert on output, not internals. Then the test breaks only when behavior breaks, not when I refactor.”

What is the testing trophy, and how does it differ from the pyramid?core
Model answer

The trophy weights toward integration/component tests — the best confidence-per-effort — with fewer unit and E2E tests on top and static analysis (TypeScript + lint) as the base. The pyramid pushed mostly isolated unit tests; the trophy argues those give less real confidence than testing components the way they’re used.

Say it out loud say it

“Trophy: static analysis at the base, mostly integration tests in the middle, a few unit and E2E. Integration buys the most confidence per test.”

Vitest vs Playwright — when each?warm
Model answer

Vitest + React Testing Library for unit and component tests — fast, in jsdom or the now-stable Browser Mode. Playwright for end-to-end: real browsers (Chromium/Firefox/WebKit), multiple pages, auth, the genuinely cross-cutting flows. Use Vitest for the bulk and Playwright for a handful of critical journeys.

Say it out loud say it

“Vitest plus RTL for components, Playwright for a few real end-to-end journeys across pages. Bulk in Vitest, critical paths in Playwright.”

What’s the state of linting — ESLint 10 vs Biome?core
Model answer

ESLint 10 only supports flat config (eslint.config.js) — the old .eslintrc format is gone — paired with typescript-eslint 8. Biome 2 is the fast Rust alternative that does lint and format in one tool. Pick ESLint for the mature plugin ecosystem, Biome when speed and a single config win.

Say it out loud say it

“ESLint 10 is flat-config only with typescript-eslint 8; Biome 2 is the fast all-in-one. Ecosystem → ESLint, speed and simplicity → Biome.”

What do you actually mock in a component test?stretch
Model answer

The network boundary, not your own modules — intercept requests (e.g. MSW) so the component runs its real code against fake responses. Mocking internal functions couples the test to implementation; mocking the network keeps it behavioral while staying fast and deterministic.

Say it out loud say it

“I mock the network with something like MSW, not my own modules — real component code, fake responses, behavior intact.”

What does the build toolchain look like in 2026?warm
Model answer

Vite 8 with Rolldown (Rust) as the default bundler for SPAs; Next 16 ships Turbopack by default. Vitest 4 for tests with stable Browser Mode, pnpm 11 as the common package manager with bun as the fast challenger, and TypeScript + flat-config ESLint or Biome as the static-analysis base.

Say it out loud say it

“Vite 8 on Rolldown for SPAs, Turbopack in Next 16, Vitest 4 for tests, pnpm 11 — the whole chain went Rust-fast.”

07 Accessibility

What’s the single highest-leverage accessibility practice?core
Model answer

Use semantic HTML. A real <button>, <nav>, <a>, or heading comes with keyboard support, focus behavior, and the correct role for free. A div with an onClick is invisible to keyboards and screen readers until you reinvent all of that — usually incompletely.

Say it out loud say it

“Semantic HTML. A real <button> gives me keyboard, focus, and role for free — a clickable div makes me rebuild all of it.”

When is ARIA appropriate — and when does it hurt?core
Model answer

ARIA is for what native HTML can’t express — custom widgets (combobox, tabs), live regions, dynamic state like aria-expanded. It only adds semantics; it never adds behavior, so you still wire keyboard and focus yourself. The first rule of ARIA is don’t use ARIA when an element exists — wrong ARIA is worse than none.

Say it out loud say it

“ARIA only for what HTML can’t express, and it adds meaning not behavior. No ARIA beats wrong ARIA.”

How do you handle focus in a modal dialog?stretch
Model answer

On open, move focus into the dialog (often the first control or the heading) and trap Tab within it; on close, restore focus to the trigger. Mark it role="dialog" with aria-modal="true" and a label, and let Escape close it. The native <dialog> element or a primitive like Radix gives you most of this.

Say it out loud say it

“Focus moves in and traps, Escape closes, focus returns to the trigger. Native <dialog> or Radix handles most of it.”

Why does focus management matter in a client-routed SPA?core
Model answer

A full page load resets focus to the top; client navigation doesn’t, so after a route change a keyboard or screen-reader user is stranded wherever they clicked. Move focus to the new page’s main heading (or an announced region) on navigation so the next Tab starts somewhere sensible.

Say it out loud say it

“Client routing doesn’t reset focus like a page load, so I move focus to the new heading on navigation — otherwise keyboard users are lost.”

What’s in your 60-second accessibility audit?warm
Model answer

Tab through the whole page with no mouse — can I reach and operate everything, and is the focus ring visible? Then check semantic landmarks and one logical heading order, labels on every input, alt text and icon-button names, and 4.5:1 contrast on body text. Those five catch the majority of real issues.

Say it out loud say it

“Tab through with no mouse, check visible focus, semantics and headings, input labels, and contrast. That catches most of it fast.”
