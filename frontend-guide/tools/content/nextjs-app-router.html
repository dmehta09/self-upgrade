The App Router model

The App Router turns your app/ directory into the router: folders are URL segments and a handful of special files declare the UI for each one. Master the conventions and routing, layouts, loading and errors all fall out of where you put files.

00 The idea

The filesystem is the router. A folder is a URL segment; special files give it behavior.

Each segment can declare a layout (persistent shell), a page (the route’s UI), and states like loading and error. Layouts nest as folders nest, so a route’s UI is the chain of layouts wrapping its page.

Think of it like… analogy

A building’s address. app/dashboard/settings/ is just “floor dashboard, room settings.” You don’t register the address anywhere — walking the folders is walking the URL. Add a folder, you’ve added a route.

FileWhat it declares
layout.tsxShared shell wrapping a segment + its children; persists across navigations (no remount).
page.tsxThe UI unique to this route. A segment is only routable if it has a page.
loading.tsxInstant fallback shown via Suspense while the segment’s server work streams in.
error.tsxClient error boundary for the segment; gets error + reset().
not-found.tsxRendered when a segment calls notFound() (or hits an unmatched route).
route.tsAn HTTP endpoint (GET/POST…) instead of UI — a segment is a page or a route, not both.
(folder)
Route group: organizes files / shares a layout without adding a URL segment.
@slot
Parallel routes: render multiple independent pages into one layout at once.
(.)folder
Intercepting routes: show a route (e.g. a modal) in the current context instead of a full nav.

01 How a request composes

A navigation doesn’t throw away the shell. Layouts stay mounted while the changed leaf swaps — nested layouts wrap from the root inward to the page.

Request → /dashboard/settings
root
app/layout
<html>, fonts, providers
segment
dashboard/layout
sidebar, nav (persists)
leaf
settings/page
the changing UI

Wrap a segment in loading.tsx and Next auto-creates a Suspense boundary there: the layout paints instantly, the page streams in.

02 Async params & metadata

Per-route request inputs are async in Next 16 — you await them. That keeps a route static until it actually reads request data. Define page <title>/SEO with the Metadata API, not manual tags.

app/blog/[slug]/page.tsx
// params & searchParams are Promises now — await them.
export async function generateMetadata(
  { params }: { params: Promise<{ slug: string }> }
) {
  const { slug } = await params;
  return { title: `Post: ${slug}` };       // Metadata API, not <head>
}

export default async function Page(
  { params }: { params: Promise<{ slug: string }> }
) {
  const { slug } = await params;
  return <article>{slug}</article>;
}
Common trap gotcha

In Next 16, params, searchParams, cookies() and headers() are all async. Reaching for params.slug or cookies().get(…) synchronously is the #1 migration error — await them first.

03 Turbopack is the default

As of Next.js 16, Turbopack is the default bundler for both next dev and next build — no flag needed. Config lives in next.config.ts; the old middleware.ts is now proxy.ts.

package.json · scripts
{
  "scripts": {
    "dev": "next dev",
    "build": "next build",
    "build:webpack": "next build --webpack"
  }
}

Both commands run on Turbopack automatically; pass --webpack only if a legacy plugin still needs it.

Why doesn’t a shared sidebar in dashboard/layout.tsx flash or reset when you navigate between two pages under it?

Right. A layout wraps its children and stays mounted while you move between sibling pages. Only the segment that actually changed re-renders, so layout state (scroll, open menus) survives.

04 Interview rapid-fire

Name the special files in an App Router segment and what each does.core
Model answer

layout is the persistent shell, page the route’s UI, loading the Suspense fallback, error the segment error boundary, not-found the 404 UI, and route an HTTP endpoint instead of UI. A segment needs a page or route to be reachable.

Say it out loud say it

“layout, page, loading, error, not-found, route. Layout is the shell that persists; page is the leaf; loading and error are auto-wired Suspense and error boundaries.”

How do nested layouts work, and why do they matter for UX?core
Model answer

Layouts nest as folders nest: a route’s UI is every layout from the root down, wrapping its page. Because they persist across navigation, shared chrome (nav, sidebars) doesn’t remount — state and scroll survive and only the changed segment streams.

Say it out loud say it

“Layouts compose root-to-leaf and persist between navigations, so shared UI stays mounted and only the leaf re-renders.”

Why are params and cookies() async in Next 16?stretch
Model answer

Making request inputs Promises lets Next keep a route static and start rendering before request data resolves — the route only becomes dynamic at the await. It’s the API shape that makes dynamic-by-default plus partial prerendering possible.

Say it out loud say it

“They’re async so rendering can start before request data is read — the route stays static until you await it, which is what enables partial prerendering.”
