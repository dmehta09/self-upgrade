React 19: Actions, use(), compiler

React 19 (19.2 as of June 2026) is mostly about deleting boilerplate. Forms, pending states, refs, and memoization that you used to hand-wire are now first-class — or written for you by the compiler.

00 The idea

The framework now writes the plumbing — form submission, pending/optimistic UI, and memoization — that you previously coded by hand.

The throughline: less ceremony. Actions standardize async form work with built-in pending and error state. use() reads promises and context flexibly. ref is a normal prop. And React Compiler 1.0 auto-memoizes so you stop sprinkling useMemo.

Think of it like… analogy

You upgraded from a manual car to an automatic. You still decide where to go, but the gear-shifting (form state, pending spinners, memoization) now happens for you. Less to operate, fewer ways to stall — you focus on the destination, not the clutch.

02 Actions & form state

Actions are async functions wired to a form or transition; React tracks their pending and error state for you. useActionState wraps an action and hands back the latest result plus isPending; useFormStatus lets a nested button read the parent form’s pending state without prop-drilling. useOptimistic shows an instant predicted result while the action runs.

NameForm.tsx
const [error, submit, isPending] = useActionState(
  async (_prev, formData) => {
    const res = await save(formData.get("name"));
    return res.ok ? null : "Save failed";
  },
  null, // initial state
);
return (
  <form action={submit}>
    <input name="name" />
    <button disabled={isPending}>Save</button>
    {error && <p>{error}</p>}
  </form>
);

No onSubmit, no manual useState for pending/error — the action owns that lifecycle.

03 use(): read promises & context

use() reads a resource during render: pass it a promise and the component suspends until it resolves (pair with <Suspense>); pass it a context and it reads the value — but unlike useContext, use() may be called conditionally.

Comments.tsx
// commentsPromise is created by a parent/loader.
function Comments({ commentsPromise }) {
  // Suspends here until the promise resolves.
  const comments = use(commentsPromise);
  return comments.map(c => <p key={c.id}>{c.text}</p>);
}
// Wrap the caller in <Suspense fallback={...}> for the loading UI.
Common trap gotcha

Don’t reach back for useFormState — it’s renamed to useActionState; the old import is gone. And the React Compiler is opt-in for existing apps: it’s GA and stable, but you still enable it (and respect the rules of React) — it doesn’t silently rewrite a codebase you never configured.

Which is the correct React 19 hook for an async form’s result and pending state?

Right. useActionState is the stable name (it superseded the experimental useFormState). It returns [state, action, isPending], so you don’t hand-track loading state.

04 Interview rapid-fire

What’s new in React 19?core
Model answer

Actions with useActionState/useFormStatus/useOptimistic, the use() API for promises and context, ref as a plain prop (no forwardRef), automatic document-metadata hoisting, <Context> as its own provider, and a stable React Compiler for auto-memoization.

Say it out loud say it

“Actions for forms, use() for promises and context, ref as a normal prop, metadata hoisting, and a stable compiler that auto-memoizes. Mostly: way less boilerplate.”

What is use() and how does it differ from hooks?core
Model answer

use() reads a resource — a promise (the component suspends until it resolves) or a context value. Unlike normal hooks it can be called conditionally and inside loops, because it isn’t tracked by call-order slots the same way.

Say it out loud say it

“use() reads a promise or context during render — promises suspend. Unlike other hooks, you can call it conditionally.”

Is the React Compiler automatic? Should I delete all my memo calls?stretch
Model answer

It’s GA and stable, but opt-in — you enable it in the build, and your code must follow the rules of React. Once on, it auto-memoizes, so most manual useMemo/useCallback/memo becomes redundant; keep hand-tuning only for profiled hotspots it can’t cover.

Say it out loud say it

“Stable but opt-in — I turn it on and follow the rules of React. Then it memoizes for me, and I only keep manual memo for profiled hotspots.”
