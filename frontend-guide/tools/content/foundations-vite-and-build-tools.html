Vite & the build toolchain

Vite gives you a near-instant dev server and a lean production build — two different machines wearing one CLI. Knowing what each does (and when Vite isn’t the right tool) is table stakes for a pro.

00 The idea

Dev and build are two pipelines. Dev serves native ESM on demand; build emits an optimized bundle. Vite 8 ships Rolldown as its bundler.

In development, the browser’s own ES-module support means Vite only transforms files you actually request — so startup doesn’t scale with app size. For production it bundles, tree-shakes, and minifies into a handful of cache-friendly files.

Think of it like… analogy

The dev server is a made-to-order kitchen — it cooks only the dish you order, the moment you order it, so service starts instantly. The build is a mass-production line — slower to set up, but it packages everything for shipping at scale. Same restaurant, two very different machines.

One CLI, two pipelines
dev
Native ESM
browser imports modules; no bundling
edit
HMR
swap one module, keep state
build
Rolldown bundle
tree-shake, minify, hash, split
Dev server
Serves source over native ESM; transforms on request via esbuild; HMR hot-swaps a changed module without a full reload.
Production build
Bundles with Rolldown (the Rust bundler that’s default in Vite 8): tree-shaking, code-splitting, minification, content hashes.
Transforms
esbuild (Go) and SWC (Rust) do the fast TS/JSX-to-JS work in place of a slower JS-based transpiler.

01 A minimal setup

A React + Vite config is tiny — one plugin. The CLI is three commands you’ll use daily. Package managers (pnpm, bun) just install and run; the build tool is Vite.

vite.config.ts
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";

export default defineConfig({
  plugins: [react()], // JSX/Fast Refresh; uses Rolldown to build
});
terminal
# scaffold, then the three you live in
pnpm create vite my-app --template react-ts
pnpm dev      # native-ESM dev server + HMR
pnpm build    # Rolldown production bundle → dist/

02 Vite or Next.js?

This is the real interview fork. Vite is a build tool for client apps and libraries; Next.js is a full-stack framework with routing, SSR, and React Server Components. Pick by what the app needs — not by habit.

NeedReach for
Client-only SPA (dashboard, internal tool)Vite + React Router
Publishing a component libraryVite (library mode)
SSR / SSG / RSC, file-based routingNext.js (App Router)
SEO pages, server data, edge/server functionsNext.js
Fastest possible dev startup, full controlVite

Next.js has its own bundler, Turbopack (now stable and the default for next dev and next build). Vite’s equivalent is Rolldown. Both replace older JS bundlers with Rust for speed.

Common trap gotcha

Vite is a build tool, not a server framework. Out of the box it produces a static client bundle — there’s no built-in SSR rendering layer or React Server Components. If you need server rendering, RSC, or file-based server routing, that’s a job for Next.js, not raw Vite.

You’re building a public marketing site that needs server-side rendering for SEO and React Server Components. Which tool fits?

Right. SSR and RSC are framework features. Next.js gives them out of the box; Vite is a build tool that produces a client bundle, so you’d be assembling a server framework yourself.

03 Interview rapid-fire

Vite vs Next.js — when do you pick which?core
Model answer

Vite for client-side SPAs and libraries where I want a fast, minimal build tool and full control over routing. Next.js when I need server rendering, RSC, file-based routing, or server data — it’s a full-stack framework, not just a bundler. The deciding question is “do I need a server?”

Say it out loud say it

“Vite is a build tool for SPAs and libraries; Next is a full-stack framework with SSR and RSC. If I need a server, I reach for Next.”

What does Vite do differently in dev vs build?core
Model answer

In dev it skips bundling: it serves source over native ES modules and only transforms files the browser requests, with HMR for instant updates — so startup doesn’t grow with app size. For production it bundles with Rolldown: tree-shaking, code-splitting, minification, and hashed filenames for caching.

Say it out loud say it

“Dev serves native ESM on demand with HMR — no bundling, instant startup. Build bundles everything with Rolldown for an optimized, cache-friendly output.”

What is Rolldown, and why does it matter?stretch
Model answer

Rolldown is Vite’s Rust-based bundler, the default in Vite 8. It replaces the older Rollup/esbuild split for production with a single fast, Rollup-compatible bundler — so big apps build noticeably faster while keeping the plugin ecosystem. It’s Vite’s answer to Next’s Turbopack.

Say it out loud say it

“Rolldown is Vite 8’s default Rust bundler — Rollup-compatible but much faster for production builds. Think of it as Vite’s Turbopack.”
