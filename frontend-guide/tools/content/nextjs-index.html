Next.js App Router — overview

The App Router is React Server Components, routing, data fetching and rendering fused into one model — driven by your app/ folder. As of Next.js 16.2 it’s the default, Turbopack builds it, and caching is opt-in. This module takes you from “it works” to being able to explain why.

00 What’s here

In the App Router, your folder structure literally is your routing, layout, and rendering plan.

There’s no separate route table or render config to keep in sync. A folder is a URL segment; the special files inside it (layout, page, loading) declare the UI and how it renders. Learn the conventions once and the framework becomes predictable.

Think of it like… analogy

A well-organized filing cabinet where the drawer labels are the table of contents. You don’t maintain a separate index — the way folders nest is the map. In the App Router, your folder tree is simultaneously the routing, the layout nesting, and the rendering plan.

Mental model
Server-first. Components run on the server unless you opt a subtree into the browser with "use client".
Rendering
Dynamic by default; you opt into caching with "use cache" (Cache Components).
Tooling
Turbopack is the default for next dev and next build. Node 20.9+.
