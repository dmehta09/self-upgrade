End-to-end with Playwright

E2E is the top of the trophy — the thinnest layer. Playwright drives a real browser through your actual app: real navigation, real network, real rendering. It’s the highest-confidence test you can write, and the slowest — so you reserve it for the flows that truly matter.

00 The idea

Playwright is a robot user in a real browser. Same locators as RTL (getByRole), plus auto-waiting — so no manual sleeps.

You script a user’s journey — visit a URL, click, type, expect — and Playwright executes it in Chromium, Firefox, or WebKit. Locators are lazy and resilient, and every action and assertion automatically waits for the element to be ready, which kills the timing flakiness that plagues older e2e tools.

Think of it like… analogy

It’s a tireless robot QA tester. You hand it a checklist — “log in, add to cart, check out” — and it sits at a real browser and does exactly that, every time, in seconds. It even waits patiently for slow pages on its own, so it never clicks a button that hasn’t appeared yet.

01 A Playwright test

Same readable shape as an RTL test — page.goto then role-based locators — but it’s driving a real browser. The web-first expect auto-retries until the assertion passes or times out, so you never write waitForTimeout.

checkout.spec.ts
import { test, expect } from "@playwright/test";

test("user can check out", async ({ page }) => {
  await page.goto("/cart");
  // locator: same role-first idea as RTL
  await page.getByRole("button", { name: /checkout/i }).click();
  await page.getByLabel("Card number").fill("4242 4242 4242 4242");
  await page.getByRole("button", { name: /pay/i }).click();

  // web-first assertion: auto-waits, no manual sleep
  await expect(page.getByRole("heading", { name: /order confirmed/i })).toBeVisible();
});

When a test does fail, Playwright’s trace viewer replays each step with DOM snapshots and network, and fixtures let you share setup (a logged-in page) cleanly across tests.

Common trap gotcha

Don’t e2e everything. End-to-end tests are slow and the most flake-prone — a giant e2e suite becomes a CI bottleneck people start ignoring. Cover the handful of critical paths (login, payment, signup) with Playwright and push everything else down to fast integration tests.

02 Balancing the trophy

Every flow could be tested at multiple layers; the skill is choosing the cheapest layer that gives real confidence. Validation logic? Integration. The end-to-end happy path of your money-maker? That’s what e2e is for.

Reach for e2e when
The flow spans pages, services, and real navigation — and breaking it would be a business incident (checkout, auth).
Stay in integration when
You’re verifying a component or feature’s behavior — faster feedback, far less flake.

You need to verify a form’s field-validation rules (required, email format, min length). Best layer?

Right. Validation is component-level logic — integration tests cover it in milliseconds. Save Playwright for the critical end-to-end journey (e.g. submitting the form actually creates the account), not every validation branch.

03 Interview rapid-fire

When do you reach for e2e over unit/integration?core
Model answer

When a flow crosses page, network, and service boundaries and breaking it would be a real incident — auth, checkout, signup. E2e gives the highest confidence because it exercises the whole stack, but it’s slow and flakier, so I keep the suite small and let fast integration tests cover everything else.

Say it out loud say it

“For the few business-critical journeys that span the whole stack. Highest confidence, but slow — so I cover critical paths only and push the rest to integration.”

What are locators and auto-waiting?core
Model answer

A locator is a lazy, reusable handle to an element — usually getByRole — resolved fresh each time it’s used. Auto-waiting means Playwright automatically waits for an element to be present, visible, and actionable before clicking, and its web-first expect retries until the assertion holds. Together they eliminate manual sleeps and most flakiness.

Say it out loud say it

“Locators are lazy role-based handles; auto-waiting means every action and assertion waits for the element to be ready. So no sleep calls and far less flake.”

How do you balance the testing trophy?stretch
Model answer

Lean on the layer with the best confidence-per-second: TypeScript and lint as a free base, a wide band of Vitest + RTL integration tests, some unit tests for tricky pure logic, and a thin top of Playwright e2e for critical flows only. The goal is maximum confidence with a suite that stays fast and isn’t flaky.

Say it out loud say it

“Static types at the base, lots of integration in the middle, a few units, and a thin e2e top for critical flows. Confidence per second is the metric.”
