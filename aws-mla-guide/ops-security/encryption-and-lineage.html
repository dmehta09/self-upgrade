Operate · encryption & lineage

Encrypt artifacts in flight and at rest; prove where models came from.

KMS wraps S3 model artifacts, EBS volumes on training instances, and optional endpoint encryption in transit. SageMaker Lineage and Model Cards document intent, metrics, and risks for auditors. MLA-C02 merges security with responsible ML governance.

01 KMS for ML data paths

Default SSE-S3 works for many labs; production stems ask for SSE-KMS with customer managed keys (CMKs), separate keys per env, and least-privilege key policies for training vs endpoint roles.

flowchart LR
  data["S3 datasets SSE-KMS"] --> train["Training job"]
  train --> art["Model artifact SSE-KMS"]
  art --> ep["Endpoint TLS + decrypt"]
  ep --> cap["Capture to encrypted S3"]
S3
SSE-S3 (AWS managed) vs SSE-KMS (CMK audit via CloudTrail).
EBS
Encrypted volumes on training/processing instances — same CMK or dedicated.
In transit
HTTPS for invoke; VPC mode endpoints keep traffic private.
Secrets
Secrets Manager for DB/API creds in processing — not in code.

02 Lineage & Model Cards

Lineage tracks entities: data source → processing job → training job → model package → endpoint. Model Cards (often with Clarify) capture intended use, limitations, bias eval, and contact — the human-readable audit doc.

Lineage graph
  • Automatic from Pipelines
  • Query “what data trained v12?”
  • Compliance traceability
Model Card
  • Business & ethical context
  • Metric summaries, caveats
  • Regulatory-facing narrative
Ledger Bank tip

Every Approved fraud model package links to a Model Card noting protected attributes tested with Clarify and the training snapshot date — auditors skip manual spreadsheet hunts.

03 Clarify in the governance story

Clarify runs pre-training (data bias), post-training (model bias, SHAP explainability), and can integrate with Monitor for post-deploy bias drift. Lineage stores clarify job outputs as artifacts.
