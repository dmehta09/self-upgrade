Model development · SageMaker training

Train on SageMaker without over-building.

MLA-C02 wants you to pick the lightest training mode that fits: built-in algorithm, script mode, or bring-your-own container. Match instance family to workload; add distributed training or VPC only when the stem forces it.

01 Built-in vs script vs container

Built-in algorithms for standard tabular/NLP/image jobs with minimal code. Script mode when you need custom loops but still want the managed Training Job API. BYOC when dependencies or entrypoints don’t fit the SageMaker contract.

flowchart LR
  stem["Training need"] --> builtin{"Built-in fits?"}
  builtin -->|yes| bi["Built-in algo job"]
  builtin -->|no| script{"Standard SDK train loop?"}
  script -->|yes| sm["Script mode + Estimator"]
  script -->|no| byoc["Custom container"]
Built-in
XGBoost, Linear Learner, BlazingText, Object Detection — fastest path, hyperparameters via job config.
Script mode
Your train.py in SageMaker’s directory contract; channels for train/val data in S3.
BYOC
Exotic stack, legacy training code, or framework version not on prebuilt images.
Acme Health
Readmission tabular model → built-in XGBoost or Linear Learner; data already in S3.
Ledger Bank
Custom graph fraud model with internal libs → script mode or BYOC on GPU if needed.

02 Instance types & distributed training

CPU instances (ml.m*, ml.c*) for most tabular jobs. ml.g* / ml.p* when the stem mentions deep learning or large batches. Distributed = multiple instances only when single-node time or memory fails — exam answers prefer the simplest scale-up first.

Common trap gotcha

VPC for every training job. Default SageMaker training reaches S3 over AWS network — no VPC required. Put the job in a VPC only when data or license servers live in private subnets.

03 VPC & exam quiz

Ledger Bank trains on CSV in a private S3 bucket; features must never traverse the public internet. Training reads only from that bucket and a private feature DB in the VPC. What do you add?

Right. “Private data / no public internet” → VPC-attached training with endpoints to S3 and DB. NAT alone without endpoints is a cost/ops trap; laptop training fails managed MLOps stems.

04 Exam rapid-fire

Built-in vs script mode in one sentence?warm-up
Model answer

Built-in = AWS-owned algorithm + hyperparameters; script mode = your training script packaged for the same managed Training Job lifecycle.

Say it out loud say it

"Built-in when the algo exists; script mode when I need custom code but still want SageMaker jobs."

When is distributed training the right exam answer?core
Model answer

When a single instance cannot finish within SLA (time or GPU memory) and the framework supports data or model parallelism — not as default for tabular XGBoost stems.

Say it out loud say it

"Scale instance first; go distributed when one node can't meet time or memory."

Acme Health: standard XGBoost on S3 CSV — minimum SageMaker pattern?stretch
Model answer

S3 train channel → SageMaker built-in XGBoost Training Job on ml.m5.xlarge (or similar CPU) → model artifacts to S3. No VPC, no BYOC, no multi-node unless stem cites hour-long runs.

Say it out loud say it

"S3 in, built-in XGBoost job, S3 artifacts out — simplest managed path."
