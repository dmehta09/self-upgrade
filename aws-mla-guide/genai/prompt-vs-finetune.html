GenAI · prompt vs fine-tune

Climb the ladder: prompt → RAG → PEFT.

Start with the cheapest intervention that meets quality. MLA-C02 rewards the escalation ladder — don’t fine-tune when a system prompt fixes tone, don’t RAG when the answer is in the prompt context.

01 The intervention ladder

Prompt engineering shapes behavior without weight changes. RAG grounds answers in fresh private docs. PEFT / fine-tune updates weights when style, format, or domain language must be baked in and prompt+RAG plateau.

flowchart BT
  ft["PEFT / fine-tune"]
  rag["RAG + KB"]
  prompt["Prompt engineering"]
  ft --> rag --> prompt
  q["Quality gap?"] --> prompt
  prompt -->|still wrong facts| rag
  rag -->|style/format stuck| ft
Prompt wins
JSON output format, tone, few-shot examples, guardrail-friendly system instructions.
RAG wins
Answers must cite hospital policies or loan docs that change monthly — knowledge not in weights.
Fine-tune wins
Consistent medical shorthand, internal code names, or classification into bank-specific labels after RAG exhausted.
Acme Health
Start prompts for triage tone → add Knowledge Base for formulary PDFs → PEFT only if nurses still reject phrasing.
Ledger Bank
RAG for regulatory memos; fine-tune rare for “always output SAR field X” if prompts fail at scale.

02 When each wins (exam cues)

Stop at prompt when…
  • Facts already in context window
  • Behavior/style tweak only
  • POC or “fastest path”
  • Zero private training data policy
Escalate to RAG / fine-tune when…
  • Dynamic corpus too large for prompt
  • Hallucination on proprietary facts → RAG
  • Fixed output schema/language → fine-tune
  • Retrieval + prompt still miss domain jargon
Common trap gotcha

Fine-tune for changing policies. Regulations update weekly — RAG over S3, not weight updates. Fine-tune embeds static knowledge that goes stale.

03 Exam quiz

Chatbot hallucinates drug interactions not in the FM’s public training. Policies live in internal PDFs updated weekly. Next step?

Right. Fresh proprietary facts → RAG. Weekly full fine-tune is ops-heavy; pasting corpus into prompt busts context and maintenance.

04 Exam rapid-fire

Order: prompt, RAG, fine-tune — why?core
Model answer

Cheapest and fastest first: prompts need no retraining; RAG adds grounding without weight changes; fine-tune is last when behavior must be in weights and cheaper methods failed.

Say it out loud say it

"Prompt, then RAG for facts, then PEFT when style is stuck — never skip the ladder."

When is PEFT preferred over full fine-tune?warm-up
Model answer

Small adapter layers — less data, compute, and catastrophic forgetting risk when you only need domain tone or task format on a large FM.

Say it out loud say it

"PEFT when I need a light domain shift, not a new brain."

Ledger Bank: force JSON SAR fields. Prompt works 95%. Fine-tune?stretch
Model answer

Not yet — tighten prompt + response schema validation first. Fine-tune when compliance requires near-100% format adherence and prompts fail in eval.

Say it out loud say it

"95% with prompts → schema + prompt first; fine-tune is the last mile."
