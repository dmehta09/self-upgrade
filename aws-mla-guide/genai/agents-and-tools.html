GenAI · Agents & tools

Agents when the model must act, not just talk.

Amazon Bedrock Agents orchestrate FM reasoning with action groups (OpenAPI → Lambda) and optional Knowledge Bases. MLA-C02: use Agents for multi-step tool use; plain InvokeModel when a single FM call plus RAG is enough.

01 Agents, action groups & Lambda tools

An Agent plans steps, calls action groups backed by Lambda (book appointment, check balance), and can attach a Knowledge Base for retrieval — all with guardrails and session memory within the agent runtime.

flowchart LR
  user["User"] --> agent["Bedrock Agent"]
  agent --> kb["Knowledge Base"]
  agent --> lambda["Lambda tools"]
  lambda --> api["Backend APIs"]
  agent --> fm["Foundation model"]
  fm --> agent
  agent --> user
Action group
OpenAPI schema defines parameters; Agent invokes matching Lambda with structured args — exam pattern for “call internal API safely.”
Knowledge Base attach
Agent retrieves policy docs before answering or before choosing a tool.
Acme Health
Agent: retrieve formulary KB → if controlled substance, Lambda checks EHR slot availability → confirms booking.
Ledger Bank
Agent: RAG on cardholder agreement → Lambda fetches live balance → FM summarizes — not one InvokeModel call.

02 Agent vs plain InvokeModel

InvokeModel (+ optional Retrieve API) when one-shot Q&A or summarization. Agent when the stem needs sequential tool calls, parameter extraction from natural language, or orchestration across KB + APIs with minimal custom code.

InvokeModel enough
  • Single-turn FAQ with RAG context
  • Batch summarization pipeline
  • You orchestrate steps in Step Functions yourself
  • No live API side effects
Use an Agent
  • “Book, cancel, or reschedule” from chat
  • Multi-step: lookup → validate → execute
  • Least custom orchestration code
  • FM chooses which tool when user intent varies
Common trap gotcha

Agent for read-only FAQ. Extra latency, cost, and IAM surface for no tool use — Knowledge Base + InvokeModel wins “policy chatbot, no transactions.”

03 Exam quiz

Customer chatbot must quote payoff amount from core banking API after explaining terms from PDFs. Minimal custom orchestration?

Right. KB for terms + Lambda tool for live balance + Agent orchestration. InvokeModel can’t call APIs; XGBoost isn’t GenAI orchestration.

04 Exam rapid-fire

What connects an Agent to your backend?core
Model answer

Action groups defined with OpenAPI schemas targeting Lambda functions that call internal APIs with IAM-scoped permissions.

Say it out loud say it

"OpenAPI action group → Lambda → internal API — that's the Agent tool chain."

Can an Agent use a Knowledge Base and tools in one session?warm-up
Model answer

Yes — retrieve grounded context from KB, then invoke action groups when the plan requires live data or side effects.

Say it out loud say it

"KB for docs, Lambda for live actions — Agent ties both together."

Acme: read-only HR handbook Q&A — Agent?stretch
Model answer

No — Knowledge Base + RetrieveAndGenerate or InvokeModel with retrieved context. No tools, no multi-step plan needed.

Say it out loud say it

"Read-only RAG → no Agent; Agents when something must be executed."
