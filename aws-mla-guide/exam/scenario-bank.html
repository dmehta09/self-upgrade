01 Data preparation

Acme EHR features must match between batch train and real-time scoring

Data Flagship walkthrough
Story — Acme engineers rebuilt features differently in the training notebook vs the Lambda pre-processing hack. Readmission scores drifted in prod.
Underline constraint — Same feature definitions for offline training and online inference; avoid train-serve skew.
Eliminate — Duplicate SQL in notebook and Lambda (skew risk). Recompute features ad hoc at invoke time from raw EHR (latency + inconsistency).
Best answer — SageMaker Feature Store: offline store for training exports, online store for low-latency endpoint lookups, shared feature definitions.
Why — Feature Store is the exam answer for consistency + low-latency serving. Glue alone is batch; DDB is not a feature registry.
flowchart LR
  batch["Training batch"] --> off["Offline store"]
  off --> train["SageMaker train"]
  stream["Live patient"] --> on["Online store"]
  on --> ep["Endpoint"]

Ledger fraud labels leak future transaction info into training features

Data Flagship walkthrough
Story — A data scientist joined "post-fraud investigation outcome" into the training set. Offline AUC was 0.99; prod was useless.
Underline constraint — Prevent target leakage and document integrity checks before train.
Best answer — Time-based train/validation split; feature cutoff at transaction time; Processing job + Clarify/data quality checks in Pipeline before Training.
Why — Leakage is a Data domain failure. Monitoring won't fix wrong features.
flowchart TD
  raw["Raw transactions"] --> split{"Point-in-time split?"}
  split -->|yes| ok["Valid features"]
  split -->|no · trap| leak["Future label in features"]

02 Model & FM development

Acme wants best XGBoost hyperparameters without manual grid search

Model Flagship walkthrough
Underline constraint — Automated tuning on SageMaker with budget cap.
Best answer — SageMaker Automatic Model Tuning (HPO) — Bayesian or random search across Training jobs; objective metric from validation set.
Eliminate — Manual notebook loops (not repeatable). EC2 Grid Search DIY (ops overhead).
flowchart LR
  hpo["HPO job"] --> t1["Training trial 1"]
  hpo --> t2["Training trial 2"]
  t1 --> best["Best hyperparameters"]
  t2 --> best

03 Deploy & orchestrate

Ledger fraud API: spiky traffic, scale to zero overnight OK

Deploy Flagship walkthrough
Underline constraint — Minimize idle cost; 200 ms p99 after warm-up acceptable.
Best answer — Serverless Inference endpoint (or Bedrock if FM). Not always-on GPU real-time endpoint.
Why — Real-time endpoint bills 24/7. Batch wrong for online API.
flowchart TD
  q{"Steady low-latency 24/7?"}
  q -->|yes| rt["Real-time endpoint"]
  q -->|no · spiky| si["Serverless Inference"]
