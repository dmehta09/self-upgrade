Deploy · Model Registry

Version, approve, promote — govern what reaches production.

Model Registry is SageMaker’s system of record for model packages: lineage from training job, approval gates, and promotion to endpoints. MLA-C02 stems about “only approved models in prod” or “rollback to last good version” land here.

01 Registry building blocks

A model group holds versions. Each model package points at an approved artifact (S3 model.tar.gz or image). Status flows: PendingManualApproval → Approved / Rejected.

flowchart LR
  train["Training job"] --> pkg["Model package vN"]
  pkg --> reg["Model Registry group"]
  reg --> appr{"Approved?"}
  appr -->|yes| prod["Prod endpoint / Pipeline"]
  appr -->|no| block["Blocked deploy"]
  reg --> rollback["Rollback to vN-1"]
Model group
Logical name (e.g. acme-readmission-xgb) — all versions live here.
Model package
Immutable version with inference spec, metrics metadata, approval status.
Approval
Manual or automated via Pipeline step / Lambda on metric thresholds.
Lineage
Links back to training job, processing job, dataset — audit trail for compliance.

02 Promotion workflow

Production deploy should never pull arbitrary S3 paths. CI/CD reads the latest Approved package in the group — or a pinned version for canary.

1

Register

Training job completes → register model package (PendingManualApproval).

2

Evaluate

Offline metrics + Clarify bias report attached; MLOps reviews in Studio.

3

Approve

Status → Approved; rejected versions stay out of prod pipelines.

4

Deploy

Pipeline deploy step creates/updates endpoint from approved package; blue/green optional.

Exam cue tip

“Compliance requires human sign-off before prod” → Registry approval step in SageMaker Pipelines, not a shared S3 folder.

03 Ledger Bank — fraud model governance

Ledger runs three fraud model versions in Registry. Only Approved packages feed the payment endpoint. When drift triggers retrain, v47 registers pending until the risk committee approves — v46 stays live.

With Registry
  • Clear version history & rollback
  • Approval gate before prod deploy
  • Lineage to training data snapshot
Without Registry (trap)
  • Engineers overwrite s3://models/latest/
  • No audit of who promoted what
  • Rollback = guess which tarball worked

04 Multi-model & A/B endpoints

Multi-model endpoints host several approved packages on shared instances. Production variants split traffic (80/20) for champion/challenger — still sourced from Registry versions.

Common trap gotcha

Model Registry ≠ Model Monitor. Registry governs which artifact deploys; Monitor watches runtime behavior of what’s already live.

05 Rapid-fire

New model fails offline AUC gate. What happens to prod?Deploy
Answer

Package stays Rejected or pending; pipeline does not update endpoint. Previous Approved version continues serving.

Auditors need “which training job produced prod model on March 3?”Deploy
Answer

Model Registry lineage + SageMaker Lineage tracking link package → training job → dataset.
