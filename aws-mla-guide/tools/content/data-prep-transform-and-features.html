Data preparation · transform & features

Turn raw tables into train-ready features.

After ingest, ML quality depends on transforms: Glue ETL for Spark-scale jobs, SageMaker Processing for Python/sklearn pipelines, Data Wrangler for visual prototyping. Split train / validation / test before any leakage creeps in.

01 Three transform paths

Pick by scale and repeatability: Glue for scheduled Spark ETL across the lake; Processing for SageMaker-native prep; Data Wrangler to explore then export to Processing or Pipelines.

Glue ETL
Serverless Spark — joins, dedupe, type coercion across huge lakes. Writes curated Parquet back to S3.
SageMaker Processing
Runs your container/script on managed instances; standard I/O = S3 paths. Pairs with Training jobs.
Data Wrangler
Studio UI for flows (join, encode, balance). Exam: prototype here, productionize as Processing step.
Feature Store
When the same features must serve training and inference — next lesson deep dive.

02 Train, validation, test splits

Split before feature engineering that learns from the full dataset (scaling stats, target encoding). Time-series? Split by time — never random shuffle on Ledger's fraud labels.

1

Train set

Fit transforms and model weights. Largest slice — typically 60–80%.

2

Validation set

Tune hyperparameters and early-stop. Not for final exam-style metrics reporting.

3

Test set

Touch once for unbiased final metrics. Lock away until promotion decision.

4

Processing job writes all three

Output separate S3 prefixes — Training job reads train+val; test held for evaluation step.

In plain English analogy

Training data is textbook problems. Validation is practice exams while you still change study habits. Test is the final you take once — if you peek and adjust, your score is a lie.

03 Exam cues — Acme & Ledger

Stems hide the transform tool in operational words: "nightly," "same Python logic," "visual then automate," "10 TB join."

Acme Health
  • Glue joins EHR + labs → de-identified curated set
  • Processing encodes categoricals, imputes vitals
  • Time-based split: train on past admissions, test on recent quarter
Ledger Bank
  • Processing aggregates 7-day spend velocity per card
  • Data Wrangler explored rare fraud ratios, exported flow
  • Strict temporal split — no future transaction leakage
Common trap gotcha

Data Wrangler in production cron. Wrangler is the exam's prototype tool. Production recurring transforms → export to Processing or Glue, wire into Pipelines.

Team built a Wrangler flow for Ledger fraud features. They need nightly automated runs in a Pipeline. Next step?

Right. Wrangler → Processing export is the managed production path. Manual UI runs fail least-ops and repeatability stems.

04 Exam rapid-fire

Glue ETL vs SageMaker Processing?warm-up
Model answer

Glue = Spark-scale lake ETL, catalog integration, scheduled jobs across huge data. Processing = Python/sklearn/custom containers tightly coupled to SageMaker Training/Pipelines.

Say it out loud say it

"Glue for lake-scale Spark; Processing for SageMaker ML prep scripts."

What is Data Wrangler for on the exam?core
Model answer

Visual feature engineering in Studio — fast exploration and flow building. Export to Processing or Pipelines for production; not the final scheduled worker itself.

Say it out loud say it

"Wrangler prototypes; Processing or Glue productionizes."

How should Ledger split fraud data?stretch
Model answer

Time-based split: train on older transactions, validate on a middle window, test on the most recent held-out period. Never random-split time-ordered fraud labels — that leaks future behavior into training.

Say it out loud say it

"Fraud is time-ordered — split by time, not random shuffle."
