  • Four MLA-C02 domains and rough weights?

    Data prep ~28%, Model/FM ~24%, Deploy ~24%, Operate ~24%.

  • SageMaker vs Bedrock — when which?

    SageMaker = your custom/trainable models and classical ML. Bedrock = managed foundation models, RAG KB, Agents, Guardrails.

  • Feature Store offline vs online?

    Offline = historical training exports (S3). Online = low-latency DynamoDB lookup at inference. Same feature group prevents train-serve skew.

  • What is target leakage?

    Training features that include future information not available at prediction time — inflates offline metrics, fails in prod.

  • Real-time endpoint vs Serverless Inference?

    Real-time = always-on instances, steady low latency. Serverless = scale-to-zero, cold starts, best for spiky/intermittent traffic.

  • Batch Transform vs Async inference?

    Batch Transform = offline bulk S3 scoring, no endpoint. Async = large single payloads with S3 in/out and SNS/poll callback.

  • Model Registry approval flow?

    Register model package → PendingManualApproval → Approved/Rejected. Pipelines deploy only Approved versions.

  • SageMaker Pipelines ConditionStep?

    Branches the DAG on metric thresholds — e.g. register/deploy only if validation AUC beats champion.

  • Model Monitor vs CloudWatch for endpoints?

    Monitor = ML drift/quality vs baselines. CloudWatch = ops metrics (latency, errors, CPU/GPU, invocations).

  • Data drift vs model quality monitor?

    Data drift = feature distribution shift. Model quality = predictions vs ground-truth labels when labels arrive later.

  • SageMaker execution role purpose?

    IAM role assumed by Training/Processing/Endpoint jobs for temporary creds — scoped S3/KMS/ECR access. No long-lived keys.

  • Why iam:PassRole on pipelines?

    Pipeline role must pass the training/processing execution role to SageMaker when starting jobs — scoped to specific role ARNs.

  • SSE-KMS for model artifacts — common failure?

    Endpoint/training role missing kms:Decrypt on the CMK key policy — AccessDenied loading model.

  • Managed Spot Training when?

    Long, fault-tolerant training with S3 checkpointing — big cost savings; not for latency-critical single short jobs without checkpoint.

  • Inferentia / Neo value prop?

    Neo compiles models for Inferentia/Graviton/GPU — higher inference throughput per dollar at scale.

  • SageMaker HPO (Automatic Model Tuning)?

    Runs many Training jobs searching hyperparameter space (Bayesian/random) optimizing a validation metric within a budget.

  • SageMaker Clarify use cases?

    Pre/post-training bias detection, SHAP feature importance, explainability reports — not the same as live drift monitoring.

  • JumpStart when?

    Pre-trained models + fine-tuning recipes — fast start for CV/NLP/tabular with limited labels or standard architectures.

  • Prompt vs RAG vs fine-tune order?

    Try prompt engineering first, add RAG for private docs, fine-tune/PEFT last when behavior still insufficient.

  • Bedrock Knowledge Base?

    Managed RAG: ingest S3 docs → chunk → embed → vector store → retrieve at InvokeModel/Agent time.

  • Bedrock Agent vs Step Functions?

    Agent = FM-orchestrated tool/RAG loops. Step Functions = explicit deterministic multi-step workflow with retries/parallelism.

  • Bedrock Guardrails?

    Content filters, denied topics, PII handling applied to FM inputs/outputs — responsible GenAI at invoke.

  • Processing job vs Training job?

    Processing = ETL/feature prep/scoring prep at scale. Training = fit model weights. Both use managed compute + roles.

  • SageMaker Lineage vs Model Card?

    Lineage = automated artifact graph (data→job→model). Model Card = human-readable intended use, metrics, limitations, bias summary.

  • EventBridge + Model Monitor pattern?

    Monitor job fails drift check → CloudWatch alarm → EventBridge rule → StartPipelineExecution for retrain.

  • Multi-model endpoint benefit?

    Host multiple models on shared instances — A/B variants, lower idle GPU vs one endpoint per model.

  • Data capture on endpoints?

    Sample request/response to S3 for Model Monitor baselines — watch PII; mask or exclude sensitive fields.

  • Glue + S3 in ML ingest?

    S3 lake storage; Glue ETL transforms and Data Catalog tracks schemas/partitions for downstream SageMaker.

  • Kinesis in ML data prep?

    Stream ingest (Streams/Firehose) into S3 or real-time features — exam pattern for streaming + batch retrain.

  • Imbalanced classification metric?

    Prefer PR-AUC, F1, precision/recall at operating point — not accuracy alone on skewed fraud/churn data.

  • CodePipeline + SageMaker Pipelines?

    Git push → CodeBuild tests → trigger StartPipelineExecution — CI/CD wrapper around ML DAG.

  • Action group in Bedrock Agents?

    OpenAPI schema mapped to Lambda — lets the agent call APIs (leave balance, ticket lookup) during orchestration.

  • Bedrock provisioned throughput?

    Reserved FM capacity for steady high QPS — vs on-demand per-token when traffic is spiky/unknown.

  • Trainium vs Inferentia?

    Trainium (Trn) = training accelerators. Inferentia (Inf) = cost-efficient inference after Neo compile.

  • VPC mode SageMaker training?

    Jobs run in your VPC subnets for private S3/EFS/DB access — execution role + security groups + VPC endpoints as needed.

  • Studio notebook vs Training job?

    Notebook = explore/prototype. Training job = repeatable scalable prod training — exam favors jobs/pipelines for prod.

  • Embeddings for RAG — who generates?

    Bedrock embedding models or SageMaker — stored in vector DB (OpenSearch Serverless, Aurora pgvector, etc.) for retrieval.

  • Registry vs Monitor — one line each?

    Registry = which version may deploy. Monitor = whether live data/predictions still match expectations.

  • MLA exam method in one sentence?

    Underline lifecycle phase + hard constraint, eliminate anti-patterns (keys, leakage, wrong invoke mode), pick simplest managed AWS ML service.

  • Acme Health vs Ledger Bank — memory hook?

    Acme = clinical ML (readmission, SageMaker lifecycle). Ledger = fraud + policy GenAI (Registry, Agents, drift on transactions).
