Operate · monitor & drift

Catch data drift, quality decay, and endpoint failures early.

Model Monitor schedules baseline comparisons on live endpoint traffic. CloudWatch tracks latency, errors, and custom metrics. MLA-C02 ties “model degraded in production” to Monitor + alarms + retrain pipeline — not manual eyeballing.

01 SageMaker Model Monitor

Enable data capture on the endpoint → Monitor builds baselines from training data → scheduled jobs compare live distributions and optional model quality (labels required).

02 CloudWatch for endpoints

Built-in metrics: Invocations, ModelLatency, 4XX/5XX, CPUUtilization, GPUUtilization. Set alarms on latency spikes and error rates — distinct from statistical drift.

CloudWatch
  • Ops health: down, slow, throttling
  • Auto scaling triggers
  • Logs via CloudWatch Logs
Model Monitor
  • ML-specific drift & quality
  • Needs baselines & capture
  • Feeds retrain decisions
Common trap gotcha

Low latency + zero 5xx does not mean the model is still accurate. COVID-era readmission features drifted while endpoints looked “healthy.”

03 Acme Health — readmission drift

After a new EHR field rollout, length_of_stay distribution shifts. Model Monitor flags data drift; Acme’s EventBridge rule starts the retrain pipeline before AUC collapses.

04 GenAI monitoring cues

Bedrock: enable model invocation logging to S3/CloudWatch; use Guardrails for blocked prompts/responses; track token usage via CloudWatch. RAG quality often needs custom eval (human or LLM-as-judge) — not classic Monitor baselines.
