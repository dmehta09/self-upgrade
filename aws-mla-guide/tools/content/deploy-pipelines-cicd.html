Deploy · Pipelines & CI/CD

Automate retrain, evaluate, approve, deploy.

SageMaker Pipelines is the native ML workflow engine. Pair it with CodePipeline/CodeBuild for Git-triggered CI, or EventBridge for scheduled retraining. MLA-C02 rewards repeatable pipelines over one-off notebook deploys.

01 SageMaker Pipelines anatomy

A pipeline is a DAG of steps: Processing, Training, Evaluation, Condition, RegisterModel, CreateModel, Transform. Parameters make runs reusable; caching skips unchanged steps.

flowchart LR
  proc["Processing"] --> train["Training"]
  train --> eval["Evaluation"]
  eval --> cond{"Metrics OK?"}
  cond -->|yes| reg["RegisterModel"]
  reg --> dep["Deploy / Batch"]
  cond -->|no| fail["Fail pipeline"]
ProcessingStep
Feature prep, data validation, bias pre-checks.
TrainingStep
Managed training job with hyperparameters from pipeline params.
ConditionStep
Branch on metric thresholds (e.g. AUC > 0.85).
RegisterModel
Creates model package in Registry (often PendingApproval).
CreateModel / Endpoint
Deploy approved artifact — or invoke Batch Transform step.

02 CI/CD integration cues

Typical pattern: CodeCommit/GitHub → CodePipeline → CodeBuild (lint/test) → StartPipelineExecution on SageMaker Pipelines. Infrastructure as Code via CloudFormation or CDK for roles and buckets.

03 Automated retraining triggers

Schedule
  • EventBridge cron — weekly retrain
  • Good for stable domains
  • May waste compute if no drift
Event-driven
  • Model Monitor / CloudWatch alarm
  • New labeled data in S3 (EventBridge)
  • Retrain only when needed
Common trap gotcha

“Automate ML workflow” → SageMaker Pipelines, not Step Functions alone (Step Functions orchestrates AWS services including starting a pipeline, but the ML DAG lives in Pipelines).
