Deploy · inference options

Real-time, serverless, async, or batch — pick the invoke pattern.

MLA-C02 loves the latency vs cost vs payload triangle. SageMaker offers four primary invoke paths; Bedrock is its own managed FM layer. As of September 2026, match the stem’s SLA before you name an instance type.

01 Four SageMaker invoke patterns

Ask: Does the caller wait? How big is the payload? How steady is traffic? Wrong pattern = idle GPU bills or timeout failures.

flowchart TD

  wait -->|yes · ms SLA| rt{"Traffic steady?"}
  rt -->|yes · always on| real["Real-time endpoint"]
  rt -->|spiky · scale to zero OK| si["Serverless Inference"]
  wait -->|no · large payload| async["Async inference"]
  wait -->|offline bulk| batch["Batch Transform"]

02 Pattern cheat sheet

Real-time endpoint
  • HTTPS invoke, ms–low-sec latency
  • Multi-variant / multi-model endpoints for A/B
  • Auto scaling on invocations & GPU util
  • Exam: “API must respond in real time, steady load”
Serverless Inference
  • Managed concurrency, scale-to-zero
  • Cold-start penalty after idle
  • No instance type picking — memory cap
  • Exam: “intermittent traffic, minimize idle cost”
Async inference
  • Client POST → S3 in/out, SNS on completion
  • 15-minute default timeout window (extendable)
  • Large payloads, long GPU runs
  • Exam: “payload too big for sync HTTP”
Batch Transform
  • Input/output S3, no persistent endpoint
  • Split large files, aggregate results
  • Cheapest for scheduled bulk scoring
  • Exam: “score millions of rows overnight”

03 Acme Health — readmission API vs nightly cohort

Acme serves real-time risk scores at discharge (endpoint) and runs a nightly batch over the whole census (Batch Transform). Same model artifact — two invoke modes.

Common trap gotcha

Don’t put a real-time endpoint on a “run once per night over 2M rows” stem — Batch Transform wins. Don’t pick Batch when the ER dashboard needs scores in seconds.

Discharge desk
Real-time endpoint behind internal ALB; auto scaling min=2 for HA.
Nightly population score
Batch Transform on Parquet in S3; results to analytics bucket.
Whole-slide pathology (future)
Async inference — multi-GB input, callback via SNS.

04 Bedrock vs SageMaker endpoint

Bedrock = managed FM APIs (invoke, streaming, KB RAG). SageMaker endpoint = your custom container or built-in algorithm. Stem mentions “foundation model” or “Claude/Llama on AWS” → Bedrock first.

Bedrock
  • FM inference + KB + Agents
  • Token pricing, no GPU ops
  • Guardrails at invoke
SageMaker endpoint
  • Custom sklearn/XGBoost/PyTorch
  • You own instance type & scaling
  • Bring your own container
