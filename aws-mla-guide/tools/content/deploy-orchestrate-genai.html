Deploy · orchestrate GenAI

Agents, Step Functions, and multi-step FM workflows.

GenAI deploy is more than InvokeModel. Bedrock Agents orchestrate tool use; Step Functions coordinate long flows with retries, parallelism, and cost caps. MLA-C02 tests when to compose services vs call Bedrock once.

01 Bedrock Agents & action groups

An Agent plans multi-turn tasks: FM reasons → calls action groups (OpenAPI → Lambda) → returns grounded answers. Knowledge Bases supply RAG retrieval without you wiring vector DB manually.

flowchart LR
  user["User query"] --> agent["Bedrock Agent"]
  agent --> kb["Knowledge Base RAG"]
  agent --> tools["Action groups · Lambda"]
  tools --> api["Internal APIs"]
  agent --> guard["Guardrails"]
  guard --> reply["Response"]
Agent
FM + instructions + memory (session) + orchestration loop.
Action group
OpenAPI schema mapped to Lambda — “check claim status,” “book appointment.”
Knowledge Base
Managed RAG: chunk, embed, retrieve from S3/OpenSearch/etc.
Guardrails
Content filters, denied topics, PII — applied at invoke.

02 Step Functions + Bedrock

Use Step Functions when you need explicit control: parallel doc summarization, human approval, exponential backoff, or mixing Bedrock with SageMaker endpoints and DynamoDB.

flowchart TD
  start["Start"] --> split["Parallel map"]
  split --> b1["Bedrock summarize doc 1"]
  split --> b2["Bedrock summarize doc 2"]
  b1 --> merge["Aggregate"]
  b2 --> merge
  merge --> human{"Human review?"}
  human -->|yes| wait["Task token wait"]
  human -->|no| publish["Publish result"]
Bedrock Agent
  • FM decides which tools to call
  • Less boilerplate for chat UX
  • Harder to audit exact step order
Step Functions
  • Deterministic DAG you define
  • Built-in retry, catch, parallel
  • Better for regulated workflows

03 Concurrency & cost cues

Bedrock bills per token; unbounded parallel invokes explode cost. Cap concurrency with Step Functions Map state MaxConcurrency, SQS throttling, or reserved throughput where offered.

Acme clinician assistant tip

Acme caps Agent loops at 5 tool calls per session and routes high-volume batch summarization through Step Functions Map (MaxConcurrency=10) instead of 500 parallel Lambda→Bedrock invocations.

Streaming
InvokeModelWithResponseStream — better UX, same token cost.
Provisioned throughput
Reserved FM capacity when steady high QPS — exam “SLA + predictable latency.”
On-demand
Default; throttling under burst — add backoff in Step Functions.
