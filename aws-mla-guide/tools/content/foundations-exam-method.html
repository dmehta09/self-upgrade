How to take MLA-C02 without drowning.

MLA-C02 is a timed scenario exam for ML engineers: underline constraints, map to a domain, eliminate wrong architectures. As of September 2026, verify format details on the official AWS certification page (beta code MLA-C02; predecessor MLA-C01 is retired). Typical beta shape: ~85 questions / ~170 minutes — treat counts as guidance until AWS publishes final numbers.

01 Know what you're graded on

Four domains, nearly equal weight after data prep's slight lead. Train your eye for domain keywords before you fall in love with a service name.

In plain English analogy

Think of MLA-C02 as four station chiefs reviewing the same ML pipeline blueprint. One cares about clean data, one about the model, one about getting it live, one about keeping it safe and cheap in production. Answer the chief who is speaking in that question.

Domain 1 · Data preparation (28%)
Ingest, store, transform, feature engineering, integrity, bias, leakage, embeddings for RAG.
Domain 2 · Model / FM development (24%)
Algorithm choice, SageMaker training, HPO, evaluation, JumpStart, Bedrock customization.
Domain 3 · Deployment & orchestration (24%)
Inference options, Model Registry, Pipelines, CI/CD, GenAI orchestration, agents.
Domain 4 · Monitoring, security, cost (24%)
Drift, Model Monitor, IAM, encryption, lineage, cost optimizers, Guardrails.
MLA-C01 context note

MLA-C01 retired — do not study C01-specific scope. MLA-C02 adds GenAI/Bedrock weight and reframes domains; this guide targets C02 only.

02 Elimination technique

Most stems hide one hard constraint that kills 2–3 options. Underline it. Then pick the simplest remaining AWS-native ML design.

1

Underline constraints

Must, cannot, least operational overhead, latency ms, "real-time," "batch only," "no public internet," "PII," "lowest cost at scale."

2

Map to lifecycle + domain

Is this ingest, train, deploy, or operate? That narrows the service menu immediately.

3

Kill anti-patterns

Training LLMs from scratch for PDF Q&A; notebook-only prod pipelines; ignoring train/serve skew; long-lived keys on training instances.

4

Prefer managed ML paths

SageMaker jobs/Pipelines, Bedrock for FMs, Feature Store for consistency — unless the stem forces DIY.

5

Flag and move

~2 minutes average per question on a 170-minute / ~85Q beta. Mark long scenario clusters; return with fresh eyes.

Common trap gotcha

Answer shopping by brand familiarity. "I've used EC2" doesn't beat SageMaker Processing when the stem wants managed feature prep. "I've heard of Bedrock" doesn't beat XGBoost on SageMaker when the problem is tabular fraud with 200 features.

03 What to memorize vs reason

Memorize sharp dichotomies (SageMaker vs Bedrock, online vs offline Feature Store, real-time vs batch inference). Reason about scenarios using lifecycle phase and domain weight.

Memorize
  • Four MLA-C02 domains and rough weights
  • SageMaker jobs vs Studio notebooks for prod
  • Bedrock = managed FM; Knowledge Bases = RAG
  • Clarify = bias/explainability; Model Monitor = drift
  • Feature Store online vs offline stores
Reason
  • Custom train vs Bedrock from data type + ops constraint
  • Glue vs Processing vs Athena from volume + transform need
  • Real-time endpoint vs batch vs async from latency stem
  • When retrain vs when refresh RAG index

A question says "detect feature drift in production" and "alert the ML team." Which domain and first service?

Right. Production drift detection is Operate (Monitor). Glue ETL is prep; HPO is training-time tuning — neither watches live endpoint data.
