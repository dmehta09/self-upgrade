Foundations · ML lifecycle

The ML lifecycle on AWS — from raw data to monitored production.

MLA-C02 treats AWS as a pipeline of decisions: ingest → prepare → train → deploy → monitor. SageMaker is the training and classical-ML home; Bedrock sits at the GenAI layer for foundation models. As of September 2026, know where each phase lives before you pick a service name.

01 Five phases, one mental map

Every exam scenario is a lifecycle question in disguise. Ask: which phase is broken? Fix that phase with the smallest managed AWS tool — not the flashiest one.

In plain English analogy

Think of ML like running a hospital lab. Ingest is receiving samples. Prep is cleaning and labeling slides. Train is teaching residents on past cases. Deploy is opening the diagnostic desk. Monitor is checking whether today's results still match what residents learned.

flowchart LR
  ingest["Ingest"] --> prep["Prepare"]
  prep --> train["Train"]
  train --> deploy["Deploy"]
  deploy --> monitor["Monitor"]
  monitor -->|"drift / retrain"| prep
Ingest
S3 data lake, Kinesis/Firehose streaming, Glue Data Catalog metadata.
Prepare
Glue ETL, SageMaker Processing, Data Wrangler, Feature Store.
Train
SageMaker Training jobs, Studio notebooks, JumpStart, HPO.
Deploy
Real-time endpoints, batch transform, Bedrock invoke, Model Registry.
Monitor
Model Monitor, Clarify, CloudWatch, drift alarms, Guardrails for GenAI.

02 Acme Health — clinical readmission model

Acme Health predicts 30-day readmission risk from EHR extracts. The lifecycle maps cleanly to SageMaker — until they add a clinician Q&A chatbot, which pulls Bedrock into the deploy/monitor story.

Where Bedrock fits tip

When Acme adds a clinician chatbot over policy PDFs, Bedrock handles FM inference, Knowledge Bases handle RAG retrieval, and Guardrails handle safety — still under deploy + monitor, but not SageMaker Training.

03 SageMaker Studio as the training home

SageMaker Studio is the IDE; Training jobs, Processing jobs, and Pipelines are the production-grade workers. Notebooks explore — jobs scale.

Studio / notebook
  • Explore data, prototype features
  • Data Wrangler visual flows
  • Human-in-the-loop experiments
  • Not the exam answer for repeatable prod
Jobs & Pipelines
  • Training jobs on managed instances
  • Processing for batch transform prep
  • Pipelines wire steps with lineage
  • Exam picks these for CI/CD ML
Common trap gotcha

"Run training on a Studio notebook forever." Exam stems asking for reproducible, schedulable training want Training jobs or Pipelines — not an always-on notebook instance doing ad hoc fit().

04 Exam rapid-fire

Name the five ML lifecycle phases in order.warm-up
Model answer

Ingest → prepare → train → deploy → monitor. Monitoring feeds back into prep or retrain when drift or policy changes appear.

Say it out loud say it

"Ingest, prep, train, deploy, monitor — and monitor closes the loop."

Where does Bedrock sit vs SageMaker Training?core
Model answer

SageMaker Training builds or fine-tunes your classical or custom models. Bedrock provides managed foundation model inference (and optional customization) for GenAI — invoke, RAG via Knowledge Bases, agents — without you operating training clusters for the base FM.

Say it out loud say it

"SageMaker trains custom models; Bedrock serves foundation models and GenAI patterns."

A team needs repeatable nightly retraining from S3. Notebook or job?stretch
Model answer

SageMaker Pipeline (or at minimum a scheduled Training job) triggered after Glue/Processing writes fresh features. Notebooks are for exploration, not the production retrain path the exam wants.

Say it out loud say it

"Scheduled Pipeline or Training job — notebooks don't scale to nightly prod retrains."
