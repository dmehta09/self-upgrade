Production services: graceful shutdown & deploy.

The default http.Server has no timeouts and no clean stop. Production-ready means three additions: explicit timeouts, a graceful shutdown on SIGINT/SIGTERM, and a health endpoint — then ship it as one static binary in a tiny container.

01 Always set server timeouts

A zero-value http.Server (and http.ListenAndServe) has no ReadTimeout, WriteTimeout, or IdleTimeout. A single slow client can hold a connection open forever. Always construct an explicit &http.Server{...} with bounded timeouts.

In plain English analogy

No timeouts is a phone line with no "are you still there?" — a prankster picks up, says nothing, and ties up the line indefinitely. Do that across thousands of connections (the classic slowloris attack) and every line is busy, so real callers get a busy tone. Timeouts are the operator hanging up on dead air.

ReadTimeout
Max time to read the entire request, headers + body. Caps slow-send clients.
WriteTimeout
Max time to write the response. Caps slow-read clients.
IdleTimeout
Max keep-alive idle time between requests on one connection.
ReadHeaderTimeout
Just the headers — a cheap, targeted slowloris guard.

02 Graceful shutdown on SIGINT/SIGTERM

On a deploy, the orchestrator sends SIGTERM. Catch it with signal.NotifyContext, stop accepting new connections, and call srv.Shutdown(ctx) to drain in-flight requests before exiting. A hard os.Exit drops live requests on the floor.

The pattern: run ListenAndServe in a goroutine, block on ctx.Done(), then Shutdown with a bounded timeout context so a stuck handler can't block the deploy forever. Shutdown returns once all connections are idle or the context expires.

main.go
func main() {
    // Cancel the context when SIGINT or SIGTERM arrives.
    ctx, stop := signal.NotifyContext(context.Background(),
        os.Interrupt, syscall.SIGTERM)
    defer stop()

    srv := &http.Server{Addr: ":8080", ReadTimeout: 5 * time.Second}

    go func() {
        if err := srv.ListenAndServe(); err != nil &&
            !errors.Is(err, http.ErrServerClosed) {
            slog.Error("listen", "err", err)
            os.Exit(1)
        }
    }()

    <-ctx.Done() // block until a signal cancels the context
    slog.Info("shutting down gracefully")

    // Give in-flight requests up to 10s to finish, then force-stop.
    shutCtx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
    defer cancel()
    if err := srv.Shutdown(shutCtx); err != nil {
        slog.Error("shutdown", "err", err)
    }
}

03 Health checks, config, structured logs

Add a cheap /healthz (liveness) and /readyz (readiness) endpoint, read all config from env/flags (never hard-code), and emit structured logs with log/slog to stdout so the container runtime collects them.

Hard to operate
addr := ":8080"            // baked-in
log.Printf("started %s", addr) // unstructured
// log to a file inside the container -> lost on restart
12-factor friendly
addr := cmp.Or(os.Getenv("ADDR"), ":8080") // env, with default
logger := slog.New(slog.NewJSONHandler(os.Stdout, nil))
logger.Info("started", "addr", addr) // structured, to stdout

Liveness answers "is the process alive?" (restart me if not); readiness answers "should I receive traffic now?" (hold traffic while a dependency warms up). Keep /healthz dependency-free so a flaky database doesn't trigger a needless restart.

health.go
mux.HandleFunc("GET /healthz", func(w http.ResponseWriter, r *http.Request) {
    w.WriteHeader(http.StatusOK) // alive: don't touch dependencies
})
mux.HandleFunc("GET /readyz", func(w http.ResponseWriter, r *http.Request) {
    if !db.Ping() {              // ready: check real dependencies
        http.Error(w, "not ready", http.StatusServiceUnavailable)
        return
    }
    w.WriteHeader(http.StatusOK)
})

04 Ship one static binary in a tiny container

Go compiles to a single static binary with no runtime to install. Build it with CGO_ENABLED=0, then copy just that binary into a scratch or distroless image — a multi-MB container instead of a multi-hundred-MB one, with almost no attack surface.

Dockerfile
# --- build stage: compile a static binary ---
FROM golang:1.26 AS build
WORKDIR /src
COPY . .
RUN CGO_ENABLED=0 go build -ldflags="-s -w" -o /app ./cmd/server

# --- run stage: nothing but the binary ---
FROM scratch
COPY --from=build /app /app
COPY --from=build /etc/ssl/certs /etc/ssl/certs  # for outbound TLS
EXPOSE 8080
USER 65534:65534                                  # run as non-root
ENTRYPOINT ["/app"]
Pro tip 12-factor

The 12-factor basics Go makes easy: config in the environment (read with os.Getenv/flags), logs as an event stream to stdout (let the platform route them), stateless processes (no on-disk session state), and fast startup / graceful shutdown for disposability. A static binary + scratch image makes builds reproducible and deploys quick.

05 The deploy trap: dropped requests

During a rolling deploy, the platform sends SIGTERM and starts a new pod. If your old process exits immediately instead of draining, every in-flight request gets a connection reset — users see 502s on every deploy.

Gotcha trap

Three production-killers, all from skipping the boilerplate: (1) no server timeouts — one slow or silent client per connection, multiplied, is a slowloris resource-exhaustion DoS (the default server has none, so you must set them); (2) no srv.Shutdown — the process dies on SIGTERM and drops in-flight requests, so every deploy throws 502s; (3) logging to a file inside the container instead of stdout — the log collector never sees it and your logs vanish on the next restart. Set timeouts, drain on signal, log to stdout.

06 Check yourself

Your service runs http.ListenAndServe(":8080", mux) and exits via os.Exit(0) when it sees SIGTERM. On every deploy a few users get connection-reset errors. What are the two root causes?

Right. http.ListenAndServe uses a zero-value server with no ReadTimeout/WriteTimeout/IdleTimeout, and os.Exit kills the process mid-request. The fix: construct an explicit &http.Server{} with timeouts, catch the signal with signal.NotifyContext, and call srv.Shutdown(ctx) so live requests finish before the process exits.
