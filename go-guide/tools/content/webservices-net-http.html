net/http: servers, handlers & the 1.22 router.

Go ships a production-grade HTTP server in the standard library — no framework required. Since Go 1.22 the built-in ServeMux understands methods, path variables and wildcards, so the routing you used to import a third-party package for now lives in net/http itself.

01 Everything is an http.Handler

The whole server is built on one tiny interface: Handler has a single method, ServeHTTP(w ResponseWriter, r *Request). A plain function becomes one via http.HandlerFunc.

In plain English analogy

A handler is a clerk at a service window. The request r is the customer's filled-in form (URL, headers, body); the ResponseWriter w is the blank reply slip the clerk writes back on. The server's only job is to match each customer to the right window and hand the clerk both papers.

http.HandlerFunc is an adapter: it's a function type whose own ServeHTTP just calls itself. That's the trick that lets func(w, r) satisfy the Handler interface with zero ceremony.

handler.go
// The interface — one method.
type Handler interface {
    ServeHTTP(w http.ResponseWriter, r *http.Request)
}

// HandlerFunc adapts an ordinary function to that interface.
func hello(w http.ResponseWriter, r *http.Request) {
    w.Write([]byte("hello"))
}
var h http.Handler = http.HandlerFunc(hello) // a func is now a Handler

02 The 1.22 router: method + path patterns

Since Go 1.22, http.ServeMux patterns can include an HTTP method and path variables: "GET /users/{id}". Pull a variable out with r.PathValue("id").

Before 1.22 the mux only matched path prefixes — you wrote your own method check and parsed IDs by hand, or reached for chi/gorilla. Now the standard mux does it. A pattern is [METHOD ]/path; omit the method to match any method.

routes.go
mux := http.NewServeMux()
mux.HandleFunc("GET /users/{id}", getUser)     // {id} is a path variable
mux.HandleFunc("POST /users", createUser)      // method is matched too
mux.HandleFunc("GET /files/{path...}", serve)  // {path...} = trailing wildcard
mux.HandleFunc("GET /users/{id}/", subtree)    // trailing slash = subtree match

func getUser(w http.ResponseWriter, r *http.Request) {
    id := r.PathValue("id")                    // "42" for GET /users/42
    fmt.Fprintf(w, "user %s", id)
}

http.ListenAndServe(":8080", mux)
{id}
Matches one path segment. Read it with r.PathValue("id").
{path...}
Trailing wildcard — matches the rest of the path, slashes and all.
GET /x vs /x
With a method, only that method matches (and GET implies HEAD); without one, any method matches.

04 Writing JSON & status codes

There is no magic: set the Content-Type header, call WriteHeader(code) for a non-200 status, then write the body. json.NewEncoder(w).Encode(v) streams JSON straight to the response.

05 The traps: concurrency, header order & precedence

Gotcha trap

Every request runs in its own goroutine. The server calls your handler concurrently for concurrent requests, so a package-level var counter int bumped from a handler is a data race. Guard shared mutable state with a sync.Mutex or sync/atomic — or keep handlers stateless. Also: you must set headers before WriteHeader/the first Write; once the status is sent, later w.Header().Set(...) calls are silently ignored.

Two more rules to keep straight:

TopicRule
1.22 precedenceThe most specific pattern wins, regardless of registration order. /users/{id} beats /users/; a literal segment beats a wildcard. Two patterns that overlap but neither is more specific (e.g. /a/{x} vs /{y}/b) is a registration-time panic.
405 vs 404If a path matches but the method doesn't, the mux returns 405 Method Not Allowed with an Allow header — not a 404. That's only true once you register method-qualified patterns.

06 Check yourself

A handler does w.Write([]byte("hi")) and then w.Header().Set("Content-Type", "application/json"). What does the client see for Content-Type?

Right. The first Write sends the status line and headers (implicitly 200), so any header you set afterward is too late and silently dropped. Because no Content-Type was set in time, the server sniffs the body and usually picks text/plain. Always set headers before the first Write/WriteHeader.
