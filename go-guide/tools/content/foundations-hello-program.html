Getting started · anatomy

Anatomy of a Go program.

Every Go program is the same handful of parts: a package, some imports, and functions. Learn the shape once and you can read any file in the standard library.

01 The smallest program that runs

A runnable Go program is a package main with a func main() — that's the entry point the runtime calls.

In plain English analogy

Think of package main + func main() as the “front door” of a house. A library package is a room you can visit from elsewhere; main is the one door the operating system actually knocks on to start the program.

Edit and run this — press Run to reveal the output:

package main
Makes this an executable program (any other name builds a library).
import "fmt"
Pulls in the formatting package from the standard library.
func main()
The entry point — no arguments, no return value. The program ends when it returns.

02 Packages & visibility

A package is a directory of .go files that share a namespace. Visibility is by capitalization: Exported is public, unexported is package-private.

There are no public/private keywords. The first letter of a name decides everything: capital = visible to other packages, lowercase = visible only inside this one.

store/cart.go
package store

type Cart struct {        // Cart is exported — other packages can use it
    items []string        // items is unexported — hidden from outside
}

func New() *Cart { return &Cart{} }   // New is the package's public constructor
func (c *Cart) total() int { … }        // total is an internal helper
See also design

This capitalization rule is Go's whole encapsulation story — it maps onto the information-hiding ideas in the APOSD guide.

03 Printing with fmt

fmt.Println prints values with spaces and a newline; fmt.Printf uses verbs like %d, %s, and the all-purpose %v.

Handy verbs: %d integer · %s string · %t bool · %v any value · %+v struct with field names · %#v Go-syntax · %T the type · %q quoted.

04 Go is strict on purpose

Gotcha trap

An unused import or an unused local variable is a compile error, not a warning. This feels harsh at first, but it keeps every file honest — dead code can't accumulate. Use the blank identifier _ to intentionally discard, and goimports to auto-add/remove imports.

Won't compile
import (
    "fmt"
    "os"        // imported and not used
)
func main() {
    x := 10     // declared and not used
    fmt.Println("hi")
}
Compiles
import "fmt"

func main() {
    x := 10
    fmt.Println("hi", x)   // x is used
}

05 Check yourself

You write a helper func parse(...) (lowercase) in package store. Another package imports store and calls store.parse(...). What happens?

Right. Visibility is by capitalization. A lowercase first letter means package-private — only code in store can call parse. Rename it Parse to export it.
