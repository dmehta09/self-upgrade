Generics & modern Go · iterators

Range-over-func iterators (1.23).

Since Go 1.23 you can range over a function. A function shaped just right becomes a first-class sequence — so your own types, lazy generators, and database cursors all loop with the same for … range you already know.

01 A function you can range over

An iterator is a function with a specific shape. range calls it, the function pushes each item to you via a yield callback, and the loop body runs once per push.

In plain English analogy

An iterator is a tour guide. You don't grab the whole museum at once; the guide hands you one exhibit at a time and waits while you look. When you've seen enough and say "stop," the guide ends the tour — no more rooms, nothing wasted. range is you on the tour; yield is the guide handing you the next exhibit.

The producer (the iterator function) drives the loop by calling yield; the consumer (your for body) runs on each call. This is "pull-by-push": the loop looks like pulling, but under the hood the function is pushing values into your body one at a time.

02 The three signatures in iter

Package iter names just two types: iter.Seq for a stream of single values, and iter.Seq2 for pairs (index/value, key/value). The yield they pass you returns a bool.

iter.Seq[V]
func(yield func(V) bool) — one value per step (e.g. a list of names).
iter.Seq2[K, V]
func(yield func(K, V) bool) — a pair per step (e.g. index+value, key+value).
yield's return
true = "keep going"; false = "the consumer is done — stop now."

So an iterator is just a function that calls yield(v) for each item and checks the result: when yield returns false (the consumer breaked, returned, or hit an error), the iterator must return immediately and clean up.

shape.go
// the whole API surface, conceptually:
type Seq[V any]     func(yield func(V) bool)
type Seq2[K, V any] func(yield func(K, V) bool)

// an iterator pushes values and honours yield's "stop" signal:
func iterate(yield func(int) bool) {
    for i := 0; ; i++ {
        if !yield(i) { // consumer said stop
            return     // ... so we stop, immediately
        }
    }
}

05 The trap: honour yield's false

Gotcha trap

You must check yield's return value. When the consumer does break, return, or panic in the loop body, the runtime makes the next yield return false — your iterator has to stop and unwind right then. Ignore it (e.g. for v := range src { yield(v) } with no if !… guard) and a break won't actually halt your producer: it keeps pushing into a closed loop, panicking with "range function continued iteration after function returned false." Always write if !yield(v) { return }, and put cleanup (closing files, releasing locks) on a defer inside the iterator so it runs whether the consumer finishes or bails early.

Pro tip pull side

Need to advance two sequences in lockstep, or step manually instead of in a for loop? iter.Pull(seq) (and iter.Pull2) converts a push-style iterator into a next, stop := iter.Pull(seq) pair you call by hand — just remember to defer stop() so the producer can clean up.

06 Check yourself

Inside a custom iter.Seq[int], what does yield(v) returning false mean — and what must you do?

Right. yield returns false when the loop body exited early (a break, return, labelled break, or panic). That's the consumer saying "stop the tour." Ignore it and the next yield panics with "range function continued iteration after function returned false." So: if !yield(v) { return }, every time, with cleanup on defer.
