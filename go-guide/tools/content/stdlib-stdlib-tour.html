Standard library · breadth tour

A tour of the rest: net, regexp, crypto & friends.

Go's standard library is famously "batteries included." You won't memorize it — you learn the map: which package to reach for when. This is a one-line-per-package field guide to the corners you'll meet most, with two you can run.

01 Reach for it when…

The skill isn't recall — it's knowing the package exists. Skim this grid once; next time you need to hash a string or parse a URL, you'll know the door to knock on.

In plain English analogy

The stdlib is a giant, well-organized hardware store. You don't carry every tool home — you remember which aisle has hashing, which has networking, which has encoding. When a job shows up, you walk to the aisle. This page is the aisle directory.

02 regexp: RE2, linear time

Go's regexp uses the RE2 engine: it runs in time linear in the input and pattern, so it can't blow up on adversarial input the way backtracking engines do — but it also has no backreferences or lookaround.

03 crypto/sha256 + encoding/hex

sha256.Sum256(data) returns a fixed [32]byte digest; %x (or hex.EncodeToString) renders it as the familiar 64-character hex string.

The same 64 hex chars come out for that input on every machine — that's what makes hashes useful as content fingerprints, ETags, and dedup keys.

04 Two traps that bite in production

Gotcha trap

(1) math/rand is NOT cryptographically secure. It's deterministic and predictable — fine for shuffles and jitter, a security hole for tokens, password-reset codes, API keys, or session IDs. For anything an attacker shouldn't guess, use crypto/rand (e.g. crypto/rand.Read(buf)). (2) Don't compile a regexp inside a hot loop. regexp.MustCompile does real work; calling it per request or per row burns CPU. Compile it once into a package-level var and reuse the compiled value.

Insecure token
import "math/rand/v2"
// predictable — guessable by an attacker
tok := fmt.Sprintf("%d", rand.Int64())
Secure token
import "crypto/rand"
b := make([]byte, 16)
rand.Read(b)                     // CSPRNG
tok := hex.EncodeToString(b)

05 Check yourself

You need to generate a 32-byte session token an attacker must not be able to predict. Which package?

Right. Only crypto/rand is a CSPRNG. math/rand/v2 is faster and has a nicer API but is deterministic and predictable — never use it for secrets. And hashing the time doesn't help: the time is low-entropy and guessable, so a SHA-256 of it is just as predictable.
