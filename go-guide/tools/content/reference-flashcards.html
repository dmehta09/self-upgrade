01 The deck

0/0 known

  • What makes a name exported in Go?

    A capital first letter. Foo is visible to other packages; foo is package-private. There are no public/private keywords.

  • What happens with an unused import or local variable?

    It's a compile error, not a warning. Use _ to discard intentionally; goimports to auto-manage imports.

  • What is the zero value of a type?

    The value every variable gets with no initialiser: 0, "", false, and nil for pointers/slices/maps/channels/interfaces/funcs. There is no uninitialised memory.

  • What three words make up a slice header?

    Pointer, length, capacity. The header views a backing array. Passing a slice copies the 3-word header, not the data — but element writes are shared.

  • When does append allocate a new array?

    When the result would exceed cap. It allocates a bigger array (≈ doubling for small slices), copies, and returns a header pointing at the new array — so always s = append(s, …).

  • How do you stop a re-slice from aliasing its parent?

    Use a 3-index slice s[lo:hi:hi] to cap it (next append must reallocate), or copy into a fresh make'd slice.

  • What happens when you write to a nil map?

    It panics. Reading a nil map is fine (returns the zero value). Always make a map (or use a literal) before writing.

  • What is the comma-ok idiom?

    v, ok := m[k] — ok tells present-vs-absent (vs a real zero value). Also used for channel receives and type assertions.

  • Is map iteration order guaranteed?

    No — it's deliberately randomised per run, so you can't depend on it. Sort the keys if you need a stable order.

  • What does len(s) return for a string?

    The number of bytes, not characters. A multibyte UTF-8 rune counts as several bytes. s[i] is a byte; range decodes runes.

  • byte vs rune?

    byte = uint8 (one UTF-8 byte). rune = int32 (one Unicode code point). range over a string yields runes with byte offsets.

  • When is a struct comparable with ==?

    Only if all its fields are comparable. A slice, map, or func field makes the struct non-comparable — and unusable as a map key.

  • Embedding in Go is…?

    Composition, not inheritance. An embedded type's fields and methods are promoted, but there's no subtype polymorphism — interfaces provide that.

  • Value receiver vs pointer receiver?

    A value receiver gets a copy — mutations don't stick. Use a pointer receiver to mutate or to avoid copying a large struct. Be consistent per type.

  • How does a type satisfy an interface in Go?

    Implicitly — if it has the methods, it satisfies the interface. No implements keyword. Favour small interfaces defined at the consumer.

  • Why can a non-nil error hold a nil pointer?

    An interface value is a (type, value) pair. A typed nil pointer stored in an interface has a non-nil type, so err != nil is true. Return a literal nil, never a typed nil pointer.

  • Bare type assertion x.(T) — what's the risk?

    It panics if the dynamic type isn't T. Use the comma-ok form v, ok := x.(T), or a switch v := x.(type).

  • How do you check a wrapped error?

    Wrap with %w; then errors.Is(err, Sentinel) for sentinel matches and errors.As(err, &target) for typed matches. Don't compare with == or string-match err.Error().

  • In what order do deferred calls run?

    LIFO — last deferred, first to run — when the function returns (including during a panic unwind).

  • When are a deferred call's arguments evaluated?

    Immediately, when defer runs — not when the call fires. To capture a later value, defer a closure: defer func(){ … }().

  • Where must recover() be called to work?

    Directly inside a deferred function, in the same goroutine that panicked. Anywhere else it returns nil and does nothing.

  • new(T) vs make(T, …)?

    new(T) returns a *T pointing at a zeroed T. make initialises and returns a slice, map, or channel (not a pointer).

  • The loop-variable capture gotcha — current status?

    Fixed in Go 1.22: each iteration gets a fresh loop variable, so closures/goroutines capture the right value. Pre-1.22, all shared one variable (a classic bug).

  • Does Go convert numeric types implicitly?

    No. Mixing int and int64 (or int and float) needs an explicit conversion like float64(i). This prevents silent precision/sign surprises.
