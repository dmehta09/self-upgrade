Standard library · logging

Structured logging with log/slog.

The old log package writes lines of prose; log/slog (Go 1.21) writes structured records — message plus typed key/value attributes — that machines can parse, filter, and aggregate. It's the standard-library answer to "why can't I grep my logs by user_id?"

01 From prose lines to structured records

A slog call is a message plus key/value pairs: slog.Info("order placed", "id", 42, "total", 19.95). The handler turns that one record into text or JSON — your code never builds the string.

In plain English analogy

The old log package mails a postcard with one handwritten sentence — to find anything you re-read every card. slog mails a filled-in form: name, order id, amount, each in its own labelled box. A machine can instantly sort the whole mailbox by "order id > 1000" because the boxes are named, not buried in a sentence.

Old log — string interpolation
log.Printf("order %d placed, total %.2f",
    id, total)
// "order 42 placed, total 19.95"
// → to filter by id you must REGEX the line
slog — typed attributes
slog.Info("order placed",
    "id", id, "total", total)
// level=INFO msg="order placed" id=42 total=19.95
// → filter id>1000 with a field query, no regex

02 Levels & handlers

There are four built-in levels — Debug, Info, Warn, Error — and two built-in handlers: NewTextHandler (human-ish key=value) and NewJSONHandler (one JSON object per line, for log pipelines).

slog.Debug/Info/Warn/Error(msg, kv...)
Log at a level using the default logger. Records below the handler's minimum level are dropped cheaply.
slog.NewTextHandler(w, opts)
Emits time=… level=… msg=… key=value. Good for local dev / terminals.
slog.NewJSONHandler(w, opts)
Emits {"time":…,"level":…,"msg":…,…}. Feed it to Loki, ELK, CloudWatch, etc.
slog.SetDefault(logger)
Makes your configured logger the one the package-level slog.Info(…) calls use.

A real slog line carries a wall-clock time=…, so its exact text changes every run. Conceptually a JSON record looks like this (the time field is omitted here only because it's non-deterministic):

record.json
{"time":"2026-06-24T10:00:00Z","level":"INFO","msg":"order placed","id":42,"total":19.95}

05 The balanced-pairs trap

Gotcha trap

The variadic args are alternating key, value, key, value… — they must come in balanced pairs. An odd count (e.g. slog.Info("done", "id") with no value) doesn't panic; slog emits a !BADKEY attribute and your log is quietly wrong. Two fixes: use the typed constructors slog.Int("id", 42), slog.String("user", u) (the compiler enforces a value), and turn on go vet — its slog check flags mismatched/odd pairs at build time. And never log secrets (passwords, tokens, full card numbers): structured logs are shipped and retained, so redact in ReplaceAttr.

06 Check yourself

What does slog.Info("login", "user", "ada", "ip") produce?

Right. The args are alternating key/value pairs; a dangling "ip" has no value, so slog records it as !BADKEY=ip at runtime rather than failing the build. Use the typed helpers (slog.String("ip", addr)) so the compiler forces a value, and run go vet to catch these before they ship.
