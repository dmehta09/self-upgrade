Reference

Timed Go drills.

Knowing a gotcha is one thing; naming it in five seconds — mid code-review, or across the interview table — is the actual skill. Three timed chip-quiz modes plus a "what prints?" round turn Go's sharp edges into reflexes. Every miss links straight back to the lesson that fixes it.

01 How a round works

The clock
40–45 seconds per question. The bar drains; silence counts as a wrong answer — just like the pause before you answer in a review.
The chips
Click an answer or press 1–9. In Pick the primitive the chips never move, so you get faster every round. In Spot the bug and Fix it, a tempting near-miss always sits beside the right answer.
The score
Every answer is explained — the trap chips most of all. Your best score per mode persists in this browser (localStorage["go-drill"]). Questions reshuffle each round.
Keyboard tip

1–9 answer · Enter/→ next question · Esc back to the intro. A round takes about five minutes.

02 Spot the bug

A symptom from real Go code → name the gotcha. Slice aliasing vs append-clobber, nil interface vs nil pointer, a value receiver that loses the write — the confusions interviewers love to probe.

03 Pick the primitive

A concurrency scenario → which tool reaches for it? Channel vs Mutex vs WaitGroup vs atomic vs context vs errgroup sound alike until a clock is running. The chips stay put so the choice gets automatic.

04 Fix it — choose the move

You've spotted the bug — now pick the right fix, with the plausible-but-wrong one sitting right next to it. copy() vs a 3-index cap; a Mutex vs an atomic; defer cancel() vs a timeout select.

05 What prints?

The other interview classic: read a short program and predict its exact output. Each of these turns on one Go subtlety. Answer, then read why.

What does this print?

s := []int{1, 2, 3, 4}
t := s[:2]
t = append(t, 99)
fmt.Println(s)
[1 2 99 4]. t := s[:2] has len 2 but cap 4 — it shares s's backing array. The append fits in spare capacity, so it writes 99 in place, right over s[2]. The fix: s[:2:2] or copy.

What does this print?

x := 1
defer fmt.Println("deferred:", x)
x = 2
fmt.Println("now:", x)
now: 2, then deferred: 1. A deferred call's arguments are evaluated when defer runs, so it captured x == 1 immediately. The deferred call itself fires at return, after now: 2 prints. Capture the final value with a closure.

What does this print?

func main() {
    for i := 0; i < 3; i++ {
        defer fmt.Print(i)
    }
}
210. Defers run in LIFO order at function return, and each captured its own i (0, 1, 2) when the defer ran. So they fire 2, then 1, then 0.

What does this print?

xs := []int{1, 2, 3}
for _, x := range xs {
    x *= 2
}
fmt.Println(xs)
[1 2 3] — unchanged. range copies each element into x; doubling the copy never touches the slice. To mutate in place, index it: xs[i] *= 2.

What does this print?

s := "héllo"
fmt.Println(len(s))
6. len on a string counts bytes, not runes. é is two bytes in UTF-8, so "héllo" is 6 bytes. For a rune count use utf8.RuneCountInString(s) (which gives 5).
