The standard library · time

time: durations, timers & the monotonic clock.

Time in Go is a typed thing, not a loose number of seconds. A Duration carries its unit, a Time secretly carries two clocks, and formatting uses a reference date so odd you'll never forget it once it clicks.

01 Duration is typed nanoseconds

A time.Duration is an int64 count of nanoseconds with a type. Build durations by multiplying a count by a unit — 2 * time.Second, 500 * time.Millisecond — so the unit is always explicit in the code.

In plain English analogy

A bare number like 5 is ambiguous — five what? Seconds? Milliseconds? A Duration is that number with a unit tattooed on it, like writing "5 km" instead of "5". You can't accidentally pass "5 milliseconds" where "5 seconds" was meant, because the constant time.Second bakes the scale right into the value.

Because units are constants (time.Second == 1e9 nanoseconds), arithmetic just works: time.Minute + 30*time.Second is a 90-second duration. Printing a Duration gives a human string like 1m30s.

02 Formatting: the reference-time layout

Go has no %Y-%m-%d strftime codes. You write the layout by spelling out one specific reference time: Mon Jan 2 15:04:05 MST 2006 — i.e. 01/02 03:04:05PM '06 -0700. The digits 1-2-3-4-5-6-7 are the mnemonic.

Year
2006 (4-digit) or 06 (2-digit)
Month
01 (zero-padded), 1, Jan, or January
Day
02 (zero-padded) or 2
Hour
15 (24h) or 03 (12h, with PM)
Minute / Second
04 / 05

So the common ISO-ish layout "2006-01-02 15:04:05" reads as "year-month-day hour:minute:second." t.Format(layout) renders, time.Parse(layout, s) reads back.

03 Add, Sub & the monotonic clock

t.Add(d) shifts a Time by a Duration; t2.Sub(t1) returns the Duration between two times. Crucially, every Time from time.Now() carries two readings: a wall clock (for display) and a monotonic clock (for measuring elapsed time).

In plain English analogy

The wall clock is the clock on your kitchen wall — someone might move its hands forward an hour for daylight saving, or NTP might nudge it. The monotonic clock is a stopwatch that only ever ticks forward and nobody can reset. To tell what time it is you read the wall; to measure how long something took you read the stopwatch.

When you subtract two Time values that both have a monotonic reading, Go uses the monotonic part — so a backward wall-clock jump (DST, NTP) can't make your measured elapsed time go negative.

04 Timer & Ticker — and always Stop

A time.Timer fires once after a duration; a time.Ticker fires repeatedly on an interval. Both deliver on a channel. defer ticker.Stop() is mandatory — a Ticker you never stop keeps its goroutine and channel alive forever.

ticker.go
ticker := time.NewTicker(time.Second)
defer ticker.Stop()              // <- without this, the ticker leaks

for i := 0; i < 3; i++ {
    <-ticker.C                    // blocks ~1s each loop
    fmt.Println("tick", i)
}

// One-shot: time.After returns a channel that fires once.
select {
case <-time.After(5 * time.Second):
    fmt.Println("timed out")
}

For simple "do X after N" use time.AfterFunc(d, fn) or <-time.After(d). For a periodic loop, a Ticker is steadier than sleeping in a loop because it accounts for the time your work took.

Gotcha trap

Three time traps: (1) the layout string is a reference time (2006-01-02), not strftime — passing "YYYY-MM-DD" just prints those literal letters. (2) A Ticker you never Stop() leaks its goroutine and channel. (3) Subtracting two times you built (via Parse/Date) has no monotonic reading, so a wall-clock/DST shift between them can yield a wrong or negative duration — for elapsed time, always subtract values from time.Now().

05 Check yourself

You write t.Format("YYYY-MM-DD") expecting 2026-06-24. What do you actually get?

Right. Go's Format doesn't use %Y/YYYY codes. It matches the components of one reference instant — Mon Jan 2 15:04:05 MST 2006. Anything that isn't a recognized reference component (like the letters YYYY) is copied through verbatim. The correct layout is "2006-01-02".
