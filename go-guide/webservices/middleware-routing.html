Web services · middleware

Middleware, context & routing patterns.

Cross-cutting concerns — logging, auth, recovery, CORS — don't belong inside every handler. In Go they're middleware: functions that wrap a Handler and return a new one. Combined with request-scoped context values and subrouters, they keep your handlers focused on one job.

01 Middleware is just func(http.Handler) http.Handler

A middleware takes a handler and returns a wrapped handler. The wrapper does work before and/or after, then calls next.ServeHTTP(w, r) to pass control down the chain.

In plain English analogy

Middleware is airport security layers wrapped around your gate. Each layer (logging, auth, recovery) inspects the passenger on the way in, waves them through to the next layer with next.ServeHTTP, and can do paperwork on the way back out. The innermost gate is your actual handler.

Because every middleware has the same signature, they compose: wrap a wrap of a wrap. The next parameter is the rest of the chain.

middleware.go
func Logging(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        log.Printf("--> %s %s", r.Method, r.URL.Path) // before
        next.ServeHTTP(w, r)                            // call the chain
        log.Printf("<-- done")                          // after
    })
}

02 Chaining & the order trap

Wrapping is nested: Recover(Logging(Auth(handler))) runs Recover first on the way in and last on the way out. The outermost middleware should be the most defensive.

Gotcha trap

Order matters, and recovery must be outermost. A panic in a handler unwinds the stack; if your Recover middleware is inside the logging middleware, a panic in logging itself isn't caught — and the server drops the connection (the default http.Server recovers the goroutine but the client gets a broken/empty response). Put recovery on the outside so every layer below it — including auth and your handler — is protected.

03 Request-scoped values via r.Context()

Each request carries a context.Context. Middleware can attach request-scoped data — a request ID, the authenticated user — with context.WithValue, then hand a copied request downstream via r.WithContext(ctx).

Use an unexported key type so your keys can't collide with another package's. Downstream handlers read the value back with ctx.Value(key) and a type assertion:

Gotcha trap

Don't stuff everything into context values. Context values are untyped (any) and invisible to the type checker, so overusing them turns explicit dependencies into hidden, runtime-typed magic. Reserve them for genuinely request-scoped, cross-cutting data (request ID, auth principal, trace span) — pass real arguments for everything else. Never use string literals as keys directly; use an unexported key type to avoid collisions.

04 Route groups & subrouters

There's no special "group" API — you compose ServeMuxes. Mount a sub-mux under a prefix with StripPrefix, and apply middleware to just that group by wrapping the sub-mux before mounting it.

This gives you per-group middleware (e.g. auth only on /api/) using only the standard library:

groups.go
api := http.NewServeMux()
api.HandleFunc("GET /users/{id}", getUser)
api.HandleFunc("POST /users", createUser)

root := http.NewServeMux()
// Mount the api sub-mux under /api/, stripping the prefix,
// and wrap ONLY this group with auth.
root.Handle("/api/", http.StripPrefix("/api",
    RequireAuth(api)))
root.HandleFunc("GET /healthz", healthz) // no auth on /healthz

http.ListenAndServe(":8080", root)
Pro tip global vs group

Apply truly universal middleware (recovery, request ID, top-level logging) by wrapping the root mux once: http.ListenAndServe(":8080", Recover(WithRequestID(root))). Apply group-specific middleware (auth, rate limit) by wrapping the sub-mux. That separation is the whole pattern.

05 Check yourself

You wrap your routes as Logging(Recover(handler)). A handler panics. What happens?

Right. Logging(Recover(handler)) runs Logging outermost, Recover next, handler innermost — so Recover does wrap and protect the handler's panic. The subtle bug is the gap: a panic in the Logging layer is outside Recover and escapes. That's why recovery belongs outermost: Recover(Logging(handler)) protects every layer below it.
