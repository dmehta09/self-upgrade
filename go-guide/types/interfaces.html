Interfaces: implicit & structural.

Go interfaces have no implements keyword. A type satisfies an interface simply by having the right methods — duck typing checked at compile time. This one design choice shapes how idiomatic Go is wired together.

01 Implicit satisfaction — no implements

An interface lists method signatures. A type satisfies it structurally: if it has those methods, it qualifies — automatically, with no declaration.

In plain English analogy

"If it walks like a duck and quacks like a duck, it's a duck." You don't fill in a form declaring your type a Duck — you just give it a Quack() method and Go treats it as one wherever a Quacker is wanted. The compiler checks the fit, but the type and the interface never had to know about each other.

Because satisfaction is implicit, a type can satisfy interfaces that were defined after it, even in packages it doesn't import. Your type doesn't depend on the interface; the consumer does.

02 Small interfaces win

Idiomatic Go favours tiny interfaces — often a single method. The stdlib's io.Reader and io.Writer are one method each, and they compose everywhere.

io.Reader
Read(p []byte) (n int, err error) — one method.
io.Writer
Write(p []byte) (n int, err error) — one method.
fmt.Stringer
String() string — one method.

Anything that can write bytes — a file, a network socket, an in-memory bytes.Buffer, an HTTP response — satisfies io.Writer. Write your function against the interface and it works with all of them. Watch fmt.Fprintf write into a buffer that's only an io.Writer:

03 "Accept interfaces, return structs"

The proverb: accept interfaces in your parameters (so callers can pass anything that fits) and return concrete types (so callers get all the methods and fields, not a narrowed view).

Over-specified input, vague output
// forces a *os.File; hands back a fuzzy interface
func Copy(dst *os.File, src *os.File) io.Writer
Idiomatic
// takes anything readable/writable; returns a usable type
func Copy(dst io.Writer, src io.Reader) (int64, error)

Accepting an interface widens what your function can be called with. Returning a concrete struct means the caller isn't boxed into a tiny interface and can use the full type — they can always narrow it themselves if they want.

04 The empty interface & any

An interface with no methods — interface{}, spelled any since Go 1.18 — is satisfied by every type. It means "a value of unknown type."

any is the price of total flexibility: you accept anything, but you've thrown away what you know. To do anything type-specific with an any you must recover the type with a type assertion or type switch. Reach for it only at genuinely dynamic boundaries (printing, generic containers pre-generics, JSON blobs).

Pro tip prefer generics

Since Go 1.18, where you once reached for any to write "works for all types" code, a type parameter usually fits better — it keeps the compile-time type instead of erasing it. Use any for truly heterogeneous values, generics for "same code, many types."

05 An interface value is a (type, value) pair

Under the hood an interface value holds two words: the dynamic type of what it wraps, and a pointer to the value. This pairing is what powers type switches — and the nil-interface trap.

When you store a Dog in a Speaker, the interface remembers "type = Dog, value = that dog." Method calls dispatch through the type half; %T reads it back.

Gotcha trap

Resist the urge to define big interfaces with many methods. A fat interface is hard to satisfy, hard to mock, and couples callers to capabilities they don't need. Define interfaces small, and at the consumer (the package that uses the behaviour), not bundled next to the implementation. "The bigger the interface, the weaker the abstraction." — Rob Pike.

06 Check yourself

Your type JSONStore has methods Read and Write matching io.Reader/io.Writer, but you never wrote implements io.ReadWriter anywhere. Can you pass *JSONStore where an io.ReadWriter is wanted?

Right. Go interfaces are structural. If *JSONStore's method set includes Read and Write with the exact signatures, it satisfies io.ReadWriter automatically — no keyword, no import of the interface, no ceremony.
