Types & interfaces · assertions

Type assertions & type switches.

An interface hides the concrete type inside it. When you need it back — to handle an any, or to test whether an error implements something — you use a type assertion or a type switch. One form is safe; the other panics. Know which.

01 The comma-ok assertion

The two-result form v, ok := x.(T) asks "is the value in x really a T?" — ok is the yes/no and v is the unwrapped value (or T's zero value if not).

In plain English analogy

Opening a sealed box, you can either peek and ask ("is this a wrench? yes/no") or grab blindly ("hand me the wrench — and if it's not there, throw a fit"). The comma-ok assertion is the polite peek: it never crashes; it just tells you whether the type matched.

It reads the interface's hidden type slot and compares it to T. Always prefer this form when the value's type is genuinely uncertain:

02 A bare assertion panics on mismatch

Gotcha trap

The single-result form v := x.(T) panics if the dynamic type isn't exactly T — panic: interface conversion: interface {} is string, not int. Use the bare form only when you're certain of the type (or want the crash). When in doubt, use comma-ok and handle the false.

03 The type switch

A type switch — switch v := x.(type) { case int: …; case string: … } — branches on the dynamic type and binds v to that concrete type inside each case. It's the clean way to handle several possible types.

The special form x.(type) is legal only in a switch head. In each case, v has that case's type (in a multi-type case it stays the interface type). A default catches the rest:

04 Use sparingly — prefer polymorphism

A type switch is a code smell when it's faking method dispatch. If you find yourself switching on type to call different behaviour, that behaviour usually belongs in a method on an interface.

Switching to dispatch behaviour
func area(s any) float64 {
    switch v := s.(type) {
    case Circle: return 3.14 * v.r * v.r
    case Square: return v.side * v.side
    }
    return 0
}
Let the interface dispatch
type Shape interface{ Area() float64 }

func (c Circle) Area() float64 { return 3.14 * c.r * c.r }
func (s Square) Area() float64 { return s.side * s.side }

func area(s Shape) float64 { return s.Area() }

Where type switches do earn their keep: decoding an any from JSON, handling errors with errors.As-style branching, and reflective/serialization code at the edge of the program. Inside your own domain logic, reach for an interface method first.

See also interfaces

The comma-ok assertion is exactly how errors.As recovers a concrete error type from the chain — see interfaces in practice.

05 Check yourself

var x any = 3.14. You write n := x.(int). What happens?

Right. A single-result assertion x.(T) panics if the stored type isn't exactly T — it does not convert. 0 with no panic is the comma-ok form (n, ok := x.(int)). And asserting never numeric-converts; the type must match.
