Concurrency · the sync package

sync: Mutex, RWMutex, WaitGroup, Once, Cond.

Channels move data; the sync package guards data that several goroutines share in place. The star is the Mutex — and the fastest way to understand why you need one is to watch a data race lose an update, then watch a lock put it back.

01 Why a lock at all?

count++ looks atomic but isn't — it's read, add, write. If two goroutines interleave those steps on the same variable, one update is silently lost. A sync.Mutex makes the whole read-modify-write mutually exclusive.

In plain English analogy

A shared variable is a single-stall bathroom. Without a lock, two people walk in at once and chaos follows. A Mutex is the door bolt: whoever turns it gets the room to themselves; everyone else waits in line. The bolt doesn't make things faster — it makes the result correct.

The idiomatic pair is mu.Lock() then defer mu.Unlock() so the lock is released on every return path. Keep the critical section small — lock, touch the shared state, unlock; don't do I/O while holding it.

04 The rest of the toolbox

sync.RWMutex
Many concurrent readers (RLock) or one writer (Lock). Use it only when reads vastly dominate writes — otherwise a plain Mutex is simpler and often faster.
sync.WaitGroup
Wait for N goroutines to finish: Add(n), each Done(), then Wait(). Go 1.25 added wg.Go(func(){…}) which does the Add/Done for you.
sync.Once
once.Do(f) runs f exactly once, even under concurrent first calls — the clean way to do lazy, thread-safe init.
sync.Cond
A condition variable for "wait until some predicate becomes true" — rarely needed; a channel is usually clearer.
Gotcha never copy a sync value

A Mutex or WaitGroup must never be copied after first use — a copy is a different lock that guards nothing. So store them as fields and use pointer receivers (func (s *Set) Add()), and pass the struct by pointer. go vet catches most copies; heed it.

05 Check yourself

A struct holds a sync.Mutex field, and its method is declared func (s Store) Add(...) (value receiver). Why is the lock useless?

Right. A value receiver operates on a copy, and copying a Mutex yields an independent lock. Two goroutines calling Add lock different copies and freely race the shared map underneath. Use a pointer receiver and share the struct by pointer so everyone contends on the same lock.
