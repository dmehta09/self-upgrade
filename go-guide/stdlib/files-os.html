Files, os & io/fs.

Reading and writing files in Go is two function calls for the simple case and a deferred Close for the streaming one. The newer io/fs abstraction lets the same code walk a real directory, a zip, or files baked into your binary with //go:embed.

01 Two ways to read: whole-file vs streaming

For small files reach for os.ReadFile (one call → all bytes) and os.WriteFile. For large files or streaming, os.Open gives you an *os.File you read from — and must Close.

In plain English analogy

ReadFile is photocopying a whole document at once — easy, but you need a desk big enough for every page. Open is borrowing the original from the library: you read it page by page (cheap memory), but you must return it when you're done, or the librarian runs out of copies. That "return it" is f.Close().

os.ReadFile(name)
Reads the entire file into a []byte. Returns (data, err). No Close needed.
os.WriteFile(name, data, perm)
Creates/truncates and writes all bytes with the given mode. No Close needed.
os.Open(name)
Opens read-only → (*os.File, error). You stream from it and defer f.Close().
os.Create(name)
Creates/truncates for writing (mode 0666) → (*os.File, error). Also Close.

This writes a temp file, reads it back, and prints the byte count — using filepath.Join so the path is correct on any OS. Note os.Remove to clean up afterwards.

The mode 0o644 is an octal literal: owner read+write, group/other read-only. WriteFile only applies perm when it creates the file; an existing file keeps its mode.

03 Streaming with os.Open and defer f.Close()

Pair os.Open with defer f.Close() on the very next line, so the file is released on every return path — no leaked descriptors.

stream.go
f, err := os.Open(name)
if err != nil {
    return err
}
defer f.Close()                 // released on every return below

sc := bufio.NewScanner(f)
for sc.Scan() {
    process(sc.Text())          // one line at a time — constant memory
}
return sc.Err()
Gotcha trap

Two classic file traps. (1) Forgetting Close on a long-running process leaks descriptors until you hit the OS limit (too many open files). (2) When writing, a bare defer f.Close() can swallow the error from a final flush — for writers, also check the explicit err := f.Close() on the success path, since a failed close can mean lost data.

04 Args, env & exit — and why os.Exit is dangerous

os.Args is the command line (Args[0] is the program), os.Getenv reads environment variables, and os.Exit(code) ends the process immediately.

cli.go
name := "world"
if len(os.Args) > 1 {
    name = os.Args[1]              // ./greet ada  → "ada"
}
level := os.Getenv("LOG_LEVEL")   // "" if unset; use os.LookupEnv to tell unset from empty
fmt.Printf("hello %s (level=%q)\n", name, level)
Gotcha trap

os.Exit does NOT run deferred functions. Any defer f.Close(), buffered-writer flush, or unlock above it is silently skipped. Idiomatic pattern: keep main thin — do the work in a run() error, then if err := run(); err != nil { log.Fatal(err) }. (And note log.Fatal itself calls os.Exit(1), so it skips defers too — only put it in main.)

05 io/fs, embed.FS & walking directories

fs.FS is an interface for "a filesystem." The real disk (os.DirFS), a zip archive, and files baked into your binary all satisfy it — so code written against fs.FS works on any of them.

In plain English analogy

fs.FS is a power socket shape. Your code is the plug. As long as the source — disk, zip, embedded bytes — exposes that socket, your plug fits without rewiring. //go:embed is the trick that ships the files inside the executable: one binary, no "where did the templates go?" at deploy time.

The //go:embed directive (Go 1.16) reads a file at build time into a variable. A single file can land in a string or []byte; a tree goes into an embed.FS:

For a whole tree, fs.WalkDir visits every entry depth-first. It works identically over an embed.FS or the live disk:

walk.go
//go:embed templates
var assets embed.FS              // an fs.FS over the embedded tree

fs.WalkDir(assets, ".", func(path string, d fs.DirEntry, err error) error {
    if err != nil {
        return err
    }
    if !d.IsDir() {
        fmt.Println(path)       // e.g. templates/home.html
    }
    return nil
})
See also recent Go

Go 1.24 added os.Root — open a directory as a sandbox (root, _ := os.OpenRoot(dir)) and all root.Open/root.Create calls are confined inside it, with .. and absolute paths and symlink escapes rejected. Reach for it when a path comes from user input and a traversal out of the directory would be a security hole. Also: build OS-correct paths with path/filepath (separator-aware), and use path only for slash-separated things like URLs and fs.FS keys.

06 Check yourself

You open a file with os.Open, defer f.Close(), do some work, and at the end call os.Exit(0). What happens to the file descriptor?

Right. os.Exit terminates immediately and does not run deferred functions. (The OS does reclaim descriptors on process death, so a leaked Close at the very end of a program is usually harmless — but a skipped buffered-writer flush means lost data, which is why you keep main thin and return errors instead of exiting mid-work.)
