The standard library · encoding/json

encoding/json & serialization.

JSON is how Go talks to the web. Marshal turns structs into bytes, Unmarshal turns bytes back into structs — and a handful of struct tags control every detail. Master the tags and the float64 surprise and you've defused Go's most famous serialization traps.

01 Marshal & Unmarshal

json.Marshal(v) returns the JSON encoding of v as []byte; json.Unmarshal(data, &v) parses JSON into the value v points at. Only exported (capitalized) fields cross the boundary.

In plain English analogy

Marshalling is packing a suitcase for a trip across the network: you flatten your struct into a string anyone can read. Unmarshalling is unpacking it at the other end. But the suitcase only accepts items with a public label (a capital letter) — anything lowercase is left at home, invisible to the packer.

The package uses reflection to walk your value at runtime, which is why it can only see exported fields — an outside package (and encoding/json is one) cannot read unexported ones. Pass a pointer to Unmarshal so it has somewhere to write.

Note the keys are Name and Age — capitalized, exactly as the Go fields are named. To control the JSON names (and most APIs want lowercase), you reach for struct tags.

02 Struct tags: rename, omit, skip

A field tag `json:"name,omitempty"` renames the JSON key to name and drops it entirely when the field holds its zero value. A tag of `json:"-"` skips the field in both directions.

`json:"user_name"`
Encode/decode this field as the key user_name.
`json:"email,omitempty"`
Omit the key when the value is the zero value ("", 0, nil, false).
`json:"-"`
Never marshal or unmarshal this field (e.g. a password hash).
`json:",string"`
Encode a numeric/bool field as a JSON string (for APIs that want "42").
tags.go
type Account struct {
    ID       int    `json:"id"`
    Name     string `json:"name"`
    Nickname string `json:"nickname,omitempty"` // gone when ""
    Password string `json:"-"`                   // never serialized
}

Tags are plain string metadata on the field; encoding/json reads them via reflection. The same mechanism powers encoding/xml, database mappers, and validators — each looks for its own key in the backtick string.

03 A full round-trip with tags & embedding

Embedding a struct promotes its JSON fields up a level (they flatten into the parent object), unless you give the embedded field its own tag. This is how you share a common header across payloads.

04 Dynamic JSON: map[string]any, RawMessage & Number

When you don't have a struct, unmarshal into map[string]any — but every JSON number becomes a float64. Use json.RawMessage to defer parsing a chunk, and json.Number to keep numeric precision.

Gotcha trap

Three traps that bite everyone: (1) only exported fields are (un)marshaled — a lowercase field is silently skipped. (2) Decoding a number into any yields a float64, never an int — so m["age"].(int) panics; assert .(float64). (3) omitempty drops every zero value, so a real 0, false, or "" vanishes from the output. Use a pointer (*int) when you must distinguish "zero" from "absent."

m["id"] is a float64 even though the JSON wrote 7. With UseNumber(), the decoder stores a json.Number (a string under the hood) so a 17-digit integer survives without float rounding — call .Int64() or .Float64() to convert.

05 Streaming with Encoder & Decoder

json.NewEncoder(w) writes JSON straight to any io.Writer; json.NewDecoder(r) reads from any io.Reader. They stream one value at a time — ideal for HTTP bodies and newline-delimited JSON — instead of buffering the whole document in memory.

Encoder.Encode appends a trailing newline (handy for NDJSON). Decoder.Decode reads the next JSON value from the stream, so you can loop over a sequence of objects. This is what json.Marshal avoids — it builds the whole []byte at once.

See also io

Encoder/Decoder work on the io.Writer/io.Reader interfaces — the same universal I/O abstraction covered in io, bufio & readers/writers. Anything that reads or writes bytes can stream JSON.

06 Check yourself

You unmarshal {"count": 5} into a map[string]any and write n := m["count"].(int). What happens?

Right. Decoding any JSON number into an any produces a float64, never an int. The type assertion .(int) doesn't match, so it panics. Assert .(float64) and convert (int(m["count"].(float64))), decode into a typed struct field, or use UseNumber() + json.Number for exact integers.
