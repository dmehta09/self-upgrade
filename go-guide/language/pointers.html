The language core · pointers

Pointers & memory semantics.

A pointer is just the address of a value. Go keeps them simple — no pointer arithmetic, garbage-collected — and they're how you share or mutate a value instead of copying it.

01 & takes an address, * follows it

&x yields a *T — the address of x. *p dereferences it — the value at that address. There is no pointer arithmetic in Go: you can't do p+1.

In plain English analogy

A value is a house; a pointer is its street address written on a slip of paper. & reads the address off the house; * drives to that address and looks inside. Copy the slip and both copies point at the same house — repaint through one, everyone sees it.

02 Value semantics: assignment copies

Assigning or passing a value copies it. To let a function mutate the caller's value, pass a pointer — the function copies the address, but both addresses name the same value.

Pro tip escape

Returning &local from a function is safe in Go — the compiler's escape analysis moves the value to the heap and the GC keeps it alive. No dangling pointers like in C.

03 new vs make

new(T) allocates a zeroed T and returns a *T — works for any type. make is special: it builds and initializes the runtime structure for a slice, map, or channel, and returns the value (not a pointer).

new(T) → *T, zeroed
p := new(int)   // *int, *p == 0
*p = 7

m := new(map[string]int)
// *m is a NIL map — writing
// (*m)["x"]=1 would PANIC
make → ready slice/map/chan
s := make([]int, 0, 4) // usable slice
m := make(map[string]int) // writable
ch := make(chan int)      // usable chan
m["x"] = 1                // fine

04 When to pass *T — and two traps

Pass a pointer when you need to mutate the caller's value or share one instance (and to avoid copying a large struct). Otherwise prefer values — they're simpler and avoid aliasing surprises.

Gotcha trap

Dereferencing a nil pointer panics (invalid memory address or nil pointer dereference) — always confirm a pointer is non-nil before *p. And you cannot take the address of a map element: &m[k] is a compile error, because a map may rehash and move its entries. To mutate a struct stored in a map, read it out, change it, and write it back — or store *T values in the map.

05 Check yourself

You have m := map[string]Point{} where Point is a struct. Which line compiles?

Right. Map elements are not addressable (a map may move entries when it grows), so both m["a"].X = 9 and &m["a"] are compile errors. Read the struct into a variable, change it, and assign it back — or make the value type *Point so you're mutating through a pointer.
