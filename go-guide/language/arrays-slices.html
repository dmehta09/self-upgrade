The language core · slices

Arrays vs slices: the len/cap model.

Slices are the workhorse of Go — and the source of its most famous bugs. Once you can see the slice header sitting over a backing array, aliasing and the surprising append stop being mysterious.

01 Arrays are values, slices are views

An array [4]int has a fixed size and is copied when assigned. A slice []int is a tiny header — pointer, length, capacity — that views a backing array.

In plain English analogy

The backing array is a row of numbered lockers. A slice is a sticky note that says “lockers 1–3, and I'm allowed to grow into 4.” Copy the note and both notes point at the same lockers — change a locker through one, the other sees it too.

The header is three machine words. That's why passing a slice to a function is cheap (it copies 24 bytes, not the data) — but also why the callee can mutate your elements.

03 append & growth

append writes into spare capacity if there is any; otherwise it allocates a bigger array and copies, returning a header that points at the new array. Always assign the result back.

Capacity jumps 2 → 4 → 8: each grow roughly doubles for small slices, so append in a loop is amortised O(1). If you know the size, make([]T, 0, n) avoids the regrows entirely.

04 The aliasing gotcha

Gotcha trap

A re-slice shares the backing array. Mutating the sub-slice mutates the original — and an append that still fits in cap will overwrite the parent's data. This is the #1 Go slice bug.

The fix when you need an independent slice: cap the re-slice with a 3-index slice s[:2:2] (len 2, cap 2 — the next append must reallocate), or copy into a fresh slice.

fix.go
t := s[:2:2]            // cap 2 — append is forced to copy, leaving s alone
u := make([]int, len(s))
copy(u, s)              // u is fully independent

05 Check yourself

A function takes a []int, does s[0] = 0, and also s = append(s, 9) where the slice has spare cap. After it returns, what did the caller's slice see?

Right. The header is copied, so element writes go through the shared array (visible), but the callee's new len stays local — the caller never sees the appended element (it may even have been written into the backing array past the caller's len). Return the slice to make growth visible.
