Project memory · CLAUDE.md

CLAUDE.md is a short markdown file Claude Code reads at the start of every session. It's where you write the handful of things Claude can't guess from the code: how to build and test, conventions to follow, and the shape of the project. Think of it as the one-page onboarding memo you'd hand a new teammate.

01  Where it lives

./CLAUDE.md
Project root, checked into git — shared with your team. The main one.
./CLAUDE.local.md
Project root, gitignored — your personal notes for this repo.
~/.claude/CLAUDE.md
Your home directory — applies to all your projects (personal defaults).
nested dirs
A CLAUDE.md in a subfolder is picked up when Claude works there — handy for monorepos.

Generate a starter with /init, then refine it with /memory.

02  What to put in it

Keep it short and high-signal. Facts that change rarely and that aren't obvious from the code:

CLAUDE.md
# Commands
- Install: `uv sync`
- Test (fast): `pytest -q` — prefer single tests during dev
- Lint/format: `ruff check --fix && ruff format`

# Conventions
- Python 3.13, type hints everywhere (`list[int]`, `X | None`)
- Pydantic v2 for models; never edit files in `generated/`

# Architecture
- API in `app/`, background jobs in `worker/`
- Postgres via SQLModel; migrations with Alembic

# Workflow
- Run the linter after edits; keep PRs under ~300 lines
Short beats complete tip

Every line of CLAUDE.md costs context on every session. A tight 20-line memo Claude actually follows beats a 200-line wall it skims. When a section grows into a procedure, move it into a skill instead — skills load only when needed.

03  What to leave out

Don't restate the code gotcha

Skip anything Claude can learn by reading: a file-by-file tour, standard language conventions, full API docs (link them), or details that change often. If Claude can find it in the repo, it doesn't belong in the memo.

04  Auto-memory does some of this for you

Claude Code also keeps an auto-memory: as it works, it quietly saves durable learnings — the real build command, a recurring gotcha, where a thing lives — so it doesn't rediscover them every session. Review or toggle it with /memory. Your hand-written CLAUDE.md and the auto-memory work together.

Which belongs in CLAUDE.md?
Right. CLAUDE.md is for the few things Claude can't read from the code — commands, conventions, constraints. Keep it short; link docs rather than pasting them.
