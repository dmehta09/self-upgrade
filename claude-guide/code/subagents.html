Subagents

A subagent is a second Claude with its own fresh context window that you delegate a task to. It does the work, then reports back a summary — keeping all that exploration out of your main conversation. Three jobs they're perfect for: investigate, verify, and parallelize.

01  Why a separate context helps

Reading twenty files to answer “where does auth live?” would flood your main window with code you don't need afterward. A subagent reads those files in its window and hands you back two sentences. Your context stays lean; you keep the conclusion, not the file dump.

Like sending a research assistant analogy

You don't read every source yourself — you send an assistant to the library and ask for a one-page brief. You get the findings without spending your own afternoon in the stacks. That's a subagent: it does the reading, you get the answer.

02  Just ask for one

You don't configure anything to start — describe the delegation in plain English:

terminal
# investigate
> use a subagent to find how token refresh works and report back

# verify (a fresh, unbiased reviewer)
> use a subagent to review this diff for edge cases and security issues

# parallelize independent work
> use subagents to migrate these 3 services to the new logging API

03  Custom subagents

For roles you use often, define a subagent in .claude/agents/. Give it a focused job, a limited tool set, and even a specific model. Manage them with /agents.

.claude/agents/security-reviewer.md
---
name: security-reviewer
description: Reviews diffs for security issues
tools: Read, Grep, Glob, Bash
model: opus
---
You are a senior security engineer. Review changes for injection,
auth/authorization flaws, secrets in code, and unsafe data handling.
Cite specific lines and suggest concrete fixes.
The writer/reviewer pattern tip

A reviewer subagent didn't write the code, so it isn't attached to it — it catches things the author glosses over. Pairing a writer with a fresh reviewer is one of the highest-leverage habits in Claude Code.

Why delegate a big code investigation to a subagent instead of doing it in your main session?
Right. Same capability, separate context. You offload the bulky reading and keep only the conclusion — which is exactly what context hygiene is about.
