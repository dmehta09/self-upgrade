Claude Code · lesson 4 · the big one

Explore → Plan → Code → Commit

This is the workflow that turns Claude Code from a slot machine into a reliable engineer. The idea is simple: separate understanding from doing. Let Claude explore and propose a plan before it writes a line — so you catch a wrong approach in a paragraph, not in a 300-line diff.

01  The four phases

The core loop
1 · explore
read & ask
no edits yet
2 · plan
propose & approve
you review
3 · code
implement
against the plan
4 · commit
tests + git
ship it
Phases 1–2 happen in plan mode (read-only). You approve the plan, then switch to implementing.
Measure twice, cut once analogy

A carpenter doesn't start sawing the moment you describe a shelf. They look at the wall, sketch it, and check the sketch with you. Plan mode is the sketch. Five minutes agreeing on the approach saves an hour unwinding the wrong one.

02  Plan mode, the safety rail

In plan mode, Claude can read and think but can't change files. It explores, then presents a plan for your approval. Enter it with /plan, or cycle permission modes with Shift+Tab. You can edit the plan before accepting it.

a planning session
> /plan add rate limiting to the public API

# Claude reads routes, middleware, config — then proposes a plan.
# You read it, tweak it, and approve. Only THEN does it write code.

03  Watch the whole loop

Notice the mode pill in the corner switch to plan mode while Claude explores and proposes — then back to default once you approve and it starts editing.

04  When to skip planning

Planning is for changes where the approach is uncertain. For tiny, obvious edits it's overhead.

Plan it

New features, anything touching multiple files, unfamiliar code, “I'm not sure how we'd do this,” or risky areas (auth, payments, migrations).

Just do it

Typos, a log line, a rename, a one-file fix. Rule of thumb: if you could describe the diff in one sentence, skip the plan.

Explore with subagents to save context tip

For big explorations, ask Claude to “use subagents to investigate.” They explore in their own context and report back a summary — so your main window stays clean for the actual work. See Subagents.

Why does plan mode make Claude Code more reliable for non-trivial changes?
Yes. A wrong plan is a paragraph to fix; a wrong implementation is a diff to unwind. Catching the approach early is the whole point.
