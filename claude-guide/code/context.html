Context is currency

The context window is everything Claude can “see” right now — your prompts, the files it read, command output, its own replies. It's the model's working memory, and it's finite. Spend it on what matters and sessions stay sharp; fill it with noise and quality quietly drops. Managing it well is the single biggest skill in Claude Code.

01  Think of it as RAM

Modern Claude models have huge context windows (Opus and Sonnet reach a million tokens), but “huge” isn't “infinite,” and a cluttered window still hurts. The more irrelevant material is in view, the harder it is for the model to focus on the part that matters.

A desk, not a warehouse analogy

Context is the desk you're working at, not the filing cabinet behind you. A clear desk with the three right documents beats a desk buried under fifty. When it gets cluttered, you clear it — you don't try to think harder over the mess.

02  Four moves to keep it clean

/clear
Wipe the conversation and start fresh. Use it between unrelated tasks — the #1 habit. The old session stays in /resume.
/compact
Summarize the conversation so far, keeping key decisions and file state while reclaiming space. Add focus instructions: /compact keep the API changes.
/context
Visualize what's filling the window, with tips on what to trim. Diagnose before you cut.
/rewind
Restore the conversation, the code, or both to an earlier checkpoint. Shortcut: Esc Esc. Aliases: /undo, /checkpoint.
Claude auto-compacts too tip

As the window approaches full, Claude Code summarizes older turns automatically so you don't crash into the limit. You can still /compact manually when you want control over what's kept.

03  Two habits that pay off daily

Clear between tasks

The “kitchen-sink session” — one task, then an unrelated question, then back — pollutes context. Finish a thing, /clear, start the next clean.

Scope your exploration

“Investigate the whole codebase” reads hundreds of files and floods the window. Point at a folder, or hand exploration to a subagent whose context is separate.

Symptoms of a bloated window gotcha

Claude starts forgetting earlier instructions, repeats work, or gets vaguer. That's usually context, not the model. /context to check, then /compact or /clear.

04  Checkpoints make experimenting safe

Every message is an automatic checkpoint of both the conversation and your files. So you can let Claude try a bold approach knowing you can undo it:

  • Restore conversation only — keep the code, drop a confusing exchange.
  • Restore code only — keep the discussion, throw away the file changes.
  • Restore both — go back in time entirely.

This is separate from git — it's a session-level undo. Commit when you're happy; rewind when you're not.

You finish a bug fix and want to start an unrelated feature in the same session. Best move?
Right. Unrelated tasks shouldn't share a window. /clear gives the new task full focus; the finished work is still in /resume if you need it. /rewind is for undoing, not for switching tasks.
