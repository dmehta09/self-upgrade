Permissions & settings.json

Claude Code is cautious by default: it asks before editing files or running commands. That's a safety feature, not a nuisance — and you can tune exactly how much it asks. Permissions are the guardrails; settings.json is where you set them.

01  Permission modes

The mode sets the default posture. Cycle modes with Shift+Tab, or start in one with --permission-mode.

default
Ask before each new action. Safest; a little chatty. Great while you're learning a project.
plan
Read-only — explore and propose, never edit. The research half of explore→plan→code→commit.
acceptEdits
Auto-accept file edits, still ask for riskier things. Good once you trust the task.
auto
A classifier reviews each action and only stops the genuinely risky ones — fewer prompts, still guarded.
bypassPermissions
Skip all prompts. Fast, but only in trusted, sandboxed contexts. (a.k.a. --dangerously-skip-permissions.)

02  Allow / ask / deny rules

For fine control, write rules in settings.json. allow runs without a prompt, ask always prompts, deny blocks outright. Patterns match tools and arguments.

.claude/settings.json
{
  "permissions": {
    "allow": [
      "Bash(npm run test:*)",
      "Bash(git commit:*)",
      "Read",
      "Edit(src/**)"
    ],
    "ask": ["Bash(git push:*)"],
    "deny": ["Read(./.env)", "Edit(infra/**)"],
    "defaultMode": "acceptEdits"
  }
}

03  Where settings live

~/.claude/settings.json
User scope — your defaults across all projects.
.claude/settings.json
Project scope — checked into git, shared with the team.
.claude/settings.local.json
Local scope — personal, gitignored overrides for this repo.

settings.json also holds env, hooks, model, statusLine, outputStyle and more — browse them all on the cheat sheet.

04  Match guardrails to trust

Like keys for a new hire analogy

Day one, a new teammate gets read access and asks before touching production. As trust builds, you hand over more keys. Permissions work the same way: start in default, allowlist the safe-and-frequent, and reserve bypass for sandboxes you fully control.

You keep approving npm test every session. The cleanest fix?
Right. Allowlist the specific safe command and keep the guardrails for everything else. bypassPermissions removes all checks — too blunt for a single repetitive command.
