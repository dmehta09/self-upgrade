Power-user workflows

You've got the everyday loop down. This lesson is the map of what's beyond a single session: running many Claudes at once, leaving work to run in the background, orchestrating fleets of agents, and — when you outgrow the CLI — building your own agents on the same engine.

01  Many sessions at once

Git worktrees

claude -w feature-auth starts in an isolated checkout, so two sessions can work on two branches without stepping on each other.

Background agents

claude --bg "fix the flaky test" runs detached; check on all of them with claude agents or /tasks.

From soloist to team lead analogy

One session is you pair-programming. Worktrees and background agents make you a team lead: hand out independent tasks, let them run in parallel, and review the results as they land — without anyone's work colliding.

Fast mode tip

When you're iterating rapidly, toggle /fast. Fast mode runs Opus with faster output — it does not downgrade you to a smaller model — so review-edit-retry loops feel snappier. Available on Opus 4.6 and later; toggle it off when you want to read along at full detail.

02  Orchestrating fleets

For changes that sprawl across a codebase, Claude Code can coordinate many agents automatically:

ultracode
Put the keyword in your prompt (or /effort ultracode) and Claude spins up a team lead that decomposes the work and runs subtasks in parallel. Watch it with /workflows.
/batch
Decompose a big migration into 5–30 independent units, each handled by a background subagent in its own worktree, each opening a PR.
/goal
Set a finish line and let Claude work across turns until it's reached — pairs well with background runs.
Big power, so scope it note

Fleets of agents get a lot done but cost a lot of tokens. Reserve them for genuinely large, parallelizable work (a framework migration, a sweep across hundreds of files), and let smaller tasks stay in one session.

03  Headless & scripted

claude -p runs a single query and exits — the bridge from interactive use to automation. Pipe data in, get an answer out, wire it into CI or a git hook.

terminal
# answer one question and quit
git diff | claude -p "write a conventional-commit message for this diff"

# machine-readable output for scripts
claude -p "list the public API routes" --output-format json

04  Build your own agents

When you want Claude Code's powers inside your own program — custom tools, your own permission logic, your own loop — reach for the Claude Agent SDK (Python & TypeScript). It's the same engine, exposed as a library.

Continue in Track A tip

The Agent SDK builds on the platform fundamentals — tool use, the agent loop, MCP. We cover it properly in Agents, MCP & the Agent SDK over in Using Claude. That's a natural next stop.

05  You've finished Track B 🎉

That's Claude Code, end to end — from your first session to orchestrating agents. The throughline never changed: gather context, act, verify, repeat, with you steering. Everything else is a refinement of that loop.
