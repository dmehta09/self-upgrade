Claude Code · lesson 2

Your first session

Open a terminal in a project, type claude, and ask for something in plain English. From there, Claude Code runs a simple loop over and over: gather context → act → verify → repeat. Once you can see that loop, everything else in this track is just a detail of it.

You're already in one tip

If you're reading this, you may already be running Claude Code. The fastest way to learn it is to keep this guide open on one side and a real project open on the other, and try each idea as you meet it.

01  Start it in a project

Install once, then run claude from inside any project folder. It starts an interactive session in your terminal — a conversation that can also read files, edit them, and run commands.

terminal
# install (macOS / Linux / WSL) — one line
curl -fsSL https://claude.ai/install.sh | bash

# then, inside your project:
cd my-project
claude

On Windows use irm https://claude.ai/install.ps1 | iex in PowerShell. Prefer a GUI? The same engine runs in the VS Code & JetBrains extensions, a desktop app, and the web — see What is Claude Code? for all five surfaces. The session below looks the same everywhere.

02  The loop in one picture

Claude Code is not a chatbot that answers and waits. It's an agent: given a goal, it repeats a short cycle until the goal is met (or it needs you).

The agent loop
1 · gather
read context
files, grep, output
2 · act
use a tool
edit, run, write
3 · verify
check result
tests, types, output
4 · repeat / done
loop or stop
until goal met
Each pass, the model decides the single next action. Claude Code performs it (asking permission when needed) and feeds the result back in — so the next decision is better informed.
Like cooking from a recipe analogy

You don't dump every ingredient in at once. You read the next step, do it, taste, then read the next step. Claude Code "tastes" by running your tests or printing output — that feedback is what keeps it on track instead of confidently making things worse.

03  Watch a first session

Here's a real-shaped session. Press play — or step with ‹ › — and read the caption under each step. Notice how it reads before it writes, and runs the script after it edits.

That's the whole shape of working with Claude Code. Bigger tasks just mean more laps around the same loop — sometimes with a plan up front (next lessons) and sometimes with helpers like subagents.

04  How to talk to it

You don't need special syntax — just clear requests. A few habits make a big difference from day one:

Say what “done” looks like

“Add input validation” is vague. “Reject empty names with a 400 and a clear message; add a test” gives Claude a target it can hit and check.

Give it a way to verify

Point at the test command, an example input/output, or a file to compare against. Verification is what turns “looks done” into “is done.”

One task at a time

Finish a thing, then start the next. Piling unrelated requests into one session muddies the context and the results.

Interrupt freely

Going the wrong way? Press Esc to stop and redirect — you don't have to wait for it to finish a bad idea.

Ask it about the codebase, too tip

Claude Code is great for learning a project, not just changing it: “How does auth work here?”, “Where is rate limiting handled?”, “Why does this call foo() on line 42?” It reads the code and explains — no edits required.

05  Reading the screen

During a session you'll see a few recurring things. Now that you've watched one, they'll be familiar:

You see…It means…
A “thinking” lineClaude is reasoning about the next step (you can expand it to read along).
A tool call (Read / Edit / Bash …)The model asked to do something; Claude Code is running it. Reads and greps are how it gathers context.
A green/red diffA proposed file change — additions in green, removals in red — shown before (or as) it's applied.
A permission promptClaude wants to do something you haven't pre-approved (run a command, edit a file). You approve, deny, or always-allow. More in Permissions.
The context meterHow full the conversation's memory is. Keep it healthy — that's the next lesson, Context is currency.
In the agent loop, why does Claude Code run your tests after editing instead of just telling you it's done?
Right. “Looks done” and “is done” are different. A check the model can run — tests, types, a sample input — is what turns a confident guess into a verified result. You'll lean on this idea constantly in Closing the loop.
Made a mess? You can rewind go deeper

Every message you send is an automatic checkpoint. If a session goes sideways, you can press Esc Esc (or run /rewind) to restore the conversation, your code, or both to an earlier point — like an undo for the whole session. That safety net is why it's fine to experiment. We cover it properly in Context is currency.
