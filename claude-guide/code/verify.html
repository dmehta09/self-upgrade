Claude Code · lesson 5

Closing the loop

Claude Code stops when the work looks done. Without a check it can run, you become the verification loop — every mistake waits for you to notice. The fix is to hand Claude a way to check itself: a test, a build, an example, a goal. That one habit is the difference between “probably fine” and “proven.”

01  “Looks done” ≠ “is done”

A model is very good at producing plausible code. Plausible isn't the same as correct. A check it can run — and read the result of — is what catches the gap.

02  Five ways to give Claude a check

In the prompt
The simplest: “…and run the tests and fix failures,” or give example inputs/outputs. Claude iterates in the same turn.
/goal
Set a condition and Claude works across turns until it holds — great for unattended runs: /goal all tests pass.
Stop hook
A hook that runs your tests when Claude tries to end a turn and blocks until they pass. Zero-exception enforcement.
Reviewer subagent
“Use a subagent to review this for edge cases.” A fresh context critiques the work without bias — a second pair of eyes.
/code-review
Run the bundled review on your diff for correctness and cleanups; add --fix to apply.
Evidence beats assertion tip

“Here's the passing test output / the screenshot / the command I ran” is far more trustworthy — and faster to review — than “it works.” Ask Claude to show the evidence, especially before you commit.

03  Insist on root causes

When a check fails, the lazy fix is to silence it — widen a type, wrap in a try/except, delete the assertion. Don't accept that. A good prompt says so:

Watch for symptom-suppression gotcha

If a test goes green because the test got weaker, that's worse than red. Tell Claude “fix the root cause, don't suppress the error,” and skim the diff to confirm the behavior changed, not just the check.

What's the most reliable single thing you can add to a coding request?
Right. Vibes don't verify. A check Claude can run and read closes the loop on its own, so you're reviewing evidence instead of hunting for bugs.
