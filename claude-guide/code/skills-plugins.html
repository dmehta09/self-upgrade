Skills & plugins

A skill is a folder with a SKILL.md that teaches Claude something — a convention, a checklist, a multi-step procedure. The clever part: a skill's body loads only when it's relevant, so you can keep lots of reference material around for almost no context cost. Plugins bundle skills (plus hooks, MCP servers, and commands) into one installable package.

01  Skills = knowledge on demand

Where CLAUDE.md is always loaded (so it must stay short), a skill loads lazily. Claude reads only the skill's one-line description until it's actually needed — then it pulls in the full body. That's why a procedure belongs in a skill, not the memo.

.claude/skills/api-conventions/SKILL.md
---
name: api-conventions
description: REST conventions for our services — use when adding endpoints
---
# API conventions
- Paths kebab-case; JSON fields camelCase
- Every list endpoint is paginated (`?limit=&cursor=`)
- Version in the path: `/v1/...`
- Errors use the problem+json shape

Claude applies this automatically when you're adding an endpoint — or you invoke a skill directly with /api-conventions. The description is what Claude matches on, so make it specific.

02  Two kinds of skills

Knowledge skills

Facts and conventions Claude pulls in when relevant — like the API rules above. Auto-invoked.

Workflow skills

A procedure you trigger by name, like the /fix-issue command from the commands lesson. Often set disable-model-invocation: true so only you start them.

Skills you already have note

Claude Code ships with bundled skills — /code-review, /security-review, /debug, /run, /verify and more. Run /skills to list what's available. Skills follow the open Agent Skills standard, so they work across tools.

03  Plugins = bundles you can install

A plugin packages skills, subagents, hooks, MCP servers, and commands together. Install one and you get the whole kit — no copy-pasting config.

terminal
# browse and install from a marketplace
> /plugin

# or from the shell
claude plugin install code-review@claude-plugins-official

# add a marketplace (a GitHub repo of plugins)
> /plugin marketplace add anthropics/claude-plugins-community
Skills are apps; plugins are app bundles analogy

A skill is like a single app that gives Claude a new capability. A plugin is a curated bundle — apps plus their settings, automations, and integrations — that you install in one click from a marketplace (official or community).

Why put a long, multi-step procedure in a skill instead of CLAUDE.md?
Right. Keep the always-on memo short; push procedures and big reference material into skills, which Claude pulls in on demand. Same idea as context hygiene, applied to your config.
