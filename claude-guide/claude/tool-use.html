Using Claude · lesson 7

Tool use (function calling)

On its own, Claude only produces text. Give it tools — functions you describe — and it can decide to call them: look up live data, query a database, send an email. You run the function and hand back the result. This request → call → result → answer loop is exactly how agents like Claude Code work, just in miniature.

01  The loop

One tool-use round-trip
1
you send
prompt + tool defs
2
Claude asks
“call get_weather(NYC)”
3
you run it
return “12°C”
4
Claude answers
“It's 12°C in NYC.”
Crucial: Claude never runs the tool — it only asks. Your code runs it and returns the result. That's the safety boundary, and the same one Claude Code uses with permissions.

02  Define a tool

A tool is a name, a description, and a JSON-schema for its inputs. The description matters — it's how Claude knows when to reach for it.

tools.py
tools = [{
    "name": "get_weather",
    "description": "Get the current temperature for a city.",
    "input_schema": {
        "type": "object",
        "properties": {"city": {"type": "string", "description": "City name"}},
        "required": ["city"],
    },
}]

03  Run the loop

Send the tools. If Claude wants one, the response's stop_reason is "tool_use". Run the function, append the result as a tool_result, and call again so Claude can finish.

app.py
def get_weather(city):           # your real implementation
    return "12°C and clear"

messages = [{"role": "user", "content": "What's the weather in NYC?"}]
resp = client.messages.create(model="claude-sonnet-4-6", max_tokens=1024,
                              tools=tools, messages=messages)

if resp.stop_reason == "tool_use":
    call = next(b for b in resp.content if b.type == "tool_use")
    result = get_weather(**call.input)          # run the tool yourself

    messages.append({"role": "assistant", "content": resp.content})
    messages.append({"role": "user", "content": [{
        "type": "tool_result", "tool_use_id": call.id, "content": result,
    }]})

    final = client.messages.create(model="claude-sonnet-4-6", max_tokens=1024,
                                   tools=tools, messages=messages)
    print(final.content[0].text)   # "It's 12°C and clear in NYC."
Claude is the chef calling for ingredients analogy

The chef (Claude) shouts “I need diced onions!” but doesn't leave the pass. The kitchen (your code) actually fetches and dices, then hands the bowl back. The chef keeps cooking with it. Claude decides what it needs; you decide whether and how to provide it.

04  Loop it, and you have an agent

Run that round-trip in a while loop — keep going as long as Claude keeps asking for tools, stop when it returns a final answer — and you've built a tiny agent. Add tools like read file, edit file, and run command, and you've got the skeleton of Claude Code itself.

Don't hand-roll the whole agent tip

The Claude Agent SDK gives you this loop, plus permissions, context management and more — the same machinery behind Claude Code. Build tools; let the SDK run the loop.

In tool use, who actually executes the function Claude “calls”?
Right. Claude emits a request to call a tool; you execute it and feed back the result. That boundary is what makes tool use controllable — and it's the same one Claude Code's permission system guards.
