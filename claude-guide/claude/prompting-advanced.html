Using Claude · lesson 5

Prompting 2 · examples & thinking

Clarity gets you 80% of the way. These four techniques get the rest: show examples, let Claude think, structure with XML tags, and set a strong system prompt. They're Anthropic's own headline recommendations — and each is easy to apply.

01  Show, don't just tell (few-shot)

The single most powerful upgrade: include a few examples of the input → output you want. Examples pin down the format and the edge cases far better than describing them. Try it — the “no examples” reply is fine but unpredictable; the “few-shot” reply is clean and parseable.

02  Let Claude think first

For anything involving reasoning — math, logic, multi-step decisions — telling Claude to think step by step before answering measurably improves accuracy. It works because the model reasons in the tokens it generates; give it room to work and it stumbles less.

prompt
Work through this step by step inside <thinking> tags,
then give your final answer in <answer> tags.

A train leaves at 2:15pm going 60mph...

Current Claude models can also do this natively via extended thinking — in Claude Code that's the /effort slider. More in Power features.

03  Structure inputs with XML tags

When a prompt mixes instructions with data (a document to analyze, examples, context), wrap each part in named XML tags. Claude is specifically tuned to respect them, so it never confuses your instructions with the material.

prompt
Summarize the document for a new hire. Use only what's in the document.

<document>
{{paste the long doc here}}
</document>

<format>
3 short bullets, plain English.
</format>
Tags also make output easy to parse tip

Ask for the answer in <answer> tags and your code can pull it out reliably — no fragile string-matching. Tags help on the way in and the way out.

04  Set the role in the system prompt

Put durable instructions — who Claude is, the rules, the tone — in the system prompt (from the last lesson). It anchors every turn, so you don't repeat yourself.

system prompt
You are a senior code reviewer for a Python team.
Be concise and specific. Cite line numbers. Prefer
small, safe diffs. If something is unclear, ask before
assuming. Never invent APIs.
You've already used this note

A project's CLAUDE.md and a custom subagent's instructions are system-prompt material for Claude Code. Same technique, different surface.

You need Claude to label thousands of items in a strict, machine-readable format. Best technique?
Right. Examples pin down format and edge cases better than any description. A couple of well-chosen input→output pairs make the output consistent and parseable.
