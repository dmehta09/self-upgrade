Using Claude · lesson 8

Power features

Once your app works, these features make it faster, cheaper, and more capable. You don't need them on day one — but knowing they exist changes what you'll build. Here's the tour, with the “reach for it when” for each.

01  Prompt caching — the big cost lever

If you send the same long prefix every call — a big system prompt, a document, a set of examples — cache it. Cached input is dramatically cheaper and faster on subsequent calls. You mark a cache breakpoint and Claude reuses everything up to it.

caching.py
client.messages.create(
    model="claude-sonnet-4-6", max_tokens=512,
    system=[{
        "type": "text",
        "text": LONG_KNOWLEDGE_BASE,            # reused every call
        "cache_control": {"type": "ephemeral"}, # ← cache breakpoint
    }],
    messages=[{"role": "user", "content": "Answer from the KB above: ..."}],
)

Ideal for chatbots with big instructions, RAG over fixed documents, and long examples. (It's also why Claude Code stays affordable across a long session.)

02  The rest of the toolkit

Extended thinking
Let Claude reason for longer before answering — big accuracy gains on math, logic, and planning. Set a thinking budget; in Claude Code it's the /effort slider.
Vision & PDF
Send images and PDFs as input. Claude reads charts, screenshots, scanned docs — great for “explain this diagram” or extracting data from a report.
Batch API
Submit thousands of requests asynchronously for ~50% less. Perfect for non-urgent bulk jobs: labeling a dataset, generating descriptions, evals.
Structured outputs
Guarantee the response matches a JSON schema you define — no more fragile parsing. Ideal when the output feeds another system.
Citations
Have Claude cite the source passages behind its claims — essential for trustworthy RAG and document Q&A.
Files API
Upload a file once and reference it across many requests, instead of resending it each time.

03  Which one, when

Your goalReach for
Cut cost & latency on repeated contextPrompt caching
Harder reasoning / fewer mistakesExtended thinking
Analyze images, charts, or PDFsVision / PDF
Process a huge backlog cheaplyBatch API
Output must be valid JSON for codeStructured outputs
Answers must be traceable to sourcesCitations
Build first, optimize second tip

Get the basic call working, then add caching when cost matters, batch when volume grows, structured outputs when you wire it into a pipeline. Don't reach for all six up front.

Your support bot sends the same 5,000-token instruction block on every message and the bill is climbing. Best fix?
Right. A large, unchanging prefix sent every call is the textbook case for prompt caching — big cost and latency savings without touching quality.
