Practice · 3 timed drills + 2 decks

Drill it until it's reflex

Reading builds understanding; recall under a clock builds judgment. Three timed drills hit the decisions this guide trains — which mechanism, which feature, what broke — and two flashcard decks keep the reference knowledge warm. Misses link straight back to the lesson that fixes them.

01  How the drills work

Timed
Each question has a 30–45 second countdown. Timeout counts as a miss — speed is part of the skill.
Traps included
Wrong options aren't random: each question carries the plausible wrong answer, and the verdict explains why it tempts.
Scored & saved
Best score per mode persists in your browser (localStorage["claude-drill"]). The questions reshuffle every round.
Keyboard
Press 1–9 to answer, Enter/→ for next, Esc to bail to the intro.

02  Pick the mechanism

The signature Claude Code judgment call: hook or CLAUDE.md? Skill or slash command? Subagent or headless run? Read the need, pick the tool.

03  Which API feature?

Streaming, caching, batches, structured outputs, files, thinking, tools, vision — eight levers, one right pull per scenario. 30 seconds each.

04  Debug the session

A symptom walks in — Claude forgets things, a command silently dies, the bill won't shrink. Name the cause before the bar runs out.

05  Flashcards

Click a card to flip it; mark it Known when it sticks. Shuffle floats the ones you still miss to the top. Progress saves to localStorage["claude-cards"].

Commands & flags

0/0 known

  • /clear vs /compact

    /clear wipes the conversation for a new, unrelated task. /compact summarizes the current one to keep going. Unrelated task → clear; same task, full window → compact.

  • What does /context show?

    A colored map of what's filling the window — system prompt, files, tool output, history — plus trimming tips. Diagnose before you cut.

  • Undo a bad exchange but keep the code

    /rewind → restore conversation only. Every message checkpoints both convo and files; restore either or both. Shortcut: Esc Esc.

  • Start a risky feature safely

    /plan — plan mode explores read-only and proposes an approach; nothing is edited until you approve.

  • /model vs /effort vs /fast

    /model picks which brain. /effort sets how hard it thinks. /fast keeps Opus but streams output faster — same model, quicker delivery.

  • First command in a brand-new repo?

    /init — analyzes the project and drafts a CLAUDE.md with build/test commands and conventions for you to refine.

  • Reopen yesterday's session

    claude -c continues the latest session in this directory; claude --resume <name> (or /resume) picks a specific one from the list.

  • Run Claude Code inside a script

    claude -p "…" — print mode: one query in, the answer on stdout, exit. Add --output-format json when the script needs metadata (cost, session id).

  • Two features in parallel, no collisions

    claude -w feature-x gives each session an isolated git worktree; --bg runs one detached in the background (claude agents to check in).

  • Make git push always ask

    An ask rule in /permissions: "Bash(git push:*)" — it prompts in every mode, even auto-accept sessions.

  • See which hooks will fire

    /hooks lists events (PreToolUse, PostToolUse, Stop…) and their handlers. Debugging weirdness? disableAllHooks is the global off-switch.

  • What's eating my budget?

    /usage — session cost and plan limits, with a breakdown by skill, subagent, plugin, and MCP server on paid plans.

API concepts

0/0 known

  • When does prompt caching pay off?

    A long, byte-identical prefix reused across calls — system prompt, docs, few-shot examples. Keep volatile bits (timestamps, ids) below the cached prefix or it never hits.

  • Batch API in one line

    Asynchronous bulk processing at roughly half price, for jobs nobody is waiting on. Submit thousands of requests, collect results later.

  • Guarantee parseable replies

    Structured outputs: bind a JSON schema and the response validates against it every time — no prose-parsing roulette.

  • What problem does streaming solve?

    Perceived latency — tokens render as they're generated instead of after the whole answer. The model isn't faster; the experience is.

  • Extended thinking — when?

    Hard multi-step reasoning: math, logic, planning, gnarly trade-offs. You grant a thinking budget; accuracy jumps, latency and cost tick up.

  • The tool-use loop

    Model returns tool_use with args → your code executes it → you send a tool_result back → model continues. Skip the result and the model improvises.

  • Files API vs resending

    Upload once, reference by id across many requests and conversations — for shared, mostly-static assets like a big spec.

  • Correct reaction to a 429

    Honor retry-after, retry with exponential backoff + jitter, never tight-loop. The official SDKs do this automatically if you let them.

  • Model laddering

    Route easy traffic to Haiku, default to Sonnet, escalate hard cases to Opus / Fable 5. Quality where it matters, savings everywhere else.

  • 4xx vs 5xx rule of thumb

    4xx (except 429) = your bug — fix the request, don't retry. 429 / 5xx = weather — retry politely with backoff.

A good rhythm tip

Finish a track, then drill it the next day — spaced recall beats same-day cramming. Anything you miss twice, reopen the lesson the miss links to and skim just that section.
