Trees · BFS & DFS

A surprising number of tree problems are really just a walk: visit every node in some order and do a little work at each one. There are two famous ways to walk — go deep first (recursion), or go wide first (a queue). Learn these two strolls and a whole shelf of tree questions falls open. Let's watch each one move, then solve four classics.

00  The idea

A tree is just nodes connected in branches: a top node (the root), and each node points to a few children below it. To answer almost anything — "how tall is it?", "is it sorted?", "what's between these two nodes?" — you visit the nodes in a careful order. There are two orders worth knowing by heart.

Depth-first (DFS) dives down one branch all the way to the bottom, then backs up and tries the next branch. It's naturally written with recursion — a function that calls itself on each child, going deep, then returning the answer back up. Breadth-first (BFS) instead sweeps one whole layer at a time, top to bottom, using a queue — a line where you serve the node that's been waiting longest.

Exploring a building analogy

Imagine exploring a building with rooms and stairs. Depth-first is following one corridor to its very end, hitting a dead end, then walking back to try the next door — you go as deep as you can before changing course. Breadth-first is checking every room on this floor before climbing the stairs — you finish a whole level before going up. Same building, two ways to see all the rooms.

When to reach for each walk

These tells point you to a tree traversal — and tell you which one:

"Visit every node"
You must touch each node once to measure, collect, or check something — that's a traversal.
Depth or paths
Questions about height, root-to-leaf paths, or "carry info down then combine going up" → depth-first recursion.
Levels or "closest"
"Process level by level", "nodes at each depth", or shortest-steps → breadth-first with a queue.
It's a BST
A sorted tree (left < node < right) lets you skip whole branches — walk only the side that can hold the answer.
Recursion uses a hidden stack

Depth-first recursion quietly uses the call stack — the computer's own pile of "where was I?" notes. That's why its memory cost is O(h), the height of the tree: that's how deep the pile of paused calls can get. We meet stacks head-on on the Stack page, and BFS's queue cousin on the queues page.

01  Maximum Depth of Binary Tree

Trees · DFS Easy ~10 min O(n) time · O(h) space

The depth (or height) of a tree is the number of nodes on the longest path from the root down to a leaf. For the tree [3, 9, 20, null, null, 15, 7] the answer is 3 (the path 3 → 20 → 15).

Ask your kids how deep they are analogy

A node's depth is 1 + the taller of its two children's depths. So you don't measure the whole tree yourself — you ask each child "how deep are you?", take the bigger answer, and add 1 for standing on yourself. A leaf has no children, so it answers "1". The question rolls down to the leaves and the answers add up on the way back.

How to solve it

This is the cleanest depth-first recursion there is. Write a function max_depth(node):

  1. Base case: an empty spot (None) has depth 0. This is what stops the recursion at the bottom.
  2. Recurse: ask the left child and the right child for their depths.
  3. Combine: return 1 + max(left_depth, right_depth) — the taller branch, plus yourself.

Every node is asked exactly once, so the work is O(n). Connecting back to the picture: the question dives to the leaves, and each node adds 1 as the answer climbs back up.

MeasureCostWhy
TimeO(n)Each of the n nodes is visited once. Double the nodes, double the work.
SpaceO(h)The call stack goes as deep as the tree's height h (n in the worst, skewed case).

New to this notation? See the Big-O cheat-sheet.

The shape of every DFS

"Base case for empty, recurse on children, combine the results" is the skeleton of almost every depth-first tree function. Once this one clicks, the rest are variations on the same three lines.

Why does an empty node return 0 instead of 1?

Right. The None case is the floor of the recursion. Returning 0 there means a leaf (whose children are both None) correctly measures as 1 + max(0, 0) = 1 — exactly one node tall.
Stuck? Reveal a hint hint

Handle the empty case first (if not root: return 0). Otherwise the answer is just 1 + max(max_depth(root.left), max_depth(root.right)) — let recursion do the rest.

Show the solution & run it solution
max_depth.py
3

Three lines do everything: stop at empty, ask both children, return the deeper one plus one. The recursion mirrors the analogy exactly — each node trusts its kids to report their own depth.

02  Binary Tree Level-Order Traversal (BFS)

Trees · BFS Medium ~20 min O(n) time · O(n) space

Return the node values grouped level by level, top to bottom. For [3, 9, 20, null, null, 15, 7] the answer is [[3], [9, 20], [15, 7]].

A queue at a ticket counter analogy

Picture a queue — a line where you always serve whoever has waited longest. Put the root in line. To process a level, serve everyone currently in line, and as you serve each node, send its children to the back of the line. Because children always join behind the current level, the line naturally hands you the tree one full floor at a time.

How to solve it

The trick that turns a plain queue-walk into a level-by-level one is to grab the queue's size at the top of each round:

  1. If the tree is empty, return []. Otherwise start a queue holding just the root.
  2. While the queue isn't empty, note its current length k — that's exactly the size of this level.
  3. Pop precisely k nodes into a fresh level list, pushing each one's children to the back.
  4. Append that level to the result. Repeat for the next floor.

Freezing the length is the whole secret: children added during this round wait for the next round. We use Python's deque because popping from the front is O(1).

MeasureCostWhy
TimeO(n)Every node is enqueued and dequeued exactly once.
SpaceO(n)The queue can hold a whole level; the widest level can be up to ~n/2 nodes.
Snapshot the level size first

If you loop while queue without first capturing len(queue) into k, the children you add this round get swept into the same level — and your "levels" blur together. Read the size before you start popping.

What does capturing len(queue) at the start of each round accomplish?

Exactly. The frozen count k is a fence between levels. You pop only the k nodes already in line; their children land behind the fence and become the next level. Skip the snapshot and all the levels merge into one list.
Stuck? Reveal a hint hint

Use from collections import deque. Outer loop: while q. Inside, for _ in range(len(q)) pops one level, appending each node's value and enqueuing its children. Collect each round into its own list.

Show the solution & run it solution
level_order.py
[[3], [9, 20], [15, 7]]

The inner for _ in range(len(q)) is the level fence — it pops exactly today's floor while tomorrow's children queue up behind. That's the breadth-first sweep, one room-floor at a time.

03  Validate Binary Search Tree

Trees · DFS Medium ~20 min O(n) time · O(h) space

A binary search tree (BST) keeps everything sorted: for every node, all values on its left are smaller and all on its right are larger. Given a tree, return True if it obeys that rule everywhere.

A shrinking room of allowed values analogy

The BST rule isn't just "my left child is smaller and my right child is bigger" — it's that every node in my left subtree is below me, and every node on my right is above me. So as you walk down, carry a (low, high) band of still-allowed values. Step left and the ceiling drops to the current value; step right and the floor rises to it. If a node ever steps outside its band, the tree is broken.

How to solve it

Recurse with two extra arguments — the current low and high bounds — starting wide open:

  1. Base case: an empty node is a valid (sub)tree → return True.
  2. Check the band: the node's value must sit strictly inside (low, high). If not, return False.
  3. Recurse with tighter bounds: the left child inherits (low, node.val); the right child inherits (node.val, high). Both must pass.

Start the whole thing with low = -infinity, high = +infinity so the root can be anything. The band only ever shrinks as you go deeper — exactly the picture above.

MeasureCostWhy
TimeO(n)Each node is checked once against its band.
SpaceO(h)Recursion stack as deep as the tree's height h.
Checking only immediate children is the classic wrong answer

It's tempting to test just left.val < node.val < right.val for each node. But a grandchild on the left can still be bigger than an ancestor higher up and slip past that local check. The example [5,1,4,null,null,3,6] passes every parent-vs-child test yet isn't a BST — the 3 under the right side is below 5. The shrinking band catches it; local comparisons don't.

Why isn't it enough to check left < node < right at each node?

Right. The BST rule is about whole subtrees, not just neighbours. A node deep on the right must still beat an ancestor far above it. Carrying (low, high) down enforces every ancestor's limit at once.
Stuck? Reveal a hint hint

Write a helper ok(node, low, high). Empty → True. Else require low < node.val < high, then recurse left with (low, node.val) and right with (node.val, high). Kick it off with float("-inf") and float("inf").

04  Lowest Common Ancestor of a BST

Trees · BST Medium ~15 min O(h) time · O(1) space

The lowest common ancestor (LCA) of two nodes is the deepest node that has both of them somewhere below it (a node can be its own ancestor). In a BST, the sorted order makes this fast.

The fork in the road analogy

Walk down from the root holding both targets in mind. If both are smaller than where you stand, they both live to the left — step left. If both are bigger, step right. The moment they split — one on each side, or one of them equals the node you're on — you're standing exactly at the fork where their paths diverge. That fork is their lowest common ancestor.

How to solve it

No recursion needed — a simple loop down one path does it, because a BST tells you which way to turn:

  1. Start at the root with the two targets p and q.
  2. If both targets are less than the current value, the answer is left — go left.
  3. If both are greater, go right.
  4. Otherwise they've split (or one equals the node) — the current node is the LCA. Return it.

You only ever walk down a single root-to-node path, so it's O(h) time and O(1) space — no stack, no recursion. That's the payoff of the sorted BST shape.

MeasureCostWhy
TimeO(h)One step per level down a single path; h is the tree height.
SpaceO(1)Just one moving pointer — no recursion, no queue.
The sortedness is the shortcut

In a plain (unsorted) tree, LCA needs a full DFS. The BST's order lets you discard half the tree at every step — that's why this version is O(h) instead of O(n).

You're at a node and one target equals its value while the other is larger. Where is the LCA?

Correct. When one target equals the current node, that node already contains both targets in its subtree (itself plus the other on one side). It can't get any lower, so it's the LCA.
Stuck? Reveal a hint hint

Loop a cur pointer from the root. If p and q are both < cur.val, go left; if both > cur.val, go right; otherwise return cur.val. No recursion required.

The loop turns the same direction both targets point, and stops the instant they disagree. For 2 and 8 they split at the root 6; for 2 and 4 the node 2 is itself one of the targets, so it's the fork.
