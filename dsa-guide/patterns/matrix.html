Matrix

A grid is just a list of lists — but Blind 75 loves in-place tricks: mark rows with the first cell, peel layers like an onion, transpose then flip. Learn those moves once and three classic matrix problems stop feeling like geometry homework.

00  The idea

Interview grids usually ban a second copy of the board. That forces three habits: reuse the matrix as storage (first row / first column as marker strips), work by layers (outer ring, then the ring inside), and compose simple transforms (transpose + reverse = rotate 90°) instead of inventing a one-shot formula.

Sticky notes on the margin analogy

Imagine a classroom seating chart. Instead of a separate clipboard listing “which rows/columns to clear,” you stick a tiny flag in the first seat of that row or column. Later you walk the chart again and zero out anyone whose margin flag is set. The chart itself is the clipboard — that’s the O(1)-extra-space move.

The three house moves

MoveIn plain wordsWhere it shows up
First row/col markersBorrow the top strip and left strip to record “this row/col must change,” plus two booleans for the strips themselves.Set Matrix Zeroes
Transpose + reverseSwap across the diagonal, then reverse each row — a 90° clockwise rotate with no extra matrix.Rotate Image
Layer / ring walkTrack top, bottom, left, right; walk right → down → left → up; shrink the bounds.Spiral Matrix

When to reach for matrix tricks

"Modify in place" / O(1) extra space
Don’t allocate another m×n board — mark inside the grid or rotate via swaps.
"Rotate 90°"
Transpose then reverse rows (clockwise) — say it out loud before coding indexes.
"Spiral order" / peel layers
Four pointers on the current ring; shrink after each full lap.
Zeros that infect a whole row/col
Two-pass with first-row/col as markers, never zero while you still need to scan.

Why can’t you zero a whole row the moment you see a 0 while scanning?

Exactly. Early writes pollute later reads. Mark first, apply second — that’s the whole point of the marker strip.

01  Set Matrix Zeroes

Matrix Medium ~20 min O(m·n) time · O(1) space

Given an m × n matrix, if any cell is 0, set its entire row and column to 0. Mutate in place with O(1) extra space — no copy of the grid, no O(m+n) boolean arrays if you can help it.

Cross out the row and column on the margin analogy

When you find a zero, don’t paint yet — put a sticky note on the top of that column and the left of that row (using those cells as flags). After you’ve marked every original zero, walk again and paint. Two booleans remember whether the sticky-note strips themselves needed painting.

How to solve it

  1. Record whether the first row and first column themselves contain a zero (two booleans).
  2. Scan the interior: if matrix[i][j] == 0, set matrix[i][0] = 0 and matrix[0][j] = 0.
  3. Second pass over the interior: if either marker is zero, set matrix[i][j] = 0.
  4. Finally zero the first row / first column if those booleans said so.

Order matters: paint the interior using markers before you wipe the marker strips themselves.

MeasureCostWhy
TimeO(m·n)Two full scans of the grid.
SpaceO(1)First row/col as markers + two booleans — no O(m+n) arrays.

New to this notation? See the Big-O cheat-sheet.

Why do we need separate booleans for the first row and first column?

Right. matrix[0][0] is both “first row marker” and “first col marker.” Handle the strips last with dedicated flags so you don’t erase information mid-flight.
Stuck? Reveal a hint hint

Don’t allocate row_zero / col_zero arrays of length m and n. Borrow matrix[0][*] and matrix[*][0] as those arrays, and park the fate of row 0 / col 0 in two booleans.

Show the solution & run it solution
set_matrix_zeroes.py
[[1, 0, 1], [0, 0, 0], [1, 0, 1]]

Mark on the first pass, paint on the second, wipe the marker strips last. Same asymptotic cost as a copy, but constant extra memory.

Line-by-line walkthrough + flow walkthrough

Use first row/col as O(1) marker strips plus two booleans — mark, then paint, then clear the strips. Never zero while you still need to discover original zeros.

flowchart TD
  start[Record first_row and first_col flags] --> mark[Scan interior: set markers]
  mark --> paint[Zero interior from markers]
  paint --> strips{first_row or first_col?}
  strips -->|yes| wipe[Zero first row and/or col]
  strips -->|no| ret[Return matrix]
  wipe --> ret
  ret --> done[Done]
  1. def set_zeroes(matrix):Mutate so every zero’s row and column become zeros.
  2. first_row = any(...)Remember if row 0 itself must be cleared later.
  3. first_col = any(...)Same for column 0 — don’t mix this into cell markers yet.
  4. if matrix[i][j] == 0: matrix[i][0] = matrix[0][j] = 0Plant sticky notes on the margins.
  5. if matrix[i][0] == 0 or matrix[0][j] == 0:Second pass paints the interior from those notes.
  6. if first_row: ...Clear the marker strips only after the interior is done.

Time O(m·n) two passes; space O(1) — markers live inside the matrix plus two booleans.

02  Rotate Image

Matrix Medium ~15 min O(n²) time · O(1) space

Rotate an n × n matrix 90° clockwise in place. The clean interview answer is two steps: transpose, then reverse each row — no temporary n×n board.

Flip the paper, then mirror each line analogy

Transpose is like reflecting the sheet over its diagonal (rows become columns). Reverse each row is like flipping that sheet left-to-right. Those two reflections compose into a quarter-turn clockwise — same idea as how two mirrors make a rotation.

How to solve it

  1. Transpose: for i in 0..n-1, for j in i+1..n-1, swap matrix[i][j] with matrix[j][i].
  2. Reverse each row: matrix[i].reverse() (or two pointers left/right).
  3. Done — cell (i, j) lands at (j, n-1-i), which is the clockwise map.

Counter-clockwise is the twin: reverse rows first, then transpose (or transpose then reverse columns).

MeasureCostWhy
TimeO(n²)Every cell is touched a constant number of times.
SpaceO(1)Only swap temporaries — mutate the given matrix.

After transpose of [[1,2],[3,4]], what does reverse-each-row produce?

Yes. Transpose → [[1,3],[2,4]]; reverse rows → [[3,1],[4,2]], which is 90° clockwise from the start.
Stuck? Reveal a hint hint

Don’t chase four-way cycle swaps on every layer unless you enjoy index bugs. Transpose (upper triangle swaps) then row.reverse() is the interview-friendly path.

Show the solution & run it solution
rotate_image.py
[[7, 4, 1], [8, 5, 2], [9, 6, 3]]

Two mechanical transforms beat one clever formula. Say “transpose then reverse” in the interview before you touch the keyboard.

Line-by-line walkthrough + flow walkthrough

90° clockwise in place = transpose (swap across diagonal) then reverse each row. O(n²) time, O(1) extra space — no second matrix.

flowchart TD
  start[n = len matrix] --> transp[Transpose upper triangle]
  transp --> rev[Reverse each row]
  rev --> ret[Return matrix]
  ret --> done[Done]
  1. def rotate(matrix):Rotate n×n ninety degrees clockwise in place.
  2. n = len(matrix)Square side length.
  3. for j in range(i + 1, n):Only the upper triangle — each pair swapped once.
  4. matrix[i][j], matrix[j][i] = ...Transpose: rows become columns.
  5. row.reverse()Left-right flip finishes the clockwise turn.

Time O(n²) visit each cell constantly often; space O(1) swaps only.

03  Spiral Matrix

Matrix Medium ~20 min O(m·n) time

Return every element of an m × n matrix in spiral order: right along the top, down the right edge, left along the bottom, up the left edge, then the next inner ring.

Peeling an onion ring by ring analogy

Walk the outer crust of a pizza clockwise, then shrink the crust one notch inward and walk again. Four rubber bands — top, bottom, left, right — mark the current crust. When a band crosses another, the pizza is gone.

How to solve it

  1. Initialize top, bottom, left, right to the outer bounds.
  2. While top <= bottom and left <= right: walk right on top, then down on right, then left on bottom, then up on left — shrinking each bound after its side.
  3. Guard the last two legs: after moving top/right, re-check that a bottom or left walk is still needed (odd-sized or single-row/col cases).
MeasureCostWhy
TimeO(m·n)Each cell is appended exactly once.
SpaceO(1) extraOutput list is required; bounds use four integers.

On a single-row matrix, why must you skip the “left along bottom” leg after walking right?

Exactly. The if top <= bottom / if left <= right guards after shrinking are what make 1×n and m×1 cases work.
Stuck? Reveal a hint hint

Four pointers, four loops per layer. After finishing a side, shrink that bound by one. Before the bottom and left passes, check the bounds still make sense — that’s the whole bug farm for this problem.

Show the solution & run it solution
spiral_matrix.py
[1, 2, 3, 6, 9, 8, 7, 4, 5]

Layer by layer, four directions, two guards. Once the pattern clicks, every spiral variant (generate spiral, rotate layers) reuses the same bounds.

Line-by-line walkthrough + flow walkthrough

Maintain top/bottom/left/right; walk right→down→left→up and shrink. Guard bottom/left legs so single-row and single-col grids don’t double-count.

flowchart TD
  start[Init top bottom left right] --> loop{"bounds valid?"}
  loop -->|yes| rightWalk[Walk top row right]
  rightWalk --> downWalk[Walk right col down]
  downWalk --> checkBot{"top still le bottom?"}
  checkBot -->|yes| leftWalk[Walk bottom row left]
  checkBot -->|no| checkLeft
  leftWalk --> checkLeft{"left still le right?"}
  checkLeft -->|yes| upWalk[Walk left col up]
  checkLeft -->|no| loop
  upWalk --> loop
  loop -->|no| ret[Return out]
  ret --> done[Done]
  1. def spiral_order(matrix):Collect cells in clockwise spiral order.
  2. top, bottom = 0, len(matrix) - 1Vertical bounds of the current ring.
  3. left, right = 0, len(matrix[0]) - 1Horizontal bounds of the current ring.
  4. while top <= bottom and left <= right:Stop when the ring collapses.
  5. for j in range(left, right + 1):Top edge left→right, then top += 1.
  6. if top <= bottom:Only walk the bottom edge if a row remains.
  7. if left <= right:Only walk the left edge if a column remains.

Time O(m·n) one visit per cell; extra space O(1) beyond the output list.
