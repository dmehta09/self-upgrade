Design

Some interview prompts don't ask you to compute an answer — they ask you to build a small API with hard speed guarantees. The classic is LRU Cache: get and put must both be O(1). The trick is pairing a hash map (instant lookup) with a doubly linked list (instant reorder and eviction).

00  The idea

A design problem gives you methods and constraints (“O(1) get/put”, “support undo”, “median in a stream”) and you invent the supporting data structure. Almost always the answer is two structures working together — one for fast lookup, one for order or ranking.

A coat check with a queue line analogy

The hash map is the coat-check ticket → hanger lookup. The doubly linked list is the line of coats ordered by “most recently used.” Touch a coat and it jumps to the front of the line; when the rack is full, the coat at the back gets tossed.

API + complexity
You're handed method signatures and Big-O budgets, not a single input → output function.
Two structures
Map for O(1) find; list / heap / set for order or extremes.
Invariants
Every operation must leave the structure consistent — say the invariant out loud before coding.

01  LRU Cache

HashMap + DLL Medium ~35 min O(1) get/put · O(capacity) space
Say it out loud

“Hash map from key → node, plus a doubly linked list ordered MRU → LRU. get/put move the node to the head; on overflow, evict the tail.”

Design a cache with capacity capacity that supports get(key) and put(key, value) in O(1). When full, evict the least recently used key before inserting a new one. Both reads and writes count as “use.”

How to solve it

  1. Sentinel head / tail nodes bookend a doubly linked list (MRU next to head).
  2. map[key] = node for O(1) lookup.
  3. get: if missing return −1; else move node to head and return value.
  4. put: if key exists, update value and move to head; else insert at head; if over capacity, remove tail.prev from list and map.
MeasureCostWhy
get / putO(1)Hash lookup + a constant number of pointer rewires.
SpaceO(capacity)One node and one map entry per cached key.
Update must also count as use

A put on an existing key refreshes recency — move it to the head, don't leave it where it was. Forgetting that fails the classic LeetCode trace.

Why isn't a plain Python dict (insertion-ordered) enough to teach in an interview?

Right. OrderedDict / dict can implement LRU in Python, but the point of the question is naming and wiring the two structures yourself.
Stuck? Reveal a hint hint

Write helpers _remove(node) and _add_to_head(node). Sentinels mean you never special-case empty edges. Evict tail.prev.

Line-by-line walkthrough + flow walkthrough

Hash map for O(1) lookup + doubly linked list for O(1) recency order — MRU at head, evict tail.prev. Sentinels kill empty-edge cases; get and put both splice to head.

flowchart TD
  start[get / put] --> miss{"Key in map?"}
  miss -->|get miss| neg[Return -1]
  miss -->|get hit| move[Remove node; add_to_head; return val]
  miss -->|put existing| update[Update val; move to head]
  miss -->|put new| insert[Map + add_to_head]
  insert --> over{"over capacity?"}
  over -->|yes| evict["Remove tail.prev; del map"]
  over -->|no| done[Done]
  move --> done
  update --> done
  evict --> done
  neg --> done
  1. class Node:DLL node holding key, val, prev, next.
  2. self.head, self.tail = Node(), Node()Sentinel ends — real nodes live between them.
  3. self.head.next, self.tail.prev = self.tail, self.headEmpty list: head ↔ tail.
  4. def _remove(self, node):Unlink node from its neighbors.
  5. def _add_to_head(self, node):Insert node just after head (most recently used).
  6. def get(self, key):Lookup; miss → -1, hit → move to head and return val.
  7. self._remove(node); self._add_to_head(node)Refresh recency on read.
  8. def put(self, key, value):Insert or update; evict LRU if over capacity.
  9. if key in self.map:Existing key — update value and move to head.
  10. self.map[key] = node; self._add_to_head(node)New key — register and place at MRU.
  11. if len(self.map) > self.cap:Overflow — need an eviction.
  12. lru = self.tail.prevLeast recently used sits just before the tail sentinel.
  13. self._remove(lru); del self.map[lru.key]Drop from list and map together.

Time O(1) per get/put; space O(capacity) for the map and list nodes.
