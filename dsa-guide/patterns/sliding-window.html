Patterns · sliding window

Sliding Window

When a problem asks for the best, longest, or shortest contiguous run inside a list or string, you don't have to re-check every possible window from scratch. Instead you slide a window along the data — add the new item on the right, drop the old one on the left — and reuse everything in between. That turns a slow "try every window" into a fast single pass.

00  The idea

A sliding window is just two markers — a left edge and a right edge — that frame a stretch of the data. You grow the window by moving right forward, and you shrink it by moving left forward. The trick is that when the window moves, you only update for the one item that entered and the one that left — you never re-scan the middle. That's why the whole sweep is one pass.

A window on a moving train analogy

You're on a train, looking out a window. As the train rolls forward, new scenery enters on the right edge of the window and old scenery slips away on the left. You never re-look at the trees in the middle — they're already framed. Sliding the window forward shows you the next view almost for free.

When to reach for a sliding window

It's the right tool when you spot these tells:

Contiguous run
You want a subarray or substring — items next to each other, not scattered picks.
Best / longest / shortest
You're maximising or minimising over all such runs (longest unique stretch, smallest sum ≥ k, max average…).
"Recompute each window" feels slow
Brute force re-adds every window from scratch — O(n²) or worse — and you sense neighbouring windows share almost everything.
Cheap to update at the edges
Adding the new item and removing the old one is O(1) (a running sum, a count, a set).
Fixed vs. variable windows

Some windows are a fixed width (always 3 items). Others grow and shrink on the fly — expand right until a rule breaks, then pull left in until it holds again. The problems below are the growing-and-shrinking kind, which is the more common interview flavour — especially Minimum Window Substring.

A close cousin of two pointers

A sliding window is two pointers (left and right) moving the same direction, with a running "summary" of what's between them. If you've read Two Pointers, this is the next step in the same family.

01  Best Time to Buy and Sell Stock

One-pass greedy Interview note Easy ~10 min O(n) time · O(1) space
Say it out loud

Interviewers usually call this one-pass greedy (track min buy so far + best profit), not classic sliding window. We keep it on this page because the running window of “days so far” is a useful visual — but in a loop, name the pattern greedy / running min.

You're given the daily price of a stock. You may buy once and then sell once on a later day. Return the biggest profit you can make — or 0 if no profitable trade exists. For [7, 1, 5, 3, 6, 4] the best is 5 (buy at 1, sell at 6).

Remember the cheapest day behind you analogy

Walk forward through the days, one at a time. As you go, remember the lowest price you've seen so far — that's the best day you could have bought. At every new day ask one question: "If I sold today, having bought on that cheapest earlier day, how much would I make?" Keep the best answer. Your window stretches from the cheapest day so far up to today.

How to solve it

Keep two simple values as you scan left to right:

  1. min_price — the cheapest price seen so far (the best day to have bought).
  2. best — the biggest profit found so far.

At each day's price p: first update min_price = min(min_price, p), then ask "what if I sold today?" with best = max(best, p - min_price). One pass, two numbers, done. The brute force — try every buy-day paired with every later sell-day — is O(n²); remembering the cheapest-so-far collapses it to O(n).

MeasureCostWhy
TimeO(n)One left-to-right pass; each day does a tiny constant amount of work.
SpaceO(1)Just two numbers — the cheapest price and the best profit.

New to this notation? See the Big-O cheat-sheet.

Easy trap: selling before you buy

You must buy first and sell later. Because we update min_price from the days we've already passed, today's sell price is always compared against an earlier buy. If prices only fall, no trade beats 0 — that's why best starts at 0.

Why is it safe to compare today's price only against the single cheapest price so far, instead of every earlier day?

Right. Selling on a fixed day, the most profit comes from the lowest possible buy price before it. So the single cheapest-so-far is all you need to remember — that's what turns O(n²) into O(n).
Stuck? Reveal a hint hint

Don't pair every buy-day with every sell-day. Make one pass. Keep min_price (start it at infinity) and best (start it at 0). For each price, update the cheapest, then check the profit if you sold right now.

Line-by-line walkthrough + flow walkthrough

One pass tracking the cheapest buy so far is the interview default: O(n) time, O(1) space. Checking every buy/sell pair is O(n²). You only need one transaction, so "min behind me, sell today" is enough — no DP table required.

flowchart TD
  start["min_price = inf, best = 0"] --> loop[For each price p]
  loop --> updMin[min_price = min of min_price and p]
  updMin --> updBest[best = max of best and p - min_price]
  updBest --> more{More prices?}
  more -->|yes| loop
  more -->|no| out[Return best]
  out --> done[Done]
  1. def max_profit(prices):Define a function that returns the max profit from one buy and one later sell.
  2. min_price = float("inf")Cheapest price seen so far — start at infinity so the first real price wins.
  3. best = 0Best profit so far; stays 0 if prices only fall.
  4. for p in prices:Treat each day as a potential sell day.
  5. min_price = min(min_price, p)Update the cheapest buy day on or before today.
  6. best = max(best, p - min_price)Profit if we bought at min_price and sold today; keep the max.
  7. return bestHand back the best profit (or 0).

Time O(n) for one pass; space O(1) for two scalars.

02  Longest Substring Without Repeating Characters

Sliding Window Medium ~20 min O(n) time · O(min(n, alphabet)) space

Given a string, find the length of the longest run of characters with no repeats. For "abcabcbb" the answer is 3 (the stretch "abc"). For "bbbbb" it's 1.

A window of all-different letters analogy

Hold a window over a stretch of letters where every letter is different. Keep stretching the right edge to swallow the next letter. The moment a duplicate tries to enter — a letter already inside the window — pull the left edge in, dropping letters one by one, until that old copy of the duplicate has slid out. Now the window is all-different again, and you keep going.

How to solve it

Use a window [left, right] and a small map seen that remembers the last index where each character appeared. Walk right across the string:

  1. If the current character was seen inside the current window (its last index is >= left), jump left to just past that old copy — the duplicate has now slid out.
  2. Record this character's position: seen[ch] = right.
  3. The window is now repeat-free, so its length is right - left + 1. Update best with the larger value.

Each character is added once (by right) and the left edge only ever moves forward, so the total work is one pass.

MeasureCostWhy
TimeO(n)Both edges only move forward, so each character is handled a constant number of times.
SpaceO(min(n, alphabet))The seen map holds at most one entry per distinct character.
Off-by-one trap: stale duplicates

A character can sit in seen from before the window. That's why we check seen[ch] >= left, not just "is it in the map". Without that guard, left could jump backwards past a letter that already left the window, breaking the count.

When a repeated character appears, why do we move left to seen[ch] + 1 instead of just left + 1?

Exactly. Nudging left by one at a time would still contain the duplicate. Jumping straight to seen[ch] + 1 drops every letter up to and including the old copy in a single step, keeping the whole thing one pass.
Stuck? Reveal a hint hint

Keep a dictionary mapping each character to the last index you saw it. As right moves, if the character is already in the window (seen[ch] >= left), set left = seen[ch] + 1. Then update seen[ch] and track best = max(best, right - left + 1).

Line-by-line walkthrough + flow walkthrough

Sliding window + last-seen index map is the interview default: O(n) time. Nested loops checking every substring are O(n²). Jumping left to seen[ch] + 1 (only when that index is still inside the window) is what keeps it one pass.

flowchart TD
  start[seen empty, left = 0, best = 0] --> loop[For each right and ch]
  loop --> dup{"ch seen and seen ch >= left?"}
  dup -->|yes| jump["left = seen ch + 1"]
  dup -->|no| store
  jump --> store["seen ch = right"]
  store --> best[Update best with window length]
  best --> more{More chars?}
  more -->|yes| loop
  more -->|no| out[Return best]
  out --> done[Done]
  1. def length_of_longest_substring(s):Define a function that returns the length of the longest substring with all unique characters.
  2. seen = {}Map each character to the last index where we saw it.
  3. left = 0Left edge of the current repeat-free window.
  4. best = 0Longest valid window length so far.
  5. for right, ch in enumerate(s):Grow the right edge one character at a time.
  6. if ch in seen and seen[ch] >= left:Duplicate is still inside the window (not a stale index from before left).
  7. left = seen[ch] + 1Jump left just past the old copy so the window is unique again.
  8. seen[ch] = rightRecord this character's newest position.
  9. best = max(best, right - left + 1)Window [left, right] is valid — update the max length.
  10. return bestHand back the longest length found.

Time O(n) — both edges only move forward; space O(min(n, alphabet)) for the last-seen map.

03  Minimum Window Substring

Sliding Window Hard ~30 min O(n) time · O(alphabet) space
Say it out loud

This is the true sliding-window classic: grow right until the window is valid, then shrink left while it stays valid, remembering the shortest. In a loop, say “need / have counts + formed counter,” not just “two pointers.”

Given strings s and t, return the smallest substring of s that covers every character in t (with multiplicity). For s = "ADOBECODEBANC", t = "ABC" the answer is "BANC". If nothing covers t, return "".

A shopping list and a aisle window analogy

You have a shopping list t. Walk the aisle s with a window: stretch right until every list item is inside, then pull left as far as you can without losing an item — that's the tightest stretch that still covers the list. Remember the shortest such stretch, then keep walking.

How to solve it

Keep two maps: need (counts from t) and have (counts inside the window), plus a formed counter of how many distinct required chars are satisfied:

  1. Move right one step; update have. If that char hits its need, bump formed.
  2. While formed == number of required chars, the window is valid — record if it's the shortest, then drop s[left] and move left forward (decrementing formed if a need breaks).
  3. Repeat until right finishes. Return the best substring (or "").

Each index enters and leaves the window at most once → one pass.

MeasureCostWhy
TimeO(|s| + |t|)Both edges only move forward; building need is O(|t|).
SpaceO(alphabet)The two count maps hold at most the distinct characters involved.
Multiplicity matters

If t has two As, one A in the window is not enough. Compare counts carefully, and only bump formed when have[ch] == need[ch] — not on every extra copy.

After the window becomes valid, why shrink from the left instead of restarting a new window?

Exactly. Once [L, R] covers t, the shortest cover that still ends at R is found by pulling L in. Restarting would re-scan work you already paid for.
Stuck? Reveal a hint hint

Build need with Counter(t). Track have, formed, and best = (inf, 0, 0). Expand right; while formed, update best and shrink left. Return s[best[1]:best[2]+1] if finite.

Line-by-line walkthrough + flow walkthrough

Need/have counters with a missing (or formed) tally is the interview default for minimum window: O(|s|+|t|). Restarting a fresh scan at every index is O(n·m). Grow right until valid, then shrink left while valid — that's the variable-window template.

flowchart TD
  start[Build need Counter, missing = distinct needs] --> grow[Expand right, update have]
  grow --> hit{"have ch just met need ch?"}
  hit -->|yes| dec[missing -= 1]
  hit -->|no| valid
  dec --> valid{missing == 0?}
  valid -->|no| moreR{More of s?}
  valid -->|yes| record[Maybe update best window]
  record --> shrink[Drop s left, maybe missing += 1, left += 1]
  shrink --> valid
  moreR -->|yes| grow
  moreR -->|no| out[Return best substring or empty]
  out --> done[Done]
  1. def min_window(s, t):Define a function that returns the shortest substring of s covering all of t (needs from collections import Counter).
  2. if not t or not s:Empty input — nothing to cover or search.
  3. return ""Early exit with an empty string.
  4. need = Counter(t)Required counts for each character in t.
  5. missing = len(need)How many distinct required characters are still under-satisfied.
  6. have = Counter()Counts of characters currently inside the window.
  7. best_len, best_l, best_r = float("inf"), 0, 0Track the shortest valid window's length and endpoints.
  8. left = 0Left edge of the sliding window.
  9. for right, ch in enumerate(s):Grow the right edge one character at a time.
  10. have[ch] += 1Add this character into the window counts.
  11. if ch in need and have[ch] == need[ch]:This required character just hit its exact need (not every extra copy).
  12. missing -= 1One fewer distinct requirement unsatisfied.
  13. while missing == 0:Window covers t — shrink from the left while it stays valid.
  14. if right - left + 1 < best_len:Is this the shortest cover so far?
  15. best_len, best_l, best_r = right - left + 1, left, rightRemember this window's length and bounds.
  16. left_ch = s[left]Character about to leave the window.
  17. have[left_ch] -= 1Remove it from the window counts.
  18. if left_ch in need and have[left_ch] < need[left_ch]:We just broke a requirement.
  19. missing += 1Window is no longer valid — stop shrinking after this step.
  20. left += 1Advance the left edge.
  21. return "" if best_len == float("inf") else s[best_l:best_r + 1]No cover found → empty; else slice the best window.

Time O(|s| + |t|) — each index enters and leaves the window at most once; space O(alphabet) for the two counters.
