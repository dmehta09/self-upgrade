Patterns · stack

Stack

A stack is a pile where you only ever add to the top and remove from the top — last in, first out. That one rule makes it perfect for two jobs: matching things that nest (brackets, tags) and answering "what's the next bigger thing?" with a clever variant called the monotonic stack — a tool worth knowing by name. Let's see it move, then solve three classics with it, ending on the famous Largest Rectangle in Histogram.

00  The idea

A stack has just two moves: push (drop an item on top) and pop (take the top item off). You can only touch the top — never the middle or bottom. Because the most recent thing you added is the first thing you take back, a stack naturally remembers "what's still open" or "what's still waiting", in the right order, for free.

A stack of plates analogy

Think of a stack of plates by the sink. You add a clean plate to the top, and when you need one you take it from the top too. You'd never yank a plate from the middle. So the last plate you put down is the first one you pick up — exactly how a stack behaves.

When to reach for a stack

It's the right tool when you spot these tells:

Things nest or pair up
Brackets, HTML tags, function calls — each "open" must be closed by the most recent matching "open".
"Most recent" matters
You repeatedly need the last item you saw, then the one before it (undo history, back button).
Next greater / smaller
For each item you want the next element that's bigger (or smaller) — that's the monotonic stack trick.
Reverse-ish order
You need to process things in the opposite order to how they arrived.
In Python, a list is a stack

You don't need a special type. A plain list does it: stack.append(x) is push, stack.pop() takes the top, and stack[-1] peeks at it. Both push and pop are O(1).

The monotonic stack

A monotonic stack keeps its items sorted in one direction (always increasing, or always decreasing). When a new item would break that order, you pop the items it "beats" — and each pop usually answers a question, like "this is the next warmer day for those." You'll see it in Daily Temperatures below.

01  Valid Parentheses

Stack Easy ~10 min O(n) time · O(n) space

Given a string of only the brackets (), [] and {}, decide whether every bracket is correctly opened and closed in the right order. "()[]{}" is valid; "(]" is not; "([])" is valid.

A pile of opened brackets analogy

Every time you open a bracket, drop it onto a pile. When you meet a closing bracket, look at the top of the pile: it must be the matching opener. If it is, pop it off — that pair is done. If it isn't (or the pile is empty), something is mismatched. After reading everything, the pile must be empty — no opener left dangling.

How to solve it

Keep a stack (a list) and a small map from each closer to its matching opener: {")": "(", "]": "[", "}": "{"}. Read the string one character at a time:

  1. If it's an opener, push it.
  2. If it's a closer, the top of the stack must be its matching opener. Pop and check: if the stack is empty or the popped opener doesn't match, return False right away.

At the very end, the answer is "is the stack empty?" An empty stack means every opener found its closer in the right nesting order.

MeasureCostWhy
TimeO(n)Each character is pushed and popped at most once — one pass.
SpaceO(n)In the worst case (all openers) the stack holds every character.

New to this notation? See the Big-O cheat-sheet.

Two traps: empty stack and the leftover check

A closer with an empty stack means there's nothing to match — that's invalid, so check before you pop. And don't forget the end: "(((" never errors mid-way, but the stack is non-empty, so it must return False.

Why does the order matter — why is "([)]" invalid even though the counts of each bracket match?

Right. In "([)]" the ) arrives while [ is on top — they don't match, so it fails. The stack guarantees the innermost (most recent) opener is closed first, which is exactly what "correctly nested" means.
Stuck? Reveal a hint hint

Use a list as a stack. Map each closing bracket to its opener. Push openers; on a closer, check the top matches before popping. Return whether the stack is empty at the end.

Line-by-line walkthrough + flow walkthrough

A stack of openers plus a closer→opener map is the interview default: O(n) time, O(n) space. Counting alone fails on interleaved types like "([)]". Recursion/parsing trees are overkill — LIFO nesting is exactly what a stack models.

  1. def is_valid(s):Define a function that returns whether the brackets in s are correctly matched and nested.
  2. pairs = {")": "(", "]": "[", "}": "{"}Map each closer to the opener it must match.
  3. stack = []Pile of openers still waiting to be closed.
  4. for ch in s:Scan left to right.
  5. if ch in pairs:This character is a closing bracket.
  6. if not stack or stack.pop() != pairs[ch]:Empty pile or top opener doesn't match this closer — invalid.

02  Daily Temperatures

Monotonic Stack Medium ~20 min O(n) time · O(n) space

Given a list of daily temperatures, for each day report how many days you must wait until a warmer day — or 0 if no warmer day ever comes. For [73, 74, 75, 71, 69, 72, 76, 73] the answer is [1, 1, 4, 2, 1, 1, 0, 0].

A queue of people waiting for a warmer day analogy

Keep a pile of days that are still "waiting" for a warmer day, coldest waiters near the top. Each new day, look at the top of the pile: if today is warmer than that waiting day, today is the warmer day it was waiting for — pop it and write down how many days it waited. Keep popping while today beats the top. Then today joins the pile to wait for its own warmer day.

How to solve it

The brute force checks every later day for each day — O(n²). A monotonic stack (kept decreasing in temperature) does it in one pass. The stack holds the indices of days still waiting for a warmer day; their temperatures go from warm at the bottom to cold at the top.

  1. Start an answer list of all zeros and an empty stack.
  2. Walk each day i. While the stack isn't empty and today's temperature beats the day on top, that top day just found its warmer day: pop its index j and set res[j] = i - j (the wait).
  3. Push today's index i onto the stack and continue.

Any days still on the stack at the end never warmed up — their answer stays 0.

MeasureCostWhy
TimeO(n)Each day is pushed once and popped at most once — total work is linear, not n².
SpaceO(n)The stack can hold every day (e.g. temperatures only fall).
Store indices, not temperatures

We push the day's index, not its temperature. We still read the temperature with temps[stack[-1]], but keeping the index is what lets us compute the gap i - j — the number of days waited.

Even though there's a while loop inside the for loop, why is the total time O(n) and not O(n²)?

Exactly. A nested loop only means O(n²) if it can repeat work. Here every index enters the stack once and leaves once, so the inner pops add up to at most n across the entire scan — linear overall.
Stuck? Reveal a hint hint

Keep a stack of indices whose temperatures are still waiting (decreasing down the stack). For each new day, while it's warmer than temps[stack[-1]], pop that index j and set res[j] = i - j. Then push the current index.

Line-by-line walkthrough + flow walkthrough

A decreasing monotonic stack of indices is the interview default: amortized O(n). Nested "look ahead for warmer" loops are O(n²). Store indices (not temps) so the wait is just i - j at pop time.

03  Name the tool: the monotonic stack

Daily Temperatures wasn't a one-off trick — it's an instance of a named, reusable template that interviewers expect seniors to know by name: a stack you keep sorted by popping anyone who'd break the order. Saying "this is a monotonic stack problem" out loud in an interview is like a doctor naming the diagnosis: the moment it's named, the treatment is standard.

Here is the whole template — the next-greater-element skeleton. Nearly every monotonic stack problem is this loop with two blanks filled in:

monotonic_stack_template.py
stack = []                                  # indices, kept sorted by value
for i, x in enumerate(items):
    while stack and items[stack[-1]] < x:   # knob 1: the comparison
        j = stack.pop()
        # knob 2: ANSWER FOR j IS i (or x) — record it here
    stack.append(i)

The two knobs are everything. Knob 1 is the comparison direction: < keeps the stack decreasing, so each pop says "I just found j's next greater element"; flip it to > and the stack stays increasing, answering next smaller instead. Knob 2 is what you record at pop time: the distance i - j (Daily Temperatures' wait), the value x itself (classic next-greater-element), or a width between the popped index and the new stack top (the histogram problem below).

And the cost argument fits in one line: each index is pushed once and popped at most once, so the whole run is amortized O(n) — despite the nested-looking while inside the for. If that still feels like sorcery, it's exactly the trap question from the Big-O speed quiz: count total work, not loop nesting.

Where you'll sight it in the wild

Next greater / smaller element
The vanilla form — for each item, the first later (or earlier) item that beats it.
Spans
Stock Span and friends: "how many consecutive previous days were lower?" — record a width at pop time.
"How far can this extend?"
Any question where each element stretches until something stops it — the stack finds each element's stopper.
Histogram rectangles
Largest Rectangle in Histogram (next section) — each bar extends until a shorter bar walls it in on each side.
Sliding-window max
A close cousin using a deque (pop from both ends), but the same "evict everyone I beat" idea.

04  Largest Rectangle in Histogram

Stack Hard ~30 min O(n) time · O(n) space

Given bar heights (every bar has width 1), find the area of the largest rectangle that fits entirely inside the histogram. For [2, 1, 5, 6, 2, 3] the answer is 10. Let's be honest up front: this is a famous Hard — but it's the direct payoff of the monotonic template above, and a senior-loop favorite for exactly that reason.

Every bar dreams of being the shortest analogy

Every bar dreams of being the shortest bar of some rectangle: its own height, times how far it can stretch left and right before hitting a bar shorter than itself. Those two shorter bars are its "walls". Find each bar's two walls, compute each bar's dream rectangle, and the answer is the best dream in the room.

How to solve it

Use a monotonic increasing stack of indices. As long as bars keep getting taller, push. The moment a bar arrives that's shorter than the top, the top bar has met its right wall — pop it and compute its dream rectangle right there:

  1. Pop index top; its rectangle's height is heights[top].
  2. Its right wall is the current bar i; its left wall is whatever is now on top of the stack. So width = i - stack[-1] - 1 — or i if the stack just emptied, because then nothing to the left was shorter and the bar stretches all the way to the edge. Spell this case out — it is the off-by-one of this problem.
  3. Keep popping while the new bar is shorter, then push i.
  4. Append a sentinel bar of height 0 at the end so every bar still waiting is forced to finalize.
MeasureCostWhy
TimeO(n)The template's argument: each bar is pushed once and popped at most once.
SpaceO(n)A strictly increasing histogram keeps every bar on the stack until the sentinel.
The emptied-stack width

After popping, if the stack is empty, the popped bar was the smallest seen so far — no bar to its left was shorter, so it stretches all the way to the left edge: width = i. (You can think of it as i - (-1) - 1, as if a virtual wall sat at index −1 — same number, but write the empty case explicitly so you don't fumble it live.) Otherwise width is i - stack[-1] - 1: the gap strictly between the new top and i.

Why append a sentinel bar of height 0 at the end of the histogram?

Exactly. Pops only happen when a shorter bar arrives. An increasing run at the end — like the final 2, 3 in our example — would otherwise finish the scan still waiting, never measured. A height of 0 is shorter than everything, so it flushes the whole stack through the same pop-and-measure code path. No special end-of-loop logic needed.

For each bar you need two things: the first shorter bar to its left, and the first shorter bar to its right. Which structure from this lesson finds both in one pass? (When a bar gets popped, the popper is its right wall — and whatever remains below it on the stack is its left wall.)

Line-by-line walkthrough + flow walkthrough

Increasing monotonic stack + sentinel 0 is the interview default: O(n). Checking every left/right span per bar is O(n²). Popping when a shorter bar arrives finalizes that bar's max rectangle using the new top as the left wall.

flowchart TD
  start[best = 0, empty stack] --> scan["For each i,h in heights + 0"]
  scan --> while{"Stack and heights top > h?"}
  while -->|yes| pop[Pop top, compute height times width]
  pop --> upd[best = max best and area]
  upd --> while
  while -->|no| push[Push i]
  push --> more{More bars?}
  more -->|yes| scan
  more -->|no| out[Return best]
  out --> done[Done]
  1. def largest_rectangle(heights):Define a function that returns the largest rectangle area inside the histogram.
  2. best = 0Largest area found so far.
  3. stack = []Indices of bars in increasing height order (bottom to top).
  4. for i, h in enumerate(heights + [0]):Scan bars, then a sentinel height 0 that forces every remaining bar to finalize.
  5. while stack and heights[stack[-1]] > h:New bar is shorter — the top bar has met its right wall.
  6. top = stack.pop()Index of the bar whose dream rectangle we can now measure.
  7. height = heights[top]That bar is the shortest in its rectangle — use its height.
  8. width = i if not stack else i - stack[-1] - 1Empty stack → stretch to the left edge (width = i); else width is the gap between the new top and i.
  9. best = max(best, height * width)Update the champion area.
  10. stack.append(i)Push the current index (sentinel 0 may stay on the stack harmlessly).
  11. return bestHand back the largest area.

Time O(n) — each bar pushed/popped at most once; space O(n) for the stack.
