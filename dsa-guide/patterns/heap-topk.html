Heap / Top-K

When a problem asks for the K biggest or smallest things, or keeps asking you to grab the current min or max, sorting the whole list is overkill. A heap gives you the smallest (or largest) item instantly and stays cheap to update. Let's see what a heap looks like, then use it on two classic Top-K problems.

00  The idea

A heap is a special tree kept in a simple rule: every parent is no bigger than its children (a min-heap) — or no smaller, for a max-heap. That one rule means the smallest item is always sitting right at the top, free to read. Adding or removing an item only nudges one value up or down a single path, so it costs O(log n) — far cheaper than re-sorting everything.

Why bother instead of just calling sort()? Sorting all n items is O(n log n) and gives you everything in order. But if you only need the K extremes, a heap lets you stream through the data keeping just K items — O(n log k), which is much smaller when K is tiny.

A bucket where the lightest floats up analogy

Think of a min-heap as a bucket of items where the lightest one always bubbles to the top. You can grab the lightest in an instant without rummaging. Drop a new item in and it sinks until it finds its level; scoop the top one out and the next-lightest rises to take its place. You never have to sort the whole bucket — you just keep the lightest in reach.

When to reach for a heap

These tells say "heap" louder than "sort":

"Top K" / "K-th"
You need the K largest or smallest — not the full ordering — so keep a heap of size K.
Repeated min/max
You'll grab the smallest (or largest) over and over as data changes — exactly what a heap is built for.
Streaming data
Items arrive one at a time and you can't sort what you haven't seen yet; a heap updates in O(log n) each.
Merging sorted lists
Always pull the next-smallest head across many lists — a heap of heads handles it neatly.
Python only ships a min-heap

The heapq module gives you a min-heap — heappush, heappop, and the smallest item always at heap[0]. Need a max-heap? Push the negatives (-x) and flip the sign back when you pop. We lean on the min-heap directly in the first problem below.

01  Kth Largest Element in an Array

Heap / Top-K Medium ~15 min O(n log k) time · O(k) space

Given a list of numbers and a number k, return the k-th largest value (by rank, not the k-th distinct value). For [3, 2, 1, 5, 6, 4] with k = 2, the 2nd largest is 5.

A shelf that holds only the K biggest analogy

Keep a small shelf — a min-heap — that fits exactly K items: the K biggest you've seen so far. Each new number goes on the shelf. If the shelf now holds K+1, throw out its smallest (which is right on top of the min-heap). Once you've seen everything, the smallest thing still on the shelf is the K-th largest overall — it's the runt of the top K.

How to solve it

Lean on Python's heapq min-heap and keep it capped at size K:

  1. Start with an empty heap.
  2. For each number, heappush it onto the heap.
  3. If the heap now has more than k items, heappop once — that removes the smallest, keeping only the K biggest.
  4. At the end, heap[0] (the smallest of those K) is the k-th largest.

Each push/pop is O(log k) because the heap never grows past K, and we do that n times. Connecting back to the picture: the shelf only ever holds the top K, and its smallest is the K-th largest.

MeasureCostWhy
TimeO(n log k)n items, each a push/pop on a heap capped at size k.
SpaceO(k)The heap holds at most k items, regardless of how big n is.

New to this notation? See the Big-O cheat-sheet.

Min-heap for the largest? Yes.

It feels backwards, but to track the K largest you want a min-heap: its top is the weakest survivor, the easiest one to evict when a bigger number shows up. The min-heap is the bouncer guarding the door to the top K.

Why keep the heap capped at size k instead of pushing every number?

Right. Numbers that fall out of the top K can never be the k-th largest, so there's no reason to store them. Dropping them keeps the heap small — cheaper time per step and tiny memory.
Stuck? Reveal a hint hint

Use import heapq. Push each number; right after, if len(heap) > k: heapq.heappop(heap). The answer is heap[0] — the smallest of the K survivors.

A size-k min-heap is the interview default when you only need the k-th largest: O(n log k) time and O(k) space. Full sort is O(n log n); Quickselect is average O(n) but harder to get right under pressure.

02  Top K Frequent Elements

Heap / Top-K Medium ~20 min O(n log n) time · O(n) space

Given a list of numbers, return the k values that appear most often. For [1, 1, 1, 2, 2, 3] with k = 2, the two most frequent are [1, 2].

Tally the votes, then pick the winners analogy

First hold an election: walk the list once and keep a tally of how many votes (appearances) each number got. Now you just want the K candidates with the biggest tallies. Sort the candidates by votes and read off the top K — the same "grab the largest few" idea, but ranking by count instead of by the number itself.

How to solve it

Two clean steps, both leaning on the standard library:

  1. Count: a collections.Counter tallies every value in one O(n) pass.
  2. Select the top K: Counter.most_common(k) hands back the k highest-count (value, count) pairs, already sorted. Keep just the values.

Under the hood most_common uses a heap when k is given, so it doesn't fully sort when it doesn't have to. Connecting back to the picture: count the votes, then read off the top K winners.

MeasureCostWhy
TimeO(n log n)Counting is O(n); ranking the distinct values dominates in the general case.
SpaceO(n)The counter stores one entry per distinct value.
You can hit O(n) with bucket sort

Counts range only from 1 to n, so you can drop each value into a bucket indexed by its count, then read buckets from the highest down. That skips ranking entirely and runs in O(n) — handy when interviewers ask you to beat the sort.

What is the role of the Counter here?

Exactly. Counter turns the raw list into a value-to-count map in one pass. Once we know each value's count, "top K frequent" becomes "the K biggest counts" — a Top-K selection.
Stuck? Reveal a hint hint

Use from collections import Counter. Build counts = Counter(nums), then call counts.most_common(k) and keep only the value from each (value, count) pair.

Line-by-line walkthrough + flow walkthrough

Count first, then take the k highest frequencies. Counter.most_common(k) is the clear Python default; a size-k heap is O(n log k) and bucket sort is O(n) — mention those if they ask for a tighter bound than sorting the unique keys.
