Cheat-sheet & glossary

This is the page you skim the night before an interview. No new lessons — just the numbers and names you want at your fingertips: a quick self-test, how fast each Big-O grows, what every data-structure operation costs (tries and union-find included), the five bit tricks, a one-line "which pattern when" lookup across all 16 patterns, the traps that catch everyone, and a plain-English glossary of every word in the guide.

02  How fast things grow

Big-O is a speed label. It tells you how the work grows as the input gets bigger — not the exact seconds, just the shape of the growth. The table below shows roughly how many steps each shape takes for a list of 10, 100, and 1000 items. Watch how the bottom rows explode while the top rows barely move.

Rule of thumb: O(1) and O(log n) are wonderful, O(n) and O(n log n) are fine, and O(n²) or worse is a smell you should try to beat. New here? Start with the Big-O foundations page.

03  Cost per operation, by data structure

Each container is good at some things and slow at others — like a toolbox where the hammer is great for nails and useless for screws. Pick the structure whose cheap operation matches what your problem does most. "Amortised" means it's occasionally slow but cheap on average.

Average vs worst case

A hash map is O(1) on average, but if every key collides it degrades to O(n). In interviews, say "O(1) average" out loud — it shows you know the difference.

06  Interview pitfalls

Most wrong answers don't come from a missing idea — they come from a small slip. These are the ones that catch nearly everyone, so check them before you say "done".

Off-by-one in binary search

Use a loop while lo <= hi, and always move past the middle: lo = mid + 1 or hi = mid - 1. If you set lo = mid, the range can stop shrinking and you loop forever.

Forgetting empty or single-element inputs

What if the list is [] or has one item? Many bugs hide there. Walk your code through length 0 and 1 before you call it finished.

Mutating a list while iterating it

Adding to or deleting from a list inside its own for loop skips items or crashes. Loop over a copy (for x in items[:]) or build a new list instead.

Recursion depth / stack overflow

Deep recursion hits Python's limit (about 1000 frames) and crashes. For very deep trees or long chains, switch to an explicit stack and a while loop.

Confusing average vs worst case for hashing

A dict lookup is O(1) on average, not always. Don't claim a guaranteed O(1) — the worst case is O(n) when keys collide.

07  Glossary

Every term in the guide, in one plain sentence each. When a word trips you up mid-problem, this is where you look.

Big-O
A label for how fast the work grows as the input grows — the shape of the cost, not the exact time.
amortized
The average cost per operation over many operations, even if one of them is occasionally slow.
in-place
Rearranging the data inside the original container, without building a separate copy (so O(1) extra space).
stable sort
A sort that keeps equal items in their original relative order.
pointer / index
Just a position number that says "I'm looking here" in a list or string.
hash map
A box that maps keys to values and finds them in roughly one step (Python's dict).
collision
When two different keys land in the same hash slot, so the map has to do extra work to tell them apart.
recursion
A function that solves a problem by calling itself on a smaller piece of the same problem.
base case
The smallest input a recursive function answers directly, so it stops calling itself.
DFS
Depth-first search — go as deep as you can down one path before backing up and trying another.
BFS
Breadth-first search — explore everything one step away, then two steps, in widening rings.
memoization
Caching the answer to each sub-problem the first time you compute it, so you never redo it (top-down).
tabulation
Filling a table of sub-answers from the smallest up to the one you want (bottom-up dynamic programming).
memoization vs tabulation
Top-down recursion + cache vs bottom-up table fill — two routes to the same DP answer. See the DP families.
greedy
Always taking the choice that looks best right now and never undoing it.
exchange argument
The proof move behind greedy: any optimal solution can be rewritten to start with the greedy choice without getting worse.
backtracking
Trying a choice, exploring further, and undoing it to try the next when it leads to a dead end.
heap / priority queue
A structure that always hands you the smallest (or largest) item next, in O(log n) per push/pop.
trie / prefix tree
A word-tree where words share prefix paths; lookups cost the word's length. See Tries.
BST
Binary search tree — every left child is smaller and every right child is larger than its parent.
in-order traversal
Visiting a BST left-then-node-then-right, which spits out the values in sorted order.
topological sort
Ordering tasks so every task comes after the ones it depends on (only works without cycles).
two pointers
Using two position markers that move through a list to solve it in one pass instead of nested loops.
sliding window
A pair of pointers marking a contiguous stretch that grows and shrinks as you scan.
monotonic stack
A stack kept sorted by popping anyone who'd break the order; finds "next greater/smaller" in amortized O(n). See the stack page.
binary search on the answer
When "does candidate k work?" is monotonic (NNN…YYY), binary-search the number itself. See binary search.
adjacency list
A way to store a graph where each node keeps a list of the neighbours it connects to.
path compression
During find(), re-point every visited node straight at the root so later finds are one hop. See Union-Find.
invariant
A statement that stays true at every step of a loop — your proof that the loop is correct.
dynamic programming
Solving a problem by combining the answers to overlapping smaller sub-problems, each solved once.
pseudo-polynomial
Running time polynomial in a value (like the target sum), not the input length. See the partition DP.
XOR
The difference detector: 1 where bits differ; pairs cancel. See Bit Manipulation.
