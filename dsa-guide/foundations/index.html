How to use this guide

Data structures and algorithms have a reputation for being scary. They don't have to be. This guide takes the small set of ideas that actually show up in interviews and explains each one with a picture first — a everyday story you already understand — before any code or jargon. Here's who it's for and how to get the most out of it.

01  Who this is for

You've shipped real software for a few years. You can build features, fix bugs, read a stack trace at 2am. But "invert a binary tree on a whiteboard" makes your stomach drop — and the usual advice ("just grind 500 problems") feels like a wall you'll never climb.

This guide is for exactly that person. It is visual and gentle, and it assumes you're smart but rusty on the theory. The plan is small on purpose:

~50+ problems
A curated, high-signal set — the ones that teach a reusable idea. Not five hundred.
A dozen patterns
Almost every interview question is one of about twelve recognisable shapes. Learn the shapes, not the questions.
Picture first
Each idea opens with a real-world analogy and a step-by-step animation, so you see it before you read a line of Python.

If you can give yourself a few focused evenings, that's enough. You're not memorising trivia — you're learning to recognise a handful of tools and reach for the right one.

02  The loop you run in an interview

Strong candidates aren't faster typists. They run the same small loop in their head for every problem. Almost everything in this guide is one step of this picture — keep it in mind as you read.

Steps 2 and 3 are the whole game. Spot the pattern, pick the structure, and the code almost writes itself.
Think of a toolbox analogy

Imagine a carpenter with a small toolbox. They don't own a different tool for every job — they own a saw, a hammer, a drill, and they know which one a job needs. A pattern is a tool, and there are only about a dozen. The skill isn't owning more tools; it's looking at a problem and thinking "that's a job for the two-pointers tool." Once you can do that, you've done the hard part.

03  How a problem page works

Every pattern and problem page is built the same way, so once you've read one you know how to read them all. Here are the parts you'll meet, top to bottom:

The analogy
A blue callout with a real-world story, always before any code. Read this first — it carries the whole idea.
The animation
A step-by-step picture of the algorithm running. Press ▶ Play, or step with ‹ Prev / Next ›; a speed control lets you slow it down, and the arrow keys work too.
Runnable Python
The full solution in an editor you can change. Hit Run to execute it right in your browser.
Hint & solution
Two fold-out panels. Peek at the one-line hint only if you're stuck; open the solution when you're ready.
Line-by-line + flow
A third fold-out: each line of the solution explained in plain English, plus a Mermaid flowchart of the algorithm.
A quiz
A quick self-check with one right answer and a short explanation, to make sure the idea stuck.
Mark as learned
A button at the bottom of each page. Tick it and the page shows up on the dashboard on the home page.

About the runnable Python

The first time you press Run, the page quietly downloads a small Python engine — so that one time needs an internet connection. After that it works offline. If there's no connection, you'll simply see the saved, correct output instead. And if you've turned on "reduce motion" in your system settings, the animations won't autoplay; just step through them with the arrows.

04  A suggested order

Start anywhere you like — but if you want a path that builds gently and never overwhelms you, follow these four steps.

1

Build the foundations

Get comfortable with Big-O and the core data structures. This is the vocabulary every later page uses.

→ Foundations · these 5 short lessons
2

Read the pattern map

See all dozen patterns on one page and the tell that points to each. This is your mental index.

→ Patterns · the pattern map
3

Take patterns one at a time

Watch the animation, then for each problem try it yourself, peek at the hint if stuck, then reveal and run the solution.

→ try · hint · solution
4

Self-test & review

Take the quizzes, mark lessons learned, and keep the cheat-sheet open the night before the interview.

→ Quizzes · Cheat-sheet
