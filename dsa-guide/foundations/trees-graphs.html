Trees, heaps & graphs

Lists are flat, but a lot of the world branches. A tree is a family tree — one root, branching into children. A heap is a special tree that always keeps its smallest (or largest) item on top. And a graph is the most general shape of all: dots joined by lines, like a map of friendships or cities. These three power searching, scheduling, and pathfinding.

01  Trees

A tree grows from a single top node called the root. Each node points to children below it; a node with no children is a leaf. The height is how many levels deep it goes. A binary tree is the common kind where every node has at most two children.

A family tree / org chart analogy

Picture a family tree: one ancestor at the top (the root), branching down into children, then grandchildren. The people at the very bottom with no descendants are the leaves. An org chart is the same shape — one CEO up top, teams branching below. Trees are how we organise anything with a clear "parent → child" hierarchy.

Two ways to walk a tree

Visiting every node is called a traversal, and there are two famous styles:

Depth-first (DFS)
Dive all the way down one branch before backing up to try the next. Like exploring a maze by always taking the first turn until you hit a dead end.
Breadth-first (BFS)
Visit everything one level at a time — all the root's children, then all the grandchildren. Like ripples spreading out from a stone.
BFS rides a queue

Breadth-first search uses a queue: add the root, then repeatedly take one from the front and add its children to the back. The fair "first-in, first-out" order is exactly what visits the tree level by level. We explore both traversals fully on the Trees pattern page.

02  Heaps

A min-heap is a special tree with one simple rule: every parent is smaller than or equal to its children. Follow that rule everywhere and the very smallest item is guaranteed to sit at the top — ready to grab instantly.

A tournament where the smallest rises analogy

Imagine a knockout tournament, but "winning" means being the smallest number. Every parent has beaten its children, so the overall champion — the tiniest value — ends up at the very top. You never have to search for it; it's always the node you can see first.

What it's good at

A heap doesn't keep everything fully sorted — that would be expensive. It does just enough work to keep the smallest on top, which is all you need for "give me the next-smallest, over and over".

Peek the smallest
Instant — O(1). It's always the root; in Python that's h[0].
Push a new value
O(log n). The newcomer bubbles up only as far as needed.
Pop the smallest
O(log n). Remove the top, then let the tree re-settle.
Python's heapq

Python has no separate heap type — it turns a plain list into a min-heap. heapq.heapify(h) arranges it in place, heapq.heappush(h, x) adds, and heapq.heappop(h) removes the smallest. After heapifying, h[0] is always the minimum. Heaps power "Top-K" problems on the Heap page.

03  Graphs

A graph is just dots (called nodes or vertices) joined by lines (called edges). Edges can be two-way, or one-way (directed) like a one-way street. It's the most general shape — a tree is simply a graph with no loops.

A map of friendships analogy

Think of a friendship map: each person is a dot, and a line joins two people who are friends. Some links go both ways (mutual friends); on social media, "follows" can go just one way (directed). Roads between cities, web links, flight routes — they're all graphs. A graph lets us ask "who's connected to whom, and how do I get from here to there?"

How we store a graph in code

The usual way is an adjacency list: a dict that maps each node to a list of its neighbours. Looking up "who is A connected to?" is then an instant dict lookup.

Adjacency list
{"A": ["B", "C"], ...} — each key is a node, each value is its list of neighbours.
Directed vs. undirected
One-way edges (A→B only) vs. two-way (A↔B, listed under both).
Trees are graphs too
A tree is a connected graph with no cycles (no way to loop back to where you started).
The trap: forgetting to mark nodes as visited

Unlike a tree, a graph can have cycles — paths that loop back. If you walk one without remembering where you've been, you'll go round forever. Always keep a visited set and skip nodes you've already seen. More on this on the Graphs pattern page.
