Arrays, strings & hashing

Before patterns, you need the boxes the patterns play with. An array is a row of equal boxes you can jump into instantly. A string is a row of letters that, in Python, never changes. And hashing — dicts and sets — is a magic coat-check that hands you any item the moment you ask. Master these three and most interview problems stop feeling scary.

01  Arrays

An array (Python calls it a list) is a row of equal-sized boxes sitting side by side in one block of memory. Each box has a number — its index — starting at 0.

A row of numbered lockers analogy

Picture a hallway of identical lockers, numbered 0, 1, 2, 3… To open locker 3 you walk straight to it — you don't peek inside 0, 1, and 2 first. That instant jump is what makes reading any box instant, no matter how long the hallway is.

What's fast and what's slow

The single magic power of an array is the instant jump. Everything else follows from that one fact:

Read / write by index
Instant — O(1). The computer multiplies the index by the box size and lands on the spot.
Append at the end
Usually instant — there's room just past the last box, so you drop the new value in.
Insert / remove in the middle
Slow — O(n). Every box after the gap must slide over to keep the row tidy.
Search an unsorted array
Slow — O(n). With no order to exploit, you may peek into every box.
The trap: insert at the front is the slowest insert

To put a new value at index 0, every existing box must shuffle one step to the right to make room. On a long list that's a lot of shuffling — O(n). Adding at the end doesn't shove anyone, so it stays cheap.

OperationCostWhy
Index nums[i]O(1)Jump straight to the box — no walking.
Insert / remove middleO(n)Everything after the gap shifts over.

New to this notation? See the Big-O cheat-sheet.

A Pythonic aside

A Python list can hold any mix of values and grows automatically. Under the hood it keeps a little spare room at the end, which is why append is fast on average. When the spare runs out it quietly moves to a bigger block — rare enough that we still call append "O(1) amortised".

02  Strings

A string is a row of characters — like an array of letters. The twist in Python: a string is immutable, meaning it can never be changed once made. Every "edit" secretly builds a brand-new string.

A word carved into stone analogy

A Python string is like a word carved into a stone tablet — you can read it all you like, but you can't rub out one letter and write another. To "change" it you carve a whole new tablet. So gluing letters on one at a time means re-carving the tablet over and over.

Why this matters for speed

Reading a string is just like an array: word[0] is the first letter, instantly. But building a big string by repeatedly adding pieces — result = result + piece in a loop — re-copies everything each time. That quietly turns into O(n²) work.

The shortcut: collect in a list, then join once

Gather your pieces in a list with append (cheap), then fuse them in one go with "".join(list). One carving instead of many — back down to O(n). This is the standard Python way to build a big string.

Handy string facts

Index a character
word[i] — instant O(1), same as an array.
Slice a piece
word[1:4] makes a new small string with those characters.
Lower-case / replace / strip
All return a new string; the original is untouched (it can't be).
Build a big one
Use "".join(parts), not += in a loop.
The trap: s[0] = "x" raises an error

Because strings are immutable, assigning into one is illegal — Python throws a TypeError. If you truly need to edit characters in place, turn the string into a list first (chars = list(s)), edit the list, then "".join(chars) at the end.

03  Hashing — dicts & sets

A hash table is the secret weapon behind Python's dict (key → value) and set (just keys). It lets you store and look things up in roughly constant time — O(1) on average — no matter how much it holds.

The coat-check / sticky-note analogy

At a coat-check you hand over your coat and get a numbered ticket. Later you give back the ticket and they fetch your coat instantly — they don't search every hook. A dict works the same way: you hand it a key (the ticket), and it jumps straight to the matching spot. A "hash function" turns your key into the spot number behind the scenes.

How to use them

A dict stores key → value pairs; a set stores only keys, and is perfect for "have I seen this before?". Both give instant lookup, insert, and membership tests.

d[key] = value
Store or update — instant O(1) on average.
d.get(key, default)
Fetch safely — returns default if the key is missing, no error.
key in d / x in myset
Membership test — instant, instead of scanning a list O(n).
Counter(iterable)
A ready-made dict that tallies how many times each item appears.
"On average" — what about collisions?

Two different keys can sometimes hash to the same spot (a collision) — like two coats assigned the same hook. Python handles this for you automatically, so lookups stay fast in practice. That's why we say O(1) average: the rare collision doesn't change the big picture.

OperationCostWhy
Lookup / insert in a dict or setO(1)The hash sends you straight to the spot (average case).
x in a_listO(n)A plain list has no shortcut, so it may scan every item.
