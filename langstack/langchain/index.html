LangChain · the library

LangChain: the box of parts for LLM apps.

LangChain is an open-source framework that gives you standard, swappable building blocks for working with large language models — and a clean way to snap them together. It's almost always where you start.

Open source 1.3.x Python 1.4.x JS/TS LTS since 1.0 (late 2025)

Why does LangChain exist?

An LLM on its own can only do one thing: take text in, give text out. The moment you want something real — an assistant that reads your PDFs, a bot that calls APIs, a chain that summarises then translates — you hit the same chores over and over:

  • Formatting prompts and parsing the model's reply into usable data.
  • Switching between providers (OpenAI today, a local model tomorrow) without rewriting everything.
  • Loading documents, chopping them up, and searching them by meaning (that's RAG).
  • Giving the model tools it can call, and looping until a task is finished.

LangChain provides battle-tested, reusable pieces for every one of those — behind one consistent interface — so you write your idea, not the plumbing.

LangChain is like LEGO analogy

Each piece (a model, a prompt, a retriever, a tool) has the same kind of connector. Because the connectors match, you can click them together in any order — and replace one brick without rebuilding the whole model.

How the packages are organised

"LangChain" isn't one giant install — since the 1.0 redesign it's a small family of packages. You only install the pieces you need. Everything depends on a tiny shared core.

Why the split? good to know

Before 1.0 everything lived in one package, so updating a single integration could break unrelated apps. Now the core stays tiny and steady, while each provider iterates on its own schedule. You install langchain + just the providers you use.

Your very first LangChain program

Install LangChain plus one model provider, set your API key, and call the model. init_chat_model is the modern, provider-agnostic way to grab a model.

terminal
$ pip install langchain langchain-openai
$ export OPENAI_API_KEY="sk-..."
hello_langchain.py
from langchain.chat_models import init_chat_model

# One helper, any provider. Swap "openai" for "anthropic", "google_genai", ...
model = init_chat_model("gpt-4o", model_provider="openai")

response = model.invoke("Explain LangChain to me in one sentence.")
print(response.content)
# -> "LangChain is a framework that provides reusable building blocks
#     for connecting language models to data, tools, and each other."

Notice .invoke() — that one method appears on every LangChain piece. It's the heart of the whole framework, and we explain it next.

The one idea that ties it all together

Every LangChain building block — a model, a prompt, a parser, a retriever — implements the same Runnable interface, which means they all share .invoke(), .stream(), and .batch(). Because they speak the same language, you can pipe them together with the | operator, like Unix pipes:

a_chain.py
chain = prompt | model | output_parser   # read it left-to-right, like a pipeline
result = chain.invoke({"topic": "otters"})

This is called LCEL (LangChain Expression Language). Don't worry about the details yet — just hold onto the picture of data flowing left-to-right through connected blocks. We unpack it fully in Core concepts.

When do I use LangChain vs LangGraph?

A question every beginner asks. The short version:

Reach for plain LangChain when…

  • Your flow is a straight line: prompt → model → parse.
  • You're doing classic RAG: retrieve → stuff into prompt → answer.
  • You want a quick agent and the prebuilt one is enough.

Step up to LangGraph when…

  • You need loops, branches, or retries.
  • The app must remember across turns or survive a crash.
  • You want a human to approve a step, or multiple agents to collaborate.
Plot twist: they're not rivals

Since LangChain 1.0, the agents you create with create_agent actually run on LangGraph under the hood. So learning LangChain first and LangGraph second isn't switching tools — it's lifting the hood on the same engine.
