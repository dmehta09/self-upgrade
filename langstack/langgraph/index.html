LangGraph · the runtime

LangGraph: give your app a brain that can loop.

LangGraph is a low-level orchestration framework and runtime for building stateful, long-running agents. It lets your app loop, branch, remember, pause for a human, and survive a crash — the things a straight-line chain can't do on its own.

Open source 1.2.x Python 1.3.x JS/TS 1.0 since Oct 2025

Why LangGraph exists

A plain LangChain chain runs in a straight line: prompt → model → parse, and you're done. That's perfect for simple tasks. But the moment you build a real agent, that straight line falls apart — because real agents need to:

  • Loop — call a tool, look at the result, then decide what to do next (maybe call another tool, maybe answer).
  • Branch — take different paths depending on a condition ("if the user is angry, escalate").
  • Remember — carry context across many turns, even across separate sessions.
  • Pause — stop and wait for a human to approve a risky step before continuing.
  • Survive a crash — pick back up exactly where it left off instead of starting over.

LangGraph models your application as a graph — boxes (steps) connected by arrows (decisions) — so every one of those behaviors becomes natural instead of a tangle of if statements and while loops.

Recipe vs. board game analogy

A LangChain chain is like a recipe you follow top to bottom — step 1, step 2, step 3, finished. LangGraph is like a flowchart or board game: you can loop back to an earlier square, take a fork in the road based on what just happened, and pause the game mid-turn to ask a friend. Same pieces, far more freedom in how they connect.

The mental model: nodes, edges, state

LangGraph has just three core ideas. Once they click, everything else is a variation on them.

Nodes

Steps that do work. A node is just a Python function — it reads the state and returns some updates.

Edges

Arrows that decide what runs next. They can be fixed ("always go here") or dynamic ("decide based on the state").

State

A shared notebook passed to every node. Each node reads from it and returns updates that get merged back in.

Your first graph (hello world)

Let's build the tiniest possible graph: one node that writes a joke. It shows all three ideas — a State notebook, a node function, and the edges that wire it from START to END.

terminal
$ pip install langgraph langchain
hello_graph.py
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END

# 1. State = the shared notebook every node reads & writes
class State(TypedDict):
    topic: str
    joke: str

# 2. A node is just a function: receives state, returns updates
def write_joke(state: State):
    return {"joke": f"Why did the {state['topic']} cross the road? ..."}

# 3. Wire nodes together with edges
builder = StateGraph(State)
builder.add_node("write_joke", write_joke)
builder.add_edge(START, "write_joke")
builder.add_edge("write_joke", END)

# 4. Compile -> a runnable graph
graph = builder.compile()
print(graph.invoke({"topic": "otter"}))   # -> {'topic': 'otter', 'joke': '...'}

Notice the node returns a dict instead of changing things in place — LangGraph merges that dict back into the state for you.

The shortcut: prebuilt agents

Most people don't hand-build a graph to get started. The standard "agent loop" — think → act → observe, repeat — is so common that LangGraph ships it ready-made. create_react_agent builds the whole loop for you from a model and a list of tools.

prebuilt_agent.py
from langgraph.prebuilt import create_react_agent

agent = create_react_agent(model="gpt-4o", tools=[search, calculator])
result = agent.invoke({"messages": [{"role": "user", "content": "Weather in Paris?"}]})
print(result["messages"][-1].content)
Same engine you already met

create_agent in LangChain returns exactly this kind of LangGraph graph — it wraps the same prebuilt loop. So when you built an agent in LangChain, you were already running LangGraph under the hood.

Where LangGraph sits

LangGraph isn't a replacement for the rest of the stack — it's the runtime that ties it together. Here's how it relates to the tools around it:

LangChain
LangGraph uses LangChain's models, messages, and tools as the parts your nodes work with. You build the parts in LangChain; you orchestrate them in LangGraph.
LangSmith
Every node run is traced automatically. Open LangSmith and you can watch each step, see what the state looked like, and debug exactly where things went sideways.
LangGraph Platform
A managed way to deploy your graphs as scalable, persistent APIs — so a long-running agent keeps its memory in production.
LangGraph Studio
A visual debugger for your graph. Run langgraph dev locally and step through nodes, inspect state, and tweak inputs in a UI.

When to reach for it

You don't need LangGraph for everything. Here's the quick rule of thumb:

Plain LangChain is enough when…

  • Your flow is a straight line: prompt → model → parse.
  • You're doing simple RAG: retrieve → answer.
  • You want a quick agent and the prebuilt loop is all you need.

Use LangGraph when…

  • You need loops or branching logic.
  • The app must keep persistent memory across turns or sessions.
  • You want a human to approve a step, or multiple agents to collaborate.
You can start small and grow into it

Begin with create_react_agent. The day you need a custom loop, a branch, or persistent memory, you drop down to hand-built nodes and edges — without changing tools. That's what Core concepts is for.
