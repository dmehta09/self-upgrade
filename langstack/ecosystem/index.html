The big picture

Three tools, one stack — and when to use which.

LangChain, LangGraph, and LangSmith are made by the same team and designed to click together. The whole story in three words: build with LangChain, orchestrate with LangGraph, observe with LangSmith. Get this mental model first and everything else falls into place.

01  One mental model

You only need to remember one sentence per tool:

Build

LangChain

The building blocks — models, prompts, tools, retrieval/RAG, and chains you snap together with the pipe (|).

Orchestrate

LangGraph

The runtime that wires those blocks into a stateful graph — so your app can loop, branch, remember, and pause for a human.

Observe

LangSmith

The observability & eval platform that watches it all — trace every step, debug failures, and measure quality.

Think of a working kitchen analogy

LangChain is the pantry of ingredients and tools — knives, pans, flour, eggs. LangGraph is the recipe-with-decisions: taste it; if it's too bland, add salt and stir again; ask the head chef before plating. LangSmith is the food critic and the health inspector combined — watching every step, grading the dish, and flagging what went wrong.

"Somewhat" framework-agnostic?

LangChain and LangGraph are their own frameworks — but they're built around open standards and integrate with hundreds of providers. LangSmith is different: it can trace and evaluate any code, even an app that never imports LangChain at all.

If the second answer is "no", you may never need LangGraph directly. LangSmith, though, pays off on day one.

Default: LangChain

Every project starts here. If your flow is a straight line — prompt → model → parse, or classic RAG — LangChain alone is often the whole answer. When the demo meets real users, see RAG in production.

When it gets stateful: LangGraph

The moment you need to loop, branch on a condition, remember across turns, or pause for a human, reach for LangGraph. Then pick an agent architecture and open the production toolbox.

Always-on: LangSmith

Independent of the above. Flip on tracing immediately so you can see, debug, and grade every run — then graduate to a real evaluation suite.

06  Beginner misconceptions

The four mix-ups that trip up almost everyone when they start.

"Do I have to pick one?"

No — they stack. They're not competitors; they're layers of one system. Most real apps use LangChain for the parts, LangGraph when state is involved, and LangSmith to watch it all.

"Is LangChain dead, replaced by LangGraph?"

No. LangChain is the friendly, high-level API; LangGraph is the engine underneath modern agents. Since 1.0, create_agent in LangChain actually runs on LangGraph — they ship together, on purpose.

"Is LangSmith only for LangChain apps?"

No. LangSmith traces and evaluates any code — wrap a plain OpenAI call, a custom pipeline, or another framework entirely. Using LangChain/LangGraph just makes it zero-config.

"Do I need to deploy LangGraph Platform to use LangGraph?"

No — LangGraph is just a library you pip install and run anywhere. LangGraph Platform and Studio are optional extras for hosting and visually debugging graphs; you can build everything without them.
