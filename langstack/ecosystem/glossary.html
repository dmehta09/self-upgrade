Reference

Glossary

Every term used in this guide, in plain English — with a link to where it's taught.

A
Agent

A model running in a loop with tools: it thinks, optionally calls a tool, reads the result, and repeats until it can answer. Built with create_agent and run on LangGraph.

LangChain · Agents
AIMessage

The message type representing what the model replied. It may carry plain text or one or more requests to call tools.

LangChain · Messages
Annotation queue

An inbox of runs waiting for a human reviewer to grade them against a rubric. The labels feed datasets and calibrate your LLM-as-judge.

LangSmith · Annotation queues
B
Batch / invoke / stream

The three shared run methods on every LangChain piece: .invoke() runs once and waits, .stream() returns the answer token-by-token, and .batch() runs many inputs in parallel.

LangChain · Chat models
C
Chain

A sequence of building blocks connected with the pipe (|) so each one's output feeds the next — a straight-line pipeline such as prompt → model → parser.

LangChain · LCEL
Chat model

Your connection to an LLM. LangChain wraps every provider (OpenAI, Anthropic, Google, local…) in one identical interface so your code doesn't care which is behind it.

LangChain · Chat models
Checkpointer

LangGraph's automatic, persistent memory. It saves the graph's state after each step, keyed by a conversation ID, so an app can remember across turns and survive a restart.

LangGraph · Persistence
Conditional edge

An edge that picks the next node based on the current state — this is how a graph branches, loops, or decides when to stop.

LangGraph · Edges
create_agent / create_react_agent

The helper that builds an agent for you — wiring the think-call-tool-think-again loop into a ready-to-run LangGraph graph. The modern replacement for old agent classes.

LangChain · Agents
D
Dataset

A collection of example inputs (and often expected outputs) in LangSmith that you run your app against to measure quality — your test set for LLM behaviour.

LangSmith · Datasets
E
Edge

A connection in a LangGraph graph that says which node runs next. Edges can be fixed (always go to B) or conditional (decide based on state).

LangGraph · Graph
Embedding

A piece of text turned into a long list of numbers (a "vector") that captures its meaning, so texts about similar things land near each other — the basis of semantic search.

LangChain · Retrieval
Evaluator / Evaluation

Evaluation is grading your app's outputs against a dataset; an evaluator is the scorer that does it — using exact rules, an LLM-as-judge, or human feedback.

LangSmith · Evaluation
Experiment

One run of your app over a whole dataset, scored by evaluators. Compare experiments to see whether a change (new prompt, new model) actually improved things.

LangSmith · Experiments
G
Graph

LangGraph's core structure: nodes (steps) joined by edges (what runs next), sharing one piece of state. It can loop, branch, and pause — unlike a straight-line chain.

LangGraph · Graph
H
Handoff

One agent passing control directly to a peer with Command(goto="other_agent") — the building block of the swarm style, where there's no supervisor in the middle.

LangGraph · Handoffs & swarm
Human-in-the-loop

Pausing a graph so a person can review, edit, or approve a step before it continues — for example, signing off before the app sends an email or spends money.

LangGraph · Human-in-the-loop
Hybrid search

Running vector search and keyword search (BM25) on the same query and fusing the two ranked lists — usually with Reciprocal Rank Fusion (RRF). Vectors catch paraphrase; keywords catch exact IDs and jargon.

LangChain · Hybrid search
I
init_chat_model

The modern, provider-agnostic helper for grabbing a chat model. Swap providers by changing one string while the rest of your code stays identical.

LangChain · Chat models
L
LCEL

LangChain Expression Language — the way you connect Runnables with the pipe (|) so data flows left-to-right through your blocks. Streaming and batching come for free.

LangChain · LCEL
LLM

Large Language Model — the AI (GPT, Claude, Gemini…) that takes text in and gives text out. Brilliant but isolated on its own; the Lang stack connects it to data, tools, and memory.

LangChain · Overview
LLM-as-judge

Using a language model itself as the evaluator — asking it to score another model's output for things hard to check with rules, like helpfulness or tone.

LangSmith · Evaluation
N
Node

A single step in a LangGraph graph — usually a plain function that reads the state, does some work, and returns an update to it.

LangGraph · Graph
O
Online evaluation

Running evaluators on a sample of live production traces (no reference answers — the judge grades inputs and outputs only). Catches drift your offline test set never predicted.

LangSmith · Online evals
Output parser

A block that turns the model's text reply into the data your program wants — e.g. StrOutputParser pulls out the plain string, the most common final step in a chain.

LangChain · Output parsers
P
Partner package

A provider-specific install like langchain-openai or langchain-anthropic. Each lives in its own package and is versioned independently from the core.

LangChain · Overview
Playground

A LangSmith space to tweak a prompt and model and rerun them instantly — great for iterating on a prompt without touching your code.

LangSmith · Playground
Prompt Hub

A shared, versioned library of prompts in LangSmith — pull a tested prompt by name instead of hard-coding it, and update it without redeploying.

LangSmith · Prompt Hub
Prompt template

A reusable prompt blueprint with {placeholders} you fill in at runtime — testable and tidy, instead of messy f-strings.

LangChain · Prompt templates
R
RAG

Retrieval-Augmented Generation — before asking the model, fetch relevant facts from your documents and paste them into the prompt, so answers stay grounded instead of guessed.

LangChain · RAG
Reducer

A rule in LangGraph that says how a node's update should be merged into the state — for example, append to the message list rather than overwrite it.

LangGraph · Reducers
Reranking

A second, more careful pass over search results: retrieve ~25 chunks cheaply, then let a cross-encoder re-score them against the query and keep the best few. Accurate but too slow to search everything — so it sits at the end of the funnel.

LangChain · Reranking
Retriever

The thin wrapper that takes a question and returns the most relevant chunks from your vector store — the search step at the heart of RAG.

LangChain · Retrieval
Run

One recorded unit of work in LangSmith — a single LLM call, tool call, or chain step, with its inputs, outputs, timing, and cost.

LangSmith · Tracing
Run tree

The nested structure of runs that makes up one trace — a parent chain with its child model and tool runs underneath, showing exactly what called what.

LangSmith · Tracing
Runnable

The shared interface behind every LangChain block — anything with .invoke(), .stream(), and .batch(). Because they all match, you pipe them together with |.

LangChain · LCEL
S
State / StateGraph

State is the shared data every node in a graph reads and updates (often the message list). StateGraph is the class you use to define a graph around that state.

LangGraph · State
Store / long-term memory

A place to keep facts across separate conversations — like remembering a user's preferences for next time — beyond a single thread's checkpointed history.

LangGraph · Memory
Streaming

Sending results out as they're produced rather than all at once — graph updates, tokens, or events — so users see progress live instead of waiting.

LangGraph · Compile & run
Structured output

Forcing the model's reply to match a schema (e.g. a Pydantic model) so you get a real typed object back instead of fragile text — via .with_structured_output().

LangChain · Output parsers
Subgraph

A compiled graph used as a single node inside a bigger graph. Share state keys and it plugs straight in; different schemas need a small wrapper that maps state in and out.

LangGraph · Subgraphs
Supervisor

A multi-agent pattern where one router agent delegates work to specialist workers and they always report back to it — central control, predictable flow.

LangGraph · Supervisor pattern
SystemMessage / HumanMessage

Two message types: SystemMessage holds the standing instructions (who the assistant is); HumanMessage is what the user said.

LangChain · Messages
T
Thread / thread_id

A single conversation in LangGraph. The thread_id is the key the checkpointer uses to save and reload that conversation's state, keeping users' chats separate.

LangGraph · Persistence
Tool

A Python function the model is allowed to call — to search the web, do math, or hit your database. You write it, decorate it with @tool, and bind it to the model.

LangChain · Tools
Tool calling

When the model requests a tool with specific arguments instead of answering in words. Your code runs the tool and feeds the result back as a ToolMessage.

LangChain · Tools
ToolMessage

The message type that carries a tool's result back to the model, so it can read what happened and continue reasoning.

LangChain · Messages
ToolNode

A ready-made LangGraph node that runs whatever tools the model asked for and returns the results — so you don't wire the tool-running step by hand.

LangGraph · Prebuilt
Trace / Tracing

A full recording of one run of your app — every model call, tool call, input, output, latency, and cost — captured by LangSmith so you can see exactly what happened.

LangSmith · Tracing
V
Vector store

A database that stores embeddings and finds the nearest ones to a query — the searchable knowledge base that powers semantic search and RAG.

LangChain · Retrieval
W
with_structured_output

The method that makes a model return data matching your schema. It uses the model's native tool-calling to guarantee the shape — no fragile text parsing.

LangChain · Output parsers
