LangSmith · the platform

LangSmith: see inside your LLM app.

LangSmith is an observability & evaluation platform that records every step your app takes — so you can debug what went wrong, measure how good your answers are, and monitor everything once it's live in production.

0.7.x SDK Free tier: 5,000 traces/mo Cloud or self-hosted

Why LangSmith exists

LLM apps are black boxes. One simple user request can quietly fan out into many model calls, tool calls, and retrieval steps before an answer comes back. When that answer is wrong, slow, or expensive, you're left blind — which of those steps actually broke?

Without a record of what happened, debugging an AI app means re-running it over and over and squinting at print() statements. LangSmith gives you x-ray vision: it captures the inputs, outputs, timing, and cost of every single step, then draws the whole thing as a tree you can click through.

LangSmith is a flight recorder for your AI app analogy

Think of the black box on an aircraft. It quietly records everything that happens during a flight, so that afterwards investigators can replay exactly what occurred. LangSmith does the same for each run of your app — when something goes wrong, you replay the recording instead of guessing.

The mental model: traces & runs

Two words unlock everything in LangSmith:

  • A trace = one complete execution of your app — everything that happened to serve one user request.
  • A run = one step inside that trace — a single LLM call, a tool call, or a function.

Runs nest inside other runs, forming a run tree. The trace is the trunk; each run is a branch, and branches can have their own branches. Here's a tiny example for a question-answering app:

One trace, made of nested runs
trace · the whole request
rag_pipeline("What's our refund policy?")
everything below happened to answer this one question
run · retrieval
retrieve_docs(query)
searched the vector store → 3 chunks
run · llm
call_llm(prompt + docs)
asked GPT-4o to answer using the chunks
run · child
format_prompt(...)
built the final message list
run · child
parse_output(...)
pulled the clean answer string out
Click any run in LangSmith to see its exact inputs, outputs, latency, and token cost.

What it does — four jobs

Everything LangSmith offers falls into four buckets. You can use one or all of them, in any order.

Observe

Trace every step of every request. See the full run tree, inputs, outputs, errors, latency, and token cost — no guessing.

Evaluate

Grade your app's outputs against a test set so you can measure quality with numbers instead of vibes.

Iterate

Tweak prompts and models in the in-browser Playground, and version them in the Prompt Hub — fast loops, no redeploy.

Monitor

Live dashboards for volume, latency, cost, and error rate in production — plus alerts when something spikes.

Turn it on in 30 seconds

Here's the magic: for LangChain and LangGraph apps, tracing is automatic. You don't change a single line of code — you just set three environment variables and install the small SDK.

terminal
$ pip install langsmith
$ export LANGSMITH_TRACING=true
$ export LANGSMITH_API_KEY="lsv2_..."
$ export LANGSMITH_PROJECT="my-first-app"
That's the whole setup

With those four lines in place, run any existing LangChain or LangGraph code and the traces appear at smith.langchain.com — grouped under your my-first-app project. Zero code changes required.

Works with ANY code (@traceable)

LangSmith is framework-agnostic — you do not need LangChain to use it. For plain Python (or any code at all), just decorate the functions you want to see with @traceable. Each decorated call becomes a run in the tree.

plain_python.py
from langsmith import traceable

@traceable
def retrieve(query: str):
    return ["doc A", "doc B"]

@traceable
def answer(query: str):
    docs = retrieve(query)
    return f"Answer based on {docs}"

answer("What is LangSmith?")   # the whole call tree shows up as a trace

Because answer calls retrieve, LangSmith automatically nests retrieve as a child run under answer — the tree builds itself.

Pricing in plain terms

The free Developer tier gives you roughly 5,000 traces a month with no credit card. Beyond that, paid plans are broadly usage-based (you pay for the traces you send). You can run on LangSmith's cloud, or self-host it in your own infrastructure on enterprise plans. Exact numbers and tiers can change over time.

Where LangSmith sits

LangSmith wraps both LangChain and LangGraph — turn it on and their calls are traced for you — but neither of them requires it, and it isn't part of either library. It's a separate hosted product (a website plus a tiny SDK) that happily sits behind any stack: LangChain, LangGraph, or plain Python/JavaScript with a few @traceable decorators.
