EBS, EFS & FSx.

Three ways to attach durable bytes to compute: a disk for one instance (EBS), a shared NFS (EFS), or a managed specialty filesystem (FSx). The exam is almost always “which shape, and why?”

01 Pick the storage shape

S3 = objects over HTTPS. EBS = block volume for (usually) one EC2. EFS = elastic NFS many clients mount. FSx = managed Windows / Lustre / NetApp / OpenZFS when you need those protocols or performance profiles.

In plain English analogy

EBS is the hard drive bolted into one laptop — fast, local to that machine. EFS is a shared office file server: many laptops mount the same folder over the network. FSx is renting a specialized appliance (Windows file share, HPC scratch, NetApp) instead of assembling NFS yourself.

02 EBS deep cut

gp3
General-purpose SSD default — baseline IOPS/throughput tunable independently of size.
io2 / io2 Block Express
Highest IOPS & durability; Multi-Attach for clustered apps that support shared block.
Snapshots
Incremental, stored in S3 behind the scenes; copy across Regions for DR.
Encryption
KMS-backed; snapshots inherit encryption.
Common trap gotcha

EBS lives in one AZ. An instance in AZ-a cannot attach a volume that lives in AZ-b. For multi-instance shared files, use EFS/FSx, not “just attach the same EBS twice” (unless Multi-Attach + a cluster FS that supports it).

03 EFS & FSx

EFS
  • Regional, Multi-AZ by default
  • Elastic / provisioned throughput modes
  • Lifecycle → Infrequent Access / Archive
  • Mount targets per AZ; NFS locks
FSx family
  • Windows File Server — SMB, AD
  • Lustre — HPC, often linked to S3
  • NetApp ONTAP — multiprotocol, snapshots
  • OpenZFS — NFS with ZFS features

A fleet of containers across three AZs must share a POSIX filesystem for user uploads. What do you choose?

Right. Shared POSIX across AZs is EFS's job. EBS Multi-Attach is limited and not a general shared FS for containers; instance store is ephemeral and not shared.

04 Interview rapid-fire

S3 vs EBS vs EFS — one sentence each?warm-up
Model answer

S3 is object storage over the API. EBS is a block disk for one EC2 in one AZ. EFS is a shared NFS many instances mount across AZs.

Say it out loud say it

"S3 objects, EBS one VM's disk, EFS shared drive across many VMs."

When is FSx the answer instead of EFS?core
Model answer

When you need a Windows SMB share with AD, Lustre for HPC scratch (often with S3), or NetApp/OpenZFS features. EFS is the Linux NFS default; FSx is the specialty appliance.

Say it out loud say it

"EFS for Linux NFS; FSx when the question says Windows, Lustre, or NetApp."

How do you protect an EBS volume for DR?stretch
Model answer

Take regular snapshots (often via AWS Backup), copy snapshots to another Region if RPO requires it, and automate AMI/volume rebuild in the DR Region. Remember the volume itself is AZ-scoped — snapshots are the portable recovery unit.

Say it out loud say it

"EBS is stuck in an AZ — snapshots (and cross-Region copies) are how I move recovery."
