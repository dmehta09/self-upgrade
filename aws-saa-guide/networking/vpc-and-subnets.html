Networking · VPC & subnets Domain 1 · Secure

Your private network on AWS.

A VPC is an isolated IPv4/IPv6 network you control. Subnets carve it per AZ; public vs private is just routing — not a magic flag. SAA designs put load balancers (and NAT) public, apps and data private, across ≥2 AZs.

01 CIDR, subnets, and AZ pinning

Pick a VPC CIDR (commonly 10.0.0.0/16), slice non-overlapping subnet CIDRs, and place each subnet in exactly one AZ. Plan headroom for growth and secondary CIDRs if needed.

In plain English analogy

The VPC is a gated campus. Each building (subnet) sits on one city block (AZ). “Public” buildings face the street with a gate to the highway (Internet Gateway). “Private” buildings have no street door — workers go out through a guarded exit (NAT) or private tunnels (endpoints).

VPC CIDR
Private RFC1918 ranges preferred. Avoid overlap with on-prem if you’ll peer or use VPN/Direct Connect later.
Subnet
AZ-scoped IP slice + route table association. Public = route to IGW; private = no IGW route.
IPv6
Optional dual-stack; egress-only IGW for IPv6 private outbound. Know it exists for “IPv6 required” stems.

02 Canonical multi-AZ request path

Internet → IGW → ALB in public subnets (2+ AZs) → targets in private subnets → RDS Multi-AZ privately. Outbound from private tiers via NAT or VPC endpoints.

flowchart TD
  need["Private subnet needs outbound?"] --> aws{"Only AWS APIs?"}
  aws -->|yes| ep["Gateway or interface endpoint"]
  aws -->|no| third{"Need public internet?"}
  third -->|yes| nat["NAT Gateway in public subnet"]
  third -->|no| none["No default route — stay private"]
  nat --> ha["NAT per AZ for production HA"]
  ep --> tip["Prefer endpoints over NAT for S3 / DynamoDB"]

03 Public vs private — exam rules

Public subnet: 0.0.0.0/0 → IGW (+ usually auto-assign public IP for instances that need it). Private: default route to NAT or no internet — never place RDS in public for convenience.

Anti-pattern
  • RDS / ElastiCache in public subnets
  • App servers with public IPs “so SSH works”
  • One big /16 subnet in a single AZ
SAA default
  • ALB + NAT in public; apps/DB private
  • SSM Session Manager instead of bastion when possible
  • Mirrored subnets in ≥2 AZs
Common trap gotcha

NAT is not free HA. A single NAT in one AZ is a single point of failure for private egress. For production, place NAT gateways in each AZ (or use VPC endpoints to avoid NAT for AWS APIs). Also: NAT charges hourly + per-GB — heavy S3 via NAT is a cost bomb.

You need EC2 app servers that never accept inbound internet connections but must call third-party HTTPS APIs. Where do they live and how do they egress?

Right. Private + NAT = outbound-only. Public subnet instances are internet-reachable if they have public IPs/routes. Private subnets must not route 0.0.0.0/0 to the IGW.

04 Exam rapid-fire

What makes a subnet “public”?warm-up
Model answer

Its route table has a default route to an Internet Gateway. The name isn’t a checkbox — routing defines it. Instances usually also need a public or Elastic IP to be reachable inbound.

Say it out loud say it

"Public means the subnet routes to an IGW — it’s routing, not a label."

Why spread subnets across AZs?core
Model answer

Because a subnet can’t span AZs. Multi-AZ HA requires resources (or managed Multi-AZ services) placed in subnets in different AZs behind Multi-AZ-aware load balancers and databases.

Say it out loud say it

"One subnet equals one AZ, so HA needs paired subnets in two AZs."

When do you skip NAT entirely?stretch
Model answer

When private workloads only need AWS APIs reachable via VPC endpoints (S3/DynamoDB gateway; interface endpoints for others), or when there’s no outbound internet requirement at all.

Say it out loud say it

"If they only talk to AWS, I use VPC endpoints and drop NAT to cut cost and surface area."
