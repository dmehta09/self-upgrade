Six pillars, one design conversation.

The AWS Well-Architected Framework is how SAA-C03 grades trade-offs: operational excellence, security, reliability, performance efficiency, cost optimization, and sustainability. Use pillars to eliminate answers that ignore a stated constraint.

01 The six pillars (exam map)

Each SAA domain echoes WA pillars. When stuck between two “correct” services, ask which pillar the stem emphasizes.

In plain English analogy

Pillars are like building codes for a skyscraper: fire safety (security), earthquake bracing (reliability), elevator capacity (performance), operating budget (cost), day-to-day maintenance (ops), and energy use (sustainability). A design that aces elevators but fails fire code fails the inspection.

flowchart TD
  design[Architecture_choice] --> sec[Security]
  design --> rel[Reliability]
  design --> perf[Performance]
  design --> cost[Cost]
  design --> ops[Operational_Excellence]
  design --> sus[Sustainability]
Operational excellence
IaC, observability hooks, runbooks, small reversible changes — CloudFormation/CDK, Config, automated recovery.
Security
Identity-first, least privilege, encrypt in transit/at rest, detective controls — IAM, KMS, VPC isolation, WAF.
Reliability
Fault isolation, Multi-AZ, backups, throttling, graceful degradation.
Performance efficiency
Right-sized compute (Graviton), caching, edge, choose purpose-built databases.
Cost optimization
Pay for value: Savings Plans, spot where fit, S3 Intelligent-Tiering, kill idle NAT with endpoints.
Sustainability
Fewer always-on servers, efficient Regions/instance types, serverless for spiky idle — exam lightly tests awareness.

02 Pillars collide — pick intentionally

There is no free lunch: Multi-Region reliability costs money; aggressive caching can stale data; tight security can add latency. The stem tells you which pillar wins.

Stem says “cost-effective”
  • Prefer Single-Region Multi-AZ over active-active
  • Gateway endpoints over NAT for S3/DynamoDB
  • Graviton + Savings Plans / Aurora Serverless v2 for variable load
Stem says “must not lose data”
  • Reliability & security beat cheapest option
  • Multi-AZ, backups, versioning, encryption
  • Don’t pick spot-only for stateful primary DB
Common trap gotcha

Over-architecting “best practices” without a constraint. Adding Global Accelerator + multi-Region Aurora when the stem only asks for AZ resilience wastes cost and is often the wrong answer. Match the pillar the question actually graded.

03 Lightweight review habit

Before locking an answer, run a 20-second WA checklist: identity? blast radius? failover path? right-sized? idle cost?

1

Security

No public DB; roles not keys; encrypt; least privilege SG.

2

Reliability

≥2 AZs; health checks; backups match RPO.

3

Perf & cost

Cache/edge if global; managed over DIY; trim NAT/data transfer.

A solution is secure and highly available but leaves NAT gateways pulling terabytes from S3 monthly. Which pillar is failing, and what’s the fix?

Right. Heavy S3 via NAT burns cost and adds latency. Gateway endpoints for S3/DynamoDB are the classic WA cost fix. Public buckets are a security anti-pattern.

04 Exam rapid-fire

Name the six Well-Architected pillars.warm-up
Model answer

Operational excellence, security, reliability, performance efficiency, cost optimization, and sustainability.

Say it out loud say it

"Ops, security, reliability, performance, cost, and sustainability — six lenses on every design."

How do you use WA when two answers both “work”?core
Model answer

Re-read the stem for the weighted pillar — “most cost-effective,” “minimize operational overhead,” “highest availability.” Discard the option that optimizes the wrong pillar.

Say it out loud say it

"Both can work — I pick the one that wins the pillar the question actually asked for."

Give one 2026-default that hits cost and performance together.stretch
Model answer

Prefer Graviton instance families / Fargate Graviton where the workload supports ARM — better price/performance. Pair with Savings Plans for steady baseload and serverless or Spot for elastic bursts.

Say it out loud say it

"Graviton for price/perf, Savings Plans for steady load, serverless or Spot for the spikes."
