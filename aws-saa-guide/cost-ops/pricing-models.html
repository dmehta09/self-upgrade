Cost & Operations · Pricing models Domain 4 · Cost-optimized

Pay for what you use — then commit where it sticks.

On-Demand is flexible. Savings Plans / Reserved Instances discount steady load. Spot discounts interruptible work. Graviton and right-sizing beat buying a bigger box. The exam rewards matching commitment to workload shape.

01 The pricing menu

Pick the model from the stem's keywords: steady → commit; spiky/unknown → On-Demand or serverless; batch/fault-tolerant → Spot.

In plain English analogy

On-Demand is a walk-up hotel rate. Savings Plans / RIs are a corporate rate for nights you know you'll stay. Spot is a standby flight — cheap if you're OK getting bumped.

02 Cost levers beyond the price tag

Right-size
CloudWatch + Compute Optimizer → smaller / fewer instances before you buy a Savings Plan.
Graviton
ARM instances often better price/performance — prefer when compatible.
S3 classes
Intelligent-Tiering / lifecycle to IA / Glacier for cold data.
Data transfer
Same-AZ free-ish; cross-AZ and internet egress cost. Keep chatty tiers co-located; use CloudFront for public bytes.
Serverless
Lambda / Fargate / Aurora Serverless v2 — pay for use when idle time dominates.
Common trap gotcha

Don't put Spot on a single stateful primary database or anything that can't tolerate interruption. Don't buy a 3-year RI for a workload you haven't right-sized. Savings Plans ≠ "free compute forever" — unused commitment is waste.

A fleet of containers runs 24×7 at steady utilization; architecture may change instance families. Lowest cost with flexibility?

Right. Steady load → commit dollars. Compute Savings Plans stay flexible across instance families and Fargate; Spot alone is wrong for always-on critical capacity.

03 Stem signals → answer

  • "Minimize cost" + fault-tolerant batch → Spot (+ checkpoint / ASG mixed instances).
  • "Predictable" / "steady state" → Savings Plans or RI.
  • "Unpredictable traffic" / "rarely used" → On-Demand or serverless.
  • "License tied to cores / sockets" → Dedicated Host.
  • "Infrequently accessed objects" → S3 IA / Glacier / Intelligent-Tiering.

04 Exam rapid-fire

Savings Plans vs Reserved Instances?core
Model answer

Both discount committed usage. Compute Savings Plans are the flexible modern default ($/hr across instance family, size, Region options, and Fargate/Lambda). RIs lock more narrowly to instance attributes — still valid, less flexible.

Say it out loud say it

"Commit dollars with Savings Plans when you want discount + flexibility; RI when the stem is stuck on a specific reservation."

When is Spot appropriate?warm-up
Model answer

Stateless or checkpointable workloads that can lose capacity with ~2 minutes notice — CI workers, batch, big data, scalable web fleets with On-Demand baseline. Never as the sole home for a non-replicated primary DB.

Say it out loud say it

"Spot is cheap capacity that can vanish — use it where interruption is boring."

Name three cost wins that aren't a pricing model.core
Model answer

Right-size / stop idle; prefer Graviton; lifecycle data to colder S3 classes; cut cross-AZ and internet egress; use CloudFront; pick serverless for spiky idle-heavy apps.

Say it out loud say it

"Discount the right size first — don't Reserved-Instance a wasteful architecture."
