Elastic Load Balancing patterns.

Pick the balancer by protocol and feature needs: ALB for HTTP(S) L7, NLB for extreme performance / TCP-UDP / static IPs, GWLB for inline appliances. Always Multi-AZ.

01 ALB vs NLB vs GWLB

The exam loves “which load balancer?” Map the requirement → product, then place targets in private subnets across AZs.

In plain English analogy

ALB is a smart receptionist who reads the URL and sends you to the right department (path/host rules). NLB is a high-speed turnstile that barely looks at you — just pushes packets through insanely fast. GWLB is a security checkpoint lane that forces every car through inspection appliances.

02 ALB patterns that show up on SAA

Path / host routing
/api/* → API target group; app.example.com → web TG.
TLS termination
ACM certs on HTTPS listeners; optionally re-encrypt to targets.
Sticky sessions
Only when the app is not yet stateless — prefer external session store.
WAF association
Attach Web ACL on ALB (or front with CloudFront + WAF).
Internal vs internet-facing
Internal ALB for service-to-service inside VPC; never expose admin UIs publicly.
Common trap gotcha

ALB nodes live in subnets you select — for public ALBs you need public subnets (or correct routing). Targets can stay private. Cross-zone load balancing changes how traffic fans out and can affect data transfer — know it’s often on by default for ALB.

03 NLB & PrivateLink adjacency

NLB preserves source IP (with target type choices), supports TLS listeners, and fronts PrivateLink services (Endpoint Service). PrivateLink mindset: expose a service to other VPCs/accounts via interface endpoints instead of peering everything.

Reach for NLB when…
  • Need static IPs or allowlisted EIPs
  • Non-HTTP protocols / extreme scale
  • PrivateLink endpoint service attachment
Reach for ALB when…
  • HTTP content-based routing
  • OIDC / Cognito auth at the edge of the LB
  • gRPC or WebSockets with L7 awareness

Partners must allowlist two static IPs and speak raw TCP to your service. Which LB?

Right. Static IPs + TCP → NLB. ALB doesn’t provide static EIPs the same way; Classic is legacy and single-AZ is wrong.

04 Interview rapid-fire

When is ALB the wrong choice?core
Model answer

When you need static IPs, ultra-high performance L4, UDP, or PrivateLink endpoint services — choose NLB. When you need inline security appliances, choose GWLB. ALB shines at HTTP routing features.

Say it out loud say it

"ALB for HTTP smart routing; NLB for static IP and raw TCP/UDP; GWLB for appliance chains."

How does ALB support microservices?warm-up
Model answer

One listener, many target groups, rules on host/path/headers. Each service ASG or IP targets register independently. Health checks are per target group so one bad service doesn’t take down routing for others.

Say it out loud say it

"Path and host rules fan out to separate target groups — each service scales and health-checks on its own."

NLB and PrivateLink — how related?stretch
Model answer

A VPC endpoint service is powered by an NLB. Consumers create interface endpoints (PrivateLink) in their VPC and reach your service privately without traversing the public internet or full VPC peering mesh.

Say it out loud say it

"PrivateLink endpoint services sit on an NLB — consumers get a private ENI to my service without exposing it publicly."
