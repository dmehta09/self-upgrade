01 The deck

Recall beats re-reading. Try to answer out loud before flipping — that's the muscle SAA-C03 tests.

0/0 known

  • IAM user vs IAM role?

    Users are long-lived identities (people). Roles are assumable identities that issue temporary credentials — preferred for EC2, Lambda, federation, and cross-account.

  • How should an EC2 app access S3?

    Instance profile IAM role with least-privilege S3 permissions — never bake access keys into the AMI or userdata.

  • Security group vs NACL?

    SG = stateful, ENI/instance level, allow-only. NACL = stateless, subnet level, allow and deny. Shape traffic primarily with SGs.

  • When use a VPC gateway endpoint for S3?

    Private subnets need S3 without NAT/internet — traffic stays on AWS backbone; often cheaper than NAT for heavy S3.

  • SSE-S3 vs SSE-KMS?

    Both encrypt at rest. SSE-S3 uses AWS-managed keys (simple). SSE-KMS uses CMKs with audit via CloudTrail and key policies — more control.

  • What do Organizations SCPs do?

    Set maximum permissions for member accounts (a permission ceiling). They don't grant access — IAM still must allow.

  • WAF vs Shield?

    WAF = Layer-7 web ACL rules (SQLi, XSS, bots). Shield = DDoS protection (Standard included; Advanced for premium features/cost).

  • CloudTrail vs Config vs CloudWatch?

    Trail = API who/what. Config = resource config history + compliance. CloudWatch = metrics, logs, alarms (health).

  • Multi-AZ vs multi-Region?

    Multi-AZ survives AZ failure inside a Region (default HA). Multi-Region survives Region-level disasters — more cost and complexity.

  • RPO vs RTO?

    RPO = max acceptable data loss (time). RTO = max acceptable downtime. Tighter either way costs more.

  • Pilot light vs warm standby?

    Pilot light keeps data (and tiny core) on; scale compute at failover. Warm standby runs a scaled-down full stack always — faster RTO, higher idle cost.

  • Is RDS Multi-AZ a read replica?

    No — it's a synchronous standby for failover HA. Use read replicas for read scaling (async).

  • SQS vs SNS?

    SQS = queue buffer, consumers pull. SNS = pub/sub fan-out, push to many subscribers. SNS→SQS for durable fan-out.

  • When EventBridge over SNS?

    Content-based routing, many AWS service events, SaaS partners, schedules, and fine-grained rules — an event bus, not just a topic.

  • Why a dead-letter queue?

    After max receive attempts, poison messages go to a DLQ so they don't block the main queue forever and can be inspected.

  • ALB vs NLB?

    ALB = L7 HTTP/HTTPS, path/host routing, WAF. NLB = L4 TCP/UDP, extreme performance, static IPs, PrivateLink.

  • EBS vs EFS vs S3?

    EBS = AZ-scoped block disk. EFS = Multi-AZ shared POSIX file. S3 = object storage via API, not a filesystem.

  • When S3 Intelligent-Tiering?

    Access patterns unknown or changing — auto-moves objects between tiers; good default when you can't predict IA vs hot.

  • One Zone-IA risk?

    Cheaper infrequent access stored in a single AZ — if that AZ is destroyed, data can be lost. Not for critical Multi-AZ durability.

  • CloudFront + private S3 modern pattern?

    Origin Access Control (OAC) so only CloudFront can read the bucket; users hit the distribution, not the bucket URL.

  • Route 53 failover routing?

    Health checks primary; if unhealthy, DNS returns secondary (e.g. DR Region). Latency/geolocation are different policies.

  • DynamoDB on-demand vs provisioned?

    On-demand = pay per request, spiky/unknown. Provisioned (+ auto scaling) = steady predictable traffic, often cheaper at scale.

  • ElastiCache use case?

    In-memory cache (Redis/Memcached) for hot reads, sessions, leaderboards — cut DB load and latency.

  • ECS/Fargate vs EKS vs Lambda?

    Fargate = simple serverless containers. EKS = managed Kubernetes. Lambda = event-driven functions, short runtime, pay-per-invoke.

  • Scale ASG workers on SQS?

    Use queue depth / age of oldest message as the scaling metric so backlog drives capacity.

  • Savings Plans vs RI?

    Both discount commit. Compute Savings Plans are flexible across families/Fargate/Lambda. RIs are more specific reservations.

  • When Spot Instances?

    Fault-tolerant, interruptible work (batch, CI, stateless fleets with baseline). Not sole stateful primary DBs.

  • Why Graviton for cost?

    AWS ARM CPUs often better price/performance than comparable x86 — prefer when the workload is compatible.

  • Cost Explorer vs Budgets?

    Explorer analyzes spend. Budgets alert (or act) on thresholds. Activate allocation tags for chargeback.

  • NAT Gateway purpose?

    Private subnet outbound internet without inbound exposure. Costly at scale — prefer endpoints for AWS APIs when possible.

  • PrivateLink / interface endpoint?

    Private connectivity to AWS services or NLB-fronted SaaS via ENIs in your VPC — no internet traversal.

  • Aurora storage HA fact?

    Aurora storage is replicated across AZs automatically; add reader instances for read scale and faster failover options.

  • S3 CRR requirement?

    Versioning on source (and usually destination); replication role; used for multi-Region object durability/DR.

  • Least privilege in one line?

    Grant only the actions and resources needed — prefer roles, scoped policies, and SCPs as org guardrails.

  • Shared responsibility — customer owns?

    In the cloud: data, identity, OS/app config (for IaaS), network controls, encryption choices. AWS owns the cloud infrastructure.

  • Sticky sessions downside?

    Uneven load and pain on instance replace. Prefer external session store (ElastiCache/DynamoDB) for scale-out.

  • API Gateway + Lambda pattern?

    Serverless HTTP APIs: scale to demand, pay per use — great for spiky/idle-heavy workloads.

  • Step Functions vs SQS?

    Step Functions orchestrate multi-step workflows with state, retries, branching. SQS is a dumb durable queue between producers/consumers.

  • Data transfer cost trap?

    Cross-AZ and internet egress cost money. Keep chatty tiers together; use CloudFront for public bytes; same-AZ / VPC endpoints reduce bills.

  • Four SAA-C03 domains?

    Design Secure, Resilient, High-performing, and Cost-optimized architectures — roughly 30 / 26 / 24 / 20% weighting.
