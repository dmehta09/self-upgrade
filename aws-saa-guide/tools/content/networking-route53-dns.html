DNS that steers traffic — and fails over.

Route 53 is authoritative DNS plus health-aware routing. SAA cares less about registrar trivia and more about record types, routing policies, alias vs CNAME, and private hosted zones for VPC name resolution.

01 Public vs private hosted zones

Public hosted zones answer on the internet. Private hosted zones answer inside associated VPCs — split-horizon friendly for internal service names.

In plain English analogy

Public DNS is the phone book everyone can buy. A private hosted zone is the internal company directory on the intranet — same names can point to different numbers inside vs outside. Routing policies are the receptionist deciding which office gets the call based on location, load, or who’s awake.

Alias records
Route 53-specific; point apex (example.com) to ALB, CloudFront, S3 website, API Gateway, etc. No extra charge for alias queries to AWS resources.
CNAME
Standard DNS; can’t sit on the zone apex. Use alias for apex → AWS targets.
TTL
Lower TTL = faster failover visibility, more query volume. Balance with health-check failover needs.

02 Routing policies that matter on SAA

Pick the policy from the stem’s goal: simple, failover, latency, geolocation/geoproximity, weighted, multivalue.

Common trap gotcha

DNS failover ≠ connection draining. Clients and resolvers cache TTLs; failover isn’t instant. For app-layer HA inside a Region, prefer ALB/NLB health checks. Use Route 53 failover for Region-level or discrete endpoint failover — and set TTLs knowingly. Alias to ALB still relies on the LB for target health within the Region.

03 Health checks & modern pairings

Route 53 health checks probe endpoints (or calculated/CloudWatch alarms). Pair with failover or multivalue. For global anycast acceleration of TCP/UDP, consider Global Accelerator — DNS still often points there.

Route 53 latency / failover
  • Works at DNS decision time
  • Great for Multi-Region web entry
  • Subject to TTL caching
Global Accelerator
  • Anycast IPs, steady endpoints
  • Fast regional failover on the AWS edge network
  • When stem wants static IPs + global performance

You need example.com (apex) to point to a CloudFront distribution. Which record type?

Right. Apex can’t be a CNAME in standard DNS. Route 53 alias records support CloudFront (and other AWS targets) at the zone apex.

04 Exam rapid-fire

Alias vs CNAME — when must you use alias?warm-up
Model answer

For the zone apex and when pointing to AWS resources like ALB/CloudFront/S3 website endpoints. Alias is Route 53-specific and avoids apex CNAME limitations.

Say it out loud say it

"Apex to ALB or CloudFront needs a Route 53 alias — not a CNAME."

Latency vs failover routing — which for what?core
Model answer

Latency sends users to the best-performing Region among healthy targets. Failover is active-passive: primary while healthy, else secondary — classic DR DNS pattern.

Say it out loud say it

"Latency optimizes performance across Regions; failover is primary/secondary DR."

When is a private hosted zone the answer?stretch
Model answer

When EC2/ECS/Lambda-in-VPC must resolve internal names (e.g., db.internal) without publishing them on the public internet — associate the zone with the right VPCs (and enable DNS hostnames/resolution).

Say it out loud say it

"Private hosted zones keep internal DNS inside the VPC — not on the public internet."
