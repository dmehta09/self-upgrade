SQS, SNS & EventBridge.

Decouple producers and consumers. Queues buffer work, topics fan out notifications, and the event bus routes events by rule. As of 2026, treat EventBridge as the default for application and SaaS events (not “raw CloudWatch Events” as the mental model).

01 Which primitive?

SQS = pull queue (buffer, retry, DLQ). SNS = push fan-out to many subscribers. EventBridge = content-based routing across buses, SaaS partners, and schedules.

In plain English analogy

SQS is a ticket spike at a deli — workers pull the next order when free. SNS is the PA system announcing “order 42” to every station at once. EventBridge is the smart mailroom that reads the envelope and routes only matching packages to the right floors (and can schedule nightly sweeps).

02 SQS & SNS details

Standard vs FIFO SQS
Standard = best-effort ordering, nearly unlimited throughput. FIFO = exactly-once processing within a group + ordered — use when the stem demands order.
Visibility timeout
Hide in-flight messages while processing; set ≥ worst-case work time.
DLQ
After maxReceiveCount failures, poison messages land here for inspection.
SNS + SQS
Classic fan-out: one SNS topic, many SQS queues (durable subscribers).
Common trap gotcha

Don't use SQS when you need instant push to many heterogeneous targets with filtering — that's SNS or EventBridge. Don't use EventBridge as a long durable work queue — put durable work in SQS (EventBridge can target SQS).

03 EventBridge as the 2026 default

Prefer EventBridge for application events, AWS service events, partner SaaS events, and Scheduler one-offs/crons. Rules filter on content; targets include Lambda, SQS, SNS, Step Functions, API destinations.

  • Default bus for AWS events; custom buses for your domain events; partner buses for SaaS.
  • Archive + replay for debugging and recovery.
  • Schema Registry helps discover event shapes.

Serverless consumers often sit on Lambda — see DevOps · Containers & serverless.

04 Interview rapid-fire

SQS vs SNS vs EventBridge?core
Model answer

SQS buffers work for competing consumers with retries/DLQ. SNS push-fan-outs one message to many subscribers. EventBridge routes events with rules — the 2026 default for app/SaaS/AWS events and schedules. Combine them: EventBridge/SNS → SQS for durable processing.

Say it out loud say it

"SQS queues work, SNS fans out, EventBridge routes events — default to EventBridge for event-driven designs."

Standard vs FIFO SQS?warm-up
Model answer

Standard maximizes throughput with at-least-once and best-effort order. FIFO preserves order per message group and supports exactly-once processing — use when the business requires sequence.

Say it out loud say it

"Need order or exactly-once → FIFO; otherwise Standard for scale."

Why EventBridge over “just SNS” for domain events?stretch
Model answer

EventBridge adds content filtering, multiple buses, SaaS partners, archive/replay, schemas, and Scheduler — SNS is simpler fan-out. For evolving event-driven architectures, EventBridge is the default bus.

Say it out loud say it

"EventBridge filters and routes across buses and partners; SNS is the blunt fan-out tool."
