Foundations · cloud mental model

Think in building blocks, not boxes.

SAA-C03 rewards architects who map requirements to AWS primitives — compute, network, data, identity — and pick the managed service that fits durability, scale, and blast radius. Skip “which logo?”; decide “what failure mode and who owns the patching?”

01 The five blocks every design uses

Every SAA answer is a composition of compute, network, storage/data, identity, and edge/integration. Name the block first; the service second.

In plain English analogy

AWS is a city of prefabricated rooms, not a blank lot. You don’t pour concrete for a kitchen — you rent a kitchen module (RDS), a hallway (VPC), and a front desk (IAM). Exam questions ask which module fits the guest list and the fire code, not how to build the stove.

EC2, Lambda, ECS/Fargate, EKS — where your code runs and how it scales.
Network
VPC, subnets, routes, endpoints, load balancers — who can talk to whom.
Storage / data
S3, EBS, EFS, RDS/Aurora, DynamoDB — durability, consistency, access pattern.
Identity
IAM roles, Identity Center, policies — least privilege, never long-lived keys on hosts.
Edge / integration
CloudFront, Route 53, API Gateway, SQS/SNS/EventBridge — global entry and decoupling.

02 Compose a request path

A “web app on AWS” stem is usually edge → load balancer → private compute → Multi-AZ data, glued with IAM roles. Trace one hop at a time before picking logos.

Acme tickets
Global fans + dynamic checkout → edge (CloudFront) + ALB + private app + Multi-AZ RDS. Identity = roles on compute, not keys in the AMI.
Ledger Co · overnight batch
Finance CSV land in S3 (data). EventBridge/SQS wakes a Fargate task (compute + integration). No public entry — VPC endpoints for S3, IAM task role only. Different blocks, same mental model.

03 Managed vs you-operate

Default to managed when the exam cites undifferentiated ops (patching, Multi-AZ failover, backups). Pick self-managed only when you need OS/kernel control or a constraint the managed service can’t meet.

You operate
  • EC2 + self-installed DB
  • You own patches, HA, backups
  • Exam usually wants this only for special OS or licensing
AWS managed (prefer)
  • RDS/Aurora, DynamoDB, ElastiCache
  • Fargate / Lambda over pet VMs
  • S3 over DIY object stores
Common trap gotcha

“EC2 can do anything” is true and wrong for the exam. If the stem says Multi-AZ automatic failover for a relational DB, the answer is RDS/Aurora, not “EC2 in two AZs with your own scripts.” Managed = the control plane does the HA dance.

04 The exam decision lens

Read stems for constraints: latency, RPO/RTO, compliance, cost, throughput, “no internet,” “least privilege.” Constraints kill otherwise-valid options.

1

Underline the hard requirement

Words like must, cannot leave the VPC, global users, cost-effective, strong consistency.

2

Map to a block

Is this really a storage question wearing a compute costume?

3

Eliminate overkill

Multi-Region when Multi-AZ suffices; NAT when a gateway endpoint works.

A team needs a relational DB with automatic Multi-AZ failover and managed backups. They already know MySQL. What’s the SAA-default pick?

Right. Relational + managed Multi-AZ + backups → RDS/Aurora. DynamoDB is NoSQL; DIY MySQL on EC2 shifts HA onto you — the exam almost never wants that when managed exists.

05 Exam rapid-fire

How do you approach a vague “design a web app on AWS” stem?warm-up
Model answer

I name the blocks: public entry (ALB or CloudFront+ALB), compute in private subnets (ASG or Fargate), data store Multi-AZ (RDS/Aurora or Dynamo), IAM roles not keys, and decide Multi-AZ vs Multi-Region from RPO/RTO. Then I trim cost with Graviton, Savings Plans, and VPC endpoints for AWS traffic.

Say it out loud say it

"I sketch entry, private compute, Multi-AZ data, and IAM roles — then I only add Multi-Region or extra services if the RPO/RTO or constraints demand it."

When is “managed service” the wrong answer?core
Model answer

When you need a custom kernel, unsupported engine, or a licensing/ISO image that managed won’t run — or when the stem explicitly requires full OS control. Otherwise prefer managed for HA, patching, and backups.

Say it out loud say it

"Managed unless I need OS-level control the service doesn’t offer — the exam loves managed Multi-AZ by default."

What’s the difference between a requirement and a preference on SAA?stretch
Model answer

Requirements are hard constraints (compliance, “no public IPs,” RPO=0 within a Region). Preferences are soft (“simple,” “cost-effective”). Over-engineering for a preference loses points; missing a requirement always loses.

Say it out loud say it

"I satisfy musts first, then pick the cheapest or simplest option that still meets them."
