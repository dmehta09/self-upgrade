API Gateway & Step Functions.

Front doors for HTTP/WebSocket APIs, and durable workflows that orchestrate Lambda, services, and human approvals. The exam separates request/response APIs from long-running orchestration.

01 API Gateway flavors

HTTP APIs = cheaper/faster for most Lambda/JWT proxies. REST APIs = full feature set (API keys, WAF-heavy enterprise patterns, usage plans). WebSocket APIs = bidirectional chat/push.

In plain English analogy

API Gateway is the hotel front desk — auth, rate limits, and routing guests to the right room (Lambda, HTTP backend). Step Functions is the concierge checklist for a multi-day event: do A, wait for B, retry C, escalate to a human if stuck.

02 Step Functions

flowchart TD
  start[Start] --> task1[TaskLambda]
  task1 --> choice{Success}
  choice -->|yes| task2[TaskService]
  choice -->|no| retry[RetryThenCatch]
  retry --> dlq[AlertOrSQS]
  task2 --> wait[WaitOrCallback]
  wait --> endNode[End]
Standard workflows
Long-running (up to 1 year), exactly-once, full history — human approvals, ETL sagas.
Express workflows
High-volume, short duration, at-least-once — streaming/event enrichment.
Integrations
Call AWS SDK APIs directly; reduce “Lambda glue.”
Error handling
Retry/Catch with backoff; map over arrays; parallel branches.
Common trap gotcha

Don't orchestrate long multi-step business processes inside a single Lambda with sleeps — use Step Functions. Don't use Step Functions as a dumb queue — durable buffering is still SQS. API Gateway sync integrations must finish within API timeouts; async patterns use callbacks or queues.

03 Combining the two

  • API Gateway → Lambda for simple request/response.
  • API Gateway → Step Functions (sync/async start) for multi-step workflows.
  • EventBridge rule → Step Functions for event-driven orchestration.
  • Express + EventBridge for high-volume pipelines; Standard for durable sagas.

Loan application needs credit check, manual underwriter approval (days), then funding — with retries. Best orchestration?

Right. Multi-day durable orchestration with human steps → Standard Step Functions. Lambda sleeps are billed/fragile; API Gateway alone has no long-running state.

04 Interview rapid-fire

HTTP API vs REST API on API Gateway?warm-up
Model answer

HTTP APIs are cheaper and lower latency for common Lambda/JWT proxy cases. REST APIs unlock richer features (usage plans, API keys, more middleware-style options). Pick HTTP unless you need REST-only features.

Say it out loud say it

"HTTP API by default; REST when I need usage plans or the heavier feature set."

Standard vs Express Step Functions?core
Model answer

Standard for long-running, auditable, exactly-once workflows (approvals, sagas). Express for high-volume, short, at-least-once pipelines where cost/throughput matter more than year-long duration.

Say it out loud say it

"Days and human waits → Standard. Flood of short events → Express."

When is Step Functions better than chaining Lambdas?stretch
Model answer

When you need visible state, retries/catches, parallel branches, waits, and service integrations without custom glue. Chained Lambdas hide failures and reinvent orchestration; Step Functions is the managed state machine.

Say it out loud say it

"Multi-step with retries and waits → Step Functions, not Lambda calling Lambda in a loop."
