Foundations · shared responsibility Domain 1 · Secure

AWS secures the cloud; you secure in it.

Shared Responsibility is the security framing behind IAM, encryption, patching, and network isolation questions. The line moves with the service model — more managed means AWS owns more of the stack, but never your data classification or identity choices.

01 Where the line sits

AWS is responsible for security of the cloud (facilities, hardware, virtualization, global network). You are responsible for security in the cloud (OS/apps where applicable, data, identity, network config, encryption choices).

In plain English analogy

AWS is the landlord of a secured apartment building: locks on the lobby, cameras in the halls, fire systems. You still lock your own door, decide who gets keys, and don’t leave passports on the kitchen table. Renting a furnished suite (Lambda) doesn’t mean strangers can read your mail — you still own the contents.

Responsibility shifts by abstraction
EC2
You patch OS
SG, IAM, data
RDS / Fargate
AWS patches more
You: data, IAM, net
Lambda / S3
AWS runs platform
You: code, ACLs, keys
Higher abstraction → AWS owns more patching; you still own identity and data.

Common trap gotcha

“AWS encrypts everything for me” is incomplete. Many services offer encryption defaults or easy toggles (S3 SSE, EBS, RDS), but you choose CMKs vs AWS-managed keys, key policies, and whether client-side encryption is required. Misconfigured bucket policies remain your incident.

03 Modern identity defaults

Prefer IAM roles and IAM Identity Center over long-lived access keys. Prefer instance/task/Lambda roles and OIDC federation from CI.

Humans
Identity Center (SSO) → short-lived roles into accounts; MFA enforced.
Workloads
EC2 instance profiles, ECS task roles, Lambda execution roles, EKS Pod Identity / IRSA.
Automation
GitHub Actions / GitLab OIDC assume-role — no static keys in secrets if avoidable.

On Amazon RDS for PostgreSQL, who is responsible for applying database engine patches?

Right. RDS is managed: AWS patches the engine/host. You don’t SSH the underlying OS. You still own DB users, data, and network access.

04 Exam rapid-fire

State shared responsibility in one sentence.warm-up
Model answer

AWS secures the cloud infrastructure; customers secure what they put in it — identities, configurations, applications, and data — with the customer share shrinking as the service becomes more managed.

Say it out loud say it

"AWS protects the cloud; I protect my configs, identities, and data inside it."

EC2 vs Lambda — what do you still patch?core
Model answer

On EC2 you patch the guest OS and apps. On Lambda, AWS patches the execution environment; you still secure your code, dependencies, IAM role, and any VPC/network settings.

Say it out loud say it

"EC2: I own the OS. Lambda: AWS owns the runtime host; I still own code and IAM."

Is encryption “AWS’s job” or yours?stretch
Model answer

Both: AWS provides the mechanisms (KMS, SSE, TLS endpoints); you decide when encryption is required, which keys, key policies, and that clients enforce TLS. Leaving a bucket unencrypted or world-readable is on you.

Say it out loud say it

"AWS gives me KMS and SSE; I choose keys and policies so data is actually protected."
