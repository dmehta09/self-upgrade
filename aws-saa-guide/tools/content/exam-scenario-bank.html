Exam prep · scenario bank

Architecture scenarios, SAA style.

Twenty design stems across Secure · Resilient · High-performing · Cost. Expand each card: best answer, why, and the domain chip. Reason out loud before you open.

01 Secure architectures

App on EC2 must call S3 without long-lived keys on the instance.Secure
Best answer

Attach an IAM role to the instance (instance profile) with least-privilege S3 permissions; use the AWS SDK default credential chain.

Why

Roles issue temporary credentials via IMDS. Access keys in files/userdata are an anti-pattern the exam punishes.

Private EC2 must reach S3 without internet / NAT.Secure
Best answer

Gateway VPC endpoint for S3 (or Interface endpoint) + endpoint policy; keep the bucket private.

Why

Traffic stays on the AWS network. NAT works but adds cost and public path — wrong when "no internet" is stated.

Enforce encryption on all new S3 buckets org-wide.Secure
Best answer

SCP (and/or Config Rules + remediation) denying s3:CreateBucket / Put without encryption; prefer SSE-S3 or SSE-KMS defaults.

Why

Account-level IAM alone doesn't govern every member account — Organizations SCPs set a floor.

Web app needs protection from common Layer-7 exploits and volumetric DDoS.Secure
Best answer

CloudFront + AWS WAF (+ Shield Standard included; Shield Advanced if the stem demands premium DDoS features/cost tradeoff).

Why

WAF filters HTTP rules; Shield absorbs volumetric attacks at the edge. SG alone is L3/L4 and insufficient for SQLi/XSS stems.

DB credentials must not live in code or AMI; rotate automatically.Secure
Best answer

Secrets Manager (or Parameter Store SecureString + rotation Lambda) with IAM auth to fetch at runtime; KMS encryption.

Why

Secrets Manager natively rotates RDS/Aurora credentials. Hardcoded secrets fail both security and operations stems.

02 Resilient architectures

Survive AZ failure for a three-tier web app with RDS.Resilient
Best answer

ALB + ASG across ≥2 AZs; RDS Multi-AZ; subnets in multiple AZs.

Why

Multi-AZ is the default HA pattern. Multi-Region is overkill if only AZ failure is in scope.

RTO < 1 hour, RPO near-zero, tolerate Region loss, control cost.Resilient
Best answer

Pilot light or warm standby in a second Region with continuous DB replication (Aurora Global / cross-Region replica) + Route 53 failover.

Why

Cold daily backups miss RPO/RTO; full active-active overspends when "control cost" appears.

Order API must accept requests even if fulfillment is slow/down.Resilient
Best answer

API writes to SQS; workers consume asynchronously; DLQ for poison messages.

Why

Decoupling turns dependency failure into backlog instead of 5xx for users.

Notify email, Lambda, and a queue from one business event.Resilient
Best answer

SNS topic with those subscriptions (SQS subscription for durability), or EventBridge rules to multiple targets.

Why

Pub/sub fan-out; SQS alone is 1:1 pull, not multi-protocol fan-out.

Need point-in-time restore for DynamoDB tables.Resilient
Best answer

Enable DynamoDB PITR (continuous backups) and/or on-demand backups; AWS Backup for centralized policy.

Why

PITR covers fine-grained RPO; EBS snapshots don't apply to DynamoDB.

03 High-performing architectures

Global users, mostly static assets, lowest latency.High-performing
Best answer

S3 origin + CloudFront (optional OAC); cache at edge.

Why

Edge caches cut origin load and RTT. Multi-Region active app stacks are overkill for static.

Read-heavy relational DB; writes are modest.High-performing
Best answer

Aurora/RDS read replicas (or Aurora readers) + connection routing; cache hot keys in ElastiCache if needed.

Why

Scale reads horizontally; Multi-AZ standby is not a read replica for classic RDS.

Millions of key-value lookups with single-digit ms latency.High-performing
Best answer

DynamoDB (DAX if microsecond cache) or ElastiCache in front of a DB — pick based on whether Dynamo is already the system of record.

Why

Single-node RDS won't meet that scale/latency; design for access patterns.

TCP/UDP ultra-low latency load balancing to game servers.High-performing
Best answer

Network Load Balancer (NLB) — L4, preserves source IP, extreme performance.

Why

ALB is L7 HTTP/HTTPS. Classic CLB is legacy. NLB fits non-HTTP and latency-sensitive.

Shared POSIX file system for many EC2 across AZs.High-performing
Best answer

EFS (Regional, Multi-AZ). FSx when Windows/Lustre/NetApp features are required.

Why

EBS is single-AZ. S3 is object, not POSIX. Instance store is ephemeral and local.

04 Cost-optimized architectures

Steady 24×7 EC2/Fargate fleet; maximize savings with flexibility.Cost
Best answer

Compute Savings Plans (after right-sizing); prefer Graviton where possible.

Why

Steady → commit. Compute SP beats rigid RI when families may change.

Fault-tolerant nightly analytics jobs; minimize compute cost.Cost
Best answer

Spot (EMR/ASG/Batch with diversified pools); checkpoint progress.

Why

Interruptible + cheap. On-Demand Savings Plans waste money on batch that can die.

Petabytes in S3; rarely accessed after 90 days.Cost
Best answer

Lifecycle rules to IA / Glacier Instant / Deep Archive — or Intelligent-Tiering if access is unpredictable.

Why

Storage class is the cost lever; replication alone doesn't reduce $/GB.

Spiky API, idle most of the night; minimize idle cost.Cost
Best answer

API Gateway + Lambda (or Aurora Serverless v2 / Fargate scale-to/near-zero patterns as fit).

Why

Pay per use beats always-on ASG for sparse traffic.

Finance wants alerts before monthly spend blows the budget.Cost
Best answer

AWS Budgets with SNS notifications (and Cost Explorer / Anomaly Detection for investigation).

Why

Budgets are the threshold tool; CloudWatch CPU alarms don't watch dollars.

05 Mixed / trick stems

Secure + resilient: public web, private app/DB, Multi-AZ.Secure
Best answer

Public subnets: ALB only. Private: app ASG. DB: private Multi-AZ RDS; SG least privilege; no bastion keys if SSM Session Manager fits.

Why

Classic three-tier VPC — security groups as primary firewall, Multi-AZ for resilience.

Perf + cost: cache session data for a fleet of web servers.High-performing
Best answer

ElastiCache (Redis) shared across instances — not sticky sessions alone on one node.

Why

Externalized sessions enable scale-out and survive instance replace; cheaper than oversized sticky singles.

Who changed a security group last Tuesday?Secure
Best answer

CloudTrail (optionally Config for before/after config).

Why

API attribution is Trail; Config answers compliance history, not identity by itself.
