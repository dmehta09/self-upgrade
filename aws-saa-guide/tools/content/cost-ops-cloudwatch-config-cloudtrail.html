Metrics, config truth, and an audit trail.

CloudWatch watches health and performance. Config records what resources look like and whether they comply. CloudTrail records who did what via the API. Different questions — don't swap them on the exam.

01 Three tools, three questions

"Is it healthy?" → CloudWatch. "Is it configured correctly / what changed?" → Config. "Who called the API?" → CloudTrail.

In plain English analogy

CloudWatch is the car's dashboard (speed, temp). Config is the inspection checklist (did someone remove the seatbelts?). CloudTrail is the security camera of who opened the hood.

flowchart TD
  q1[Is_it_healthy] --> cw[CloudWatch]
  q2[Is_config_compliant] --> cfg[AWS_Config]
  q3[Who_changed_what] --> ct[CloudTrail]
  cw --> alarm[Alarms_SNS]
  cfg --> rules[Config_Rules]
  ct --> lake[Trail_to_S3_or_Lake]

02 CloudWatch essentials

Metrics & alarms
CPU, ALB 5xx, custom metrics → alarm → SNS / Auto Scaling / incident chat.
Logs
Log groups; metric filters turn log patterns into alarms.
Dashboards
Ops visibility; not a substitute for alarms.
Events → EventBridge
Schedule and react to AWS events (modern home for many "CloudWatch Events" patterns).
Common trap gotcha

CloudWatch does not replace CloudTrail for API audit. Config is not a performance monitor. Turning on a trail without an S3 bucket / Lake destination (and encryption) fails the "audit" stem.

03 Config & CloudTrail

  • Config — continuous inventory + history; Config Rules (managed or custom) for "S3 must be encrypted," "SG must not be 0.0.0.0/0," etc. Conformance packs for packs of rules.
  • CloudTrail — management (and optional data) events; multi-Region trail to S3; org trail from the management account; CloudTrail Lake for searchable history.
  • Together — Trail shows who changed a SG; Config shows what the SG was before/after and whether it violates a rule.

Security needs proof of which IAM principal opened an S3 bucket to public and whether buckets stay encrypted. Best pair?

Right. Attribution is CloudTrail; continuous compliance posture is Config. Metrics and billing tools don't answer that.

04 Exam rapid-fire

CloudWatch vs CloudTrail vs Config — one line each.warm-up
Model answer

CloudWatch = metrics/logs/alarms (health). CloudTrail = API activity audit. Config = resource configuration history + compliance rules.

Say it out loud say it

"Dashboard, camera, and inspection checklist — don't mix them up."

How do you alarm on a log phrase?core
Model answer

Send logs to CloudWatch Logs, create a metric filter for the pattern, alarm on that metric, notify via SNS.

Say it out loud say it

"Turn the log line into a metric, then alarm like any other metric."

Org-wide audit of API calls?core
Model answer

Create an organization trail in the management account, multi-Region, deliver to a locked-down S3 bucket (or CloudTrail Lake), encrypt with KMS, restrict who can stop logging.

Say it out loud say it

"One org trail to a vaulted bucket — every account, every Region."
