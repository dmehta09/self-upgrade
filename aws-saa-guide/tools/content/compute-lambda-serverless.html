Lambda & serverless compute.

Event-driven functions that scale to zero. Know triggers, limits (15 min, concurrency, cold starts), VPC ENI implications, and when to prefer containers instead.

01 Mental model & triggers

You ship a handler; AWS runs it on events. Pay for requests + GB-seconds. Prefer Graviton (Arm) architectures for Lambda when packages support it — better price-performance.

In plain English analogy

Lambda is a food truck that fires up only when an order arrives — you pay while it’s cooking, then it shuts off. Great for spikes; awkward for an always-open sit-down restaurant (long-lived WebSockets, multi-hour jobs).

Common trap gotcha

Recursive Lambda (function writes to the same S3 bucket that triggers it) can loop until spend explodes — use prefixes, conditions, or reserved concurrency = 0 as emergency brake. Also: Lambda in VPC still needs a path to AWS APIs — prefer VPC endpoints / PrivateLink over “give it a NAT and hope.”

03 When Lambda wins vs containers

Choose Lambda when…
  • Spiky / idle-most-of-the-time workloads
  • Glue between AWS events
  • Short APIs and stream processors
  • You want scale-to-zero cost
Choose ECS/EKS when…
  • Long-running or steady 24/7 services
  • Custom runtimes / sidecars / sticky sockets
  • Jobs > 15 minutes
  • Heavy local state or specialized networking

Container alternative when you need long-running processes: ECS vs EKS.

Resize images on S3 upload; traffic is bursty and idle overnight. Best fit?

Right. Event-driven + idle → Lambda. Always-on polling wastes money; Classic/single-AZ is an HA anti-pattern.

04 Interview rapid-fire

Name three hard Lambda limits for architecture.core
Model answer

15-minute invocation cap, statelessness (durable state elsewhere), and cold starts / concurrency affecting latency and throughput. Those three decide when to move to containers or Step Functions.

Say it out loud say it

"Fifteen minutes, no durable local state, and cold start plus concurrency caps — that’s when I reach for ECS or Step Functions."

How does Lambda get AWS credentials?warm-up
Model answer

Via its execution role — temporary credentials injected by the Lambda service. Scope the role to exact APIs/resources. Never put long-lived access keys in environment variables.

Say it out loud say it

"Execution role only — short-lived creds, least privilege, no access keys in env."

Sync API vs SQS-triggered Lambda?stretch
Model answer

API Gateway → Lambda is request/response with client-facing latency and timeouts. SQS → Lambda is asynchronous buffering: absorb spikes, retry with visibility timeout, send poison messages to a DLQ. Use queues when producers shouldn’t block on processing.

Say it out loud say it

"Sync for user-facing APIs; SQS when I need a buffer, retries, and DLQ between producer and worker."
