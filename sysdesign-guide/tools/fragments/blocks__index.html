Building blocks · overview

The boxes you draw.

Almost every architecture is assembled from the same small kit of parts. Learn what each box does and when to reach for it, and "design a scalable backend" becomes a matter of arranging familiar pieces. This module is that kit; the rest of the guide just combines them.

01  The path of a request

In plain English analogy

It's a LEGO set. There's a small box of standard bricks — a baseplate, beams, connectors — and almost anything you build is those same pieces arranged differently. Learn what each brick does once, and "design a scalable backend" stops being scary: it's just clicking familiar parts together in the right order.

02  The kit, box by box

Each gets its own lesson. As a map:

Load balancer
Spreads incoming traffic across many identical servers, and routes around dead ones. The reason you can add capacity by adding boxes.
API gateway / reverse proxy
The front door: TLS, auth, rate limiting, routing to the right service. One place for cross-cutting concerns.
CDN
A global cache for static (and increasingly dynamic) content, served from the edge so bytes travel a short distance.
Cache
An in-memory store (Redis/Memcached) for hot data, turning slow database reads into ~1 ms lookups.
Message queue / stream
Decouples producers from consumers so slow work happens asynchronously and spikes get absorbed.
Database
The durable source of truth — SQL or NoSQL, sharded and replicated. Covered in the Data module.
The golden rule: keep services stateless

If your app servers hold no per-user state (sessions live in a cache/DB, not in memory), then any server can handle any request — so a load balancer can spread traffic freely and you scale by simply adding more boxes. Almost every scaling story starts here.

In this stack, where does slow or non-urgent work (sending emails, updating analytics) belong?

Right: anything that doesn't need to finish before replying to the user goes on a queue and is processed by background workers. It keeps the request path fast and lets a traffic spike grow the queue instead of timing out users.
