Reference · glossary

Glossary.

Every term used in this guide, defined in one line. Skim it before an interview, or jump here whenever a word on another page is fuzzy. Grouped by theme; press / to search the whole guide.

Fundamentals

Latency
Time for one request to complete. You optimise the tail (p99), not just the average.
Percentile (p50 / p95 / p99)
The latency value a fraction of requests beat: p99 = 99% are faster, the slowest 1% worse (p50 = median; p999 = p99.9). Optimise the tail — fan-out makes a rare slow call the common case. See the numbers.
Throughput
Work done per unit time — e.g. requests/second (QPS) or tokens/second.
QPS
Queries per second. The headline load number you estimate first.
Back-of-the-envelope
Quick order-of-magnitude estimation of QPS, storage, and bandwidth from a few assumptions.
Availability
Fraction of time the system is up, quoted in "nines" (99.9% = three nines).
SLI / SLO / SLA
The measured indicator (good ÷ valid requests) / your internal objective for it / the contractual agreement with customers (looser, with penalties). See availability.
Error budget
100% − SLO — the amount of failure you're allowed per window (99.9%/month ≈ 43 min). Spent on risky releases; when exhausted, freeze changes and fix reliability. See error budgets.
Horizontal vs vertical scaling
Add more machines (out) vs make one machine bigger (up). Horizontal scales further but needs statelessness.
Stateless service
A server that holds no per-user state, so any instance can serve any request — the basis of easy scaling.

Networking & delivery

Load balancer
Spreads requests across a server pool and routes around dead ones (L4 = transport, L7 = HTTP-aware).
Reverse proxy
Server-side proxy facing clients; basis of an API gateway.
API gateway
The front door: TLS, auth, rate limiting, and routing in one place.
CDN
Globally distributed caches that serve content from an edge near the user.
Cache hit ratio
Fraction of requests served from cache; the metric that decides how much load reaches your origin.
WebSocket
A persistent, bidirectional connection enabling the server to push data (real-time chat, presence).
Long polling / SSE
Hold a request open for updates / one-way server→client stream — lighter alternatives to WebSockets.

Data & storage

ACID
The strong transaction guarantees of relational databases: Atomicity (all-or-nothing), Consistency (a valid state moves only to another valid state), Isolation (concurrent transactions don't see each other's half-done work), Durability (once committed, data survives a crash).
BASE
Basically Available, Soft state, Eventual consistency — the looser NoSQL philosophy.
Index
A sorted side structure that turns a full scan into an O(log n) lookup; speeds reads, slows writes.
LSM-tree
Write-optimised index: buffer writes in memory, flush to immutable sorted files, compact in the background (Cassandra, RocksDB). The B-tree's mirror image.
Inverted index
Term → documents-containing-it; the engine behind full-text search.
Sharding / partitioning
Splitting data across machines by a shard key to scale writes and storage.
Shard key
The field that decides a record's shard. A near-irreversible choice — pick for even load + local queries.
Replication
Keeping copies of data on multiple machines for durability and read scaling.
Leader–follower
One node takes writes and streams them to read replicas; a follower is promoted on failure.
Quorum (W + R > N)
Requiring overlapping read/write majorities so reads see the latest write in leaderless stores.
Consistent hashing
Mapping keys to nodes on a ring so adding/removing a node moves only ~1/N of keys.
Object storage
Cheap, durable, near-infinite blob store (S3-like) for large immutable files.
Write-ahead log (WAL)
Append-only log written before applying changes, enabling durability and replication.
Bloom filter
Compact probabilistic set: "definitely not present" or "maybe present" — no false negatives.

Caching & messaging

Cache-aside
App reads cache, falls back to the DB on a miss and fills the cache. The default pattern.
Write-through / write-back
Write to cache+DB together / write to cache and flush to DB later (fast but loss-prone).
Eviction (LRU / LFU)
Policies for dropping data when the cache is full — least-recently / least-frequently used.
Hot key
One key so popular it overloads its single node; fixed by replicating the key.
Cache stampede
Many requests miss a just-expired key at once and hammer the DB; fixed with jitter/coalescing.
Message queue
Buffer that decouples producers from consumers for async work and spike absorption.
Pub/sub
One message delivered to every subscriber (fan-out), vs a work queue's one-of-N.
Kafka / event log
Partitioned, replayable, ordered log; consumers track their own offset.
Idempotency
An operation safe to repeat — doing it twice has the same effect as once (key the request).
Dead-letter queue
Where repeatedly-failing messages go for inspection instead of blocking the line.
Fan-out (write vs read)
Doing work at write time (push to all) vs read time (gather on demand) — the feed trade-off.

Reliability & consistency

CAP theorem
During a partition, choose Consistency or Availability (Partition tolerance is mandatory).
PACELC
CAP plus the normal case: Else, trade Latency vs Consistency. The 2026-expected framing.
Strong consistency
Every read sees the latest write. Needs coordination → costs latency/availability.
Eventual consistency
Replicas converge over time; reads may be briefly stale. Fast and available.
Read-after-write
You always see your own latest change, even if others see it slightly later.
Failover
Detecting a failure and routing to a healthy replacement (active-passive / active-active).
Leader election / consensus
Algorithms (Raft, Paxos) for replicas to agree on one leader / one value.
Circuit breaker
Stop calling a failing dependency for a while so you don't pile on and cascade.
Rate limiter
Caps requests per client/window (token bucket, sliding window) to protect the system.
Idempotency key
A unique token attached to a request so retries are deduplicated — core to correct payments.
