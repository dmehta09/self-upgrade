Advanced · YouTube / Netflix

Design video streaming.

Let anyone upload a video and let everyone, on any device and any connection, watch it smoothly. The bytes are gigantic, so two things dominate: a transcoding pipeline (one upload → many qualities/codecs, in parallel) and a CDN (serve from the edge). Egress bandwidth — not storage or compute — is the bill, which is why every choice optimises bytes-on-the-wire.

01  Requirements & capacity

✅

Functional

Upload (resumable); process into streamable formats; watch with adaptive quality; search + recommend.

📐

Non-functional

EB-scale storage, enormous read bandwidth, global low-latency playback, and cost control (egress dominates by 1–2 orders of magnitude).

Anchor: ~500 h uploaded/min → ~720k video-hours/day; >1B watch-hours/day. At ~3 Mbps blended, 1B watch-hours ≈ ~1.35 EB/day egress — ~100–250× the ingest bytes. Even at $0.003/GB that's ~$4M/day, so a 1-point CDN-offload gain or a codec that cuts bytes ⅓ is worth enormous money.

GET/seg/{id}/{rendition}/{n}.m4simmutable CMAF segment — long CDN TTL

Polyglot persistence: video metadata (title, codecs, rendition catalog, DRM key refs) in a sharded RDBMS; raw mezzanine + transcoded segments in object storage (immutable, content-addressed); and view counts in a separate high-write counter store — never in the metadata row (a hot trending video would melt that row). Resumable uploads must terminate at the nearest edge PoP to cut first-byte latency.

03  The upload & transcoding pipeline

The raw upload lands in object storage; the creator sees "processing…" instantly. A DAG of jobs then chunks the video (GOP-aligned), transcodes each chunk across a farm in parallel, stitches, packages (CMAF), and warms the CDN — with thumbnails, captions, and QC on parallel branches.

Per-title (and per-shot) encoding

Instead of a fixed ladder, run trial encodes, plot bitrate-vs-quality (VMAF) curves, and pick rungs on the convex hull. Simple content reaches 1080p at ~1.5 Mbps; complex "water/action" content caps at 720p even at 8 Mbps. Netflix goes per-shot (Dynamic Optimizer). The encode happens once and is amortised over billions of views, so spending compute to save bytes always wins — which is also why Google built the Argos VCU ASIC (~20–33× transcode efficiency).

04  Adaptive bitrate, codecs & the player

The watch path is almost entirely CDN: the player fetches a small manifest (the bitrate ladder), then streams immutable segments from the nearest edge, switching quality per segment. Protocols: HLS (.m3u8) and MPEG-DASH (.mpd), converging on CMAF (one set of fMP4 segments, both manifests, encrypt once for 3 DRMs). Low-latency (LL-HLS / CMAF-LL) uses ~200–400 ms partial chunks for ~2–5 s glass-to-glass.

abr.py
# ladder: ascending [(bitrate_bps, height)]; measured_bps: EWMA of recent segment throughput
def pick_rendition(ladder, measured_bps, buffer_s,
                   safety=0.85, low_buf=10, panic_buf=4):
    usable = measured_bps * safety                 # headroom for variance
    affordable = [r for r in ladder if r[0] <= usable]
    pick = affordable[-1] if affordable else ladder[0]   # else lowest rung

    if buffer_s < panic_buf:
        return ladder[0]                           # near-stall: drop to floor
    if buffer_s < low_buf:
        return pick                                # cautious: throughput-bounded
    idx = ladder.index(pick)                        # healthy buffer (BOLA-style):
    if idx + 1 < len(ladder) and buffer_s > 2 * low_buf:
        return ladder[idx + 1]                     # spend buffer to raise quality
    return pick

Production players are hybrid: throughput-based when the buffer is low (startup/seek), buffer-based (BOLA) when healthy — and never switch up so hard you risk a rebuffer. On codecs (2026): AV1 is the dominant VOD codec (~⅓ less bandwidth than H.264; Netflix ~30% of streaming, YouTube >75% of videos), with H.264 as the live/fallback baseline. AV1 encode is far costlier — fine for VOD (encode once), not for live.

05  CDN, the edge & cost

Multi-tier
edge PoP → regional mid-tier (origin shield, collapses duplicate misses) → origin/object storage. Immutable segments → long TTLs → very high hit rates.
Head vs long tail
Cache the popular head hot at the edge; the cold long tail lives in cheaper storage and is fetched on demand. Optimise byte-offload (≥95%), not request hit-ratio — bytes map to dollars.
Owned CDNs
Netflix Open Connect embeds appliances inside ISP networks (~190+ Gbps each) so popular bytes never touch transit. Multi-CDN steering adds resilience + price leverage.
Cost levers
per-title + AV1 (fewer bytes), owned/embedded CDNs (near-zero marginal transit), CMAF (encode once for HLS+DASH+3 DRMs), custom transcode silicon to make the expensive recipes cheap at 500 h/min ingest.

06  Failure, multi-region & observability

🔁

Transcode failure

Jobs are idempotent (content-addressed outputs) + retried with backoff; chunk-level granularity re-runs only the failed chunk. Poison jobs → DLQ so one bad upload can't block the farm.

📤

Resumable upload

Chunked + 308/Range resume survives flaky networks; partial bytes persisted so the client never restarts from zero.

🌍

Multi-region

Regional storage (residency + locality), global CDN for delivery, upload at the nearest ingest PoP; immutable segments are safe to serve stale on origin/PoP failover.

📊

QoE observability

Rebuffer ratio (SLO < 1%), startup/join time (2 s delay → >50% abandon), start-failure rate (< 0.5%), bitrate served, CDN byte-offload (≥95%). Alert on rebuffer spike by region/CDN/ISP and byte-offload drops (cost blowout).

07  Trade-offs & interview recap

Why transcode each upload into many bitrates and chop it into short segments up front?

Right: pre-made bitrate ladders + short segments enable adaptive bitrate streaming (smooth playback on any connection) and make playback a series of cacheable edge fetches — the two things that make global streaming work and stay affordable.
Say this to nail it

"Upload to object storage, then an async transcode DAG chunks the video and encodes a per-title bitrate ladder in AV1 (encode once, amortise over billions of views). Package as CMAF so one set of segments serves HLS+DASH and encrypts once for three DRMs. The watch path is ~95%+ CDN: the player runs hybrid ABR over immutable, cacheable segments. The entire design optimises egress because that's the dominant cost — per-title encoding, AV1, byte-offload, and owned/embedded CDNs are all bytes-on-the-wire levers."
