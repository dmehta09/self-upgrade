The cheat sheet.

One page to skim the night before an interview: the numbers, the formulas, the seven-step method, a few hard-won heuristics, and where to go deeper. Everything here is taught in full elsewhere in the guide — this is the compressed version.

Latency numbers (rounded)

OperationTime
L1 / RAM reference~1 ns / ~100 ns
Read 1 MB from RAM~3 µs
SSD random read~16 µs
Datacenter round trip~0.5 ms
Read 1 MB from SSD~1 ms
Round trip, same continent~30 ms
Round trip, intercontinental~150 ms

The story: memory ≫ SSD ≫ disk ≫ network. Cache to stay in memory; move data near users to beat the speed of light. Full lesson →

Sizes & powers of two

Seconds / day
86,400 ≈ 10⁵. So 1M/day ≈ ~12/s; 1B/day ≈ ~10,000/s.
2¹⁰ / 2²⁰ / 2³⁰ / 2⁴⁰
≈ thousand (KB) / million (MB) / billion (GB) / trillion (TB).
Item sizes
char 1 B · int/long 4–8 B · UUID 16 B · tweet ~300 B · photo 0.5–5 MB · 1 min HD video ~50 MB.
Peak factor
Multiply average QPS by ~2–10× to design for spikes, not the mean.

Capacity formulas

Write QPS
DAU × writes-per-user-per-day ÷ 86,400
Read QPS
write QPS × read:write ratio
Peak QPS
(read + write QPS) × peak factor
Storage
writes/day × bytes/item × retention-days × replication
Bandwidth
QPS × bytes/item
Servers
⌈ peak QPS ÷ per-server QPS ⌉

The 7-step method

1

Clarify & scope

Ask questions; agree a small core; name what's out of scope.

2

Requirements

Functional + non-functional. "Read-heavy or write-heavy? How fresh must data be?"

3

Estimate

QPS, storage, bandwidth — numbers justify every choice.

4

API

A few endpoints to pin the contract.

5

Data model

Core entities; SQL vs NoSQL from the access pattern.

6

High-level design

Draw the boxes and the request path; start simple.

7

Deep-dive & scale

Caches, shards, replicas, queues where the numbers demand. Name trade-offs & bottlenecks.

Heuristics that usually apply

  • Read-heavy? Cache hard; add read replicas; precompute.
  • Write-heavy? Queue + batch; wide-column store; shard by the write key.
  • Needs to feel instant globally? CDN + regional replicas; move data near users.
  • Must be correct (money, inventory)? Strong consistency, ACID, idempotency keys.
  • Can tolerate staleness (likes, feeds)? Eventual consistency, async, cache.
  • Real-time push? WebSockets + a session registry.
  • Find nearby? Geospatial index (geohash/QuadTree).
  • Spiky load? A queue absorbs the spike; autoscale on queue depth.
  • Always mention failure, bottlenecks, and cost — and start simple before scaling.
