Load balancing.

A load balancer sits in front of a pool of identical servers and spreads requests across them — so no single server is overwhelmed, and a dead one is quietly skipped. It's the component that turns "add more servers" into actual extra capacity, and it's the first box you draw on almost every whiteboard.

01  The idea

In plain English analogy

It's the host at a busy restaurant directing arrivals to whichever waiter is free. Diners (requests) don't pick a waiter; the host (load balancer) does — keeping everyone evenly busy and steering people away from a waiter who's gone home (a failed server).

Watch a load balancer hand four requests to a pool of servers, round-robin. If one died, it would simply be skipped.

02  Layer 4 vs Layer 7

Two flavours, named after the OSI layer they understand:

🔌

L4 — transport

Routes by IP + port, blind to content. Extremely fast and cheap; can't make decisions based on the URL or headers. Good for raw TCP/UDP throughput.

🧠

L7 — application

Understands HTTP: can route by path (/api vs /img), terminate TLS, do sticky sessions, and rate-limit. Slightly more work per request, far more flexible. The common default.

03  Algorithms & health checks

Round robin
Next server in rotation. Simple, great when servers are equal and requests are uniform.
Least connections
Send to the server with the fewest in-flight requests. Better when request durations vary.
Weighted
Bigger servers get a larger share. Handy with mixed hardware.
Hash (by IP / key)
Same client always lands on the same server — a poor man's stickiness. (For data, prefer consistent hashing.)

Crucially, the load balancer runs health checks — pinging each server and removing any that stop responding, so traffic only goes to live boxes. The LB itself must be redundant (two of them, or a managed one) so it isn't a single point of failure.

Why do we insist app servers be stateless for load balancing to work well?

Right: if a user's session lived only in one server's memory, the LB couldn't freely route them and a server crash would lose their state. Keep state in a shared cache/DB and every server is interchangeable.
