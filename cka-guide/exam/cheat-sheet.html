01 kubectl fluency

$</span> kubectl config use-context <ctx>
$</span> kubectl config set-context --current --namespace=<ns>
$</span> kubectl api-resources | grep -i net
$</span> kubectl explain pod.spec.containers.livenessProbe --recursive
$</span> kubectl get events -A --sort-by=.lastTimestamp | tail
$</span> kubectl get po,svc,ep,deploy,rs,pvc -n <ns> -o wide
$</span> kubectl describe <kind>/<name> -n <ns>
$</span> kubectl logs <pod> -c <c> --previous -n <ns>
$</span> kubectl exec -it <pod> -n <ns> -- sh
$</span> kubectl debug -it <pod> -n <ns> --image=busybox:1.36 --target=<c>
$</span> kubectl run tmp --rm -it --restart=Never --image=busybox:1.36 -- sh
$</span> kubectl apply -f m.yaml | kubectl apply -k overlays/prod
$</span> kubectl delete pod <p> --force --grace-period=0   # last resort
-o yaml / -o wide / -o jsonpath
Inspect, layout, extract fields for scripts.
--dry-run=client -o yaml
Imperative scaffold → edit → apply.
-w / --watch
Watch Ready / rollout progress.

03 kubeadm & RBAC

$</span> kubeadm token create --print-join-command
$</span> kubeadm token list
$</span> sudo kubeadm join <api>:6443 --token <t> --discovery-token-ca-cert-hash sha256:<h>
$</span> sudo kubeadm upgrade plan
$</span> kubectl -n <ns> create sa bot
$</span> kubectl -n <ns> create role r --verb=get,list --resource=pods
$</span> kubectl -n <ns> create rolebinding rb --role=r --serviceaccount=<ns>:bot
$</span> kubectl create clusterrole cr --verb=get --resource=nodes
$</span> kubectl create clusterrolebinding crb --clusterrole=cr --serviceaccount=<ns>:bot
$</span> kubectl auth can-i list pods --as=system:serviceaccount:<ns>:bot -n <ns>
$</span> helm install|upgrade|list|uninstall <rel> <chart> -n <ns>
$</span> kubectl apply -k overlays/prod
$</span> kubectl get crd; kubectl explain <crd.kind>
RBAC reflex

Namespace objects → Role + RoleBinding. Cluster-scoped (nodes, PVs, namespaces) → ClusterRole + ClusterRoleBinding. Always finish with auth can-i.

NetworkPolicy
podSelector, policyTypes, from/to with namespaceSelector + podSelector, ports.
Ingress
rules.host / path → backend serviceName:port; needs controller + class.
Gateway API
Gateway (listeners) + HTTPRoute parentRefs + backendRefs. Prefer for new CKA paths.
DNS
<svc>.<ns>.svc.cluster.local; debug with busybox nslookup.

05 Storage

$</span> kubectl get pv,pvc,sc -A

07 Quick check

apply -f vs apply -k? Core

Say it out loud: Dash f is a file or directory of manifests. Dash k runs Kustomize on a kustomization root.

Answer

-f raw manifests; -k Kustomize build+apply. Helm is a separate CLI.

Gateway vs Ingress one-liner? Warm

Say it out loud: Ingress is one resource with annotations; Gateway splits listeners and routes with parentRefs.

Answer

Both expose HTTP(S) to Services. CKA v1.35 expects Gateway API familiarity alongside classic Ingress.
