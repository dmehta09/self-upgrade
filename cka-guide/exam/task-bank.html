Performance task bank.

Flagship labs by domain. Each card is constraint → commands → verify. Do them cold with docs open; then race the clock on the timed mock.

01 How to use

One card = one exam muscle. Finish verify before you peek at the gotcha.

Story
What the stem feels like in the PSI terminal.
Constraint
Exact end state graders care about.
Commands
A workable path — not the only path.
Verify
What you re-check in the last 30 seconds.

02 Troubleshooting · 30%

CrashLoop + Pending twin

Story
Deployment storefront in shop shows 0/2 Ready. One Pod Pending, one CrashLoopBackOff.
Constraint
Both Pods become Ready without deleting the Deployment. Fix root causes on the owner object(s).

Commands

$</span> kubectl -n shop get pods -o wide
$</span> kubectl -n shop describe pod <pending>
$</span> kubectl -n shop describe pod <crash>
$</span> kubectl -n shop logs <crash> -c <c> --previous
$</span> kubectl -n shop edit deploy storefront

Verify: kubectl -n shop get deploy storefront shows READY 2/2; Events quiet.

Gotcha

logs without --previous is empty after backoff. Pending is Events (taints/PVC/CPU), not app logs.

Lesson → Troubleshoot pods & apps

Worker NotReady

Story
Node worker-b is NotReady. Apps on other nodes still answer; this node’s Pods are Terminating or stuck.
Constraint
Restore Ready (or cordon/drain safely if disk must be fixed first). Leave control-plane alone.

Commands

$</span> kubectl get nodes -o wide
$</span> kubectl describe node worker-b
$</span> kubectl cordon worker-b
$</span> kubectl drain worker-b --ignore-daemonsets --delete-emptydir-data
$</span> sudo systemctl status kubelet
$</span> sudo journalctl -u kubelet -n 50 --no-pager

Verify: kubectl get node worker-b → Ready; uncordon when healthy.

Gotcha

Drain before “fixing” kubelet when possible. DiskPressure / PLEG / containerd stopped are different fixes — read Conditions first.

Lesson → Troubleshoot nodes

Service selects nothing

Story
Clients hit ClusterIP; curl hangs. Pods are Running and Ready.
Constraint
Service api in prod has Endpoints; DNS name resolves from another Pod.

Commands

$</span> kubectl -n prod get svc api -o yaml
$</span> kubectl -n prod get endpoints api -o yaml
$</span> kubectl -n prod get pods --show-labels
$</span> kubectl -n prod run dns-test --rm -it --image=busybox:1.36 --restart=Never -- nslookup api.prod.svc
$</span> kubectl -n prod get networkpolicy

Verify: Endpoints list Pod IPs; wget -qO- api.prod.svc:PORT from a client Pod succeeds (or NP allows it).

Gotcha

Empty Endpoints = selector/port/targetPort mismatch. Full Endpoints + timeout often = NetworkPolicy or wrong port on the app.

Lesson → Services, DNS & NetworkPolicy

03 Cluster Architecture · 25%

RBAC least privilege

Story
ServiceAccount ci-bot in ci must list/get Pods and create Jobs only in that namespace.
Constraint
Role + RoleBinding (not ClusterRole) grant exactly those verbs; no secrets access.

Commands

$</span> kubectl -n ci create role ci-bot-role --verb=get,list --resource=pods --verb=create --resource=jobs
$</span> kubectl -n ci create rolebinding ci-bot-rb --role=ci-bot-role --serviceaccount=ci:ci-bot
$</span> kubectl auth can-i create jobs --as=system:serviceaccount:ci:ci-bot -n ci
$</span> kubectl auth can-i get secrets --as=system:serviceaccount:ci:ci-bot -n ci

Verify: can-i create jobs → yes; can-i get secrets → no.

Gotcha

ClusterRoleBinding is wrong for namespace-scoped asks. Imperative create role may need a second pass for multiple resource groups — check the Role YAML.

Lesson → RBAC

kubeadm join worker

Story
New host ready with containerd; must join as worker using a fresh token.
Constraint
Node appears Ready; kubelet uses the cluster’s CA; no control-plane join flags.

Commands

$</span> kubeadm token create --print-join-command
$</span> # on worker:
$</span> sudo kubeadm join <api>:6443 --token <t> --discovery-token-ca-cert-hash sha256:<h>
$</span> kubectl get nodes

Verify: New node Ready; kubectl get pods -A -o wide | grep <node> shows system Pods.

Gotcha

Expired tokens fail silently until you read kubelet logs. Do not paste --control-plane for a worker task.

Lesson → kubeadm

Helm install + Kustomize overlay

Story
Install chart web into apps with Helm; separately apply a Kustomize overlay that sets replicas=3.
Constraint
Release listed; Deployment shows 3 replicas from the overlay path given in the stem.

Commands

$</span> helm install web ./charts/web -n apps --create-namespace
$</span> helm list -n apps
$</span> kubectl apply -k overlays/prod
$</span> kubectl -n apps get deploy

Verify: Helm release deployed; overlay Deployment READY 3/3.

Gotcha

kubectl apply -f on a kustomization directory fails — need -k. Helm and Kustomize are separate tools; don’t mix flags.

Lesson → Helm & Kustomize

04 Services & Networking · 20%

NetworkPolicy allow-list

Story
Namespace db must accept TCP 5432 only from Pods labeled role=api in app.
Constraint
Default deny ingress on db workloads; allow that one peer; egress left as stem requires.

Commands

$</span> kubectl -n db apply -f - <<'EOF'
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: db-allow-api
spec:
  podSelector: {}
  policyTypes: ["Ingress"]
  ingress:
  - from:
    - namespaceSelector:
        matchLabels:
          kubernetes.io/metadata.name: app
      podSelector:
        matchLabels:
          role: api
    ports:
    - protocol: TCP
      port: 5432
EOF
$</span> kubectl -n db get networkpolicy

Verify: From an role=api Pod, connect; from unlabeled Pod, timeout. Policies are additive — check for competing NPs.

Gotcha

Namespace selectors need labels on the namespace (often kubernetes.io/metadata.name). Empty podSelector: {} selects all Pods in the NP’s namespace.

Lesson → NetworkPolicies

Gateway API HTTPRoute

Story
Existing Gateway edge in gateway-system. Route /shop to Service shop in store.
Constraint
HTTPRoute attaches to that Gateway; path prefix works; classic Ingress not required.

Commands

$</span> kubectl -n gateway-system get gateway edge -o yaml
$</span> kubectl -n store apply -f httproute-shop.yaml
$</span> kubectl -n store describe httproute shop
$</span> curl -sS -H "Host: shop.example" http://<gateway-ip>/shop/

Verify: Route Parent Accepted; backend Service has Endpoints; curl returns 200.

Gotcha

parentRefs must match Gateway name/namespace/sectionName. Mixing Ingress annotations into Gateway YAML does nothing.

Lesson → Gateway API

CoreDNS ConfigMap tweak

Story
Cluster DNS fails for external names; CoreDNS Pods CrashLoop after a bad edit.
Constraint
Restore working Corefile; kubernetes plugin present; Pods Ready.

Commands

$</span> kubectl -n kube-system get cm coredns -o yaml
$</span> kubectl -n kube-system edit cm coredns
$</span> kubectl -n kube-system rollout restart deploy/coredns
$</span> kubectl -n kube-system logs -l k8s-app=kube-dns

Verify: CoreDNS Ready; nslookup kubernetes.default from a test Pod works.

Gotcha

YAML indentation in Corefile string breaks the Pod. Fix ConfigMap first; restart only after syntax is valid.

Lesson → CoreDNS

05 Workloads & Scheduling · 15%

Rollout undo

Story
Bad image pushed to Deployment payments; traffic failing readiness.
Constraint
Return to previous revision; leave a record of the current revision first.

Commands

$</span> kubectl -n pay rollout history deploy/payments
$</span> kubectl -n pay set image deploy/payments app=bad:1.9
$</span> kubectl -n pay rollout undo deploy/payments
$</span> kubectl -n pay rollout status deploy/payments

Verify: READY matches desired; image is the prior good tag.

Gotcha

rollout undo needs history. If maxUnavailable/maxSurge block progress, check rollout status and Events.

Lesson → Deployments & rollouts

Taint + toleration

Story
Node gpu-1 has taint sku=gpu:NoSchedule. Only Deployment trainer may run there.
Constraint
Trainer Pods schedule on gpu-1; other workloads stay off it.

Commands

$</span> kubectl taint nodes gpu-1 sku=gpu:NoSchedule
$</span> kubectl -n ml patch deploy trainer --type=json -p='[{"op":"add","path":"/spec/template/spec/tolerations","value":[{"key":"sku","operator":"Equal","value":"gpu","effect":"NoSchedule"}]}]'
$</span> kubectl -n ml get pods -o wide

Verify: Trainer Pods on gpu-1; a non-tolerant Pod stays Pending if forced there.

Gotcha

Toleration alone does not pin a Pod — add nodeSelector/affinity if the stem requires only that node.

Lesson → Scheduling

Probes + HPA floor

Story
Deployment ready but HPA won’t scale; also readiness uses wrong path.
Constraint
Readiness probe hits /readyz; requests set; HPA targets CPU and has minReplicas ≥2.

Commands

$</span> kubectl -n web set resources deploy/api --requests=cpu=100m,memory=128Mi
$</span> kubectl -n web edit deploy api   # readinessProbe.httpGet.path=/readyz
$</span> kubectl -n web autoscale deploy api --cpu-percent=70 --min=2 --max=6
$</span> kubectl -n web describe hpa

Verify: Pods Ready; HPA shows targets (not <unknown>); metrics-server healthy.

Gotcha

HPA without CPU requests shows unknown. Liveness ≠ readiness — wrong liveness path causes CrashLoops.

Lesson → Probes · Resources & HPA

06 Storage · 10%

PVC Pending

Story
Pod stuck Pending; Events mention unbound PVC data.
Constraint
PVC Bound via StorageClass (or static PV matching access mode/capacity); Pod mounts and runs.

Commands

$</span> kubectl -n data get pvc,pv,sc
$</span> kubectl -n data describe pvc data
$</span> kubectl -n data edit pvc data   # storageClassName / accessModes
$</span> kubectl -n data get pods

Verify: PVC STATUS Bound; Pod Running; volume mounted.

Gotcha

ReadWriteOnce ≠ ReadWriteMany. Wrong access mode or missing default StorageClass leaves PVC Pending forever.

Lesson → PV & PVC

StorageClass default

Story
PVC without storageClassName stays Pending; cluster has two classes.
Constraint
Mark fast-ssd as default; new PVC binds dynamically.

Commands

$</span> kubectl get sc
$</span> kubectl annotate sc fast-ssd storageclass.kubernetes.io/is-default-class=true --overwrite
$</span> kubectl annotate sc slow-hdd storageclass.kubernetes.io/is-default-class- --overwrite
$</span> kubectl -n data get pvc

Verify: Only one default SC; PVC Bound with fast-ssd.

Gotcha

Two defaults confuse provisioning. Clear the old annotation (trailing -) before relying on the new default.

Lesson → StorageClass

07 Quick check

Empty Endpoints — first three checks? Core

Say it out loud: selector labels, targetPort versus container port, then Ready Pods.

Answer

Match Service selector to Pod labels; align port/targetPort; ensure Pods are Ready (probes).

When is RoleBinding wrong? Warm

Say it out loud: When the stem needs cluster-scoped objects — nodes, PVs, namespaces — use ClusterRole plus ClusterRoleBinding.

Answer

Namespace Role cannot authorize cluster-scoped resources. Use ClusterRole/ClusterRoleBinding for those verbs.
