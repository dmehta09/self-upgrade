Logs, events & kubectl debug.

CKA rewards fast signal: Events for cluster decisions, logs for process output, ephemeral debug when the image has no shell.

01 Three signal sources

Events explain the control plane; logs explain the container; debug/exec lets you poke the live environment.

Black box + ATC transcript analogy

In plain English: Events are the air-traffic transcript (“cleared to land,” “go around”). Container logs are the cockpit voice recorder. kubectl debug is strapping a mechanic into a jump seat when the plane has no spare seatbelt (distroless image).

kubectl logs
Stdout/stderr of a container. Use -c, -f, --previous.
Events
Namespaced cluster messages on objects. Sort by time when noisy.
exec
Shell into a running container if the image includes a shell.
kubectl debug
Ephemeral container (or copy Pod) with a tooling image for distroless/debug.

02 When to use what

flowchart LR
  P[Problem] --> E[describe / events]
  E --> L[logs / logs -p]
  L --> X{Need filesystem / curl?}
  X -->|image has shell| EX[kubectl exec]
  X -->|distroless / locked| DB[kubectl debug ephemeral]
  DB --> V[Verify fix on owner object]

Debug containers share the Pod network namespace — great for testing Service reachability.

03 Command patterns

Constraint: Distroless app Pod fails readiness. You need to curl localhost and inspect DNS from the Pod network.

$</span> kubectl -n apps describe pod web-0 | sed -n '/Events/,$p'
$</span> kubectl -n apps logs web-0 -c app --tail=100
$</span> kubectl -n apps logs web-0 -c app --previous
$</span> kubectl -n apps exec -it web-0 -c app -- sh   # may fail on distroless
$</span> kubectl -n apps debug -it web-0 --image=busybox:1.36 --target=app -- sh
exec
  • Fast when shell exists
  • Same container filesystem
  • Fails on minimal images
debug / ephemeral
  • Attach tooling image
  • Share netns with target
  • Does not permanently mutate Deployment
Gotcha · wrong container in a Pod

Sidecar + app means default logs/exec may hit the wrong container. Always name -c when describe shows multiple containers. Ephemeral debug needs --target for process namespace tricks.

04 Quick check

Best tool when the app image has no shell and you must curl the Service from the Pod’s network?

Ephemeral containers add a tooling image to the running Pod for interactive checks without rebuilding the app image.

05 Exam rapid-fire

Events vs logs — one sentence each? Warm

Say it out loud: Events are Kubernetes narrating; logs are the process speaking.

Answer

Use Events for pull/schedule/probe failures; logs for app stack traces and exit messages.

Why --previous? Core

Say it out loud: After a crash restart, current logs may be empty — previous is the dead container’s output.

Answer

Critical for CrashLoopBackOff. Combine with describe Last State exit code.

Does debug permanently change the Deployment? Core

Say it out loud: Ephemeral containers are temporary on the Pod; fix the owner object separately for lasting change.

Answer

Use debug to learn; apply the real fix to Deployment/ConfigMap/Service. Some debug copy-pod modes create a new Pod — read the help text on the exam version.
