ConfigMaps & Secrets.

Decouple config from images. Create ConfigMaps and Secrets, mount them as env or volumes, and know what “immutable” and base64 actually mean on exam day.

01 The idea

ConfigMaps hold non-sensitive settings; Secrets hold credentials — both are API objects Pods consume as env vars or files.

Analogy

ConfigMap is the laminated instruction card taped to a machine. Secret is the key in a lockbox. Same mounting slots (env or volume), different trust story — and Secrets are still just objects in etcd unless you add encryption at rest.

flowchart LR
  CM[ConfigMap]
  SEC[Secret]
  POD[Pod]
  CM -->|envFrom / env| POD
  CM -->|volumeMount| POD
  SEC -->|envFrom / env| POD
  SEC -->|volumeMount| POD

02 Create and consume

Imperative creates are fastest on CKA. Prefer --from-literal / --from-file, then wire the Pod with env, envFrom, or a volume mount.

create ConfigMap & Secret 
kubectl create configmap app-cfg \
  --from-literal=LOG_LEVEL=info \
  --from-file=nginx.conf=./nginx.conf

kubectl create secret generic app-creds \
  --from-literal=username=admin \
  --from-literal=password='s3cret!'

kubectl get cm,secret
kubectl describe configmap app-cfg
pod · env + volume 
apiVersion: v1
kind: Pod
metadata:
  name: demo
spec:
  containers:
  - name: app
    image: busybox:1.36
    command: ["sleep","3600"]
    envFrom:
    - configMapRef:
        name: app-cfg
    env:
    - name: DB_USER
      valueFrom:
        secretKeyRef:
          name: app-creds
          key: username
    volumeMounts:
    - name: cfg
      mountPath: /etc/app
      readOnly: true
  volumes:
  - name: cfg
    configMap:
      name: app-cfg
env / envFrom
Injected at container start — later CM updates do not rewrite running env
volume mount
Projected as files; kubelet can refresh file contents (app must re-read)
optional: true
Pod can schedule even if the CM/Secret is missing

03 Immutable & base64 caveat

Mark objects immutable: true when you want to block accidental updates and reduce API-server watch load. Secrets store data as base64 — that is encoding, not encryption.

Base64 myth
  • “Secret = encrypted”
  • echo s3cret | base64 is obfuscation
  • Anyone with get secrets can decode
Exam-safe view
  • RBAC limits who can get secrets
  • Encryption at rest is a cluster setting
  • Use stringData in YAML to avoid hand-encoding
inspect & decode 
kubectl get secret app-creds -o jsonpath='{.data.password}' | base64 -d; echo
kubectl create configmap locked --from-literal=k=v --dry-run=client -o yaml \
  | sed 's/metadata:/immutable: true\nmetadata:/' | kubectl apply -f -
kubectl explain secret.data
kubectl explain configmap.immutable
Gotcha base64

Putting a Secret in a volume does not encrypt the files on disk inside the container. Treat node filesystem access and RBAC as part of the threat model — even on the exam narrative questions.

You create a Secret with --from-literal=password=hi. What does .data.password contain?

Base64 encoding only. Decode with base64 -d. Use stringData in manifests so kubectl encodes for you.

04 Updates that actually take effect

Changing a ConfigMap used only as env leaves running containers stale. Trigger a rollout, or mount as a volume and make the app reload files.

roll after CM change 
kubectl create configmap app-cfg --from-literal=LOG_LEVEL=debug -o yaml --dry-run=client | kubectl apply -f -
kubectl rollout restart deployment/web
kubectl rollout status deployment/web
kubectl exec deploy/web -- printenv LOG_LEVEL

05 Exam rapid-fire

Env var vs volume mount — when does each refresh? Core
Say it out loud

“Env is fixed at process start. Volume files can update later, but the app must re-read them — and I usually rollout restart to be sure.”

What does immutable: true buy you? Warm-up
Say it out loud

“It blocks updates to that ConfigMap or Secret. To change data I delete and recreate — safer for static config under load.”

Fastest imperative Secret for username/password? Core
Say it out loud

“kubectl create secret generic NAME --from-literal=username=… --from-literal=password=… then reference secretKeyRef or mount it.”
