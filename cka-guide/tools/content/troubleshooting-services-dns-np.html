Troubleshoot Services, DNS & NetworkPolicy.

Empty Endpoints, broken CoreDNS, and deny-all NetworkPolicies look like “app down.” Prove selector → Endpoints → DNS → policy before rewriting Deployments.

01 Path of a request

Service VIP only helps if Endpoints/EndpointSlices list Ready Pods and the network allows the packet.

Reception desk + door policy analogy

In plain English: the Service is the reception number. Endpoints are who is on duty today. DNS is the phone book entry. NetworkPolicy is the security door — correct number, wrong badge, call fails silently.

Selector mismatch
Service labels ≠ Pod labels → empty Endpoints.
Not Ready Pods
Failed readiness → removed from Endpoints (ClusterIP still exists).
DNS
svc.ns.svc.cluster.local needs CoreDNS + working cluster DNS config.
NetworkPolicy
Default-deny / missing egress to DNS or upstream = timeouts, not “connection refused.”

02 Debug flow

flowchart TD
  A[Service ClusterIP exists?] -->|no| C[Create / fix Service]
  A -->|yes| B[Endpoints empty?]
  B -->|yes| D[Fix selector / Ready probes]
  B -->|no| E[DNS resolve?]
  E -->|no| F[CoreDNS /dnsPolicy / NP egress 53]
  E -->|yes| G[Curl Pod IP vs Service]
  G --> H{Works to Pod?}
  H -->|yes, not SVC| I[kube-proxy / datapath]
  H -->|no| J[App / NetworkPolicy ingress]

Always compare Pod IP success vs Service VIP failure — that isolates app vs networking.

03 Worked checks

$</span> kubectl -n prod get pods --show-labels
$</span> kubectl -n prod get networkpolicies

$</span> kubectl -n prod run tmp --rm -it --image=busybox:1.36 --restart=Never -- nslookup api.prod.svc.cluster.local
Gotcha · allow app, forget DNS

Egress NetworkPolicies that only allow the backend port break name resolution unless you also allow UDP/TCP 53 to kube-dns. Symptom: nslookup hangs; curl by IP works.

04 Quick check

Service selector is app=api. Pods are labeled app=API. Endpoints?

Selectors match exactly. Case mismatch → no Endpoints. NetworkPolicy does not empty Endpoints; it drops packets.

05 Exam rapid-fire

How do you prove a selector mismatch in 30 seconds? Warm

Say it out loud: Compare Service selector to Pod labels and confirm Endpoints is empty.

Answer

kubectl get svc -o yaml + kubectl get pods --show-labels + kubectl get ep. Fix labels or selector — not the image.

ClusterIP works by IP, FQDN fails — next check? Core

Say it out loud: DNS path — CoreDNS Pods, ConfigMap, and NetworkPolicy egress to DNS.

Answer

Test nslookup from a debug Pod. Inspect kube-system DNS Pods and the client’s dnsPolicy.

Default-deny NetworkPolicy — what must you add? Core

Say it out loud: Explicit allow rules for needed ingress and egress; nothing is permitted until you say so.

Answer

Select pods, allow namespaces/pods/ports you need. Remember DNS egress and kubelet probes if policies are aggressive.
