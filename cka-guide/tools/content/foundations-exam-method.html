How to take CKA.

Performance exam, not multiple choice. Two hours on live clusters via PSI Bridge, Kubernetes v1.35, pass ≥66%. Strategy and docs speed matter as much as kubectl trivia.

01 Format & scoreboard

Roughly 15–20 tasks, weighted by domain — missing a Troubleshooting item hurts more than missing Storage.

Open-book lab with a buzzer analogy

In plain English: CKA is a timed lab practical. The proctor watches you through PSI Bridge; you get a terminal, the clusters named in each item, and kubernetes.io documentation. Nobody asks theory essays — only “is the cluster in the state they asked for?”

03 PSI Bridge & allowed docs

Settle logistics before exam day: webcam, ID, clean desk, stable network. During the exam you work in the PSI environment with the provided terminal and browser access to allowed docs.

Bookmark before the clock

Open and bookmark https://kubernetes.io/docs/ (and the kubectl cheat sheet / Concepts search). Allowed resources are defined by Linux Foundation candidate docs — typically kubernetes.io documentation (and related kubernetes.io properties listed in the current FAQ). Do not rely on random blogs or this field guide inside the exam.

Gotcha · wrong context = free zero

Each item names a cluster (context). Solving the right problem on the wrong cluster scores nothing. First 20 seconds of every task: kubectl config use-context … and set/check namespace. See kubectl fluency.

04 Flag / skip strategy

You do not need 100%. You need ≥66% with time left to verify. Treat the attempt like a weighted sprint.

1

Triage in 30 seconds

Skim for domain and length. Easy create/scale/RBAC? Do now. Multi-hop network debug? Flag if you are cold.

2

Protect Troubleshooting points

Budget extra time for 30% domain items. A clean describe → events → logs → fix loop beats rewriting YAML blindly.

3

Leave breadcrumbs

If you skip, note the context alias and what you already applied. Partial correct state can still score when you return.

4

Last 10 minutes = verify only

Re-check high-weight items: Ready replicas, Service Endpoints, NetworkPolicy effects, node conditions. No new heroics.
