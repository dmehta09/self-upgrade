Cluster · HA & lifecycle Domain 2 · Cluster Architecture (25%)

HA control plane & cluster lifecycle.

High availability means multiple control-plane nodes behind a stable endpoint, plus safe node add/remove and upgrade discipline. CKA wants the topology and the kubectl/kubeadm moves — not deep etcd surgery.

01 The idea

HA = redundant API servers (and etcd quorum) behind a load-balanced controlPlaneEndpoint. Lifecycle = join, drain, cordon, upgrade, and remove nodes cleanly.

Analogy plain English

One reception desk closes for lunch and the building freezes. HA puts three receptionists behind one phone number (the endpoint VIP/LB). Workers only dial that number — they never care which desk answers.

02 HA control plane with kubeadm

First control plane: kubeadm init --control-plane-endpoint … --upload-certs. Additional control planes join with --control-plane and certificate key.

HA join sketch 
$</span> sudo kubeadm init --control-plane-endpoint "lb.example:6443" \
  --upload-certs --pod-network-cidr=10.244.0.0/16
$</span> # printed join for extra control planes includes --control-plane --certificate-key</span>
$</span> sudo kubeadm join lb.example:6443 --token <t> \
  --discovery-token-ca-cert-hash sha256:<h> \
  --control-plane --certificate-key <key>
$</span> kubectl get nodes -o wide
$</span> kubectl -n kube-system get pods -l tier=control-plane -o wide
Odd etcd count
  • 3 or 5 members for quorum
  • Lose 1 of 3 and still majority
Even / single
  • Single CP = no HA
  • Even counts waste quorum budget
Gotcha exam trap

Workers must use the endpoint, not a single node IP, or failover won’t work. Certificate-key for joining extra CPs expires quickly — regenerate with kubeadm init phase upload-certs --upload-certs if needed.

03 Node lifecycle

Before maintenance: cordon → drain. After: uncordon. Removing a node: drain, then delete Node object / kubeadm reset on the host as the task states.

drain & remove 
$</span> kubectl cordon worker-1
$</span> kubectl drain worker-1 --ignore-daemonsets --delete-emptydir-data
$</span> kubectl uncordon worker-1
$</span> kubectl delete node worker-1
$</span> # on the host if asked:</span>
$</span> sudo kubeadm reset

Why prefer an odd number of etcd members in HA?

etcd is a Raft quorum store. With 3 members you tolerate 1 failure; with 4 you still only tolerate 1 — wasted node.

04 Exam rapid-fire

What is controlPlaneEndpoint? core

A stable DNS/IP:port for the API that front-ends all control-plane nodes — what kubeconfigs and join commands should target.

Say it out loud

“One VIP for many API servers — that’s the HA phone number.”

cordon vs drain? core

Cordon marks unschedulable (no new Pods). Drain cordons and evicts workloads so the node can be maintained.

Say it out loud

“Cordon closes the door; drain also clears the room.”

Add a second control-plane node — flags? stretch

Same join as workers plus --control-plane and a valid --certificate-key from upload-certs.

Say it out loud

“Join with --control-plane and a fresh certificate-key.”
