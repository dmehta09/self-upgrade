01 Context first, then namespace

Wrong cluster or wrong namespace is the fastest way to “finish” a task that never gets scored.

Hotel keycard, not master key analogy

In plain English: a kubeconfig context is which hotel and which room key you hold — cluster + user + default namespace. Switching contexts mid-exam is swapping buildings. Always read the task’s cluster alias before you type.

orient.sh 
# Orient at the start of every task
kubectl config get-contexts
kubectl config use-context <alias-from-question>
kubectl config set-context --current --namespace=<ns>
kubectl get ns
kubectl get all

Prefer an explicit -n on mutating commands when the question names a namespace. Default context namespace is a convenience, not a guarantee you typed what you meant.

02 explain · dry-run · -o yaml

Field memory fades under stress. kubectl explain is offline docs for the object schema on the exam cluster’s API version.

flowchart TD
      A[Need an object] --> B{Know the fields?}
      B -->|No| C["kubectl explain RES[.field] --recursive"]
      B -->|Yes| D{Need a starting YAML?}
      D -->|Yes| E["kubectl create|run … --dry-run=client -o yaml"]
      D -->|No| F[Edit existing live object]
      E --> G[Redirect to file · edit · apply]
      C --> E
      F --> H["kubectl get OBJ -o yaml"]
      G --> I[Verify with get / describe]
      H --> I
explain
kubectl explain deployment.spec.strategy — short docs; add --recursive when hunting nested fields.
dry-run=client
Validates locally and prints YAML without hitting the API. Ideal scaffold for exam YAML.
-o yaml / json
Inspect live objects; strip status and noisy metadata before re-applying when needed.
-o wide
Extra columns (node, pod IP) — often enough without describe.
Gotcha · dry-run=server ≠ free pass

--dry-run=server still talks to the apiserver (admission runs). For scaffolding YAML on the exam, --dry-run=client -o yaml is the usual move. Don’t leave a dry-run as your only “fix” — apply and verify Ready.

03 docs.k8s.io under PSI

Allowed documentation is your second brain. Bookmark the search box and the kubectl cheat sheet before the timer starts. See How to take CKA for the full allow-list.

1

Search the concept, not the blog

Query Deployment, NetworkPolicy, PersistentVolumeClaim — open the Tasks / Concepts page with copy-pasteable YAML.

2

Prefer reference tables

Resource types, probe fields, and Service types live on docs pages. Don’t re-derive from memory when a table is one Ctrl-F away.

3

Copy → paste → rename

Paste into the exam editor, change names/namespaces/images to match the stem, then apply. Verify before moving on.

fast-scaffold.sh 
kubectl create deployment web --image=nginx:1.27 -n app --dry-run=client -o yaml > web.yaml
# edit replicas / labels / ports in the file
kubectl apply -f web.yaml
kubectl rollout status deployment/web -n app

05 Exam rapid-fire

When do you use kubectl explain vs docs.k8s.io? Warm

Say it out loud: explain for exact field paths on this cluster’s API; docs.k8s.io for examples, concepts, and copy-paste YAML.

Answer

Use explain when you know the resource but forgot a nested field. Use docs when you need a worked example (Ingress rules, NetworkPolicy ingress/egress blocks, StorageClass parameters).

Why -o yaml after create --dry-run=client? Core

Say it out loud: dry-run client emits a legal skeleton you can edit and apply — faster and less typo-prone than writing apiVersion from scratch.

Answer

You get correct apiVersion/kind structure for the cluster, then add exam-specific names, labels, and mounts. Pair with YAML vs imperative.

Name three orientation commands before mutating. Core

Say it out loud: get-contexts, use-context, then get ns / get all in the target namespace.

Answer

kubectl config get-contexts, use-context, and a namespace-scoped inventory (get all, get deploy,svc,pod -n …). Confirm the stem’s names exist or must be created.
