CLUSTER · extension interfaces Domain 2 · Cluster Architecture (25%)

CRI, CNI & CSI.

Kubernetes does not bake in a container engine, network fabric, or storage driver. Three stable interfaces keep the core portable — and CKA expects you to know which layer owns which failure.

01 The idea

CRI runs containers, CNI gives Pods network, CSI attaches volumes — kubelet orchestrates all three; none of them is “Docker as the cluster runtime.”

Three wall sockets analogy

In plain English: the house (kubelet) has three sockets. Plug in any compliant appliance — a container runtime, a network plugin, a volume driver — without rewiring the walls. Swap brands; keep the plugs the same.

CRI
Container Runtime Interface. kubelet ↔ runtime (almost always containerd on modern CKA labs).
CNI
Container Network Interface. Assign Pod IPs, routes, (often) NetworkPolicy enforcement.
CSI
Container Storage Interface. Provision/attach/mount volumes via controller + node plugins.

02 Boundaries that matter on the exam

Blame the right interface. Image pull errors are CRI. Pods have no IP / cannot reach peers — CNI. PVC stuck Pending or mount fails — CSI (or StorageClass).

kubelet is the hub. Controllers talk CSI attach via the API; the node plugin finishes the mount.

Outdated mental model
  • “Docker is the Kubernetes runtime”
  • Debug with only docker ps on every node
  • Assume kube-proxy is the only datapath forever
2026 / K8s 1.35 default
  • containerd (or CRI-O) via CRI
  • crictl / ctr for node debugging
  • CNI may use eBPF and replace classic kube-proxy
Gotcha · Docker socket ≠ CRI

dockershim was removed years ago. A node may still have Docker for building images; that does not mean kubelet uses it. Check the kubelet --container-runtime-endpoint (often unix:///run/containerd/containerd.sock).

03 Commands that map to each interface

On the exam you verify from the API first, then drop to the node when the API cannot help.

CRI · CNI · CSI checks 
# CRI — runtime on a node
crictl info
crictl ps -a
crictl images

# CNI — Pod networking
kubectl get pods -o wide
ls /etc/cni/net.d/
kubectl -n kube-system get ds,deploy | grep -Ei 'cni|flannel|calico|cilium'

# CSI — storage plugins
kubectl get csidrivers
kubectl get csinode
kubectl get storageclass,pvc,pv

A Pod is Running but has no IP and cannot be reached by other Pods. Which interface is the first place to look?

Pod IP allocation and cross-node routing are CNI’s job. CSI is volumes; scheduler already bound the Pod if it is Running.

04 Exam rapid-fire

Why did Kubernetes invent CRI/CNI/CSI? Warm

Say it out loud: Stable interfaces let vendors swap runtimes, networks, and storage without forking kubelet.

Answer

The core stays small and portable. You install a CNI DaemonSet or CSI driver as cluster add-ons; kubelet only speaks the contract.

Is Docker required for CKA clusters? Core

Say it out loud: No — expect containerd via CRI; use crictl on nodes, not Docker-as-runtime assumptions.

Answer

Images still look like Docker Hub references. The runtime that pulls and runs them is almost always containerd.

PVC Pending forever — CRI or CSI? Core

Say it out loud: CSI and StorageClass provisioning — check PVC Events, provisioner logs, and whether a matching StorageClass exists.

Answer

kubectl describe pvc usually names the culprit. CRI only enters after a volume must be mounted into a container.
