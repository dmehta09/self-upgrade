StorageClass & dynamic provisioning.

A StorageClass names a provisioner and parameters. When a PVC asks for that class, CSI (or in-tree legacy) creates a PV automatically — the default path on modern CKA clusters.

01 The idea

StorageClass = recipe for new volumes. provisioner + parameters decide how disks appear; PVC only requests size, modes, and class name.

Analogy plain English

StorageClass is a vending-machine button: “SSD, delete-on-return, wait until someone sits.” Pressing it (creating a PVC) dispenses a new PV. The default button is the one with the annotation gold star.

02 Fields that bite on the exam

provisioner
CSI driver name (e.g. rancher.io/local-path, cloud CSI). Must match an installed driver.
reclaimPolicy
Usually Delete for dynamic disks; Retain if the task says keep data after PVC delete.
volumeBindingMode
Immediate vs WaitForFirstConsumer — latter delays bind until a Pod is scheduled (topology-aware).
allowVolumeExpansion
When true, you can patch PVC storage requests upward (driver permitting).
storageclass.yaml 
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: fast
  annotations:
    storageclass.kubernetes.io/is-default-class: "false"
provisioner: example.com/csi-driver
reclaimPolicy: Delete
volumeBindingMode: WaitForFirstConsumer
allowVolumeExpansion: true
parameters:
  type: ssd
Gotcha exam trap

PVC without storageClassName uses the default StorageClass (annotation storageclass.kubernetes.io/is-default-class: "true"). If none is default — or two are marked default — binding behaves oddly. Set the class explicitly when the task names one.

Immediate
  • PV appears as soon as PVC is created
  • Fine when topology doesn’t matter
WaitForFirstConsumer
  • PVC stays Pending until a Pod schedules
  • Don’t “fix” by recreating SC — schedule the consumer

PVC Pending, Events say “waiting for first consumer.” What is most likely?

WaitForFirstConsumer intentionally delays provisioning until a Pod that mounts the claim is scheduled.

04 Exam rapid-fire

What does a StorageClass do? core

It defines how dynamic PVs are provisioned: which driver, parameters, reclaim policy, and binding mode.

Say it out loud

“StorageClass is the provisioner recipe; PVC picks the recipe by name.”

How do you find the default StorageClass? core

kubectl get sc and look for (default), or the annotation storageclass.kubernetes.io/is-default-class=true.

Say it out loud

“Default class is an annotation — I never guess the name.”

Expand a PVC — prerequisites? stretch

StorageClass allowVolumeExpansion true, driver supports expansion, patch PVC to a larger size, wait for FileSystemResizePending to clear / filesystem resize to finish.

Say it out loud

“I grow requests only upward — and only if the class allows expansion.”
