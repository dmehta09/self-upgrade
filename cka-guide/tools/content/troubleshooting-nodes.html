TROUBLESHOOTING · nodes Domain 1 · Troubleshooting · 30%

Troubleshoot nodes.

NotReady, DiskPressure, and runtime failures are node-plane problems. Prove kubelet and CRI health before blaming the app YAML.

01 Node as a worker contract

A node is Ready only when kubelet heartbeats and conditions say the machine can run Pods.

Factory floor badge analogy

In plain English: Ready is a badge that says “this station is staffed and powered.” If the shift lead (kubelet) stops checking in, or the floor floods (DiskPressure), the dispatcher (scheduler) stops sending work — even if old machines are still humming.

Ready
Kubelet reachable; node can accept Pods (unless cordoned).
NotReady
Heartbeat lost, runtime down, or critical condition — investigate on the node.
Cordon
Marks unschedulable; existing Pods stay until drained or deleted.
Drain
Cordon + evict workloads (respect PDBs). Used for maintenance.

02 Conditions & pressures

Read kubectl describe node Conditions and Allocatable. Pressure conditions trigger eviction and block new Pods.

flowchart LR
  KL[kubelet] --> RT[container runtime]
  KL --> CNI[CNI]
  KL --> API[API heartbeat]
  API --> ND[Node object]
  ND --> SCH[scheduler]
  RT -.->|down| NR[NotReady]
  ND -.->|DiskPressure| EV[evictions]

NotReady is often kubelet ↔ runtime or kubelet ↔ apiserver — not a Deployment bug.

On the node (SSH / console)
  • systemctl status kubelet
  • runtime: systemctl status containerd
  • disk: df -h / image GC
  • journal: kubelet unit logs
From kubectl
  • kubectl get nodes -o wide
  • kubectl describe node …
  • kubectl get pods -A -o wide --field-selector spec.nodeName=…
  • cordon / drain / uncordon

03 Cordon, drain, runtime

Constraint: Worker node-2 is NotReady after disk fill. Evacuate workloads safely, fix disk/runtime, return capacity.

1

Confirm & isolate

kubectl get node node-2 → describe. If still reachable for scheduling mistakes, kubectl cordon node-2.

2

Drain when Safe

kubectl drain node-2 --ignore-daemonsets --delete-emptydir-data (flags as exam allows). Watch PDBs if drain blocks.

3

Fix plane

Clear disk, restart containerd/kubelet, verify Ready, then kubectl uncordon node-2.

Gotcha · cordon ≠ drain

Cordon only stops new Pods. Existing Pods keep running on a sick node until you drain or they die. Exam tasks often want both: cordon, fix, uncordon — or a full drain for maintenance.

04 Quick check

Node shows DiskPressure=True and Pods are being evicted. What should you fix first?

DiskPressure is a node condition. Evictions are kubelet protecting the node. Clear disk (logs, unused images), restore runtime health, then Pods can reschedule.

05 Exam rapid-fire

How do you list Pods on one node? Warm

Say it out loud: Field-select by spec.nodeName, or use -o wide and filter.

Answer

kubectl get pods -A -o wide --field-selector spec.nodeName=<node>. Essential before drain.

Runtime down — what breaks? Core

Say it out loud: kubelet cannot create or restart containers via CRI, so the node goes NotReady and Pods stick.

Answer

Check containerd (or CRI-O) service, socket path in kubelet flags, then restart kubelet after runtime is healthy.

When is drain the wrong first move? Stretch

Say it out loud: If the control plane is sick or only one Ready worker remains, draining can strand the cluster — stabilize first.

Answer

Also avoid blind drain when etcd/apiserver are down — you cannot reschedule. Fix API access, then evacuate.
