Requests, limits & HPA.

Requests drive scheduling and QoS. Limits cap bursts. HorizontalPodAutoscaler scales replicas from metrics-server — know the trade-offs when you size for the exam cluster.

01 The idea

requests reserve capacity for the scheduler; limits cap usage. HPA changes replica count when metrics say the workload is hot or cold.

Analogy

A request is the table reservation the host needs before seating you. A limit is the fire-code max occupancy. HPA is the manager opening more dining rooms when the waitlist grows — but only if someone is measuring the queue (metrics-server).

02 Requests, limits, QoS

Set CPU in cores/millicores and memory in Mi/Gi. QoS class falls out of how you fill the fields — kubelet uses it under node pressure.

Guaranteed
Every container has request == limit for CPU and memory
Burstable
At least one request set, but not Guaranteed
BestEffort
No requests or limits — first to be evicted under pressure
set resources 
kubectl set resources deployment/web \
  --requests=cpu=100m,memory=128Mi \
  --limits=cpu=500m,memory=256Mi
kubectl get pod -l app=web -o custom-columns=\
NAME:.metadata.name,QOS:.status.qosClass,REQ:.spec.containers[*].resources
kubectl describe node | sed -n '/Allocated resources/,/Events/p'
Gotcha OOM

Memory limit exceeded → container OOMKilled (exit 137). CPU limit is throttling, not a kill. If Pods won’t schedule, check requests vs node Allocatable — not limits.

03 HorizontalPodAutoscaler

HPA needs metrics-server (or an equivalent metrics API). Classic exam target: CPU utilization relative to requests.

HPA create & watch 
kubectl top nodes
kubectl top pods
kubectl autoscale deployment/web --cpu-percent=50 --min=2 --max=6
kubectl get hpa web -w
kubectl describe hpa web
kubectl get deploy web -o jsonpath='{.spec.replicas}{"\n"}'

HPA shows <unknown> for targets. First check?

HPA needs metrics. CPU% is relative to requests — missing requests or a dead metrics-server yields unknown targets.

04 Exam task pattern

Guarantee requests exist before you autoscale. Verify with kubectl top and describe hpa.

end-to-end 
kubectl -n kube-system get deploy metrics-server
kubectl set resources deployment/web --requests=cpu=200m,memory=128Mi
kubectl apply -f - <<'EOF'
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: web
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: web
  minReplicas: 2
  maxReplicas: 5
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 60
EOF
kubectl get hpa web
