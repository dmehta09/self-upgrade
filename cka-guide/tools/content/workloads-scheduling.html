Scheduling: affinity, taints & admission.

Pin Pods with nodeSelector and affinity, keep them apart with anti-affinity, and reserve nodes with taints/tolerations. Quotas and LimitRanges enforce policy at admission time.

01 The idea

The scheduler filters and scores nodes. You steer it with labels, affinity rules, and taints — while admission objects like ResourceQuota reject oversized asks early.

Analogy

nodeSelector is a sticky note: “GPU room only.” Affinity is a preference sheet with must/should. Taints are a velvet rope — you need a matching wristband (toleration) to enter. ResourceQuota is the bouncer counting total guests for the party.

flowchart TB
  POD[Pending Pod]
  FILT[Filter: selector / affinity / taints / resources]
  SCORE[Score: preferences]
  BIND[Bind to node]
  ADM[Admission: Quota / LimitRange]
  ADM --> POD --> FILT --> SCORE --> BIND

02 nodeSelector & affinity

nodeSelector is a simple AND of node labels. Affinity adds operators, multiple terms, and soft preferences (preferredDuringSchedulingIgnoredDuringExecution).

labels & selector 
kubectl get nodes --show-labels
kubectl label node node01 disk=ssd --overwrite
kubectl run ssd-pod --image=nginx --dry-run=client -o yaml \
  | sed '/containers:/i\  nodeSelector:\n    disk: ssd' | kubectl apply -f -
kubectl get pod ssd-pod -o wide
podAntiAffinity · basics 
affinity:
  podAntiAffinity:
    requiredDuringSchedulingIgnoredDuringExecution:
    - labelSelector:
        matchLabels: { app: cache }
      topologyKey: kubernetes.io/hostname

Hard anti-affinity on hostname spreads replicas across nodes — great for HA, fatal if you ask for more replicas than nodes.

03 Taints & tolerations

A taint repels Pods unless they tolerate it. Effects: NoSchedule, PreferNoSchedule, NoExecute.

Taint the node
  • kubectl taint nodes node01 sku=gpu:NoSchedule
  • Control-plane nodes often already tainted
Tolerate on the Pod
  • Match key, operator, effect
  • NoExecute can evict running Pods
taint · tolerate 
kubectl taint node node01 dedicated=payments:NoSchedule
kubectl explain pod.spec.tolerations
# remove with a trailing hyphen:
kubectl taint node node01 dedicated=payments:NoSchedule-
kubectl describe node node01 | sed -n '/Taints/,/Unschedulable/p'
Gotcha Pending

Pending + “didn’t tolerate …” in Events means taints, not “the cluster is broken.” Read kubectl describe pod before you start draining nodes.

04 Quotas & LimitRange (admission)

These run at admission — before the scheduler. ResourceQuota caps namespace totals; LimitRange sets defaults/min/max per Pod or container.

quota · limitrange 
kubectl create namespace team-a
kubectl create quota team-a-q -n team-a \
  --hard=cpu=2,memory=2Gi,pods=10
kubectl apply -n team-a -f - <<'EOF'
apiVersion: v1
kind: LimitRange
metadata: { name: mem-defaults }
spec:
  limits:
  - type: Container
    default: { memory: 256Mi, cpu: 200m }
    defaultRequest: { memory: 128Mi, cpu: 100m }
EOF
kubectl describe quota -n team-a
kubectl describe limitrange -n team-a

A node has taint sku=gpu:NoSchedule. A Pod without tolerations will:

NoSchedule filters the node out. Add a matching toleration (and usually a nodeSelector/affinity) for GPU workloads.
