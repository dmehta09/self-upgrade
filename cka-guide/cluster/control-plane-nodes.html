CLUSTER · control plane Domain 2 · Cluster Architecture (25%)

Control plane & node components.

Know which process owns each hop. CKA cluster tasks fail when you debug kubelet for an etcd problem — or restart the wrong static Pod under /etc/kubernetes/manifests.

01 The idea

The API server is the only front door; etcd remembers; scheduler and controller-manager decide; kubelet and kube-proxy make nodes real.

City hall + job sites analogy

In plain English: city hall (API server) files every permit in the vault (etcd). Planners (scheduler) assign work sites. Inspectors (controllers) chase missing buildings. Crews on each lot (kubelet) pour concrete; traffic cops (kube-proxy) route visitors to the right address.

kube-apiserver
Authn, authz, admission, REST. Clients and components talk here — never straight to etcd.
etcd
Consistent key-value store for cluster state. Lose quorum → lose writes.
kube-scheduler
Binds unbound Pods to nodes (nodeName). Does not start containers.
kube-controller-manager
ReplicaSet, Node, Job, EndpointSlice, and other control loops.
kubelet
Per-node agent: watches assigned Pods, drives CRI, reports status.
kube-proxy
Programs Service VIP → Pod forwarding (iptables/IPVS or replaced by eBPF CNI).

02 Static Pods & manifests

On kubeadm clusters, control-plane binaries run as static Pods. kubelet watches a directory and creates Pods that never go through the scheduler.

Static Pod (control plane)
  • Manifests in /etc/kubernetes/manifests
  • kubelet owns lifecycle locally
  • Mirror object appears in API (read-mostly)
  • Edit YAML → kubelet restarts the component
Normal Pod (workloads)
  • Created via API / controllers
  • Scheduler picks the node
  • Full status, Events, rolling updates
  • Survive only if desired state says so
inspect static Pods 
ls /etc/kubernetes/manifests
# kube-apiserver.yaml  kube-controller-manager.yaml
# kube-scheduler.yaml  etcd.yaml   (on stacked CP)

kubectl get pods -n kube-system -o wide
crictl ps   # runtime view when API is down
Gotcha · delete the mirror Pod

kubectl delete pod kube-apiserver-… -n kube-system only removes the mirror. kubelet recreates it from the file. To change behavior, edit the manifest (or fix certificates / flags) — not “delete until it works.”

03 Request path: write → schedule → run

Walk one create. Every “nothing happened” question is “which box stalled?”

Pending = often scheduler. Bound but not Running = often kubelet/CRI. Service has no Endpoints = labels or not Ready.

component health 
kubectl get --raw='/readyz?verbose'
kubectl get cs 2>/dev/null || true
kubectl -n kube-system get pods -l tier=control-plane
journalctl -u kubelet -e --no-pager | tail -n 40

04 Quick check

You need to change a kube-apiserver flag on a kubeadm control-plane node. Where do you edit?

kubeadm runs apiserver as a static Pod. Edit /etc/kubernetes/manifests/kube-apiserver.yaml; kubelet reloads it. There is no Deployment for the apiserver.

05 Exam rapid-fire

Name the six processes and one job each. Core

Say it out loud: apiserver front door, etcd memory, scheduler binds, controller-manager reconciles, kubelet runs Pods, kube-proxy programs Services.

Answer

Memorize the split: control plane decides and stores; node agents execute. Cloud-controller-manager appears only when cloud integrations are out-of-tree.

Does the scheduler start containers? Warm

Say it out loud: No — it only writes a binding; kubelet starts containers through the CRI.

Answer

If nodeName is set and the Pod still fails, leave the scheduler alone and inspect kubelet, image pull, and mounts.

API is down — how do you still inspect containers? Stretch

Say it out loud: SSH the node and use crictl / journalctl against the runtime and kubelet — kubectl needs a healthy apiserver.

Answer

crictl ps, crictl logs, and kubelet logs diagnose static Pod crash loops when the API is unreachable. Fix manifests and certs on disk.
