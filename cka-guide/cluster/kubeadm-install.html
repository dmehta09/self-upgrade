kubeadm: create & manage clusters.

CKA expects you to bootstrap and maintain clusters with kubeadm: init, join, upgrade, and token/cert workflows — not invent a custom installer.

01 The idea

kubeadm configures the control plane and worker join path. You still provide OS packages, container runtime (containerd), and a CNI after init.

Analogy plain English

kubeadm is the flat-pack furniture instructions: it bolts the control-plane pieces together and prints the join command for more chairs. You still unpack the boxes (packages), plug in power (CRI), and lay the network carpet (CNI).

02 Init & join

Typical exam flow: prepare node → kubeadm init with a pod network CIDR → apply CNI → join workers with token + discovery hash.

init & join 
$</span> sudo kubeadm init --pod-network-cidr=10.244.0.0/16
$</span> mkdir -p $HOME/.kube && sudo cp /etc/kubernetes/admin.conf $HOME/.kube/config
$</span> sudo chown $(id -u):$(id -g) $HOME/.kube/config
$</span> kubectl apply -f <cni-manifest.yaml>
$</span> kubeadm token create --print-join-command
$</span> # on worker:</span>
$</span> sudo kubeadm join <cp-ip>:6443 --token <token> --discovery-token-ca-cert-hash sha256:<hash>
admin.conf
Cluster-admin kubeconfig written under /etc/kubernetes/.
bootstrap token
Short-lived join secret; recreate with kubeadm token create.
Static pods
Control-plane components as manifests in /etc/kubernetes/manifests/.
Gotcha exam trap

Pods stay Pending with no CNI → CoreDNS won’t be Ready. Match --pod-network-cidr to the CNI you install. Expired join tokens fail with unauthorized — create a fresh token, don’t debug the worker forever.

03 Upgrade & certs

Upgrade order: control plane first (kubeadm → kubelet/kubectl packages), then workers. Drain/uncordon as the task requires.

upgrade sketch 
$</span> sudo kubeadm upgrade plan
$</span> sudo kubeadm upgrade apply v1.35.x
$</span> sudo apt-mark unhold kubelet kubectl && sudo apt-get install -y kubelet=1.35.x-* kubectl=1.35.x-*
$</span> sudo systemctl daemon-reload && sudo systemctl restart kubelet
$</span> kubeadm certs check-expiration
$</span> sudo kubeadm certs renew all

After kubeadm init, CoreDNS is Pending and no Pod has an IP. First fix?

kubeadm does not install a network plugin. Without CNI, Pod networking never starts.

04 Exam rapid-fire

What does kubeadm init leave on disk? core

Static Pod manifests under /etc/kubernetes/manifests/, certs under /etc/kubernetes/pki/, and admin.conf for kubectl.

Say it out loud

“Manifests, PKI, admin kubeconfig — then I still install CNI.”

Worker join failed — token expired. Command? core

On a control-plane node: kubeadm token create --print-join-command and rerun join on the worker.

Say it out loud

“New token, new join line — don’t fight TLS with a dead token.”

Upgrade order? stretch

kubeadm upgrade plan/apply on control plane, then upgrade kubelet/kubectl packages and restart kubelet; workers after the control plane is healthy.

Say it out loud

“Control plane first with kubeadm, then kubelet — workers follow.”
