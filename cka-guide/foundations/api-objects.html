API objects, namespaces & labels.

Everything you administer is an API object: a kind, a name, optional namespace, and metadata. Labels select; annotations annotate. Mix them up and Services, NetworkPolicies, and rollouts silently miss their targets.

01 Resources, kinds, names

A kind is the type; a resource is the API path plural; an object is one named instance.

Library catalog card analogy

In plain English: kind is “Book,” the resource is the catalog drawer books, and each ISBN is one object. Namespaces are separate rooms in the library. Labels are color tabs you can sort by; annotations are sticky notes that don’t affect sorting.

apiVersion
Group + version (apps/v1, v1, networking.k8s.io/v1).
kind
CamelCase type: Pod, Deployment, Service, NetworkPolicy.
metadata.name
Unique within its scope (namespace or cluster).
resource
What kubectl lists: pods, deployments, short names po, deploy.
discover-api.sh 
kubectl api-resources
kubectl api-resources --namespaced=true
kubectl explain pod
kubectl get deploy web -o yaml | head

02 Namespaces: scope, not security walls

Namespaces partition names for most workload objects. They are not a substitute for NetworkPolicy or RBAC — but exam tasks almost always name one.

Namespaced
  • Pods, Deployments, Services
  • ConfigMaps, Secrets
  • PVC, NetworkPolicy, Roles
  • Jobs, CronJobs, Ingress
Cluster-scoped
  • Nodes, Namespace objects
  • PV, StorageClass
  • ClusterRole / ClusterRoleBinding
  • CSI drivers, PriorityClass
Gotcha · creating in default by accident

If the stem says namespace prod and you omit -n/metadata.namespace, the object often lands in default. Graders look in the named namespace. Always verify with kubectl get … -n prod.

03 Labels & selectors

Labels are key/value identity tags. Controllers and Services find Pods with selectors. Mismatched labels are a classic “Service has no Endpoints” failure — see Services & endpoints.

flowchart LR
      D[Deployment
selector: app=web] --> RS[ReplicaSet]
      RS --> P1[Pod
labels: app=web]
      RS --> P2[Pod
labels: app=web]
      S[Service
selector: app=web] --> E[Endpoints]
      P1 -.-> E
      P2 -.-> E
      X[Pod
labels: app=api] -.->|not selected| E
label-select.sh 
kubectl get pods -l app=web -n shop
kubectl get pods -l 'tier in (frontend,api)'
kubectl label pod web-0 env=canary --overwrite
kubectl get svc web -o jsonpath='{.spec.selector}'

Equality selectors (app=web) cover most exam tasks. Set-based selectors appear in NetworkPolicies and some controller specs — read the docs example carefully.

04 Annotations vs labels

Both live under metadata. Only labels are for identifying and selecting sets of objects. Annotations store non-identifying metadata (tooling, checksums, change-cause).

LabelsAnnotations
PurposeIdentity & selectionOpaque metadata
Used by selectors?YesNo
Size / charsStrict, short keys/valuesLarger, freer form
Exam exampleService → Pod matchkubernetes.io/change-cause on a Deployment

You need a Service to load-balance only Pods running image build v42. What belongs on those Pods?

Service selectors match labels only. Annotations cannot select Endpoints. OwnerReferences link controllers to Pods; they do not replace Service selectors.

05 Exam rapid-fire

What must match for a Service to get Endpoints? Warm

Say it out loud: the Service selector must match Pod labels in the same namespace, and those Pods must be Ready for readiness-gated endpoints.

Answer

Compare spec.selector on the Service with metadata.labels on Pods. Namespace must match. Then check readiness probes if Endpoints stay empty.

Is a PersistentVolume namespaced? Core

Say it out loud: No — PVs and StorageClasses are cluster-scoped; PVCs are namespaced claims that bind to PVs.

Answer

Create/get PV without -n. Create PVC inside the app namespace. Binding couples them — details in PV & PVC lifecycle.

Why not put “version notes” in labels? Core

Say it out loud: Labels are for selection and must stay query-friendly; put long notes in annotations so you don’t break selectors or hit label constraints.

Answer

Label values have length/character limits and every unique label multiplies selector surface. Use annotations for URLs, build IDs that only humans/tools read, and change-cause text.
