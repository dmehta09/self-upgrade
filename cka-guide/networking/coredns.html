CoreDNS.

Cluster DNS is CoreDNS behind the kube-dns Service in kube-system. Config lives in the Corefile ConfigMap. CKA expects FQDN fluency, ndots quirks, and a crisp DNS failure debug path.

01 The idea

Pods use cluster DNS to resolve Service (and Pod) names. The stable Service name is still kube-dns; the Pods running the server are CoreDNS.

Analogy plain English

CoreDNS is the office phone book. You ask for “api” and it returns the Service ClusterIP. The book’s rules (Corefile) say how to look up internal names and when to ask the public internet. If the librarians (CoreDNS Pods) are down, every app suddenly “can’t connect” even though Services still exist.

Service DNS
my-svc.my-ns.svc.cluster.local (short forms work inside the same ns).
Pod DNS
pod-ip.my-ns.pod.cluster.local (dots in IP become dashes).
kube-dns Service
ClusterIP that kubelet puts into Pod /etc/resolv.conf as nameserver.
Corefile
ConfigMap (usually coredns) in kube-system—plugins, forward, kubernetes zone.

02 Names, ndots, and resolv.conf

Inside namespace shop, api, api.shop, and api.shop.svc all expand via search domains. Prefer FQDN with a trailing dot when debugging to skip search path surprises.

inspect DNS plumbing 
$</span> kubectl -n kube-system get svc kube-dns -o wide
$</span> kubectl -n kube-system get pods -l k8s-app=kube-dns -o wide
$</span> kubectl -n kube-system get cm coredns -o yaml
$</span> kubectl -n shop exec deploy/api -- cat /etc/resolv.conf
$</span> kubectl -n shop run dnstest --rm -it --image=busybox:1.36 --restart=Never -- nslookup api.shop.svc.cluster.local
Gotcha exam trap

DNS success ≠ HTTP success. nslookup returning a ClusterIP only proves name→VIP. Empty Endpoints, wrong port, or NetworkPolicy can still break curl. Conversely, NetworkPolicy deny-egress without allowing UDP/TCP 53 breaks DNS first.

03 Debug DNS failures

Order matters: CoreDNS Pods Ready → kube-dns Endpoints → resolve from a debug Pod → then app config.

Corefile sketch 
.:53 {
    errors
    health {
       lameduck 5s
    }
    ready
    kubernetes cluster.local in-addr.arpa ip6.arpa {
       pods insecure
       fallthrough in-addr.arpa ip6.arpa
    }
    prometheus :9153
    forward . /etc/resolv.conf
    cache 30
    loop
    reload
    loadbalance
}
failure triage 
$</span> kubectl -n kube-system get pods -l k8s-app=kube-dns
$</span> kubectl -n kube-system logs -l k8s-app=kube-dns -c coredns --tail=100
$</span> kubectl -n kube-system get endpoints kube-dns
$</span> kubectl -n kube-system edit cm coredns   # fix Corefile, then wait for reload/rollout</span>
$</span> kubectl -n kube-system rollout restart deploy coredns
$</span> kubectl run -n shop dig --rm -it --image=busybox:1.36 --restart=Never -- \
    nslookup kubernetes.io
In-cluster name works
  • Use svc.ns.svc.cluster.local
  • Confirm Service exists in that ns
  • Then test Endpoints / port
External name fails
  • Corefile forward / upstream DNS
  • Node egress / firewall
  • NP blocking DNS or outbound

From a Pod in dev, which name reliably addresses Service redis in namespace cache?

Short name redis only works inside the cache namespace’s search path. Cross-namespace needs the FQDN with the Service’s namespace.

04 Exam rapid-fire

Where is CoreDNS configured? core

ConfigMap in kube-system (commonly named coredns) holding the Corefile. Pods are selected by k8s-app=kube-dns; clients talk to Service kube-dns.

Say it out loud

“Corefile ConfigMap in kube-system; Service name kube-dns; deployment is CoreDNS.”

What does ndots:5 change? warm

Lookups with fewer than five dots append search domains before treating the name as absolute. That adds latency and can cause surprising resolutions; trailing-dot FQDNs skip the search list.

Say it out loud

“ndots:5 makes short names walk the search path; I use FQDNs when debugging DNS.”

Apps can’t resolve Service names—first three checks? core

(1) CoreDNS Pods Ready and logs clean. (2) kube-dns Service/Endpoints present. (3) nslookup from a debug Pod using the FQDN; if that works, inspect app DNS config / NetworkPolicy / wrong namespace name.

Say it out loud

“CoreDNS healthy, kube-dns endpoints up, then prove resolution with nslookup before touching the app.”
