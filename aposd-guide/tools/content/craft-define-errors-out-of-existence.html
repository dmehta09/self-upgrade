Everyday craft

Define errors out of existence.

Exception handling is one of the worst sources of complexity: every error you throw is a new path each caller must understand, write, and test. Ousterhout's most contrarian advice is to reduce the number of places that throw — often by redefining the semantics so the “error” simply isn't one.

01 Every exception is a path

Exceptions multiply control-flow paths. The best handler is the one you never have to write because the error can't occur.

In plain English analogy

You can put up a “Mind the step” sign (make every visitor handle the hazard) — or you can remove the step so the floor is flat. Defining errors out of existence is removing the step: there's nothing left to trip on, so nobody needs the sign.

02 Four ways to cut exceptions

Define them away
Redefine the API so the “error” case is just a normal result. Unix lets you delete an open file — no error. Python's list[5:99] returns what exists instead of throwing.
Mask low
Handle the exception at a low level and recover, so higher levels never see it (e.g., transparent retry on a transient network blip).
Aggregate
Catch many exceptions in one high-level handler instead of sprinkling try/except everywhere (e.g., one place turns any request error into a 500).
Just crash
For truly unrecoverable, rare conditions (out of memory, corrupt invariant), fail fast and loudly rather than threading handling through the code.

03 Redefine the “error” as normal

A lookup that throws on a missing key forces a try/except at every call site. Redefining “missing” as “return the default” deletes that whole class of handling.

Before · throws
def get_config(cfg, key):
    if key not in cfg:
        raise KeyError(key)
    return cfg[key]

# every caller pays the tax:
try:
    timeout = get_config(cfg, "timeout")
except KeyError:
    timeout = DEFAULT_TIMEOUT
After · defined away
def get_config(cfg, key, default=None):
    return cfg.get(key, default)  # missing = normal

# one path, no handler, nothing to forget:
timeout = get_config(cfg, "timeout", DEFAULT_TIMEOUT)

Why it's better: “key not found” is no longer an exceptional event — it's an ordinary result with a default. Every try/except disappears, along with the chance of forgetting one.

Red flag — both extremes gotcha

Throwing exceptions for ordinary conditions (and forcing handlers everywhere) is the disease. But the cure can be abused: a bare except: that swallows everything hides real bugs. Define away conditions that are genuinely normal — never silence ones that signal a defect.

04 Check yourself

A method throws NotFound whenever a key is absent, and absence is common. Best fix?

Define it away. If absence is common it isn't exceptional — model it as a normal return. Try/except at every call site spreads complexity; a bare except: additionally buries genuine bugs.
