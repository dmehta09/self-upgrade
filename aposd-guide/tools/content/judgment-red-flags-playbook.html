Judgment

The red-flags playbook.

The whole book in two lists. The principles are what to aim for; the red flags are the smells that tell you complexity is creeping in. Learn to spot a red flag mid-edit and you'll catch bad design before it sets.

01 The one rule under all the rules

In plain English analogy

Every red flag is a smoke detector for the same fire: complexity. You don't need to memorise fifteen rules — you need to notice smoke and ask “what made this harder to understand, and how do I undo it?”

It's all about complexity. The principles below are angles of attack; the red flags are how complexity announces itself locally.

02 The design principles

01 · Complexity is incremental
It accrues a grain at a time — fight it continually, not in cleanup sprints. →
02 · Be strategic
Working code isn't enough; invest ~10–20% in design. →
03 · Make modules deep
Simple interface, powerful implementation. →
04 · Hide information
Bury each design decision; avoid leakage & temporal decomposition. →
05 · Somewhat general-purpose
A general interface is usually simpler and deeper. →
06 · Different layer, different abstraction
Each layer must add value — no pass-throughs. →
07 · Pull complexity down
Let the module's author absorb it, not its users. →
08 · Define errors out of existence
Fewer exceptions = fewer paths. →
09 · Comment what code can't say
Capture the why/units/contract; write comments first. →
10 · Names precise & consistent; code obvious
Reader confusion is the test. →
11 · Design it twice
Two real alternatives beat the first idea. →

04 Spot them live

Reading the table is one thing; noticing the smell in real code mid-review is the skill. Three rounds — click the line where the red flag lives.

05 Check yourself

You can't think of a good name for a method, and a short comment won't capture what it does. What's that telling you?

It's a design smell. Difficulty naming or describing something usually means it does too many unrelated things — the entity, not your vocabulary, is the problem. Splitting or reshaping it makes both the name and the comment fall out easily.
