Deep modules · the core move

General-purpose modules are deeper.

Counter-intuitively, a slightly general interface is usually simpler than a narrowly special-purpose one — and deeper. The trick is “somewhat general-purpose”: make the interface general enough to serve several uses, even while the implementation handles only what you need today.

01 “Somewhat” general-purpose

Aim for an interface that is general enough to support multiple uses, but don't build machinery for futures you can't see.

In plain English analogy

Put a power outlet in the wall, not a lamp soldered to the wires. The outlet is more general and simpler — one socket serves lamps, chargers, vacuums. A wall full of purpose-built sockets (“lamp-only,” “charger-only”) is both harder to use and harder to build.

02 Ousterhout's text-editor example

A text class can expose one special method per UI gesture — backspace, delete_selection, insert_char — each baking in cursor/selection rules. Or it can expose two general primitives. The general pair is fewer methods, deeper, and stops the cursor knowledge from leaking into the text storage.

Before · special-purpose
class Text:
    # a shallow method per UI gesture; each
    # one now KNOWS about cursors and selections
    def backspace(self, cursor): ...
    def delete_selection(self, sel): ...
    def insert_char(self, cursor, ch): ...
    def delete_to_end_of_line(self, cursor): ...
    # new gesture? add another method here.
After · general-purpose
class Text:
    def insert(self, pos, s): ...        # two
    def delete(self, start, end): ...    # primitives

# the UI layer composes gestures from them,
# and owns the cursor knowledge itself:
def backspace(text, cursor):
    if cursor > 0:
        text.delete(cursor - 1, cursor)

Why it's better: two general methods cover every gesture, present and future, so Text is deeper. Cursor/selection logic lives in the UI where it belongs instead of leaking into storage — fewer methods, less coupling.

03 Three questions to find the sweet spot

Before settling an interface, Ousterhout asks:

Simplest interface?
What's the simplest interface that still covers all my current needs? (Fewer methods and general usually win together.)
How many uses?
In how many situations will this be used? If a method serves only one caller, it may be too special.
Easy today?
Is the general interface still easy to use for what I need right now? If not, it's too general.
Red flag — both directions gotcha

Too special → a pile of shallow methods that leak caller knowledge. Too general → false generality: knobs and hooks for imagined futures that never arrive (a violation of YAGNI). “Somewhat” means: general interface, today's implementation.

04 Check yourself

Why is a general-purpose interface often simpler than a special-purpose one?

Fewer, deeper primitives. One general pair (insert/delete) covers every gesture, so there are fewer methods to learn and the special-case logic moves up to the layer that actually has the context. More options “for the future” is the opposite mistake — false generality.
