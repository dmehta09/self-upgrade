What is an object, really?

Before pillars and patterns, one idea: an object bundles data and the behavior that works on it into a single thing. Get that, and everything else is just refinements.

01  Objects: nouns that can do things

Procedural code keeps data in one place (variables, dicts) and behavior in another (functions). You pass the data into functions and hope nobody mangles it. Object-oriented code instead bundles the two: an object holds its own data and the methods that act on it.

An object is like a microwave analogy

A microwave has state (door open/closed, timer, power level) and behavior (start, stop, set time). You don't reach inside and twist the magnetron — you press buttons. The buttons are its methods; the internals are hidden. An object is exactly that: state you can't corrupt directly, reached only through well-labelled buttons.

In short: state (the data, called attributes or fields) + behavior (the functions, called methods) = an object.

02  Class vs object: the cookie cutter and the cookie

A class is the blueprint; an object (or instance) is a real thing built from it. One class, many objects — each with its own data.

The class defines what every dog has and does; each object fills in its own values.
dog.py
class Dog:
    def __init__(self, name: str, age: int):
        self.name = name        # attribute (state)
        self.age = age

    def speak(self) -> str:     # method (behavior)
        return f"{self.name} says woof!"

# Build two independent objects from the one blueprint:
rex = Dog("Rex", 3)
bella = Dog("Bella", 5)

print(rex.speak())          # Rex says woof!
print(bella.age)            # 5
print(rex is bella)         # False — different objects
OutputRex says woof! 5 False
What is self?

self is just the object the method was called on — Python passes it automatically. rex.speak() really means Dog.speak(rex). It's how a method knows which dog's data to use.

03  The two dunders you'll use constantly

"Dunder" = double underscore. These special methods let your objects plug into Python's built-in machinery. Two earn their keep immediately:

__init__
The constructor — runs when you create the object, to set up its starting state.
__repr__
The developer-friendly string shown in the REPL, debugger, and when you print() a list of objects. Make it unambiguous.
point.py
class Point:
    def __init__(self, x: float, y: float):
        self.x = x
        self.y = y

    def __repr__(self) -> str:
        return f"Point(x={self.x}, y={self.y})"

p = Point(2, 3)
print(p)              # Point(x=2, y=3)   <- thanks to __repr__
print([p, Point(0, 0)])
OutputPoint(x=2, y=3) [Point(x=2, y=3), Point(x=0, y=0)]
Let @dataclass write the boilerplate

If a class is mostly "hold these fields," the @dataclass decorator generates __init__ and __repr__ for you. We'll use it throughout — but it's worth writing them by hand once so you know what it's doing.

point_dataclass.py
from dataclasses import dataclass

@dataclass
class Point:
    x: float
    y: float

# __init__ and __repr__ are generated automatically:
print(Point(2, 3))    # Point(x=2, y=3)

04  The four pillars, at a glance

Everything in OOP is built from four ideas. We give each its own deep dive next — here's the one-line version so you know where you're headed.

🔒

Encapsulation

Bundle data with the methods that guard it; hide the internals behind a clean surface.

🎭

Abstraction

Expose what something does, not how. Program to a simple idea, not a messy implementation.

🧬

Inheritance

Build a new class on top of an existing one, reusing and specializing its behavior.

🔀

Polymorphism

Many types respond to the same call in their own way — so your code works with all of them.

05  Check yourself

A class is to an object as…

Right: the class is the cutter (the blueprint); each object is a cookie stamped from it, with its own data. One class makes many objects.

In rex.speak(), what is self bound to inside the method?

Right: rex.speak() is shorthand for Dog.speak(rex) — Python passes the instance as self, so the method reads that dog's attributes.
