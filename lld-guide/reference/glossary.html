Glossary & cheatsheet

One page to look things up. Plain-English definitions of every term used across the guide, a SOLID cheatsheet, a "which pattern do I want?" picker, the Pythonic shortcuts, and the UML legend. Press / to search the whole site, or Ctrl+F to find a word on this page.

01  Glossary

The vocabulary of object-oriented design, grouped by theme. Each entry is one crisp sentence — enough to jog the memory, not a whole lesson.

Object-oriented basics

class
A blueprint that defines the attributes and methods every object of that kind will have.
object / instance
A concrete thing built from a class, with its own values in its attributes.
attribute
A piece of data stored on an object (its state), also called a field.
method
A function defined inside a class that operates on an object's data (its behavior).
constructor / __init__
The special method that runs when an object is created, to set up its starting state.
dunder
A "double-underscore" special method (like __init__ or __repr__) that hooks into Python's built-in machinery.
self
The first parameter of a method, automatically bound to the object the method was called on.
encapsulation
Bundling data with the methods that guard it and hiding the internals behind a clean public surface.
abstraction
Exposing what something does while hiding how it does it.
inheritance
Building a new class on top of an existing one to reuse and specialize its behavior (an "is-a" link).
polymorphism
Letting many different types respond to the same method call, each in its own way.
duck typing
Treating an object by the methods it actually supports rather than its declared type — "if it quacks, it's a duck."
abstract base class
A class that can't be instantiated on its own and declares methods subclasses must implement (Python's abc.ABC).
interface / Protocol
A promised set of methods a type must provide; in Python expressed structurally with typing.Protocol.
property
A method exposed as if it were an attribute, letting you add logic behind plain obj.value access.
dataclass
A decorator that auto-generates __init__, __repr__ and more for classes that mainly hold fields.
enum
A type whose values are a fixed, named set of constants (Python's enum.Enum).
composition
A "has-a" relationship where the whole owns its parts and they share its lifetime.
aggregation
A "has-a" relationship where the parts can live independently of the whole.
association
A lasting link between two peer objects that neither owns the other.
coupling
How tightly one piece of code depends on the details of another — looser is better.
cohesion
How focused a class or module is on a single, well-defined responsibility — higher is better.

SOLID & principles

SRP
Single Responsibility — a class should have one reason to change.
OCP
Open/Closed — open for extension, closed for modification.
LSP
Liskov Substitution — a subtype must be usable anywhere its base type is expected.
ISP
Interface Segregation — many small, focused interfaces beat one fat one.
DIP
Dependency Inversion — depend on abstractions, not concrete implementations.
DRY
Don't Repeat Yourself — every piece of knowledge should have a single source of truth.
KISS
Keep It Simple — prefer the simplest design that solves the problem.
YAGNI
You Aren't Gonna Need It — don't build for requirements you don't yet have.
Law of Demeter
"Talk only to your friends" — an object should call methods on its own parts, not reach through them.

Design patterns

design pattern
A named, reusable solution to a recurring design problem.
creational
A pattern family concerned with how objects are created.
structural
A pattern family concerned with how objects are composed into larger structures.
behavioral
A pattern family concerned with how objects interact and share responsibility.
anti-pattern
A common "solution" that looks helpful but creates more problems than it solves.

Low-level design

LLD
Low-Level Design — the detailed class-and-method design of a single component or feature.
HLD
High-Level Design — the system-wide view of services, data stores and how they connect.
entity
A core "thing" in the problem domain that your classes model (a user, an order, a vehicle).
class diagram
A UML drawing of classes and the relationships between them.
UML
Unified Modeling Language — a shared visual notation for describing object-oriented designs.
sequence / state
UML diagrams for time-ordered message flow (sequence) and an object's lifecycle of states (state).
requirement
A stated need the design must satisfy, either functional (what it does) or non-functional (how well).
finite state machine
A model that is always in exactly one of a fixed set of states, changing only via defined transitions — encoded as a table or as State classes.
guard
A condition on a transition: the same event can lead to different states depending on data (e.g. the ATM's third wrong PIN capturing the card).
invariant
A property that must hold at all times — "never two crossing greens," "size ≤ capacity." Name them in the first five minutes of an interview.

Concurrency

race condition
Two threads touch shared data at once and the result depends on timing — see the primer's live demo.
read–modify–write
The three-step shape (x += 1) behind most races; a thread can be switched out between the steps.
critical section
The lines that read-then-write shared state; they must run under one lock, kept as small as possible.
lock / RLock
Mutual exclusion: one holder at a time. RLock lets the same thread re-acquire (needed when locked methods call each other, as in the KV store).
Condition
A lock plus a waiting room: wait(timeout) sleeps until notify() — how the scheduler's workers sleep exactly until work is due.
GIL
CPython's Global Interpreter Lock — serialises bytecodes, not your multi-step logic; compound operations still race.
coroutine / await
An async def function that pauses itself at await points; the event loop switches tasks only there — see the async deep-dive.
backpressure
Making fast producers slow to the consumers' pace (a bounded queue) instead of buffering unboundedly.
transaction / rollback
A group of changes that commits atomically or vanishes entirely; the KV store nests them as a stack of delta maps.
TTL
Time-to-live: data that expires after a duration — lazy expiry on read plus a sweeper, measured on the monotonic clock.

04  The Pythonic shortcut

Many classic patterns exist to work around limits Python doesn't have. Functions are first-class, modules are singletons, and decorators are built in — so the textbook ceremony often collapses to a line or two.

Classic patternIdiomatic Python
SingletonA module (imported once) or a function wrapped in @functools.cache.
StrategyPass a first-class function instead of a strategy object.
IteratorWrite a generator with yield — Python builds the iterator for you.
DecoratorUse the @decorator syntax with functools.wraps to preserve metadata.
CommandStore a callable, or bundle args with functools.partial.
FactoryA dict mapping keys to constructors (dict dispatch).
Prototypecopy.deepcopy(obj) to clone an existing instance.
ObserverKeep a list of callbacks and call each on change.
AdapterDuck typing — give an object the method names the caller expects.

05  UML notation

The five relationship arrows you'll draw in almost any class diagram. The full walkthrough is on Relationships & UML.

Inheritance (is-a)hollow triangle → points to the parent
Composition (owns)filled diamond at the whole; part dies with it
Aggregation (has)hollow diamond; part can outlive the whole
Association (uses)solid arrow; a lasting link between peers
Dependency (needs)dashed arrow; a passing use (a method argument)
Reading the class box

A class is drawn as a box with up to three compartments — name on top, attributes in the middle, methods at the bottom — where + marks public members and - marks private/internal ones.
